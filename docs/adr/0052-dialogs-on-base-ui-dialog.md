# 所有弹窗建在 Base UI Dialog 上，关闭规则只写一处

原先弹窗是自己画的：一层遮罩 `div` 点一下就关，Esc 由各弹窗在 window 上各自监听，叠放时靠一个全局栈在捕获阶段抢 Esc。结果是：在输入框里拖选文字、松在遮罩上，浏览器把这次点击算到遮罩上，填了一半的表单就没了；焦点不锁在弹窗里，Tab 能跑到遮罩后面去按背后的按钮；被隐藏的 Tab 里的对话框仍在收整个窗口的 Esc，会被悄悄取消；Git 面板在捕获阶段先拿走 Esc，关掉的是对话框后面的 diff。

我们决定：所有弹窗建在一个外壳 `ui/dialog` 上，它用 Base UI 的 Dialog（项目已在用的组件库，结构照 shadcn base-nova 的 dialog），关闭规则只写在这一处：

- **Esc 即取消**。里面的控件已收下这次 Esc（`preventDefault`：关补全、清空输入框）时不关；输入法合成中不关（Base UI 自带）。
- **点遮罩按有没有文本输入分**：有的不关，没有的即取消。按下或松开落在面板里的不算点遮罩（Base UI 自带）。
- **弹窗所在的 Tab 被隐藏，就把 Base UI 的打开状态设为关闭、保留挂载**：弹窗收起、填的内容还在，收起期间不挡界面、不收键，切回来再显示。Tab 面板常驻、切走只隐藏（见 Console），后台操作的结果（Git 操作「隐藏」后失败、文件在磁盘上被改的询问）会弹在它所在的 Tab 里，等切回去再看。
- **叠放**写成 Base UI 的嵌套对话框：上层写在下层的子树里，Esc、点遮罩只作用于最上层。挂在 App 根、与下层不在一棵树里的（SSH 提问、传输同名询问）靠 Base UI 对并列模态框的支持（各自的遮罩、焦点在谁里面 Esc 归谁）。
- **焦点**锁在面板内；关掉后还给打开前的元素。Base UI 默认还给触发按钮，我们的弹窗没有触发按钮，而且常被 `autoFocus` 先把焦点移进去，所以外壳在首次渲染时自己记下打开前的焦点，经 `finalFocus` 交回。
- **弹窗显示时即模态**：外壳登记显示中的弹窗（`isDialogOpen()`），应用快捷键（主进程拦下后交给渲染端的切 Tab、切项目等）与面板级的全局键盘监听一律让位。

## Considered Options

- **继续自己画，逐个补洞**：拖选误关、焦点不锁、叠放 Esc、隐藏面板收键都要各写一份判断，这正是原先散落在七八处的 Esc 监听的来路，排除。
- **弹窗一律挂到 body、不管所在 Tab**：代码最省，但别的项目的错误框、冲突询问会直接盖在正在用的 Tab 上，也看不出来自哪个项目，排除。
- **挂载点指到所在面板**（Portal 的 `container`）：面板隐藏时弹窗跟着看不见，但 Base UI 仍当它开着——外面的元素被设成 `aria-hidden`、Esc 与点外面照样收，排除。
- **应用内通知**（WebStorm 的气泡 + 通知列表）：后台操作的结果更适合用通知，但需要做选择的询问仍是弹窗、弹窗开着时被别的途径切走 Tab 也还在，「Tab 隐藏 = 弹窗收起」这条规则仍需要。通知另做（见 docs/backlog.md）。

## Consequences

- 弹窗的内容比外壳晚一拍挂载（Base UI 的 Portal 在 layout effect 里建节点）：外层组件挂载时用 ref 聚焦或测量弹窗里的元素会落空。打开时要聚焦的元素交给外壳的 `initialFocus`；输入框上的 `autoFocus` 不受影响。
- 新增弹窗一律用 `ui/dialog`（或建在它上面的 `FormDialogShell`、`SettingsModal`），不要再自己画遮罩、接 Esc。有文本输入的不传 `dismissOnOutsidePress`。
- 新增 Tab 面板要包在 Console 的 `TabPane` 里，面板里的弹窗才会随面板收起。
- 新增面板级全局键盘监听要在 `isDialogOpen()` 时让位（Files 的用 `overlayOpen()`，已含它）。
