# Diff 面板改用 @pierre/diffs 的 CodeView 渲染，观感对齐 Files 编辑器

ADR-0007 选的 `@git-diff-view/react` 没有虚拟滚动，大 diff 全量渲染；左右对比默认是左右两张表，库逐 hunk 同步行高（先写高度再读 `getBoundingClientRect`），每次都强制整表重排。一份约 300 个 hunk、6 千多行的 diff 在左右对比下渲染 37.5 秒（统一视图 0.6 秒），整个应用卡死；截至 0.1.8 库未修。只在左右对比开库的换行模式能绕开，但「左右对比不能横向滚动」是功能缺口。

我们决定：

- **正文改用 `@pierre/diffs` 的 `CodeView`**：只渲染视口附近的行，同一份 diff 两种视图都在 0.3 秒内画完、滚动不卡；长行是否折行由头部开关决定（两种视图共用），不折行时横向滚动。仍以 git 原始 unified diff 为输入（`parsePatchFiles`），主进程与 IPC 不变；文件与符号链接互换时的两段（ADR-0059）解析成两个文件段，各成一个条目上下排列。
- **观感对齐 Files 编辑器**：代码配色是编辑器同一方案（WebStorm 配色表）生成的 TextMate 主题，与编辑器的 Lezer 高亮规则在 `cm6-setup.ts` 里相邻维护、颜色同源；字排同编辑器（JetBrains Mono 13px / 字重 500 / 行高 22px / 关连字），行号色同编辑器行号栏，改动条同编辑器行号旁的改动条纹，diff 底色沿用应用的 `--diff-*` token。
- **定制面**：库渲染在 shadow DOM 里，样式经宿主上的 `--diffs-*` CSS 变量传入（main.css `.git-diff-body`）。例外一处经库的 `unsafeCSS` 选项注入：改动行底色（库把覆盖色当基色、再与正文底按固定比例混合，比例是 shadow DOM 里的元素级变量，归零后即 token 原色）；升级库后需回归这一处。
- **横向滚动条贴面板底部（`pnpm patch`，`patches/@pierre__diffs@1.6.4.patch`）**：库里每个代码列各自横向滚动、高度随内容，自带的横向滚动条长在内容底部——内容短时悬在面板中间，内容长时在视口之外，库没有相关选项。补丁给 `CodeView` 加公开方法 `attachHorizontalScrollbar(元素)`：面板在正文下方放一个普通元素交给它，补丁在里面为每个代码列（统一视图一列、左右对比两列）各放一条原生横向滚动条，横向位置与宽度对齐该列、与代码列双向同步；库自带的那条隐藏；横向滚轮落在代码列以外（内容下方的空白等）时转给这些滚动条，正文里任何位置都能横向滚动。同一补丁让代码列的可滚宽度**只增不减**（同 VS Code / CodeMirror 的做法，两者都按已渲染过的行定宽、不按全文最长行）：库只渲染视口附近的行，内容列宽度随之变，经过长行后又缩回去；补丁记下出现过的最宽内容并留住（网格布局写进库的列模板变量 `--diffs-code-grid`，flex 布局写内容列的 min-width），换内容、换视图或切换换行时清掉重记，换行模式不留（代码列元素由库复用，留下的宽度会让长行不在视口内折行）。
- **改动块导航（同一补丁）**：块取自解析结果（库的 change 内容段）；当前块由滚动位置、视口高与各块位置决定。库的公开接口只能取到已渲染条目的行位置，也不通知布局变化；按已渲染的内容推算，结果随渲染时机而变（高亮器加载中时正文晚一步才画出，整段在视口外时取不到位置）。补丁给 `CodeView` 加两个公开方法：`getTopForLine(条目, 行号, 侧)` 按库的布局模型算行位置，与库按行滚动同一算法，条目不必已渲染；`subscribeToRender(监听)` 在每轮渲染收尾时通知——滚动、视口尺寸、换视图 / 换行、行高实测都在一轮渲染里落定，当前块在此重算。跳转交给库按行滚动（`scrollTo` 的 line 目标，位置与滚动范围的夹紧都由库算）；跳转后的显式块下标以库实际停下的位置为落点（到底时停不到锚位，不能拿预期位置比对），停在落点时保住。
- **滚动位置**：换视图、切换换行、同文件内容刷新时正文不重挂，由库按行锚定（停在原来看的那一行）；应用只在正文挂上时处理（同文件回到上次的位置，换文件从头看），不按像素硬恢复——那会盖掉库的锚定。
- **补丁范围**：以上三个公开方法，另删掉库遗留的调试钩子（`setup` 里把实例挂到 `window.__INSTANCE`，面板关了实例也不释放）。补丁只在库内部取代码列元素、布局与渲染时机，应用代码只用这三个方法。

## Considered Options

- **左右对比固定换行（继续用 `@git-diff-view/react`）**：改动最小，但左右对比不能横向滚动，且统一视图在更大的文件上仍随行数线性变慢。
- **给 `@git-diff-view/react` 打补丁**：把行高同步改成按帧整批读写、查行改用一次性索引，原型实测同一份 diff 从 37.5 秒降到约 1.2 秒、左右对齐不变；但库不做虚拟滚动，更大的 diff 仍随行数线性变慢，代码高亮也只看得到改动片段。
- **`@codemirror/merge`**：与编辑器同一套，但要新旧两份全文（主进程要改），且自行计算差异，结果可能与 git 不一致（`files-diff-gutter.md` 已因此不用它的 Chunk API）。
- **Monaco diff editor**：体积大，配色体系与项目编辑器不是一套。
- **react-diff-view、diff2html**：同样不虚拟化；react-diff-viewer-continued 虽虚拟化，但要两份全文，社区规模小得多。

## Consequences

- git diff 只含改动附近几行，高亮器没有整个文件的上下文：从结构内部开始的 hunk，开头几个记号可能归类不准（如 JSON 的键被当成字符串）。旧库同样如此；要根治需取全文（库的 `loadDiffFiles`），未做。
- TextMate 与 Lezer 分词规则不同，个别记号的归类与编辑器有出入（如 TextMate 分不出函数调用与方法调用）。
- 改编辑器高亮规则时要同步 `cm6-setup.ts` 里的 TextMate 主题。
- 横向滚动条与改动块导航依赖补丁；`@pierre/diffs` 升级时补丁会失效，须对照新版重做（补丁登记在 `pnpm-workspace.yaml`，版本不符时安装即报错）。
