# Files Tab 音频预览用 wavesurfer.js 画波形进度条，在界面层整文件解码

音频预览要把进度条换成波形：整段音频的起伏画成一条轮廓，已播部分染色，点击或拖动跳转（样子参照 Pixabay 的音乐播放条）。波形来自整段音频的峰值，得先把文件解码一遍。我们用 [wavesurfer.js](https://wavesurfer.xyz)（零依赖）：它在界面层用 Chromium 的 `decodeAudioData` 解码，`<audio>` 能播的格式它都能解，不用另带解码器；波形绘制、高分屏、已播染色、点击与拖动跳转、悬停时间都是库的，我们只写一行控件。

播放仍由我们自己的 `<audio>` 元素承担，经 `media` 选项交给库：库只借它读进度、做跳转，不替换播放源，所以既有的快捷键、方向键切媒体、`dc-media://` 流式播放（ADR-0010）都不变。解码用的数据是库另外按同一地址整文件读取的。

整文件读进内存再解码，耗时与内存都随时长增长，所以**超过 10 分钟的音频不解码**：给库一组全零的峰值和时长，它就不读文件，画成一条平线，进度与跳转照常。解码失败的同样处理——画不出波形只有这一种样子。

## Considered Options

- **保留原生 `<audio controls>`，波形另起一行**：改动最小，但同屏两条进度条。
- **主进程随包带解码程序（ffmpeg / audiowaveform）边读边算峰值**：任意时长都不占界面层内存，但每个平台的安装包要多几十 MB，还要多一条取峰值的通道与缓存。项目里的音频多是音效、配乐、语音片段，不值得。
- **自己解码、自己在画布上画**：解码只是一次 API 调用，但绘制、高分屏、容器变宽重画、拖动跳转、悬停都要重写，正是库已经做好的部分。
- **官方的 React 封装（@wavesurfer/react）**：它把建实例包成 hook；我们要等读到时长再决定建法、换主题时只改颜色，直接用库的实例更直白，不为此多一个依赖。

## Consequences

- 波形与已播段画在画布上，吃不了 CSS 变量：建实例时从元素上读 `--fg-disabled` / `--fg-primary` 的实际色值，换主题时重读（JS 侧色源随 store 的 `theme`，ADR-0026）。悬停的竖线与时间标签是普通 DOM，直接写变量。
- 库往自己的 shadow DOM 里写一段 `<style>`，解码前用 `fetch` 读文件；CSP 里现有的 `style-src 'unsafe-inline'` 与 `connect-src dc-media:` 已经放行，不用改。
- 解码期间波形区空着、音频照常可播；服务器上的音频是下载到本机后走同一预览，同样适用。
- 10 分钟是按「内存随时长线性增长」估的，没有逐机型实测；长音频确有需要时再调这个数，或改走主进程算峰值的方案。
