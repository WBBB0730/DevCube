# 控制台上下文以服务器为准，按 Tab 记住

**Data Source Tab** 的控制台要能选在哪个库上执行：PostgreSQL 还要选模式（不写前缀的表落在哪个模式由 search_path 决定），MySQL / MariaDB 选库，Redis 选库编号（键列表也列这个库）。这就是 **Console Context**（`docs/prd/database.md`「控制台上下文」）。它能从工具栏的下拉改，也能在控制台里直接写语句改（`use`、`set search_path`、`SELECT n`），还会被别的语句顺带改掉（换角色、删掉控制台所在的库、事务回滚）。我们决定：

- **以服务器为准**：主进程按 Tab 持有控制台上下文，只推送回查到的服务器实际状态，渲染端不自己推算。下拉切换是先在控制台的连接上执行（PostgreSQL 设 search_path，MySQL / MariaDB 发 `USE`，Redis 发 `SELECT`），再回查、推送；控制台执行了可能改它的语句后，同样回查。哪些语句算写成纯函数，按第一个关键字判断，宁可多查：PostgreSQL 连所有改结构的语句（建、删、改名模式或授予、收回模式的使用权会改 `current_schema()`，按第一个关键字认不出是哪一种，所以都查）与结束事务的语句都算；Redis 按回复判断，`MULTI` 里排着的 `SELECT` 等 `EXEC` 真正执行了才算。
- **PostgreSQL 切库用会话里的按库连接**：目录展开别的库时本来就按库另连（每个库一条，留到断开），控制台切过去就在那条连接上执行，Tab 自己的连接不动。每条按库连接记下后端进程号：叫停（含断开时先叫停）另开一条连接，对执行语句的那条连接的进程号发 `pg_cancel_backend`。
- **选模式是放到 search_path 最前**：原有各项原样留在后面（去掉同名的那一项），不是把 search_path 整个换成它；只选库不改 search_path。
- **按 Tab 记住，连上即重新应用**：登记的数据源的每个 Data Source Tab 记住自己的（PostgreSQL 记库与整个 search_path），连上、重连、重启后先设回去再回查；记住的库已不在或切不过去时，这一次用默认库，记住的留着下次再试。连接信息被改时忘掉。同一个数据源的各个 Tab 互不影响。
- **事务里的不记**：PostgreSQL 的控制台连接在事务里时，回查到的只推送、不记；结束事务的语句触发的那次回查才记（提交了记新值，回滚了记回滚后的）。
- **补全跟着它**：PostgreSQL 的补全在控制台所在的库上读、按库各存一份；不写前缀的表补全到哪里，直接取控制台上下文。
- **执行与切换互斥**：执行中不能切换，切换中不能执行，免得一条语句落到切到一半的库上。

## Considered Options

- **渲染端记住选中的值，当它是真相**：最简单，但控制台里手写的 `use`、`set search_path`、`SELECT n` 之后，下拉就与服务器不一致了；要跟上只能在渲染端按语句推算，而事务回滚、`SET LOCAL`、换角色、删库这些都推算不准。
- **每次执行前把选中的上下文重新设一遍**：下拉永远说了算，但控制台里手写的 `use` 会被下一次执行悄悄冲掉，违背用户在控制台里的本意；每次执行还多一次往返。
- **PostgreSQL 切库时重连 Tab 的连接**：不多占连接，但目录读取与查询排队共用这条连接，重连会打断它们，连接上的临时表、没提交的事务也随之丢掉；按库连接本来就有。
- **每条语句执行后都回查**：不用认语句，但每条都多一次往返。改为只对可能改它的语句回查，认不出的（如在函数里改的）等下一次回查。
- **选模式时把 search_path 整个换成它**：写法最直观，但会丢掉原有的 `"$user"`、`public` 等项，不写前缀的函数、类型可能就找不到了。
- **不管事务，回查到就记**：事务里的 `SET` 随回滚撤销，`SET LOCAL` 随事务结束失效；记住了，下次连上就会把一个临时值设成会话级。

## Consequences

- PostgreSQL 控制台在别的库上时多占一条按库连接（同目录展开别的库），留到断开。工具栏的「模式」只列控制台所在库的模式，不为列模式另连别的库；要换到别的库的模式，先换库、再换模式，或在目录里那个模式上右键「在控制台中打开」。
- 可能改上下文的语句执行后多一条回查查询，PostgreSQL 每条改结构的语句都多一次。
- 只按语句的第一个关键字认：函数里改的 search_path（如 `select set_config('search_path', …)`）认不出，下拉要等下一次回查才跟上。
- 回滚到保存点（`ROLLBACK TO SAVEPOINT`）不结束事务，不触发回查：保存点之后的 `SET` 被撤销时，下拉要到事务结束或下一次回查才跟上。
- Redis 6.2 以前没有 `CLIENT INFO`，回查不到库编号时按执行成功的 `SELECT n` / `RESET` 推算。
- Redis 的键列表、看键与下拉都用控制台那条连接：控制台开着事务（执行了 `MULTI`、还没 `EXEC` / `DISCARD`）时，发出去的命令只会排进事务，所以这时下拉切不过去，键列表、看键也不发命令，都报「事务还没结束」，要先在控制台里结束事务。
- 控制台所在库的按库连接在事务中途断开、重连时，按内存里的上下文重设 search_path，这可能是事务里的临时值（记住的仍是事务之前的）。
- 运行配置不受控制台上下文影响：每次运行按配置的库另开连接（ADR-0044）。
