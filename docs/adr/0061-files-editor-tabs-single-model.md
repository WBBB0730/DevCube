# Files 面板改为 Editor Tab 加左右两栏；「一次一个」是上限为 1 的特例，由偏好开关决定

**Files Tab** 原先同一时刻至多打开一个条目，`files-tab.md` 把「内层多文件 Tab / 分屏编辑」明确列为不做，ADR-0005 让 ⌘W 在 Files Tab 上无效。现在有用户要同时开着一组文件来回切、并把两个文件左右对照；另一些用户仍要现在这种一次一个的轻。范围见 `docs/prd/files-editor-tabs.md`。

我们决定：

- **一套模型**：每个 Files 面板（项目、服务器的 **Files Tab** 与 **Preview Window**）有 1–2 栏，每栏一排有序的 **Editor Tab** 与其中的当前 Tab，每栏至多一个临时 Tab。打开文件、固定、关闭、移动、分栏都只按这个模型写一遍。
- **临时 Tab**（同 VS Code 的 preview editor）：单击、方向键切媒体等打开都放进当前栏的临时 Tab，下一次打开即替换它；改了内容、双击树里的文件或双击 Tab 才固定。不固定的人用起来与原先一次一个相同。
- **偏好开关就是上限**：设置「偏好 → 文件」的「启用编辑器标签页」默认关。开着时 Tab 数不限、可分两栏；关着时每个面板只有 1 个 Tab、1 栏，这个 Tab 因此永远是临时的（固定后再打开别的文件就要第二个位置）。整套逻辑只在两处读开关：Tab 上限（由它决定能否固定、能否分栏）与 Tab 行是否显示；其余规则不判断开关，关着时的行为由规则自然推出，正是原先的行为。
- **两层 Tab 的键分开**：项目 Tab 栏的键（⌥⌘← / →、⌃Tab、⌘1…9）不变；Editor Tab 用 ⌘W 关当前 Tab（Files Tab 本身仍关不掉）、⇧⌘[ / ⇧⌘] 切上一个 / 下一个、⌘\ 向右分屏（Windows / Linux 为 Ctrl+W、Ctrl+PageUp / Ctrl+PageDown、Ctrl+\，同 VS Code）。
- **三处同构**：项目、服务器、预览窗口用同一模型。服务器「会丢修改前先问」统一为「有未保存修改的 Editor Tab 被替换或关闭之前先问」：开着时改过即固定、不会被替换，只在关 Tab 时问；关着时不会固定，于是在换文件时问，与原先一致。预览窗口里用 ⌘W 关掉最后一个 Tab 即关窗（`×`、菜单或文件被删除关掉最后一个时回空态，免得窗口凭空消失），关着开关时 ⌘W 照旧一按关窗。
- **层级**：每栏最上一行是 Editor Tab 行（与右侧树顶栏同高、对成一条线），其下是原有工具栏（面包屑 + 本栏动作），再下是保存栏、查找栏与正文。工具栏的内容不搬家，分栏时每栏一条、管本栏的当前文件。
- **同一文件可在两栏各开一个**：两个视图共用一份文档，按 CodeMirror 官方 Split View 示例的做法互相转发改动；转来的改动不进对方的撤销记录（CodeMirror 对这类别处来的改动只做映射，同协同编辑），所以各栏撤销的是自己的改动。不把撤销记录集中到一个视图：那样一栏切走或关掉时，记录要在视图之间交接。

## Considered Options

- **不做，维持一次一个 + ⌘E + 「在新窗口中打开」**：⌘E 只解决回到上一个文件，看不到开着哪些，也不能在同一窗口里并排。
- **每次打开都新开一个 Tab**（WebStorm 默认）：点几下就是一长排；方向键切媒体要么刷出一串 Tab，要么另设原地替换的例外；还得设上限自动关最旧的。
- **每个打开的文件成为项目 Tab 栏上的一个 Tab**：省掉一层 Tab，但文件与会话混排，文件树归哪个 Tab、两栏怎么摆都说不清，常驻 Files Tab 的意义也没了。
- **Tab 行取代面包屑那一行**：不多占高度，但分栏后半宽的一栏放不下 Tab 与 PDF 的页码、四档等类型控件，面包屑「点段在树里定位」也没了。
- **VS Code 式：Tab 行 + 细面包屑，「去别处」的按钮收进菜单**：最清爽，但常用的四颗按钮多一跳，打开 PDF 时 Tab 行同样挤。
- **焦点在 Files 面板里时 ⌥⌘← / →、⌃Tab 改管 Editor Tab**：手感同 VS Code，但焦点在编辑器里时跳不出 Files Tab，同一个键在不同地方含义不同。
- **任意横竖多栏**：最灵活，但左右各有项目树与文件树，正文本来就窄。
- **开关两头各写一套**：每条规则（⌘W、服务器何时问、重启恢复什么、方向键切媒体）都要两份，以后每个 Files 新功能都要按两种模式设计、测试。
- **不做开关**：所有人都多一行 Tab，与「Files Tab 不做成 IDE」的定位相悖，也拿走了想要原样的用户的选择。
- **不做开关，只在有固定 Tab 或分栏时显示 Tab 行**：改内容即固定，Tab 行会在打字时冒出来、把编辑器往下推。

## Consequences

- `FilesPane` 从「只有一个打开条目」重构为「栏 → Tab」：原先按面板只有一份的打开态（打开中、冲突、保存出错、Git 基线、格式化出错等）下沉到 Tab 或栏。
- 阅读位置与查找改为按「栏 + 文件」各记一份，某栏第一次打开某文件时取它在任一栏里最近的那份；关着开关时只有一栏，等同原先按文件记。编辑 / 预览开关与 PDF、PPT 的缩略图开关按栏各一份；文件树显隐仍是整个面板一份。
- 落盘形状从「上次打开路径」换成「每栏的 Tab 列表（路径、是否固定）+ 当前 Tab + 当前栏」，旧数据读成一个临时 Tab；读入时按当前上限截断（上限为 1 只取当前栏的当前 Tab，作为临时）；关着开关时只有一个 Tab，即原先的上次打开路径。预览窗口仍不落盘。
- 开关从开到关：只留当前栏的当前 Tab 并让它成为临时，其余按关 Tab 处理（本地自动保存；服务器上有未保存修改的先问，选「取消」则开关不变）；从关到开：唯一的 Tab 原样成为临时 Tab。
- ADR-0005 的「⌘W 对常驻非会话 Tab 为 no-op」在 Files Tab 上改为关当前 Editor Tab；主窗口里没有 Tab 可关时仍无效，常驻 Tab 本身任何时候都不关。
- 以后凡涉及「当前打开的文件」，一律按「当前栏的当前 Tab」写在模型上，不读开关；模型写成纯函数，同一张测试表在两种上限下各跑一遍。
