# 运行配置的参数统一写作 `${{名称}}`

**Project**、**Server**、**Data Source** 上的命令型 **Run Configuration** 都能留**参数**，每次运行前弹框填值（`docs/prd/run-config-params.md`）。参数原先只在数据源上有，照 DataGrip 写作 `${名称}`。本机与服务器上的配置却是交给 shell 执行的命令，`${名称}` 正是 shell（以及 PowerShell）读变量的写法：`${HOME}`、`docker run -v ${PWD}:/app` 都很常见。照搬的话，这些会被误认成参数、弹框并被替换掉，用户也再写不了 shell 变量。我们决定：

- 三处统一只认 `${{名称}}`，数据源上的 `${名称}` 不再算参数。bash、zsh、sh 遇到 `${{` 都报 bad substitution，能正常运行的命令里不会出现它；SQL 与 Redis 命令里也没有这种写法。外形同 GitHub Actions 的 `${{ … }}`，开发者眼熟。
- 名称为两层花括号里去掉首尾空白的文字（`${{ 名称 }}` 即 `${{名称}}`）；空的、跨行的、含花括号的不算。写在哪里都算，包括引号与注释里。
- 本机与服务器上的配置在命令、工作目录与各环境变量的值里认参数（环境变量名不认），数据源上的在内容里认；同名参数写在几处，只问一次。
- 填的值按文字原样换进去，不加引号、不转义。换好后各处照原来的用法：命令交给 shell，工作目录照旧按目录处理，环境变量的值照旧按值处理（服务器上照旧加单引号）。
- 本机与服务器上的配置由主进程替换：渲染端问好参数，随运行请求交上填的值，主进程按 id 取配置、换好再执行，配置仍以主进程存的为准。数据源上的配置照旧由渲染端换好再切语句（ADR-0044）。

## Considered Options

- **沿用 `${名称}`**：与数据源一致，但与 shell、PowerShell 的变量冲突，见上。
- **照 WebStorm 用 `$Prompt:名称$`**（可带默认值 `$Prompt:名称:默认值$`）：本项目的运行配置照 WebStorm 做，shell 里也没有这种写法。但每个参数都要多写一个单词；数据源上还得留着另一种写法（JetBrains 自家也是 DataGrip 用 `${}`、运行配置用 `$Prompt$`），同一个概念两种写法。
- **照 VS Code 用 `${input:名称}`**：与 bash 截取子串的 `${变量:偏移}` 同形；VS Code 还要另写一段 inputs 定义，在命令里直接写名称等于自创。
- **`{{名称}}`**（Postman、Apifox）：docker、kubectl 的 `--format '{{.Names}}'` 这类 Go 模板会被误认。
- **`$名称$`**：shell 里常把变量连着写（`$A$B`、`$PATH:$HOME`），会被误认。
- **`%名称%`**：Windows cmd 读变量的写法，`date +%Y%m%d` 这类格式串里也有。

## Consequences

- 数据源上的写法不再同 DataGrip：习惯写 `${名称}` 的人不会看到参数框，这段原样发给数据库，报错即可看出。数据源上的参数还没发版，不用迁移。
- 没有转义：内容里要原样出现 `${{…}}`（比如往文件里写 GitHub Actions 的表达式）时，会被当成参数。真遇到再加转义。
- 没有默认值的写法：第一次运行时输入框为空，之后预填上次填的值。
- PowerShell 里的 `${{…}}` 没有实测（本机没有 PowerShell）。
- 记住的值从数据源上的配置推广到全部命令型配置，按配置 id 存；删除配置、移除所在条目时一并删掉。
