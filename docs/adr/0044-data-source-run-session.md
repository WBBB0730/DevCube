# 数据源上的配置的运行会话不走终端：结果由主进程持有，执行完一次推送

**Data Source** 也能有命令型 **Run Configuration**：内容是一段 SQL（Redis 为几行命令），在它的某个库上执行（`docs/prd/database.md`「运行配置」）。其他 **Run Session** 都是 PTY 里的进程，输出是字节流，由 xterm 显示（ADR-0001、ADR-0004）。数据库执行的结果却是表格和各条语句的影响行数，控制台早就有一套现成的结果区。我们决定：

- 数据源上的配置是命令型的第三种归属（**Project** 在本机、**Server** 在服务器上、**Data Source** 在某个库上），沿用同一份配置数组（ADR-0002）、同一个配置对话框外壳、左树的配置行，以及 Run Session 的状态、Tab、操作栏与单实例规则。runner 仍是 Run Session 唯一的对外出口：运行、停止、关闭、列出会话、退出确认都经它，只是把这类配置转给数据源一侧执行，写法同服务器上的配置转给 exec 通道。
- 它的 Run Session 不是终端：输出是这次执行的结果（SQL 为表格或语句列表，Redis 为 redis-cli 式的记录），由主进程持有，**执行完一次推送**，正文用控制台同一个结果区显示；渲染端重载后向主进程取回，对应 PTY 会话的快照回填。整个没能执行（连不上、没有要执行的语句、已取消等）时正文写明原因，没有运行头与结束行。
- 要执行的语句由渲染端切好、随运行请求一起交给主进程：SQL 同控制台的切法——`@codemirror/lang-sql` 的语法树切词、补全引擎照搬的 sqlparse 切分（ADR-0047），字符串、注释、PostgreSQL 的 `$$` 函数体、建过程 / 函数 / 触发器时的 BEGIN … END 块里的分号都不切——Redis 一行一条。
- 配置里的参数（写法见 ADR-0048）也在渲染端替换：运行前的参数框本来就在渲染端，填好的值先按文字原样换进内容，再切语句，所以填的值里带分号、换行时照样切得对。主进程只收到切好的语句，不知道有过参数（本机、服务器上的配置则由主进程替换，见 ADR-0048）。
- 每次运行开一条自己的连接，执行完即断开，不与任何 **Data Source Tab** 共用；编辑数据源的连接信息不打断正在运行的这一次，下次运行才用新的连接信息（同服务器上的配置）。
- 停止即取消：还在连接或等密码时立即以「已取消」结束；执行中叫停服务器上正在执行的语句（PostgreSQL `pg_cancel_backend`、MySQL / MariaDB `KILL QUERY`、SQLite 结束查询线程、Redis 断开这条私有连接）再断开，被打断的那条记为已取消。被停止的一次一律按失败收尾；重跑先叫停旧的一次。
- 密码被拒（或要密码却没记住）时，运行会话保持「运行中」等密码，正文出与 Data Source Tab 未连接页相同的密码框，交上来即带着密码重跑（同服务器上的配置运行时弹提问，状态仍是运行中）。
- 操作栏仍只有按钮：运行 / 重跑、停止，SQL 类型另有「导出」（导出这次取回的结果），**不出「清空」**——输出是一次执行的结果快照，不是持续增长的日志，清空没有用处。

## Considered Options

- **把结果打成文字写进 xterm**：Run Session 只有一种正文，但丢掉了表格、分页、选区复制和导出，看宽表只能靠横向滚一堆字符。
- **像控制台那样由渲染端驱动**：不用在主进程另写编排，但渲染端一重载，运行的状态和结果就丢了；退出确认也看不到它，退出时不会先叫停语句。
- **共用 Data Source Tab 的连接**：省一次建连，但控制台、目录都在那条连接上排队，一段长语句会把它们一起卡住；运行还得依赖某个 Tab 开着、连着，控制台里 `use`、`set search_path`、没提交的事务也会串进来。
- **主进程自己切语句**：运行就不必由渲染端发起，但要么把 `@codemirror/lang-sql` 编进主进程产物——连同 CodeMirror 的语言包及其界面层依赖（如 `@codemirror/view`）一起带过去，主进程只为切语句背上一套编辑器；要么按分号切，会切坏字符串、注释和 PostgreSQL 的 `$$` 函数体。
- **每执行完一条就推送一次**：长脚本能看到进度，但控制台执行中也不显示进度、执行完才给结果；为此要给执行函数加进度回调、让「执行中的结果」多一层含义，得不偿失。

## Consequences

- Run Session 有了两种正文：终端（xterm）与结果区。ADR-0001、ADR-0004 只适用于终端型的运行会话；清空输出、stdin、改尺寸对数据源上的配置都不适用。
- 运行只能由渲染端发起（参数要由它问、语句要由它切好交来）。以后要做定时运行这类不经界面的触发，得先解决「谁来填参数、谁来切语句」。
- 每次运行都要建一次连接（加密协商、认证），比在已连着的 Tab 里执行多一段等待；换来的是互不阻塞、状态干净。
- 运行会话的结果与连接都不跨重启（同其他 Run Session，ADR-0002、ADR-0008）。退出确认把运行中（含等密码）的算作运行会话；退出时先叫停正在执行的语句，最多等 2 秒再断开（同 Data Source Tab 的控制台）。
- 运行会话的操作栏在数据源上的配置里与其他配置不同：没有「清空」，SQL 类型另有「导出」。
