# Files Tab 表格预览用 react-xlsx 的 DOM 渲染、页面线程解析，CSV 按原文转成工作簿交同一预览

Files Tab 要内嵌看 Excel。我们用四份真实表格（4000 多行的大表、中文清单、样式很密的宋体表、小表）加一份自造的功能样本（图表、图片、条件格式），逐表对比了三个纯前端方案：react-xlsx（@extend-ai/react-xlsx，解析核心是编译成 WebAssembly 的 @dukelib/sheets-wasm）、FortuneSheet + FortuneExcel（老牌表格编辑器加一个导入插件）、File Viewer 的表格模块（@file-viewer/renderer-spreadsheet）。FortuneSheet 把日期画成序号、百分比与金额画成原始数字、TRUE / FALSE 画成 1 / 0，也没有图表，大文件还最慢；File Viewer 有三张表整体错一行、没有冻结窗格。react-xlsx 在数字格式、图表、冻结窗格上最可靠，选它。它最年轻（0.x、主要一人维护、解析核心也是 0.1 版的个人项目），这是「效果最好」与「最稳」不是同一个库时的取舍。Univer 开源版不能导入 xlsx，SheetJS / ExcelJS 只读数据、样式与合并冻结图表全要自己画，都没进对比。

用法上有两处偏离库的默认：用 DOM 渲染而不是默认的画布（画布不画溢出到邻格的长文字、丢居中的合并大标题）；在页面线程解析而不是后台线程（线程里没有 DOMParser，条件格式、表格样式、合并标题等靠 XML 结构的信息会悄悄丢掉，生产态的 `file://` 下起线程也另有麻烦）。代价是解析期间界面等它（900 KB 约 1.5 秒），所以 Excel 超过 10 MB 不预览。库的缺陷同 PPT 那次（ADR-0033）用 pnpm 补丁修在库上（钉在 0.16.5）：缺字体时按原字体风格补同风格备选（原先一律补无衬线，宋体画成黑体）；条件格式图标集没写样式时按 OOXML 默认三色交通灯（原先整条规则被丢）；「选中格子」加 `reveal` 选项，复用方向键移动选中格的滚动规则把格子滚入视口（查找定位要用，库原本选中不滚动）；页面线程取数的范围修正——库把冻结行也算进「视口上下各多 48 行」的取数范围，范围于是总从表头连到视口，越往下每滚一步取得越多（4000 行的表滚到底部每帧近 1 秒），且每滚一步都整批重取。改为只按滚动区算（冻结行只有几行，走库现成的逐格读取），并把范围按 128 行一块对齐，视口在块内滚动时 useMemo 直接沿用已取的行（库的后台线程路径同样复用已取范围）；后台线程路径不动（它没有逐格读取的兜底）。补丁暂不提交给上游。

CSV / TSV 不另找渲染器：用 Papa Parse 解析，每格按原文字符串写进一个新工作簿，存成 xlsx 字节交给同一个预览，所以两种表格一套外观与操作。不用引擎自带的 CSV 导入——它按 Excel 规则转类型（`00123` 变 123）、也不认 TSV。

## Considered Options

- **FortuneSheet + FortuneExcel / File Viewer 的表格模块**：见上，格式或行号冻结是硬伤；FortuneSheet 本体也已停更。
- **库的默认画布渲染 + 后台线程解析**：大文件不卡界面，但长文字截断、条件格式与表格样式丢失，预览不可信。
- **库的深色模式**：白字落到浅底上、边框看不见；表格保持浅色，同 PDF / PPT 页面。
- **CSV 走编辑器里的纯文本、或自己画一张 HTML 表**：前者就是现状的问题；后者要重做缩放、选中复制、查找与大表虚拟滚动，徒增一套。

## Consequences

- 解析核心的 WebAssembly（约 4.4 MB）经 `dc-media` 应用资源通道 `a=xlsx` 读取：打包时 extraResources 复制到 resources/xlsx，开发态读 node_modules；通道从只服务 PDF.js 泛化为按资源包声明放行路径。CSP `script-src` 加 `'wasm-unsafe-eval'`（只放开编译 WebAssembly）。
- 库里引用了它自带的解析线程脚本，打包工具仍要处理它：渲染层打包的线程输出格式改为 ES 模块（默认 iife 不支持线程里的动态 import）。产物因此多一份用不到的线程脚本和一份 WebAssembly（胶水代码按自身路径引用它，打包工具照例带上），不借补丁去掉。
- 补丁只改库的 ES 构建与类型声明；升级库版本时补丁对不上，pnpm 安装直接失败，须按新版本重做（或等上游修复后删掉）。
- 大表滚动在块内每帧约 17 毫秒；跨过行块边界的那一帧要取一整批（含样式）数据，约 0.1 秒。按行增量缓存能去掉这一下，但要在库最热的代码里加缓存与淘汰，暂不做。
- 库在 DOM 渲染下不接 Cmd/Ctrl+滚轮与捏合缩放，由我们接：只经公开的 `setZoomScale` 改倍率，锚点换算需要库的滚动视口，经公开的 `renderScroller` 取得（写法同库默认，按工作表重挂）。
- 还画不出的：格子内分段的富文本颜色、文字旋转。
