# 文件打开方式：安装只注册候选，设为默认按平台走官方路径

DevCube 要能被设为图片 / PDF / PPT / Excel / 音频 / 视频 / 文本的默认打开程序（`docs/prd/file-preview-window.md`）。登记打开方式（macOS Info.plist 文件关联：角色 Viewer + LSHandlerRank Alternate；Windows 由应用登记候选；Linux desktop MIME）只让 DevCube 出现在系统「打开方式」列表，**安装不改用户选过的默认**；设为默认是设置里的显式动作，按平台：

- **macOS**：Electron 只暴露 URL scheme 的默认程序接口，文件类型要走 LaunchServices。我们随包带一个用 `swiftc` 编译的单文件 CLI 小助手（`build/mac/DefaultAppHelper.swift`，`get` / `set` 两个子命令，调 NSWorkspace 官方接口、不弹确认框），放在 `Contents/Resources`，由 @electron/osx-sign 遍历 Contents 时自动签名公证。`set` 按 .app 路径指定应用。**LaunchServices 只接受声明了该文档类型的应用**：对未声明的应用设默认会静默无效（退出码 0、查询仍为空），Finder「打开方式」也只列声明过的。Dev 跑的 node_modules 里的 Electron.app 什么都没声明，于是 Dev 身份用系统自带的 `osacompile` 在 Dev 数据目录生成一个「DevCube Dev.app」AppleScript 小壳（Info.plist 声明「文件打开方式」各类文件、bundle id `com.wbbb.devcube.dev`，`on open` 把文件 `open -a` 转给运行中的 dev 实例），改完 plist 后 ad-hoc 重签并经助手调公开接口 `LSRegisterURL` 注册（不用 Support 目录下的 lsregister）——实证小壳必须落在用户目录常规位置且签名有效，临时目录里的应用不会被列为候选。与快速操作在 Dev 下同一口径：dev 实例未运行则只拉起空 Electron。不做 FinderSync 那种扩展工程（ADR-0025 的反对理由是 Xcode 工程 + 扩展 + 签名面，单文件 CLI 三者都没有）。
- **Windows**：Win8 起默认程序选择由系统用用户级签名锁住，程序不可改；伪造签名的 SetUserFTA 类 hack 明确不用。按钮 = 登记候选，再打开 `ms-settings:defaultapps`（Win11 深链到本应用条目）让用户点选；状态一次读出全部 `FileExts\<ext>\UserChoice` 的 ProgId 比对。
  - **候选由应用自己登记，不用 electron-builder 的文件关联**：它的 NSIS 安装脚本对每个扩展名都把 `.ext` 的默认值写成本应用（用户没手选过的类型装完就被抢走），ProgId 直接用「PDF」「Image」这种通用名（正式版与 Beta 写同一个键，后装覆盖先装、卸一个另一个也没了），卸载时又不还原默认值（留下指向已删 ProgId 的残留）。因此文件关联只写进 macOS 配置；Windows 由应用生成一份 .reg 经 `reg import` 一次写入 HKCU：各类 ProgId（产品名去空格 + 类别，按 Edition 区分）、各扩展名 `OpenWithProgids` 挂上该 ProgId（「打开方式」据此列出）、Capabilities + RegisteredApplications（「默认应用」页据此列出），不碰 `.ext` 的默认值。安装版每次启动对齐（装完要启动一次才出现在「打开方式」里），便携版与 Dev 不在启动时写注册表、只在点「设置」时登记。真卸载时 `build/installer.nsh` 删掉各类 ProgId、Capabilities、RegisteredApplications，并遍历各扩展名键摘掉本应用的 OpenWithProgids；安装 / 更新时把 v1.10–v1.15 留下的、仍指向已不存在通用 ProgId 的 `.ext` 默认值删掉。经资源管理器「始终使用此应用」把旧版设成默认的用户，ProgId 变了需要重选一次。
  - 一个扩展名一条 `reg add` 的写法在文本一类（几十个扩展名）下要起上百个进程，故改为 .reg 一次导入。
- **Linux**：`xdg-mime default <desktop> <mime…>`，状态用 `xdg-mime query default`。

各类扩展名表与 Files 面板的类型判定同源（`FILES_OPEN_WITH_EXTS`），保证设成默认的类型恒能在 Files 面板里预览或编辑；`svg` 归图片组、CSV / TSV 归 Excel 组，虽然它们的打开分流是文本（打开即预览态）。CSV 在 DevCube 里打开就是表格，原默认多是 Excel / Numbers / WPS 这类表格软件：把代码交给 DevCube 的人未必想让 CSV 也离开表格软件，把表格交给 DevCube 的人多半要连 CSV 一起，故随 Excel 组而非文本组；树顶类型筛选同样归「Excel」，行名不改。音频与视频在设默认上分开（用户常只想接管其一），在 Files 树顶的类型筛选里仍并作「音视频」一类。

文本（代码、Markdown、配置、日志等）是一组：Files 文本扩展名表里真正的扩展名，去掉 html / htm（双击网页应交给浏览器）、svg（已在图片组）与 CSV / TSV（已在 Excel 组）；`.gitignore`、`.env` 这类点文件名不进——系统按扩展名关联，这类文件在 macOS 上实测没有扩展名。macOS 把 `.ts` / `.mts` 识别成 MPEG-2 传输流视频（`public.mpeg-2-transport-stream` / `public.avchd-mpeg-2-transport-stream`），按扩展名设默认会连带接管这类视频；开发者手里的 `.ts` 几乎都是 TypeScript，接受这个代价。Linux 只写 TypeScript 自己的 `application/typescript`（较新的 shared-mime-info 才有），不写 `video/mp2t`；规范名在新旧版本间改过的（javascript / yaml / shellscript）新旧两个名字都写。

「不改用户选过的默认」在 macOS 上有一个平台例外（实测 macOS 15，Dev 小壳）：用户没手选过默认、系统也不认识的扩展名（动态类型，如 go / rs / vue / scss / toml / sql），LaunchServices 不按 LSHandlerRank 挑默认，DevCube 一登记就可能直接成为默认，哪怕别的应用声明了 Owner，重新登记那个应用也挑不回去；`.mts` 同理（QuickTime 只声明上级类型，DevCube 声明的精确类型胜出）。用户手选过的默认、系统认识的类型都不受影响。这与任何声明这些扩展名的编辑器相同（被挑中的原本也是系统随手挑的），接受，不为此在 macOS 上去掉这批扩展名——那会让 go、rs、vue 等无法设为 DevCube 打开，且「系统认识哪些扩展名」随 macOS 版本变化，只能写死一张会过时的表。
