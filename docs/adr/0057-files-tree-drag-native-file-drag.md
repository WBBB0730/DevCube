# Files 文件树的拖动走系统原生文件拖拽，不用 dnd-kit

文件树要支持三种拖动（`docs/prd/files-tree-move-copy.md`）：树内拖到别的文件夹即移动、从 Finder 拖进来即复制、从树拖到 Finder 或聊天窗口即带出文件本身。左树与 Tab 栏的拖拽排序用的是 dnd-kit，但它基于指针事件、只在页面内部生效：接不住从系统拖进来的文件，也拖不出页面。拖出文件在 Electron 里只有一条官方路径：在 `dragstart` 里拦下页面拖放，经 IPC 让主进程调 `webContents.startDrag`，交给系统发起原生文件拖拽。

我们决定：本机的树开始拖动时一律交给系统原生文件拖拽，同一次拖动既能拖出去，也能落回树内。落回树内时，拖动的就是普通的系统文件，以真实来源为准：都在这棵树的根内即移动（按住 ⌥ / Ctrl 为复制），否则复制进来。这与 Finder 判断同一磁盘内移动、跨磁盘复制的规则一致，也让「从 Finder 把项目里的文件拖到项目的另一个文件夹」得到同样的结果。拖动过程中页面拿不到来源路径，所以落点能不能放（不能落到自身或它里面）、显示移动还是复制，按「这次是不是从本树拖出的」判断：开始拖时记下条目，松手后指针第一次移动即清掉（原生拖拽结束时页面收不到 `dragend`）。

服务器上的文件不在本机，无法交给系统拖拽，树内拖动走页面内拖放（自定义的数据类型带着路径），只能落回树内。

## Considered Options

- **系统原生文件拖拽（选中）**：一种拖动同时覆盖树内移动、拖入、拖出三件事，判定规则与 Finder 一致。
- **dnd-kit 管树内移动，另做拖入 / 拖出**：一次手势只能属于其中一套机制，树内拖出去或从外面拖进来都要另起一套，同一个动作有两种手感。
- **页面内拖放（HTML5 DnD）管树内移动**：拖出页面得不到文件本身；Chromium 的 `DownloadURL` 拖放只有 Chrome 支持，且只认真实的 HTTP 地址，Electron 里用不上。

## Consequences

- 系统原生拖拽允许的效果由平台决定：Windows 上 Electron 的 `startDrag` 只许复制 / 链接（electron/electron#15361），树内移动时光标也只能显示为复制，落下后照样是移动。macOS 上是否允许显示为移动、多文件拖出与拖回的手感待实测。
- 拖动的图标取系统给第一个文件的图标，取不到用应用图标（macOS 上图标不能为空）。
