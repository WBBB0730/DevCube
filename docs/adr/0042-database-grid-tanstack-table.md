# 数据源的表格用 TanStack Table 9 自己画

**Data Source Tab** 里，「当前对象」和控制台结果都是表格。它要撑得住上百万行、上百列，能拖选一片格子复制到 Excel，能拖列宽，以后还要在格子里直接编辑。我们决定：

- 表格状态（区域选择、列宽）交给 TanStack Table 9；排序不用它的，点表头改的是 ORDER BY 框里的文字，由数据库排序；
- 行和列的虚拟化交给项目已在用的 TanStack Virtual；
- 渲染、按键和编辑状态由我们自己画，按 DESIGN.md 用 Tailwind。

选它的关键是 TanStack Table 9 新增的区域选择：支持拖选、Shift 扩展、多块选区，还能直接取出选中的数据。「选一片复制」是数据库工具里最常用的操作，而 react-data-grid 做不到。

## Considered Options

- **react-data-grid（7.0.0-beta）**：虚拟滚动、列宽、单格选中、编辑状态和键盘操作都现成。但它只能选单个格子或勾选整行，没有区域选择，硬加只能给库打补丁；页面结构是固定的，外观只能通过 CSS 变量和类名改；而且多年停在 beta。
- **Glide Data Grid**：用 canvas 画，最快。但稳定版停在 6.0.3，只声明支持到 React 18（项目用的是 React 19），2024 年还停更过一阵。
- **AG Grid Community**：功能最全，但区域选择和剪贴板都在收费版里，体积也大。
- **RevoGrid**：免费版就有区域选择和剪贴板，但它本身是 Web Component，在 React 里要多包一层，改外观要穿透它自己的样式体系。
- **react-xlsx**（Files Tab 的表格预览，ADR-0034）：只读，按 Excel 的样子画，不适合显示查询结果。

## Consequences

- 表格外壳归我们维护：渲染、按键绑定、编辑状态、把选中格子滚到可见位置。格子本身怎么画、编辑器怎么做，无论选哪个库都得自己写。
- 行和列都走 TanStack Virtual，宽表（上百列）也只画视口里的那些列。
- 复制时生成 TSV：含制表符、换行或引号的格子整格加引号，格内的引号写两遍，这是电子表格认的规则。
- 以后要在表格里直接改数据，编辑状态和改动标色都在这一层做，不受库的限制。
