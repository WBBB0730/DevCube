# Files 面板的按键按焦点分文件树与正文两边：大部分键两边一样，文件树自己的操作只在焦点在树上时生效

Files 面板（项目、服务器的 **Files Tab** 与 **Preview Window**）原先「只看焦点」：焦点在文件树上方向键归树，在正文上归正文（切媒体、翻页），空格、查找、缩放又各有各的条件。界面不画焦点框，同一个键按下去落到哪里看不出来；从正文回文件树、在左右两栏之间切只能用鼠标；PDF、PPT、表格一打开就自动拿走焦点，换文件要先点回树上。历史对话里反复出现的就是「按键没反应，要先点一下」。

我们决定：

- **按焦点分两边**：焦点在文件树上算文件树，其余都算正文区。
- **大部分键两边一样**：↑ / ↓ 换文件，← / → 在文件内前后（看图换相邻媒体、音视频快退快进、PDF / PPT 翻页），播放键、翻页滚动、查找、缩放、保存——这些键只有一个可能的去处，不要求先点对地方。
- **文件树自己的操作只在焦点在树上时生效**：Enter、重命名、删除、全选、剪切复制粘贴、文件夹开合。看着正文按下的键不会动到文件。
- **进了正文才归正文的键**：「进得去」的正文只有文本编辑器、表格、PDF / PPT、Markdown 预览与 SQLite 视图——它们自己要用方向键或要输入。看图与音视频不分里外。进正文靠 Enter、双击、鼠标点、⇧⌘E 等显式动作；打开文件本身不进。
- **⇧⌘E 轮转**：文件树 → 左栏 → 右栏 → 文件树，是键盘进出正文与切栏的专用键。
- **看得见**：焦点在树上时选中行是蓝的，不在时是灰的，仍不画焦点框。蓝即这棵树此刻接按键；规则与样式各树共用（左树、数据源的目录与键列表、「选择服务器上的目录」弹窗）。
- **焦点的落点靠还回去，不靠放宽条件**：在文件树上发起的操作做完，焦点回到文件树；进了正文之后换文件、换视图，焦点跟到新的正文上；正文工具栏与查找栏上的钮按下不抢焦点；关掉查找后焦点回到打开之前的地方。
- **不做「在树上打字即写入筛选」**，所有树一致；筛选用 ⌥⌘F（聚焦当前面板的筛选框）与 ⌥⌘P。
- **归属只判一次**：方向键归文件树、归正文还是都不接，由一个纯函数按「处境 × 焦点行是不是文件夹 × 正文类型」判定，文件面板的键盘处理与各正文的键盘处理都调它，同一次按键只有一个去处。

完整规则见 `docs/prd/files-tab.md`「按键归属」。

## Considered Options

- **文件树的操作也不看焦点**（先做过这一版）：重命名、删除、全选、粘贴、Enter 在焦点不在树上时照样生效，选中行只在进了正文时才变灰。起因是「删完再按删除没反应」，但那是焦点落点的问题，早已由「删除后焦点留在文件树」修好；放宽条件的结果是看着正文按 ⌘A 全选了整棵树、按 ⌘V 把文件粘了进去，蓝色也失去了含义。
- **完全只看焦点，另加切换键**：按键规则最传统；但换文件、播放、翻页这些只有一个去处的键也要先切焦点，纯键盘逐个听音效、看图时尤其碎。
- **完全不分焦点，方向键固定分工**（↑ / ↓ 恒为换文件，← / → 恒归正文）：点进 PDF 再按 ↓ 却换了文件，与大多数软件相反；表格与文本编辑器仍得靠焦点。
- **保留「在树上打字即写入筛选」**：它正是「空格、M、F 被筛选框截走」的来源。
- **各正文各挂各的全局键盘监听、互相用守卫让位**（原做法）：同一阶段的监听互相拦不住，只能靠各自的条件凑成不重叠；归属集中到一个纯函数后可以表驱动单测。

## Consequences

- 推翻了三处原有决定：PDF / PPT 的 ← / → 原为换文件、现为翻页；看图与音视频在正文上的 ↑ / ↓ 原只走媒体文件、现逐行走所有文件（看图用 ← / → 跳过别的文件，音视频没有跳过的键）；焦点在文件树上时，文件行的 ← / →（同 WebStorm）在正文用得上这两个键时让给正文。
- PDF、PPT、表格打开时不再自动拿走焦点。
- 焦点在文件树上时 PageUp / PageDown / Home / End 与空格滚的是正文，不是文件树。
- 各树的选中行在焦点离开那棵树后是灰的；左树的当前条目因此多数时候是灰的。
- 新增正文类型时要先定它「进不进得去」、拿方向键做什么，并在归属判定的表里补上对应的行。
