# 一个项目多个仓库：扫整个项目，Git Tab 一次看一个，按仓库目录分桶

**Git Tab** 原先默认每个 **Project** 只有一个仓库（从项目目录往上找到的那个），嵌套仓库、子模块、本身不是仓库的「仓库集合」文件夹都处理不好。范围见 `docs/prd/git-nested-repos.md`。

我们决定：

- **一个 Project 有 0..N 个 Repository**：项目自己所在的仓库，加上项目里的嵌套仓库与子模块。发现时扫整个项目、深度不限（同 JetBrains），跳过隐藏目录、`node_modules` 与被 git 忽略的目录；仓库里面交给 git（`ls-files --others` 里以 `/` 结尾的条目即嵌套仓库，子模块读 `.gitmodules`），不在仓库里的目录才自己读目录。项目目录被上层仓库忽略时不认那个上层仓库（同 JetBrains）。
- **打开项目时才完整发现**（同 JetBrains、VS Code、Zed 打开项目 / 文件夹时才找）：启动时每个项目只查它自己所在的仓库（监听要它，与原先同等开销）；渲染端第一次要某个项目的仓库清单时（选中它、打开它的 Git / 文件页）才扫整个项目，扫完缓存并接进监听。
- **Git Tab 一次看一个**（同 Git Graph、Zed），工具栏的仓库下拉切换，选中的按项目记住。
- **按「在哪个目录跑 git」分桶**：渲染端状态、每仓库设置、`git:changed`、Task 都以 `GitRepo.path` 为键——项目自己的仓库就是项目路径，嵌套仓库是它的根目录。主进程的读写接口不改形状，只是传进来的目录换成选中的仓库。
- **文件归离它最近的仓库**：外层的未提交更改不含嵌套仓库（「全部暂存」也排除它们），Files Tab 的 Git 颜色与编辑器的改动条纹按文件所在的仓库；子模块照常在外层显示为一条改动。监听仍是一个项目一条订阅，事件按这条规则分到各仓库，子模块的变化顺带通知上级。

## Considered Options

- **所有仓库的提交混在一张图里**（WebStorm）：一眼看全，但图谱布局、分支筛选、右键动作、仓库设置都要改成多仓库的含义，近乎重做 Git Tab；收益主要在多仓库同步开发，少见。
- **每个嵌套仓库各登记成一个 Project**（同 ADR-0028 的工作树）：Git Tab 不用改，但左树会多出很多条目，运行配置与终端也散到好几个项目里；「仓库集合」文件夹这种最常见的布局反而最难用。
- **只往下找一层，更深的等打开里面的文件再补**（VS Code、Zed 的折中）：开销最小，但 Git Tab 是项目级的视图，没打开过文件的深层仓库就一直看不到。
- **不自动找，手动添加**（Git Graph 默认）：最省，但用户得先知道有这个入口，也违背「仓库状态随文件系统自动跟进」。
- **状态桶键用「项目 + 仓库」组合**：同一个仓库出现在两个项目里时各有一份状态，但主进程每个接口都要多带一个参数、`git:changed` 要按组合扇出；按目录分桶时同一仓库共用一份，正合「同一个仓库」的语义。
- **启动时把左树每个项目都完整发现一遍**：监听一开始就能把嵌套仓库的事件分对，但大多数项目这次根本不会打开，启动时的进程数随项目数与目录大小涨，还要和当前项目抢同时在跑的名额（实测 25 个项目时当前项目排到最后才轮到）。没打开过的项目里嵌套仓库的事件只会通知它们没加载过的状态，晚些接进监听没有损失。
- **每次 Git Tab 到前台都整个重新发现**：最稳妥，但仓库多的目录每次切回都要起几十上百个 git 进程；改为只重查项目根（与原先同等开销），嵌套仓库的增删交给监听与手动刷新。

## Consequences

- 发现有代价：项目里每个仓库一次 `ls-files --others`、一次 `.gitmodules` 读取，外加每个候选一次 `rev-parse`；只在第一次打开项目、`.git` 增删与手动刷新时发生，并限制同时在跑的进程数。不在仓库里、又很大的目录（如把下载文件夹加成项目）第一次打开时要逐层读完，Git Tab 等它读完才显示。
- 没打开过的项目只知道它自己的仓库：项目移除时，每仓库设置按路径清理（在它目录里、又不在别的项目目录里的），不靠发现过的清单。
- 渲染端的 Git 组件以 `repoPath` 定位状态，要用到项目的地方（在 Files Tab 打开、开终端、找回 Task）经仓库清单找所在项目：先当前项目，再按左树顺序。新增 Git 界面时沿用这条约定。
- 外层的状态解析靠「`--untracked-files=all` 下只有嵌套仓库以 `/` 结尾」；以后若改用别的未跟踪模式，要另找嵌套仓库的判断。
- 同一个仓库同时在几个项目里时共用一份状态与设置（包括打开着的对话框）；Git Tab 一次只显示一个，实际不冲突。
- 项目是仓库的子目录时，项目外的文件不在 Files Tab 的树里，Git Tab 的「打开文件」对它们不做任何事。
- 嵌套仓库的增删要靠监听看到 `.git` 或所在目录的变化；监听停着时（WSL 发行版没连上）的变化，要等下次重新发现才跟上。
