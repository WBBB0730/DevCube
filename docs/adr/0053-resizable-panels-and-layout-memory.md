# 可拖分隔统一用 react-resizable-panels，布局记忆放主进程、按开关落盘

原先只有 Git 详情区与内容搜索预览能拖，各自手写一套（全局 mousemove、全屏遮罩保光标、手动钳制），侧栏固定 280px；窗口几何只在进程内记。现在所有面板要可拖，尺寸全局共享，并由设置决定是否跨重启保留（docs/prd/resizable-panels.md）。

我们决定：

- **所有可拖分隔用 react-resizable-panels**（v4，shadcn Resizable 的底层），封在 `ui/resizable`，不再手写拖拽。它自带像素 / 百分比限位、窗口缩放时保持像素（`preserve-pixel-size`）、键盘调整、拖拽光标，并且能区分用户拖拽与其他布局变化，我们只在用户拖完时记尺寸。
- **共享尺寸靠命令式 `resize()` 对齐**。库只在挂载时读默认尺寸，之后布局归它自己管；`defaultSize` 固定传出厂默认，记住的尺寸一律经 `resize()` 摆上去（随记住的尺寸变的话，每变一次面板就在库里重新注册一次）。Tab 面板常驻、切走只隐藏，同一个尺寸会同时挂着好几处。对齐时机：尺寸变了、面板组重新有了尺寸、库重排之后（`onLayoutChanged`）。面板组隐藏着（宽为 0，没法换算）或库还没排过版（`getLayout()` 为空）时不动。`resize()` 按库记的组尺寸换算，赶在库处理组尺寸变化之前调用会算偏，库处理完通知时再调用一次即对上；是否已经对齐交给库按它的布局判断，不拿 DOM 比（库通知时 React 还没提交，DOM 是旧的）。用户拖完的尺寸在这次布局提交到 DOM 之后再量。
- **不用库的 `useDefaultLayout`**。它按百分比存整组布局、只在挂载时读，做不到「侧栏按像素记」，也做不到多处共用一个宽度。
- **双击分隔线由我们处理，不用库自带的「回到 defaultSize」**：库的双击只会回到 `defaultSize`（出厂默认），不认按场景给的默认（Git 详情区在提交面板时更高），也不清掉记住的尺寸。我们关掉库的双击，自己清掉这一项，交给上面的对齐回到默认。
- **布局记忆（窗口几何与面板尺寸）放在主进程内存**，所有窗口共享；「记住窗口和面板布局」开着时同步写进集中配置（ADR-0002），关掉时清掉盘上的，内存照旧。
- **恢复的几何在页面首帧之前就位**，不在画面上出现中间状态。窗口按记住的位置尺寸建，紧接着套上最大化 / 全屏，再加载页面。Electron 套这两种状态时必然把窗口显示出来（官方文档），所以这类窗口建好即显示、页面加载期间由窗口底色垫底（同 VS Code）；普通窗口仍等页面画好（`ready-to-show`）再显示。面板这边，对齐放在绘制之前（`useLayoutEffect`、ResizeObserver 回调）。
- **窗口几何跟着窗口实时记，事件驱动**。位置、尺寸、最大化、全屏一变（`move`、`resize`、`maximize`、`unmaximize`、`restore`、`enter-full-screen`、`leave-full-screen`）就重新计时，停稳后按窗口此刻的读数记一次，开关开着即落盘；关窗、退出时只补记还没记的那次。事件只当「变了」的信号，状态从读数里取。
- **每种状态取可靠的来源**：最大化现读 `isMaximized()`（没有异步问题，不必指望 `maximize` / `unmaximize` 覆盖 macOS 上每一种铺满途径）；全屏取事件记的（`enter-full-screen` / `leave-full-screen`，建窗时套全屏的从一开始就算）与现读 `isFullScreen()` 的并集，即从开始进入到退出完成都算全屏：macOS 的全屏切换是异步的，实测窗口矩形与 `isFullScreen()` 同时翻转，两个事件都晚约 0.6~0.7 秒，只认事件会把进入途中的全屏矩形当成正常尺寸，只认现读会把建窗时还没开始的切换当成没全屏；正常位置尺寸只在窗口处于普通状态时取 `getBounds()`，最大化 / 全屏 / 最小化期间保持原样，不用 `getNormalBounds()`（它在非普通状态下返回 Electron 内部推算的值，各种铺满途径下是否准确没有保证）。
- **应用发起的全屏切换在 macOS 上排队**：同一时间只执行一个窗口的全屏切换，切换途中别的窗口发起的直接被丢弃（实测），所以建窗时进全屏、恢复默认布局时退出全屏都排队，任一窗口的 `enter-full-screen` / `leave-full-screen` 算前一次完成，发起的窗口关掉也算；被丢弃的按实际状态记。
- **每个窗口各记一份，最近变化过或聚焦过的那个代表这一类窗口的记忆**。新窗按记忆开，开窗时不现读别的窗口；记忆来自还开着的同类窗口时错开。
- **恢复时挪进屏内，不整份丢弃**：与某块显示器有交集就放在交集最大的那块、收进它的工作区；与所有显示器都没交集（如拔掉外接屏）才用默认大小在主显示器工作区居中。

## Considered Options

- **继续手写**：每处一套 mousemove、遮罩、限位与像素保持，还没有键盘支持，排除。
- **存在渲染端 localStorage**：每个窗口各存一份，主进程读不到（窗口几何本来就在主进程），与集中配置分成两处，排除。
- **只在关窗 / 退出时记几何，最大化 / 全屏都按事件记，位置尺寸取 `getNormalBounds()`**（本 ADR 先前的做法）：崩溃、强退、Windows 关机（官方文档：此时不发 `before-quit`）丢掉整次运行的变化；状态与正常尺寸的正确性押在事件覆盖与 Electron 内部推算上；恢复时要求完全落在某块显示器内，压边或跨屏就整份丢弃，多显示器下常失效。排除。
- **electron-window-state**：同样只在关窗时写盘、越界即重置为默认，正是上面要解决的两处；也接不上开关与恢复默认布局。排除。

## Consequences

- 新增可拖分隔一律用 `ui/resizable`。库要求面板与分隔线是面板组的直接 DOM 子元素，所以侧栏外框（如 `TreePanel`）本身就是面板，外面不能再包一层。
- 要记的尺寸在共享键表里登记（单位、默认、限位）。
- 新开窗口一律经 `createAppWindow`：几何、状态与显示时机都在那里定，不要在窗口建好之后再改尺寸或状态。要记几何的窗口（主窗口、Preview Window）经布局记忆的 `createRememberedWindow` 建，它按记忆解析几何、建窗并接上实时记录。
