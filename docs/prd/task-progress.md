# task-progress

**耗时操作的进度与任务清单**

## Problem Statement

DevCube 里不少操作要跑上几秒到几分钟：克隆仓库、拉取、推送、下载应用更新。现在只有克隆能看到阶段和百分比；拉取、推送只有一个转圈小窗，看不出进展，也停不下来；点「隐藏」之后它就从眼前消失了，失败了要切回它所在的 Tab 才看到错误框；应用更新下载只写一句「正在下载」。已有的几处进度（克隆、服务器文件的传输栏与打开进度、压缩按钮上的百分比）各写各的，样子和能看到的信息都不一致，也都没有速度和剩余时间。取消也不彻底：叫停克隆时只结束了最外层的 git，子模块的克隆还在后台继续往目标目录里写。退出应用时，只有运行会话和服务器传输会提醒，克隆、推送做到一半直接退出不会。LFS 文件的传输也看不到：推送前 git-lfs 上传 LFS 文件时界面一直是「准备中」，上万个小文件时可以持续几十分钟，看起来像卡死；git 的百分比按个数算，小对象在前、大对象在后时进度条先到头、体积还在涨；传完后速度落到 0 B/s，同样像卡住。

## Solution

引入 **Task（任务）**：用户发起的、会报进度的耗时操作。主进程有一个任务登记处，各操作只往里报数，速度、剩余时间由登记处统一算；界面只有一套进度显示。

- 每个 Task 先在进度弹窗里显示：阶段、完成几个 / 共几个、已传多少、速度；知道总量时再加总量和剩余时间。能安全停下的才有「取消」；都有「隐藏」。
- 被隐藏的 Task 进顶栏右侧的任务清单；顶栏任务钮只在有被隐藏的 Task 时出现。成功了悄悄消失；失败了不弹框，任务钮变红，原因留在清单里直到关掉。点清单里的一项，就把它放回眼前，和没隐藏过一样。
- 进行中的 Task 在 macOS 的 Dock 图标、Windows 的任务栏按钮上显示进度；退出应用时若还有 Task 没做完，退出确认一并提醒。
- 本轮接入 Git 的联网收发：克隆、拉取、推送（含推送标签、新建标签并推送）、把远程分支获取到本地分支、填了远程地址的初始化。
- 应用更新下载不是 Task（不是用户发起的），但用同一套进度显示：设置「关于」页里的「正在下载」换成进度条、总量、速度与剩余时间。

## User Stories

1. 作为用户，我想在拉取、推送时看到当前阶段和它完成了几个、共几个，这样知道它在干什么、走到哪儿了。
2. 作为用户，我想在下载或上传数据的阶段看到已经传了多少、每秒多少，这样能判断网络快慢、是不是卡住了。
3. 作为用户，我想在还没有百分比的阶段看到一根来回滑动的进度条，这样不会以为程序卡住了。
4. 作为用户，我想进度条只在传数据时出现、按这一步完成的个数从 0 走到 100，其余阶段显示加载动画、几个加载阶段连着时动画接着滑，这样进度条走了多少就是真传了多少个，不会一开始就冲到一截。
5. 作为用户，我想在阶段名右边看到完成了几个、共几个（对象或 LFS 文件），这样进度条快满而体积还在涨时，知道是剩下的几个大文件在传。
6. 作为用户，我想推送、克隆、拉取在传 LFS 文件时看到「上传 LFS 文件」/「下载 LFS 文件」、个数、已传与速度，这样大量 LFS 文件慢慢传时不会以为卡死了。
7. 作为用户，我想推送被取消后再推时，服务器上已有而被跳过的 LFS 文件也算进个数，这样进度从开头就在动、最后能走满。
8. 作为用户，我想不传数据的阶段（处理增量、检出）不显示速度，这样不会看到「0 B/s」以为卡住。
9. 作为用户，我想在克隆、推送、拉取的下载阶段点「取消」，这样发现推错分支、拉错远程或网络太慢时不必干等。
10. 作为用户，我想在拉取进入合并或变基后看到「取消」变灰，这样不会在半路停下、把仓库弄乱。
11. 作为用户，我想点了「取消」就真的全停下——包括推送前的钩子、子模块的克隆、拉取的下载，这样不会有 git 在背后偷偷跑完。
12. 作为用户，我想点「隐藏」把进度弹窗收起来、操作照常继续，这样能接着干别的。
13. 作为用户，我想在进度弹窗里按 Esc 是隐藏而不是取消，这样手滑按到 Esc 不会中止一个跑着的操作。
14. 作为用户，我想隐藏后在顶栏右侧看到一个任务钮，钮上的小圆环随进度推进，这样不打开清单也知道大概进展。
15. 作为用户，我想点任务钮打开任务清单，逐项看到每个被隐藏的任务的名称、所属项目、进度与速度，这样同时跑几件事也一目了然。
16. 作为用户，我想在清单里直接取消某一项，这样不必先把它找回来。
17. 作为用户，我想点清单里进行中的一项，就回到它所在的项目和 **Git Tab**，重新看到它的进度弹窗，这样随时能找回。
18. 作为用户，我想没有被隐藏的任务时顶栏不出现任务钮，这样顶栏保持干净。
19. 作为用户，我想被隐藏的任务成功后悄悄从清单里消失，这样不被打扰。
20. 作为用户，我想被隐藏的任务失败时不弹框打断我，而是任务钮变红、清单里写明原因，这样手上的事不被打断，回头也能看到。
21. 作为用户，我想失败的任务一直留在清单里直到我关掉，这样不会错过。
22. 作为用户，我想点清单里失败的一项，看到和没隐藏时一样的失败界面（Git 操作是错误框，克隆是带着原输入与报错的填写界面），这样能接着处理或改了重试。
23. 作为用户，我想同一个仓库上排在后面的操作显示「等待中」，这样知道它不是卡住了，而是在等前一个做完。
24. 作为用户，我想等待中的任务也能取消，这样排错了能撤回。
25. 作为用户，我想很快就完成的操作不弹进度弹窗，这样不会闪一下。
26. 作为用户，我想克隆也能隐藏，这样克隆大仓库时能先去做别的。
27. 作为用户，我想被隐藏的克隆成功后项目照常出现在左树里，但不抢走我当前的选中，这样不打断手上的事。
28. 作为用户，我想在有被隐藏的克隆时再点「从 Git 仓库克隆…」，回到那个进行中的克隆，这样不会以为它没了。
29. 作为用户，我想切到别的应用时，在 Dock 图标（macOS）或任务栏按钮（Windows）上看到进度，这样不用切回来也知道做完没有。
30. 作为用户，我想在还有任务没做完时退出应用会被提醒，这样不会让推送、克隆做到一半就断掉。
31. 作为用户，我想在设置「关于」里看到更新下载的进度、总大小、速度和剩余时间，这样知道还要等多久。
32. 作为用户，我想自动获取与手动刷新仍然只在刷新钮上转圈、不弹窗也不进清单，这样频繁的刷新不打扰我。
33. 作为用户，我想合并、变基、检出这类几秒就完的操作保持现在的样子，这样界面不会变吵。

## Implementation Decisions

**Task 与任务登记处**

- **Task** 是用户发起的、会报进度的耗时操作。本轮包括：克隆；Git 动作里会联网收发提交的——拉取分支、推送分支、推送标签、新建标签并推送、把远程分支获取到本地分支、填了远程地址的初始化。只删远程分支或标签（`push --delete`）不传数据、报不出进度，不是 Task；刷新（含拉取 / 推送对话框里的行内刷新）与自动获取也不是 Task。
- 主进程持有唯一的任务登记处。每个 Task 有：id、标题（动作 + 对象，如「拉取 origin/main」「推送 main → origin/main」「克隆 <地址>」）、所属 **Project**（克隆没有）、状态（等待中 / 进行中 / 失败）、进度、此刻能否取消、是否被隐藏、失败原因。登记处节流（同服务器传输的 200ms）后经一条事件通道推全量快照；渲染端重载后先取一次快照再订阅（与服务器传输同一形态）。登记处核心不依赖 electron，IPC 接线另放。
- 进度值统一为：阶段名、百分比（可无）、已完成字节（可无）、总字节（可无）。速度与剩余时间不用来源自报的数字，由共享的计速器按「已完成字节」随时间的变化算（近几秒的滑动平均），各来源口径一致；剩余时间只在知道总字节时给出。计速器是纯函数，登记处与更新下载共用。
- 成功、取消的 Task 从登记处移除。失败的留在登记处直到被关掉：没被隐藏的当场以错误框 / 填写界面呈现，关掉即移除；被隐藏的留在任务清单，找回后同样呈现。界面都按登记处呈现，渲染端重载后也接得上。
- Dock / 任务栏进度：只在 DevCube 不在前台时显示（同 IntelliJ；在前台时界面上已经看得到）。主窗口 `setProgressBar`，取所有进行中 Task 的平均总百分比（没有百分比的不计入）；全部没有百分比时为不确定状态；回到前台或没有进行中的 Task 时移除。只有 macOS 与 Windows 有效（Linux 仅 Unity，不另做）。
- 退出确认多一项：「N 个任务未完成」，退出将「中止这些任务」。

**Git 侧**

- 上述动作改走 git 的流式执行（stderr 逐块回调、可取消），命令加 `--progress`。流式执行已有本机与 WSL 两条路径（克隆在用），一次性执行的路径保留给其余动作。
- 进度解析由克隆专用扩展为 git 通用：阶段名中文表补上推送与小包获取的阶段（`Writing objects` 发送对象、`Unpacking objects` 解包对象），并从 `Receiving objects` / `Writing objects` / `Unpacking objects` 行取已传字节（git 用 KiB / MiB / GiB 二进制单位，字节数出现在吞吐量算出之后）；`Filtering content`、`Uploading LFS objects` 为「下载 LFS 文件」/「上传 LFS 文件」。git 在下载完之前不知道包有多大，Git Task 只有百分比与已传字节，没有总量与剩余时间。
- 进度条只给传数据的阶段：接收 / 发送 / 解包对象、上传 / 下载 LFS 文件，按这一步自己完成的个数从 0 走到 100（推送先传 LFS 文件再传提交，克隆、拉取先传提交再下 LFS 文件）。清点、压缩、处理增量、检出文件、拉取的合并 / 变基等其余阶段一律为不确定状态，个数照报；连着几个不确定阶段共用一段动画，接着滑、不重来。git 的阶段按清点 → 压缩 → 收发 → 处理增量出现，后面的出现后前面阶段的行不再计入。原先照 IntelliJ 把各阶段按权重（5% / 10% / 80% / 5%）拼成一根进度条：拼出来的位置与这一步的个数对不上，清点、压缩通常一两秒做完，进度条一开始就冲到 15%，不是真实进度，已弃用。
- 阶段名右侧写这一步的「完成 / 总数」（git 进度行里的计数，如「接收对象」右侧「2,999 / 3,003」；不知道总数时写「N 个」），不另写百分比：git 的百分比按个数算、不按字节，小对象在前、大对象在后时进度条先到头、体积还在涨，有了个数才看得懂。进度条按个数算（打出来的百分比是取整后的，git-lfs 会把 400 / 402 打成 100%），没传完不到头。
- 已传字节只在传数据的阶段（收发、LFS 文件）有，速度按阶段算、换了阶段从头算；处理增量、检出这类阶段不显示已传与速度（原先会停在最后的体积、速度落到 0 B/s，像卡住）。
- **LFS 文件**：git-lfs 的输出不接终端时不报进度，推送前的钩子里上传 LFS 文件时界面一直是「准备中」。各操作的数据来源不同，各取准的那份：
  - 推送：让 git-lfs 照样打自己的进度行（`GIT_LFS_FORCE_PROGRESS`），个数与百分比看它——它把服务器上已有而跳过的文件也算进完成数，取消后再推也能从开头动起、最后走满；它边数要传的文件边报总数（加进第一个文件就打出「0 / 1」，实测 1.4 万个文件约 1.2 秒数完）、不说什么时候数完，总数与上一帧相同才算数完，数完前当作还在准备（「准备中」），这期间已传的体积数完后一并显示；已传字节看 LFS 进度文件（`GIT_LFS_PROGRESS`，逐个文件的已传字节，精确），进度行的体积把跳过的文件也算作已传、用十进制单位，不用。git-lfs 的进度行落在 git 的哪一路输出随 git 版本（实测 Apple Git 2.50 在普通输出），两路都读，报错里两路都剔掉进度帧。
  - 克隆：检出时 git 自己报下载进度（`Filtering content`，带总数与已传字节），以它为准，不用进度文件（那里逐个文件下，每行的预计总数都是 1）。
  - 拉取：整合那条命令改为流式执行并跟读进度文件（git 这时不报进度）；逐个文件下载、不知道总数，进度条不确定，只写已下几个、已传与速度；仍不可取消。
  - 进度文件由 DevCube 建在临时目录（WSL 项目在发行版的 `/tmp`，经 `\\wsl.localhost` 读），定时跟读，命令结束后删掉；只认上传、下载的行（合并时的 `clean` 是本机算哈希）。拉取的总进度只算下载那一步；一个 Task 含多条联网命令时（推送标签到多个远程），按命令条数平分。
- 一个动作含多条命令时（推送标签到多个远程、新建标签后推送、初始化后获取），整个动作是一个 Task，进度跟随当前那条命令。
- 同一仓库的写动作仍按 FIFO 串行。排在后面的 Task 状态为等待中；取消即出队，轮到时不执行。
- 取消结束整棵进程树：macOS / Linux 上让 git 自成一个进程组、向整组发 SIGTERM（每个 git 进程照常做信号清理）；Windows 结束整棵进程树；WSL 照旧结束发行版里的进程组。原因：git 会再起子进程——拉取的下载、推送前的钩子、子模块的克隆——只结束最外层的 git，它们会照样跑完（实测：拉取的下载又跑了约 40 秒并更新了远程分支；pre-push 钩子照样跑完；子模块的克隆又跑了约 44 秒，还在往目标目录里写，打乱克隆失败后的兜底清理）。退出应用时由登记处逐个取消进行中的 Task、结束各自的进程树，不靠应用退出后管道断开顺带结束 git。可取消的：克隆、推送分支、推送标签、新建标签并推送的推送部分、获取到本地分支、初始化后的获取、拉取的下载部分。
- **拉取 = 先获取、再拉取**：先单独执行 `git fetch --progress <remote> <branch>`（下载阶段，可取消），再执行原有的 `git pull`（此时其中的获取已没有新内容，主要是合并或变基，阶段名为「合并」/「变基」，「取消」置灰）。原因：`git pull` 的下载在 git 另起的子进程里，叫停外层进程停不掉它；合并或变基中途停下，可能把工作区和暂存区留在半完成状态。先获取后的 `git pull` 与直接 `git pull` 结果相同（合并依据它自己写的 FETCH_HEAD，变基的分叉点依据远程跟踪分支的引用日志）。
- 被隐藏的 Git Task 失败时，不落该 Project 的错误框，失败原因进登记处；找回时再在它的 Git Tab 里弹错误框。没被隐藏的失败照旧弹错误框。
- 成功后的软刷新照旧。

**克隆**

- 克隆并入登记处：原先专用的进度通道与对话框里手写的进度条，换成登记处与通用的进度弹窗。
- 单例语义不变（同一时刻至多一个克隆，见 `docs/prd/clone-project-from-git.md`）；有被隐藏的克隆在进行时，「从 Git 仓库克隆…」直接打开它的进度弹窗。
- 被隐藏期间成功：照常登记 Project、对齐监听、记住父目录，但不改左树选中、不滚动。
- 被隐藏期间失败：留在清单；找回时打开填写界面，带着原输入与 git 报错（原输入随 Task 存在主进程）。

**界面**

- 统一的进度条组件建在 Base UI 的 Progress 上（项目已装）：有百分比时按百分比填充，没有时为不确定动画。
- 进度弹窗是 Task 在前台的样子：标题（「正在」+ Task 标题）、阶段与右侧的个数、进度条、明细（「已传 X（速度）」，有总量时为「已传 X / 总量（速度）· 剩余时间」；一进传数据的阶段就显示，已传从 0 起，速度还算不出时写 0）、「隐藏」与「取消」。延迟 300ms 出现（同 IntelliJ），此前完成的不弹。遮罩点击不收口，Esc 即隐藏。Git Task 的弹窗在它的 Git Tab 里（Tab 被切走时随之收起，ADR-0052）；克隆的挂在应用根上。
- 顶栏任务钮与任务清单只在主窗口（**Preview Window** 没有）。点清单里一项即找回：进行中的切到所属 Project 的 Git Tab 并重新显示进度弹窗（克隆直接显示）；失败的同样切过去显示失败界面；找回后它不再算被隐藏。
- 设置「关于」页下载中：「正在下载 x…」之下加进度条与明细（「已下 X / 总量（速度）· 剩余时间」）；还没收到第一份进度时为不确定状态。数据来自 electron-updater 的 `download-progress`，经计速器后随更新状态快照推送。
- 合并、变基、检出等不是 Task 的动作，仍用原来的转圈小窗与「隐藏」。

**模块划分**

- 共享层纯函数（直接单测）：进度值类型、计速器（速度、剩余时间）、git 进度解析、格式化（字节、速度、剩余时间）、Dock 进度汇总、退出确认文案。
- 主进程：任务登记处（核心 + IPC 接线）；git 动作层按动作种类决定走流式执行并接到登记处；更新编排接上 `download-progress`。
- 渲染端：进度条组件、进度明细、进度弹窗、顶栏任务钮与任务清单、登记处快照的订阅。

## Testing Decisions

只测外部行为，不测实现细节；与既有的 `*-parse` / `*-args` 测试同形。

- **git 进度解析**：各阶段带百分比的行；带字节与吞吐量的行（`Receiving objects:  45% (450/1000), 12.34 MiB | 2.40 MiB/s`、`Writing objects: 100% (3/3), 300 bytes | 300.00 KiB/s, done.`）；各种字节单位；`remote:` 前缀；`\r` 连续刷新的整块；块边界劈断的半行；不相干的行。克隆原有的解析用例并入这里。百分比按个数算。只有收发阶段有百分比、其余阶段为不确定且个数照报；后面阶段出现后前面阶段的行不再计入；未知阶段与收尾阶段；多条命令平分。
- **LFS 进度**：进度文件的行（上传、下载、`clean` 不算、文件名含空格、半行）；git-lfs 自己的进度行（个数、十进制单位不当作已传字节）；推送 LFS 文件传完轮到提交、克隆提交传完再下 LFS 文件、拉取只有进度文件且不确定；git 报了下载进度时进度文件不再计入；子模块的克隆里不计入。
- **跟读文件**：晚建也接得上、追加的部分按块读出、停止时读完剩下的、多字节字符被劈开不乱码（真实文件）。
- **流式执行**：两路输出都回调；要 LFS 进度时的环境变量与进度文件位置（本机、WSL），结束后删掉进度文件（本机路径起一个代替 git-lfs 的钩子）。
- **计速器**：匀速、忽快忽慢（被平滑）、停住（速度回落）、没有字节（无速度）、有无总量时的剩余时间、已完成超过总量。
- **格式化**：字节、速度、剩余时间的进位与边界。
- **Dock 进度汇总**：全有百分比、部分有、全没有、没有进行中的 Task、DevCube 在前台。
- **取消结束进程树**：本机路径起一个会再派生子进程的脚本代替 git，叫停后子进程也退出（macOS / Linux 与 Windows 各一条）；WSL 路径沿用既有的模拟测试。
- **退出确认文案**：含任务数时的措辞与各项组合。
- **任务登记处核心**（假时钟）：等待中 → 进行中 → 成功移除 / 失败；被隐藏的失败保留、没被隐藏的失败移除；取消等待中的 Task；找回与关掉；节流推送；换了阶段速度从头算。
- **拉取的命令序列**：先获取再拉取，各整合方式的参数不变。

不做真实网络与 git 进程的端到端测试，与既有 git 动作层、克隆的测试口径一致。

## Out of Scope

- 服务器文件的传输栏与打开进度、压缩窗口、数据源导出：本轮不接入，仍是各自原来的显示，以后逐个换成同一套。
- 应用内通知（成功、失败的气泡）：与 `docs/backlog.md`「应用内通知」一起做，届时 Task 的成功与失败一并发通知。
- 失败后的「重试」。
- 合并、变基、检出等不报进度的动作进清单。
- 多个克隆并行（沿用克隆 PRD）。
- 已完成任务的历史记录。
- 查看 git 的原始输出。
- 检出、合并（不经拉取）时下载 LFS 文件的进度：它们不是 Task，仍是转圈小窗。
- 调高 LFS 并发：调研的客户端都不改，git-lfs 上游试过按 CPU 数放大默认值又撤回（git-lfs #6241、#6258）。

## Further Notes

- 架构决定见 ADR-0058。
- 做法对照（2026-10 调研）：拉取先获取再拉取同 Sourcetree，IntelliJ 的「更新项目」、Tower、GitKraken 也是先获取再整合；VS Code、GitHub Desktop 的拉取不能取消。取消结束整棵进程树、弹窗延迟 300ms、Dock 进度只在后台显示、退出时提醒后台任务，均同 IntelliJ。隐藏后能从清单找回同 VS Code（IntelliJ 不能调回前台）。进度弹窗里 Esc 为隐藏，同 VS Code 与 DevCube 原有的 Git 进行中小窗（IntelliJ 为取消）。几家 Git 客户端都不自己算速度，只显示 git 原始进度行里的吞吐量；这里自己算，是为了让以后不报速度的来源（服务器传输等）口径一致。
- Windows 上结束进程不走 git 的信号清理：获取被叫停时可能留下临时包文件（git 下次整理时清掉）；若恰好在更新引用的一瞬间被结束，可能留下引用锁文件，下次获取会报错并给出文件路径。与克隆的兜底清理同源，本轮不另做处理。
- 进度条做法对照（2026-10 调研）：GitHub Desktop、IntelliJ（VS Code 只在克隆时）把各阶段按权重拼成一根进度条，旁边原样显示 git 当前那一行；Git Extensions、TortoiseGit 每个阶段从头走；Sourcetree、GitKraken、SourceGit 只有不确定动画；没有一家在旁边写拼出来的整体百分比。
- LFS 进度做法对照（2026-10 调研）：GitHub Desktop、GitComet 读 LFS 进度文件（Desktop 的进度条不确定，写「已完成 N 个，预计共 M 个」）；Fork 推送、拉取、检出显示 LFS 进度（闭源，做法不详）；VS Code、IntelliJ、Sourcetree 等看不到。只读进度文件时，服务器上已有而跳过的文件不出现，完成数到不了总数，所以推送的个数改看 git-lfs 自己的进度行。
- 「Task」是本轮新增的领域词，已收进 **CONTEXT.md**。
