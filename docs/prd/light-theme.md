## Problem Statement

DevCube 只有深色一套外观。在明亮环境下用、或者跟已经切成浅色的 WebStorm / 系统其他窗口并排放时，它是唯一一块深色，长时间看着累，来回切窗口也刺眼。用户想要一个浅色主题，并且希望它和 WebStorm 的浅色是同一套观感——DevCube 的整个视觉定位就是复刻 WebStorm，主题这一层不该破例。

## Solution

设置里加一个「主题」选项，深色 / 浅色两档，默认深色，不提供「跟随系统」。选了立即生效，不需要重启窗口：整个界面、控制台、编辑器、Git 图谱与 diff 面板同时翻过去，原生菜单、托盘菜单和系统对话框也跟着变。

浅色不是把深色反相，而是取 WebStorm New UI Light 的真实取值——面板、树选中、运行按钮、语法着色、Git 状态色、终端 ANSI 16 色，都对齐 IDE 里看到的样子。

## User Stories

1. 作为用户，我想在设置里选择应用主题，这样我可以按环境和喜好决定界面明暗。
2. 作为用户，我想两个选项直接摊在那里、点一下就切，而不是先展开一个下拉再选，这样改主题只要一次点击。
3. 作为用户，我想主题默认是深色，这样升级后打开应用不会突然变样。
4. 作为用户，我想选完主题立刻看到效果，这样我不必重启应用来确认是否合意。
5. 作为用户，我想主题选择被记住，这样下次启动仍是我选的那一套。
6. 作为用户，我想应用启动时不闪一下深色再变浅色，这样冷启动观感是干净的。
7. 作为用户，我想浅色下的左树、工具栏、Tab 栏与 WebStorm 浅色的面板灰一致，这样两个窗口并排不违和。
8. 作为用户，我想浅色下的弹出菜单、下拉、对话框和输入框比面板更亮一档，这样浮层的层次仍然分得清。
9. 作为用户，我想浅色下选中行的蓝底和 hover 底能分辨，这样我知道当前选的是哪一行。
10. 作为用户，我想浅色下运行按钮的绿在白底上足够清楚，这样我不会看不清运行入口。
11. 作为用户，我想浅色下状态点（空闲 / 运行中 / 成功 / 失败）依然一眼可辨，这样我能扫一眼知道哪条配置出了问题。
12. 作为用户，我想控制台在浅色下是白底黑字，这样它和 WebStorm 浅色的 Run 面板一致。
13. 作为用户，我想控制台里带颜色的输出（npm / vite / 测试框架的 ANSI 色）在浅色下仍能读，这样日志不会失去可读性。
14. 作为用户，我想在控制台里搜索时，浅色下的命中高亮清晰可见，这样查日志不受主题影响。
15. 作为用户，我想切主题后控制台里已有的搜索高亮也跟着换色，这样不会留下一块旧配色的残迹。
16. 作为用户，我想切到别的 Tab 再切回来时，那个 Tab 的终端不是旧配色，这样主题切换是彻底的。
17. 作为用户，我想 Files 编辑器在浅色下用 WebStorm 浅色方案的语法着色，这样读代码的配色习惯是延续的。
18. 作为用户，我想切主题时正在编辑的文件不丢光标、选区、滚动位置和撤销历史，这样切换不打断我手上的事。
19. 作为用户，我想 Files 编辑器行号栏的 VCS 条纹在浅色下也按增 / 改 / 删区分，这样改动位置仍然一眼可见。
20. 作为用户，我想 Git 图谱的分支配色在两套主题下保持一致，这样我对分支颜色的记忆不会因为切主题而作废。
21. 作为用户，我想 Git 图谱的连线在浅色下依然互不糊在一起，这样交叉密集处仍可读。
22. 作为用户，我想 Git 的文件状态色（新增 / 修改 / 删除 / 冲突）在浅色下换成 WebStorm 浅色的对应色，这样它们在白底上有足够对比。
23. 作为用户，我想 diff 面板在浅色下用 IDE 的增删底色，而不是这个库自带的 GitHub 配色，这样它跟应用其余部分是一套。
24. 作为用户，我想浅色下的弹窗遮罩不要把整屏压得发灰，这样弹窗打开时背景仍然清爽。
25. 作为用户，我想原生的右键菜单、托盘菜单和选文件夹对话框也跟随主题，这样不会出现深浅混搭。
26. 作为用户（Windows），我想窗口顶栏的系统按钮在浅色下也是深色图标，这样它们在浅底上看得见。
27. 作为用户，我想拖动窗口边缘调整大小时露出的底色与当前主题一致，这样不会闪出一块异色。
28. 作为用户（非 Windows），我想「设置 → 偏好」这一段现在能看到，这样我能找到主题开关——过去它整段只对 Windows 显示。
29. 作为开发者，我想浅色取值有明确出处可查，这样后续改动不必靠肉眼比对截图。

## Implementation Decisions

**取色源与切换机制见 ADR-0026**，逐项取值与出处见 DESIGN.md 的浅色列。以下是模块层面的约定。

**偏好**：`AppPrefs` 增加 `theme: 'dark' | 'light'`，默认 `'dark'`，走既有的 `getAppPrefs` / `setAppPrefs` IPC 与 electron-store 落盘。注意主进程 store 的 `pickKnownKeys` 遍历的是默认值对象的键，新字段必须同时出现在接口和 `DEFAULT_APP_PREFS` 里，否则落盘值会被静默丢弃。读写两侧都按枚举归一，脏值回落默认。

**共享定义**：主题类型、枚举与主进程用的窗口色集中在一个 shared 模块。窗口底色与 Windows 顶栏叠层是建窗选项、吃不了 CSS 变量，与面板色 / 图标色构成同值双写，需在该模块注明。

**主进程**：一个 `applyTheme(theme)` 落到原生侧——设 `nativeTheme.themeSource`、给所有窗口 `setBackgroundColor`，非 darwin 再 `setTitleBarOverlay`。调用点两处：store 初始化之后、建窗之前各一次（保证页面加载时 `prefers-color-scheme` 已正确），以及偏好写入带 `theme` 时。原来在模块顶层无条件设深色的那行去掉——它跑在 store 初始化之前，读不到偏好。

**渲染层 CSS**：`:root` 保持深色为基线，新增一个 `@media (prefers-color-scheme: light)` 块，**只列与深色不同的 token**，其余继承。`color-scheme` 从 `dark` 改为 `light dark`。新增 `--bg-elevated`（浮起表面：弹层 / 输入控件 / 按钮）与 `--mask` / `--mask-weak`（遮罩）两组 token；`--bg-elevated` 在深色下与 `--bg-panel` 同值，故深色观感不变。原先用面板色的弹层与控件改用它，大面积容器仍用面板色。

**diff 面板**：库按 `data-theme` 挂两套自带变量。应用侧的覆写块选择器必须同时列出两个 `data-theme`——取值本身已随主题翻，但漏掉哪个，库自带的那套（浅色是 GitHub 配色）就会全量接管；降级成不带属性的选择器又压不过库的特异性。

**JS 侧色源**：渲染层 store 持有 `theme`，初值由 `matchMedia` 同步读出（与 CSS 同源，不依赖运行时事件）。四处消费：

- **xterm 调色板**：整对象替换，改属性再赋回不生效。
- **终端搜索装饰**：装饰色在创建时定死，换调色板带不动，须重画；重画前必须先清掉 addon 缓存的搜索词，否则它认为「词与选项都没变」而跳过重画（它比较选项时不看装饰色）。清掉后它还会按选区起点而非末尾重新命中，当前命中不被推进。仅在搜索框开着且有词时才跑——关着时高亮已清、词却还留着，跑一趟会凭空画出整屏高亮并滚动视口。
- **CodeMirror 主题与语法高亮**：两套预建好，靠 extensions 变更触发 reconfigure，不重建编辑器状态。
- **diff 面板的 `diffViewTheme`**。

隐藏面板（容器无尺寸）换主题不需要额外兜底：xterm 的渲染服务在不可见时处于 paused，其间的重绘请求只标记待办，由 IntersectionObserver 在恢复可见时自行全量补画。

**设置界面**：「偏好」段从仅 Windows 可见放开为全平台；其中「默认终端」仍只对 Windows 显示，shell 选项也只在 Windows 上探测。主题用**分段按钮**——两档互斥选项摊开、一次点击即切，不必先展开再选，也不遮住下面的内容；样式对齐 JetBrains New UI 的 SegmentedButton。主题写入不走本页的 `setAppPrefs`，而是走 store 的 `setTheme`，因为 JS 侧色源订阅的是 store。

**分段按钮组件**：新增一个通用控件，语义走 Base UI 的 **Radio** 而非同名的 ToggleGroup——后者单选态下再点一次已选项会取消，落到「一个都没选」，对必选项不成立；Radio 还自带方向键切换与正确的无障碍语义。配色**不新增全局 token**：选中态纯靠底色 `--selection-row`（这个应用里「选中」本来就是这个色，左树选中行同款），段上不描边，只有外容器带 `--border-input` 描边。JetBrains 为该控件单列了 `SegmentedButton.selectedButtonColor` / `selected*BorderColor` 四个键，刻意不采用——只服务一个控件的颜色不该占据全局 token 命名空间；且它那套「浮起底色 + 段描边」的画法在本工作区会与容器描边叠成相距 1px 的双层边。代价是选中态是蓝底而非 JetBrains 的中性浮起底。

**Git 图谱**：不改任何调色板。上游 vscode-git-graph 的 12 色是配置项固定默认值、不随主题；背景类已用 `--bg-deepest` 表达，自动跟随。

## Testing Decisions

好的测试只覆盖外部行为，不锁实现细节。主题这件事的绝大部分是取值与样式，靠单测锁不住也不该锁——颜色对不对是靠 DESIGN.md 记录的出处和真机对照，不是靠断言十六进制字符串。

值得测的是纯函数与契约层：主进程 `getAppPrefs` / `setAppPrefs` 对 `theme` 的归一与默认回落（脏值、缺字段、老档案），以及新字段确实能穿过 `pickKnownKeys` 落盘。这类测试的现成写法见 `src/main/user-data.test.ts` 与 `src/shared/workspace.test.ts`。

不写的：CSS 变量取值的快照测试、组件渲染色的断言、Electron 原生侧 `themeSource` 的桩测试——前两者锁死实现且随设计调整必然失效，后者测的是 Electron 而不是本应用。

真机验证清单（人工过一遍，覆盖上面 story 里靠肉眼判定的部分）：冷启动无闪烁；切换即时生效且四处 JS 色源都跟上；切主题时编辑器不丢状态；隐藏 Tab 的终端切回来配色正确；diff 面板不被库的 GitHub 配色接管；原生菜单与托盘跟随。终端搜索另需三种情形各看一眼——搜索框开着切主题（高亮换色、当前命中不挪、视口不跳）、搜索过再按 Esc 关掉后切主题（不该冒出任何高亮）、隐藏 Tab 里搜索过再切主题（切回来配色正确且视口没被滚走）。

## Out of Scope

- **跟随系统**：明确不做。主题是两档强制值。
- **自定义主题 / 用户改色**：不做，不暴露任何调色入口。
- **高对比度主题**：不做。
- **深色取值的回校**：浅色改成直取原件后，反衬出深色有四处 1 单位手取误差（已记在 DESIGN.md）。本次不动深色任何取值，避免把「加浅色」变成「重做深色」。
- **Git 图谱调色板浅色化**：按上游做法保持不变，见 ADR-0026。
- **终端 ANSI 浅色的可读性调整**：浅色的白 / 亮白在白底上对比度低，这是 JetBrains 原样取值，照搬不调。
- **`--find-match-*` 与终端搜索装饰的同值双写**：本次仍是双写（加浅色后变成两对四个值），没有借机改成从 CSS 变量读。

## Further Notes

「打开于」子菜单的三张品牌图标（cursor / codex / claude）是各家的 **macOS 应用图标**，自带圆角方形底板，不是有明暗两版的 logo。浅色下 codex 与 claude 的白色底板会与白色弹层融在一起，但图标主体本身是蓝紫 / 橙色、在白底上对比充足，仍然认得出；cursor 是深色底板，浅色下反而更清楚。本次不动这三张图。
