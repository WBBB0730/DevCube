# light-theme

**浅色主题**

## Problem Statement

DevCube 只有深色一套外观。在明亮环境下用、或者跟已经切成浅色的 WebStorm / 系统其他窗口并排放时，它是唯一一块深色，长时间看着累，来回切窗口也刺眼。用户想要一个浅色主题，并且希望它和 WebStorm 的浅色是同一套观感——DevCube 的整个视觉定位就是复刻 WebStorm，主题这一层不该破例。

## Solution

设置里加一个「主题」选项，深色 / 浅色两档，默认深色，不提供「跟随系统」。选了立即生效，不需要重启窗口：整个界面、终端与运行会话的输出、编辑器、Git 图谱与 diff 面板同时翻过去，原生菜单、托盘菜单和系统对话框也跟着变。

浅色不是把深色反相，而是取 WebStorm New UI Light 的真实取值——面板、树选中、运行按钮、语法着色、Git 状态色、终端 ANSI 16 色，都对齐 IDE 里看到的样子。

## User Stories

1. 作为用户，我想在设置里选择应用主题，这样我可以按环境和喜好决定界面明暗。
2. 作为用户，我想两个选项直接摊在那里、点一下就切，这样改主题只要一次点击。
3. 作为用户，我想主题默认是深色，这样升级后打开应用不会突然变样。
4. 作为用户，我想选完主题立刻看到效果，这样我不必重启应用来确认是否合意。
5. 作为用户，我想主题选择被记住，这样下次启动仍是我选的那一套。
6. 作为用户，我想应用启动时不闪一下深色再变浅色，这样冷启动观感是干净的。
7. 作为用户，我想浅色下的左树、工具栏、Tab 栏与 WebStorm 浅色的面板灰一致，这样两个窗口并排不违和。
8. 作为用户，我想浅色下的弹出菜单、下拉、对话框和输入框比面板更亮一档，这样浮层的层次仍然分得清。
9. 作为用户，我想浅色下选中行的蓝底和 hover 底能分辨，这样我知道当前选的是哪一行。
10. 作为用户，我想浅色下运行按钮的绿在白底上足够清楚，这样我不会看不清运行入口。
11. 作为用户，我想浅色下状态点（空闲 / 运行中 / 成功 / 失败）依然一眼可辨，这样我能扫一眼知道哪条配置出了问题。
12. 作为用户，我想终端与运行会话的输出在浅色下是白底黑字，这样它和 WebStorm 浅色的 Run 面板一致。
13. 作为用户，我想终端与运行会话里带颜色的输出（ANSI 色）在浅色下仍能读，这样日志不会失去可读性。
14. 作为用户，我想在终端与运行会话的输出里搜索时，浅色下的命中高亮清晰可见，这样查日志不受主题影响。
15. 作为用户，我想切主题后输出里已有的搜索高亮也跟着换色，这样不会留下一块旧配色的残迹。
16. 作为用户，我想切到别的 Tab 再切回来时，那个 Tab 的终端不是旧配色，这样主题切换是彻底的。
17. 作为用户，我想 Files 编辑器在浅色下用 WebStorm 浅色方案的语法着色，这样读代码的配色习惯是延续的。
18. 作为用户，我想切主题时正在编辑的文件不丢光标、选区、滚动位置和撤销历史，这样切换不打断我手上的事。
19. 作为用户，我想 Files 编辑器行号栏的 VCS 条纹在浅色下也按增 / 改 / 删区分，这样改动位置仍然一眼可见。
20. 作为用户，我想 Git 图谱的分支配色在两套主题下保持一致，这样我对分支颜色的记忆不会因为切主题而作废。
21. 作为用户，我想 Git 图谱的连线在浅色下依然互不糊在一起，这样交叉密集处仍可读。
22. 作为用户，我想 Git 的文件状态色（新增 / 修改 / 删除 / 冲突）在浅色下换成 WebStorm 浅色的对应色，这样它们在白底上有足够对比。
23. 作为用户，我想 diff 面板在浅色下用 IDE 的增删底色，而不是库自带的 GitHub 配色，这样它跟应用其余部分是一套。
24. 作为用户，我想浅色下的弹窗遮罩不要把整屏压得发灰，这样弹窗打开时背景仍然清爽。
25. 作为用户，我想原生的右键菜单、托盘菜单和选文件夹对话框也跟随主题，这样不会出现深浅混搭。
26. 作为用户（Windows），我想窗口顶栏的系统按钮在浅色下也是深色图标，这样它们在浅底上看得见。
27. 作为用户，我想拖动窗口边缘调整大小时露出的底色与当前主题一致，这样不会闪出一块异色。
28. 作为开发者，我想浅色取值有明确出处可查，这样后续改动不必靠肉眼比对截图。

## Implementation Decisions

**取色与切换（ADR-0026）**：浅色直取 WebStorm 原件、不手取；主进程按偏好钉死 `nativeTheme.themeSource`，渲染层 CSS 只响应 `prefers-color-scheme`。逐项取值与出处见 DESIGN.md 的浅色列。以下是模块层面的约定。

**偏好**：应用偏好增加 `theme`（`'dark' | 'light'`），默认深色，随既有应用偏好落盘；读写两侧都按枚举归一，脏值回落默认。

**共享定义**：主题类型与主进程用的窗口色集中在一个 shared 模块。窗口底色与 Windows 顶栏叠层是建窗选项、吃不了 CSS 变量，与面板色 / 图标色同值双写，改动需两处同步。

**主进程**：主题落到原生侧——`themeSource`、所有窗口的底色，非 macOS 再加顶栏叠层。store 初始化之后、建窗之前执行一次（保证页面加载时 `prefers-color-scheme` 已正确），偏好写入带 `theme` 时再执行。

**渲染层 CSS**：`:root` 以深色为基线，浅色用一个 `@media (prefers-color-scheme: light)` 块，**只列与深色不同的 token**；`color-scheme` 为 `light dark`。新增 `--bg-elevated`（浮起表面：弹层 / 输入控件 / 按钮，深色下与 `--bg-panel` 同值，深色观感不变）与 `--mask`（遮罩）；大面积容器仍用面板色。

**diff 面板**：应用侧覆写块的选择器必须同时列出两个 `data-theme`，漏掉哪个，库自带的那套（浅色是 GitHub 配色）就会全量接管；降级成不带属性的选择器又压不过库的特异性。

**JS 侧色源**：渲染层 store 持有 `theme`，初值由 `matchMedia` 读出（与 CSS 同源）。四处消费：

- **xterm 调色板**：须整对象替换，改属性再赋回不生效。
- **终端搜索装饰**：装饰色在创建时定死，换主题须重画；只在搜索框开着且有词时重画，关着时跑会凭空画出整屏高亮并滚动视口。
- **CodeMirror 主题与语法高亮**：两套预建好，经 reconfigure 切换，不重建编辑器状态。
- **diff 面板的 `diffViewTheme`**。

隐藏面板换主题不需要额外兜底：xterm 在不可见时暂停渲染，恢复可见时自行全量补画。

**设置界面**：「偏好」段全平台可见；其中「默认终端」只对 Windows 显示，shell 选项也只在 Windows 上探测。主题用**分段按钮**——两档摊开、一次点击即切，不遮住下面的内容。主题写入走 store 而不是本页自己的偏好写入，因为 JS 侧色源订阅的是 store。

**分段按钮组件**：新增通用控件，语义走 Base UI 的 **Radio** 而非 ToggleGroup——后者单选态下再点已选项会取消，落到「一个都没选」；Radio 还自带方向键切换与无障碍语义。选中态只靠底色 `--selection-row`，不新增全局 token，也不采用 JetBrains 的段描边画法（会与容器描边叠成双层边）；代价是选中态为蓝底而非 JetBrains 的中性浮起底。

**Git 图谱**：不改任何调色板（同上游 vscode-git-graph）；背景类已用 `--bg-deepest` 表达，自动跟随。

## Testing Decisions

主题的绝大部分是取值与样式，靠单测锁不住也不该锁——颜色对不对靠 DESIGN.md 记录的出处和真机对照，不靠断言十六进制字符串。

要测的：主进程应用偏好对 `theme` 的归一与默认回落（脏值、缺字段、老档案），以及 `theme` 确实能落盘（主进程 store 单测）。

不写的：CSS 变量取值的快照测试、组件渲染色的断言、Electron 原生侧 `themeSource` 的桩测试——前两者锁死实现且随设计调整必然失效，后者测的是 Electron 而不是本应用。

真机验证清单：冷启动无闪烁；切换即时生效且四处 JS 色源都跟上；切主题时编辑器不丢状态；隐藏 Tab 的终端切回来配色正确；diff 面板不被库的 GitHub 配色接管；原生菜单与托盘跟随。终端搜索另需三种情形各看一眼——搜索框开着切主题（高亮换色、当前命中不挪、视口不跳）、搜索过再按 Esc 关掉后切主题（不该冒出任何高亮）、隐藏 Tab 里搜索过再切主题（切回来配色正确且视口没被滚走）。

## Out of Scope

- **跟随系统**：明确不做。主题是两档强制值。
- **自定义主题 / 用户改色**：不做，不暴露任何调色入口。
- **高对比度主题**：不做。
- **深色取值的回校**：浅色直取原件后，反衬出深色有四处 1 单位手取误差（已记在 DESIGN.md）。不动深色任何取值，避免把「加浅色」变成「重做深色」。
- **Git 图谱调色板浅色化**：按上游做法保持不变，见 ADR-0026。
- **终端 ANSI 浅色的可读性调整**：浅色的白 / 亮白在白底上对比度低，这是 JetBrains 原样取值，照搬不调。
- **`--find-match-*` 与终端搜索装饰的同值双写**：仍是双写（加浅色后为两对四个值），不改成从 CSS 变量读。

## Further Notes

「打开于」子菜单的三张品牌图标（cursor / codex / claude）是各家的 **macOS 应用图标**，自带圆角方形底板，没有明暗两版。浅色下 codex 与 claude 的白色底板会与白色弹层融在一起，但图标主体是蓝紫 / 橙色、在白底上对比充足，仍认得出；cursor 是深色底板，浅色下反而更清楚。不改这三张图。
