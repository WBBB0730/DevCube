# resizable-panels

**可拖面板与布局记忆**

## Problem Statement

左侧项目树、右侧树（文件树、数据源目录、Redis 键列表）宽度固定 280px：名字长时被截断，屏幕宽时又显得局促。Git 详情区与内容搜索预览虽能拖，但关掉再开就回原样。窗口大小和位置只在本次运行里记，重启后回默认。另外，多选几个文件一起用 DevCube 打开时，只有第一个 Preview Window 按记住的状态打开，其余都是默认大小。

## Solution

1. 左侧项目树、右侧树改为可拖：拖分隔线改宽窄，双击分隔线回默认。
2. 所有可拖分隔（含 Git 详情区的高度与左右分栏、内容搜索的预览分界）用同一套实现，手感一致。
3. 设置 → 偏好新增「记住窗口和面板布局」（默认开）：开着时窗口几何与面板尺寸写进集中配置，重启后恢复；关着时只在本次运行内记，关掉开关即清掉已存的。
4. 修正多开 Preview Window 时的几何继承。

## User Stories

1. 作为开发者，我想拖动左侧项目树的右边界改宽窄，以便长名字不被截断。
2. 作为开发者，我想拖动右侧树（文件树、数据源目录、Redis 键列表）的左边界改宽窄，以便看清长文件名、表名。
3. 作为开发者，我想右侧三处树共用一个宽度，以便切 Tab、切条目时右侧边线不跳。
4. 作为开发者，我想放大缩小窗口时侧栏保持原来的像素宽、只有中间内容区伸缩，以便调好的宽度不被窗口缩放打乱。
5. 作为开发者，我想侧栏最窄 200px、最宽不超过所在区域一半，以便不把内容区挤没。
6. 作为开发者，我想双击分隔线回到默认尺寸，以便一键复原。
7. 作为开发者，我想 Git 详情区高度、详情左右分栏、内容搜索预览分界与侧栏同一手感，并且同样被记住。
8. 作为开发者，我想在一个窗口里拖过的尺寸，在其他窗口（主窗口、Preview Window）的同一处也生效，以便全局一致。
9. 作为开发者，我想在设置里开关「记住窗口和面板布局」，默认开着，以便按习惯选择。
10. 作为开发者，开关开着时，我想重启后主窗口与 Preview Window 回到上次的位置、大小、最大化 / 全屏状态，面板尺寸也恢复，以便不用每次重新摆。
11. 作为开发者，开关关着时，我想重启后一切回默认，而本次运行内拖过的尺寸与窗口几何仍保留，以便不必每开一次窗重新调。
12. 作为开发者，我想关掉开关时已存的布局随之清掉、再打开时立即记下本次运行里的布局，以便以后不会冒出很久以前的旧布局。
13. 作为开发者，我想在设置里一键恢复默认布局，所有面板回到默认尺寸、开着的窗口回到新开时的大小与位置，以便把调乱的布局一次复原。
14. 作为开发者，我想上次的位置已不在任何显示器上时（如拔掉外接屏），窗口以默认大小居中打开，以便窗口不跑到屏幕外。
15. 作为开发者，我想接连开出多个 Preview Window 时（如不同文件夹里的文件），每个都按记住的状态打开（最大化、全屏或大小），非最大化时依次错位，以便多开与单开一致。
16. 作为开发者，我想上次的窗口压在显示器边缘或跨在两块屏之间时，窗口挪进那块屏内打开、照旧最大化 / 全屏，而不是回到默认，以便多显示器下记忆不失效。
17. 作为开发者，我想应用崩溃、被强退或系统关机后再打开，窗口也回到最后的样子，以便记忆不依赖正常退出。

## Implementation Decisions

- **拖拽库**：react-resizable-panels（ADR-0053），界面层封成 `ui/resizable`。分隔线 1px，颜色沿用各处原来的边线；拖拽热区 6px；不做拖到底收起。
- **尺寸单位与限位**：侧栏与 Git 详情高度按像素记，窗口缩放时保持像素；Git 详情左右分栏与内容搜索预览分界按所在区域的百分比记。侧栏默认 280px、范围 200px ~ 所在区域 50%；Git 详情高度默认 250px（提交面板 292px）、范围 100 ~ 600px；两处分栏默认 50%、范围 20% ~ 80%。
- **记哪些**：五个尺寸，全局各一份（不按项目）：左侧项目树宽、右侧树宽（三处共用）、Git 详情高度、Git 详情左右分栏、内容搜索预览分界。Git 详情高度没拖过时按展开目标取默认高（同现状）。
- **只记用户拖拽**：只在用户拖完（指针或键盘）时记；挂载、窗口缩放、限位压缩都不记。双击分隔线即清掉这一项，回到默认。
- **恢复默认布局**：设置 → 偏好 → 窗口里的按钮，点后先二次确认（会动到开着的窗口）；确认后清掉全部面板尺寸与记住的窗口几何（盘上的一并清掉），各窗口里的面板随即回到默认；开着的主窗口与 Preview Window 当场回到新开时的样子（复原后的几何随即照常记下）：退出全屏与最大化，默认大小摆在所在显示器正中，多个 Preview Window 依次错开（同多开）。macOS 退出全屏是异步的，等退出完成再摆，多个全屏窗口依次退出（见「全屏切换排队」）。按钮常驻可点：窗口是否已是默认样子没法可靠判断，点下去窗口当场复原，本身就是反馈。
- **拖拽热区归分隔线自己**：库的热区只是几何判断，按在线旁的别的元素上会先归它们处理（如紧贴分隔线的滚动条）。分隔线用伪元素铺出与库的热区一样大的区域、盖在两侧之上，热区里的指针事件都落在分隔线上。
- **共享尺寸对齐**：Tab 面板切走只隐藏不卸载，拖拽库只在挂载时读默认尺寸；共享尺寸变了（本窗口或别的窗口），显示着的面板立即对齐，隐藏着的在重新显示时对齐。
- **记忆在主进程**：窗口几何与面板尺寸都在主进程内存里记一份，各窗口共享；开关开着时同步写进集中配置（ADR-0002），关着时只在内存里。面板尺寸改动由主进程推给全部窗口；新开的窗口经首屏快照拿到。
- **窗口几何跟着窗口实时记**：事件驱动，不轮询。窗口位置、尺寸、最大化、全屏一有变化就重新计时，停稳 300ms 后按窗口此刻的读数记一次（开关开着即落盘）；拖动、动画期间的一连串变化只记停稳后的那次，读数与记忆相同时不写盘。关窗时与退出时只补记还没记的那次（退出直接销毁窗口、不走关窗事件）。崩溃、强退、开发热重启、Windows 关机（此时不发退出事件）最多丢掉最后不到一秒的变化。
- **每个窗口各记一份**：最近变化过或聚焦过的那个代表这一类窗口（主窗口 / Preview Window）的记忆。新窗按记忆开，开窗时不现读别的窗口；记忆来自还开着的 Preview Window 且不是最大化 / 全屏时错位级联，所以同一批连开的几个也依次排开。
- **窗口几何在页面首帧之前就位**：按记住的位置尺寸建窗，紧接着套上最大化 / 全屏，再加载页面，页面第一次排版就是最终尺寸。等页面画好再套，窗口变大后会先露出一帧按原尺寸画的旧画面。Electron 套这两种状态时会把窗口直接显示出来，所以最大化 / 全屏的窗口建好即显示、页面加载期间由窗口底色垫底；普通窗口仍等页面画好再显示。
- **每种状态取可靠的来源**：最大化现读窗口。全屏从开始进入到退出完成都算：macOS 的全屏切换是异步的，窗口矩形与现读状态同时翻转，切换完成的事件晚约 0.6~0.7 秒，两者任一为真即算全屏，进入途中的全屏矩形不会被当成正常尺寸；建窗时套全屏的窗口从一开始就算全屏，所以连开的几个 Preview Window 都照记忆进全屏。正常位置尺寸只在窗口处于普通状态时取它的实际矩形；最大化、全屏期间保持原样（全屏期间是否最大化也保持进全屏前的），最小化期间整份不动，恢复时不还原最小化。
- **全屏切换排队**：macOS 同一时间只执行一个窗口的全屏切换，切换途中别的窗口发起的直接被丢弃（实测几个窗口同时进全屏只有第一个成功）。应用发起的全屏切换（建窗时进全屏、恢复默认布局时退出全屏）排队，前一次完成（任一窗口发出切换完成的事件）或那个窗口关掉再发下一次；撞上用户在别的窗口发起的切换而被丢弃时，按窗口实际状态记，不留着没兑现的全屏意图。其余平台当场完成。
- **恢复时挪进屏内**：记住的矩形与某块显示器有交集时，放在交集最大的那块，收进它的工作区（不压菜单栏、Dock、任务栏，比工作区大就缩到放得下），最大化 / 全屏照常恢复；与所有显示器都没交集时，默认大小在主显示器工作区居中。没有记忆时同样默认大小在主显示器工作区居中。

## Testing Decisions

- 单测：配置读写的归一（面板尺寸只留已知键与有限正数，窗口几何只留形状合法的记录，开关缺省为开），面板尺寸改动的合并（数值记下、null 清掉），恢复时的几何解析（挪进交集最大的显示器、无交集退回默认、错位只对非最大化 / 全屏），以及按读数更新几何的规则（普通状态取实际矩形，最大化 / 全屏 / 最小化时保持）。
- 不测拖拽库本身与 Electron 窗口生命周期；拖拽手感、多开 Preview Window、重启恢复手动验证，其中窗口几何覆盖 macOS 进出全屏（含刚点进全屏的过渡期间）、缩放与填充、拖到另一块屏、最小化后退出、强退后重启。

## Out of Scope

- 拖到底收起侧栏、快捷键开关侧栏。
- 按项目分别记尺寸。
- 文件树「整块隐藏」的可见性（仍不持久化）。
- 数据表格列宽、PDF 缩略图条宽、设置弹层的侧栏。
- 压缩窗口（按内容定高的小窗）。
