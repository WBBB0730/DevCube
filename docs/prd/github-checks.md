# github-checks

**GitHub 提交检查**

## Problem Statement

我把代码推到 GitHub 后，想知道 Actions（以及其他把结果报回 GitHub 的服务）跑没跑完、过没过，现在只能切去浏览器打开仓库页面。Git Tab 已经是我看提交历史的地方，却看不到这些提交在 GitHub 上的结果。

## Solution

在设置的「账号」栏、或 Git Tab 工具栏的「登录 GitHub」登录（设备授权：点「登录」，DevCube 显示并复制一串短码，点「打开 GitHub」后粘贴、授权即可；ADR-0054）。登录后，项目的远程指向 github.com 时，Git Tab 图谱每行提交说明后面显示该提交的 **Check** 汇总：绿勾通过、红叉失败、黄点进行中；没有检查的不显示。点开提交，详情的字段区多一栏「检查」，逐项列出每个 Check 的结果、名字与耗时，名字点开在浏览器里看。结果随图谱变化、「刷新」与前台轮询自动更新。

## User Stories

1. 作为开发者，我想在设置里点「登录」就完成 GitHub 授权：短码已经复制好，我看清之后点「打开 GitHub」，粘贴并授权即可。
2. 作为开发者，我的项目在 GitHub 上而我还没登录时，想在 Git Tab 里直接看到登录入口，不必知道设置里有这个功能。
3. 作为开发者，我想在登录弹窗里先看清短码、知道它已复制，再自己决定何时打开 GitHub 页面（关了也能再点开）。
4. 作为开发者，我想随时取消登录；在 GitHub 上拒绝授权或短码过期时，得到一句明确的失败原因。
5. 作为开发者，我想在设置里看到当前登录的 GitHub 账号，并能退出登录。
6. 作为开发者，我想在关于页一键给 DevCube 加星标，不必跳去网页；加过的能看出已加星。
7. 作为开发者，我想在 Git Tab 图谱的每一行一眼看出这个提交在 GitHub 上的检查过没过、是否还在跑。
8. 作为开发者，我想点开一个提交，看到它每一项检查的结果、名字和耗时（运行中的显示已运行多久），点名字直接去 GitHub 看日志。
9. 作为开发者，我推送之后不想手动刷新，就能看到新提交的检查出现、进行、结束。
10. 作为开发者，我想检查被重新运行后，图谱上的结果也能跟着变。
11. 作为开发者，我不登录 GitHub 时，Git Tab 和以前完全一样，不多发任何请求。
12. 作为开发者，项目不在 GitHub 上、或我没有权限时，Git Tab 照常工作，只是不显示检查。

## Implementation Decisions

- **登录**（ADR-0054）：DevCube 自己的 OAuth App + 设备授权，申请 `repo`（OAuth 凭证读私有仓库检查的唯一一档）。入口有二：设置里单独的「账号」栏（排在「偏好」之后，同 GitHub Desktop、Sourcetree、Fork 的账号页；「GitHub」小节（标题前带 GitHub 标志）下未登录显示「未登录」与「登录」，已登录显示登录名与「退出登录」）；Git Tab 工具栏右侧钮组最前的 GitHub 标志图标钮（同其余工具栏图标钮大小，标志为 GitHub 官方图标库 Octicons 的 mark-github 图形，直接内置、不引入图标库，悬浮说明「登录 GitHub，查看提交的检查结果」；与其后的钮之间隔一条竖线），只在未登录且项目有指向 github.com 的远程时出现（由主进程按查检查结果的同一套认法判断，远程地址增删改后重新判断），登录后即消失。两处打开同一个等待框。点「登录」开等待框：主进程拿到短码后复制到剪贴板，并把短码推给发起的窗口显示；框内为「在 GitHub 页面中输入此代码」（其后以次要灰字注明「（已复制）」）与大号短码，按钮「打开 GitHub」（用系统浏览器打开验证页，不自动打开——先让人看清代码）与「取消」。GitHub 的设备授权不提供带代码的验证地址，也没有文档化的预填参数，只能粘贴。授权完成即取登录名、加密保存凭证、关框；取消或关闭即中止轮询；失败换成「登录失败」错误框。同一时刻只有一次登录，再发起会取消上一次。
- **DevCube 仓库的星标**：登录后，设置「关于」页仓库链接右侧：没加过星为「星标」次要按钮（空心星），点一下即用当前账号加星（GraphQL `addStar`，POST 请求不受 REST 接口 60 秒缓存影响）；这次打开设置期间点过的，换成不可点的灰字「已星标」（实心星为 GitHub 的星标黄 `--github-star`，取自 Primer）直到关闭设置；之后再打开、读到已加过星的不再显示任何东西（星标只是邀请，加过即无用）。不提供取消。进关于页时读一次状态并记下仓库节点 id，加星只发一个请求；未登录或读不到时只显示链接；这一行固定按钮高度，按钮出现不撑高；失败弹「操作失败」错误框。只在用户点按钮时加星，绝不自动加星（GitHub 使用规范禁止不真实的互动）。
- **凭证**：safeStorage 加密后存集中配置（`githubAccount`），只在主进程解密；渲染端只拿得到登录名（启动快照带出，登录、退出、失效时推给全部窗口）。凭证被拒（401）或解不开即自动退出登录。退出只删本机凭证，不吊销授权。系统没有可用钥匙串时登录直接失败并说明原因。
- **网络**：主进程经 Octokit 发请求，fetch 换成 Electron 的 `net.fetch`（跟随系统代理），单次查询 20 秒超时，请求头带 `DevCube/<版本>`。
- **认仓库**：`git remote -v` 的获取地址（已按 insteadOf 改写），origin 指向 github.com 就用它，否则取第一个指向 github.com 的远程；认 https / http / ssh / git 协议与 scp 形式，含 `ssh.github.com:443`。不认 GitHub Enterprise 与 SSH 主机别名。每次查询现取，不缓存。
- **查询**：图谱汇总用 GraphQL 每个提交一个别名查 `statusCheckRollup.state`，每批 100 个、依次发出，某批查不到即停；只查 40 位 hash，未提交行与贮藏不查。GitHub 上没有的提交与没有检查的提交都记为「无」。各项检查查 `statusCheckRollup.contexts(first: 100)`：CheckRun 未完成为进行中，结论分通过 / 失败（含超时、启动失败、需要处理）/ 不算成败（跳过、取消、中性、过期）；Actions 作业名为「工作流 / 作业」，地址取 detailsUrl（没有则 permalink），耗时为开始到完成，正在运行（IN_PROGRESS）的另带开始时间（排队中的不带，排队不算运行）；StatusContext 按状态值映射、无耗时。GraphQL 部分出错时用随错误带回的那部分数据；其余失败静默。
- **汇总映射**：SUCCESS → 通过；FAILURE / ERROR → 失败；PENDING / EXPECTED → 进行中；其余（含没有检查）→ 无。
- **查询时机**（只在登录后、Git Tab 显示着时）：变为可见、登录、图谱列表变化（新提交、加载更多、切筛选）时查还没查过的；「刷新」（工具栏、⌘R、自动获取）的获取完成后全部重查（重新运行会让有结论的提交回到进行中）；前台（Tab 显示且窗口激活）分挡轮询进行中的，远程分支指向变化（推送、获取）后 1 分钟内，连同远程分支末端上还「无」检查的一起查（推送后 GitHub 要几秒才建出检查）。**分挡**：距上次变化 5 分钟内每 5 秒、15 分钟内每 10 秒、30 分钟内每 15 秒、再往后每 30 秒；回到前台、远程分支指向变化、查到的结果有变化都重新从 5 秒开始（GitHub 的接口额度按账号计、同一账号的各个工具共用，长时间没动静就放慢）。同一项目同一时刻只跑一个查询，期间要查的并入下一轮。换账号或退出即清空结果。
- **图谱行**：图标紧跟提交说明（同 GitHub 提交列表），说明过长时说明截断、图标保留；随行一起变淡；悬浮说明「检查通过 / 检查失败 / 检查进行中」。行点击照旧打开详情。
- **提交详情**：普通提交（非贮藏、非比较、非未提交）的字段区末尾加「检查」一栏，逐项显示结果图标、名字（有地址即为链接，经 openExternal 打开）与耗时，正在运行的显示已运行时长、每秒走一格（与图谱「日期」列共用一个整秒时钟），排队中与提交状态不显示时长；该提交汇总为「无」、没查过或未登录时整栏不出现。列表里还有没结束的项（或汇总仍是进行中、列表还没拉到）时按同样的分挡重查各项（某项开始运行、结束、出现或消失即回到 5 秒），全部结束即停——不能只看汇总：GitHub 的汇总失败优先，已有一项失败、其余还在跑时汇总已是失败。
- **颜色**：进行中新增 `--status-pending`（DESIGN.md「状态点」）；通过 / 失败沿用 `--status-success` / `--status-failed`，不算成败的用灰色。

## Testing Decisions

只测纯函数、零 mock（项目既有约定）：

- **远程地址 → 仓库**：各协议与 scp 形式、大小写主机名、末尾 `.git` 与斜杠、用户信息、443 端口；非 github.com、主机别名、层级不对、本地与 Windows 路径为 null。`git remote -v` 解析只取获取地址；origin 优先、其次第一个 GitHub 远程。
- **查询拼装与响应解析**：hash 白名单（防拼进查询的注入）、别名编号；汇总映射全表；响应里提交不存在 / 无检查 / 缺别名三种情形；各项检查的工作流名拼接、进行中无耗时、只有正在运行的带开始时间（排队中、开始时间缺失或解析不了的不带）、地址回退、结论三分、提交状态映射。
- **汇总的优先级**照 GitHub：有一项失败或出错即为失败（即使其余还在跑），否则有没结束的为进行中；图谱行原样显示。
- **查询时机**：三种模式各挑哪些提交（跳过未提交行与贮藏）、远程分支指向签名随推送 / 获取变化而不随本地提交变化；详情各项何时停止重查（汇总已失败但仍有项目在跑时不停）；分挡间隔的边界；各项检查签名随开始、结束、增减而变。
- **耗时文案**：秒、分秒、时分的边界与整分整时。
- **设备授权错误码**的说明文案。

网络请求、登录流程与界面不写自动化测试，按需手测。

## Out of Scope

- GitLab、Gitea、Bitbucket、GitHub Enterprise 等其他平台。
- 重新运行、取消检查等写操作；在应用内查看检查日志。
- 工具栏 / Tab 标签上的当前分支检查状态；检查结果通知。
- 识别 `~/.ssh/config` 里的 SSH 主机别名；一个项目同时查多个 GitHub 远程。
- 超过 100 项检查的分页。
- 在 GitHub 上吊销授权（需要 client secret）；多账号。
