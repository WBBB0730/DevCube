# 服务器与 SSH 终端

## Problem Statement

我经常要登服务器看日志、部署、排查问题。现在要么切到终端手敲 `ssh`，要么另开 FinalShell / Termius / Xshell 这类软件，可市面上没有一个既轻又好用的 SSH 工具。DevCube 已经把本地项目、终端、Git 聚在一个面板里，唯独连服务器还得出门。我的服务器大多用密码登录，每次手输很烦；FinalShell 虽然能记密码，本身却又重又不顺手。

## Solution

左树新增一种与 **Project** 并列的顶层条目：**Server（服务器）**。一台 **Server** 就像一个远在别处的 **Project**：点开它，右侧是它的 **SSH Terminal** Tab，可以开多个。

- **连接一律交给系统自带的 `ssh`**（ADR-0038）：用户已有的 `~/.ssh/config`、密钥、ssh-agent、跳板机、已知主机记录原样生效。
- **记住密码**：密码经 Electron safeStorage 加密后存放（加密密钥由系统钥匙串保管），连接时经 `ssh` 官方的 askpass 机制自动填上；首次连接的指纹确认、钥匙文件口令、验证码等提问一律以 DevCube 弹窗回答。
- **与 Project 共用左树**：**Pin**、排序、拖拽、名称筛选全部复用；排序菜单新增「项目」「服务器」两项勾选，按类型筛选显示。
- **断线不丢现场**：连接断开后 Tab 保留、报错留在原处，按回车原地重连；跨重启只恢复 Tab，不自动连接。
- **项目里也能连**：项目的新建终端菜单可直接「连接到服务器」，开出的同样是 **SSH Terminal**。
- **开着 TUN 代理也能连**（macOS / Windows）：给服务器打开「绕开代理直连」，连接就不经过代理、直接使用本机网络，不用改代理软件的规则（ADR-0039）。

远程文件管理（替代 WinSCP）是 **Server** 的另一个常驻 Tab（**Files Tab**），见 `docs/prd/server-files.md`。

## User Stories

1. 作为用户，我想从 `~/.ssh/config` 已有的主机里勾选添加 **Server**，可以一次勾多个，已添加过的置灰，以便不用重复录入连接信息。
2. 作为用户，我想手填添加 **Server**：名称（可选，默认「用户@地址」）、地址、用户名、端口（默认 22）、私钥文件（可选）、密码（可选），以便连接那些没写进 `~/.ssh/config` 的服务器。
3. 作为用户，我希望 DevCube 只在自己的配置里记住 **Server**，不改写我的 `~/.ssh/config`。
4. 作为用户，我想 **Server** 和 **Project** 排在同一个左树列表里、图标不同，以便一眼区分又不用来回切换。
5. 作为用户，我想 **Server** 也能置顶、排序、拖拽重排、按名称筛选，规则与 **Project** 完全一致。
6. 作为用户，我想在排序菜单里勾选只显示「项目」或只显示「服务器」，至少保留一项，并且跨重启保留，以便条目多的时候聚焦其中一类。
7. 作为用户，我点开一台 **Server** 时，不想一点就自动连上、弹出要我输密码；它的 **Status Tab** 未连接时显示「连接」按钮（见 `docs/prd/server-status.md`）。
8. 作为用户，我想在一台 **Server** 下开多个 **SSH Terminal**（右键菜单「新建终端」或新建终端快捷键），以便同时看日志和敲命令。
9. 作为用户，我想 `ssh` 的提问（首次连接确认主机指纹、密码、钥匙文件口令、验证码）都以 DevCube 弹窗出现，弹窗原样显示 `ssh` 的提问文字。
10. 作为用户，我想在密码弹窗里勾选「记住密码」（默认不勾），下次连接时自动填上、不再弹窗；密码输错重问时，勾选保持我上一次的选择。
11. 作为用户，当记住的密码已经不对时，我想看到弹窗提示我重新输入（可以顺便更新记住的密码），而不是一直拿错误的密码去试。
12. 作为用户，我想 **SSH Terminal** 断线后 Tab 保留，显示断开原因和退出代码，按回车就在同一个 Tab 里重连，以便看得到「连接被拒绝」「密码错误」这类原因。
13. 作为用户，我想重启 DevCube 后 **SSH Terminal** 的 Tab（名字和顺序）都还在，但处于已断开状态，按回车才连接，以便启动时不会一下子连一堆服务器、弹一堆提问。
14. 作为用户，我想编辑 **Server**：改名称；手填的可以改连接信息；修改记住的密码，或取消勾选「记住密码」来删掉它。来自 `~/.ssh/config` 的连接信息不在 DevCube 里改。
15. 作为用户，我想移除 **Server**，连到它的所有 **SSH Terminal**（包括开在项目里的）一并关闭，记住的密码一并删除。
16. 作为用户，我想在 **Project** 里新建终端时（项目右键菜单「连接到服务器 ▸」、Tab 栏「+」菜单里的「连接到服务器 ▸」）选一台 **Server**；开出的 **SSH Terminal** 挂在项目的 Tab 栏里，Tab 名是服务器名（同一处连同一台服务器的多个 Tab 按「prod / prod (2)」编号），行为与 **Server** 下的完全一致。
17. 作为用户，系统里找不到 `ssh` 时，我想在 Tab 里看到一句明确的中文提示，而不是莫名其妙的失败。
18. 作为用户，当系统没有可用的钥匙串（部分 Linux 桌面）时，我想看到「记住密码」不可用及原因，而不是让密码以接近明文的形式存下来。
19. 作为用户，我想在添加 / 编辑服务器时点「测试连接」，确认地址、端口、账号、密码都对了再保存；失败时看到 ssh 的报错原文。
20. 作为用户，我想像项目一样给 **Server** 新建命令型配置（名称、命令、服务器上的工作目录、环境变量），比如 `tail -f` 日志、重启服务，以便一点就在服务器上执行。
21. 作为用户，我想服务器上的配置和项目配置一样可以运行、重跑、停止、拖拽排序，有状态点，运行输出在该服务器的 Tab 栏里。
22. 作为用户，我想在所有输密码的地方（服务器对话框、ssh 提问弹窗）能切换显示 / 隐藏，以便确认自己输对了。
23. 作为开着 TUN 模式代理的用户，我想给 **Server** 打开「绕开代理直连」，连接时不经过代理，以便不用改代理软件的规则。
24. 作为同时在用 VPN 的用户，我想只给需要的 **Server** 打开直连，以便只能经 VPN 访问的服务器照旧走 VPN。
25. 作为用户，打开直连后如果找不到本机网络、或查不到服务器的真实地址，我想看到明确的原因，而不是悄悄改回走代理。

## Implementation Decisions

- **连接**：在 PTY 里直接跑系统 OpenSSH 的 `ssh`（ADR-0038）。引用 `~/.ssh/config` 的 **Server** 跑 `ssh <别名>`；手填的跑 `ssh -p <端口> [-i <私钥>] <用户>@<地址>`。会话复用 runner 现有的 PTY、无头屏幕缓冲与输出通道，与 **Terminal** 同一套管线。`ssh` 按登录 shell 环境的 PATH 查找（取第一个命中，Windows 补 `.exe`），与用户在终端里敲 `ssh` 找到的是同一个；Windows 上会不会落到 Git Bash 自带的那个取决于 PATH，待实测。
- **主机列表**：用成熟库 `ssh-config` 解析 `~/.ssh/config` 取出 Host 别名：跳过含通配符的模式；`Include` 由我们自行展开（该库只做文本解析）。列表里展示的地址与用户以 `ssh -G <别名>` 的结果为准，保证与真正连接时一致。
- **提问与密码**：每次启动 `ssh` 都设置 `SSH_ASKPASS`（DevCube 自带的小程序）和 `SSH_ASKPASS_REQUIRE=force`，让 `ssh` 的所有提问都交给 DevCube。小程序把提问转给主进程：若该 **Server** 有记住的密码、且本次连接还没用过，就直接作答；否则在发起连接的窗口弹窗。每次启动 `ssh` 带一个一次性令牌来区分连接，避免错误的密码被反复提交。做法参照 VS Code git 扩展的 askpass：启动脚本（posix 为 sh、Windows 为 cmd）运行时写进 userData 的 `askpass/` 下，以 `ELECTRON_RUN_AS_NODE` 运行应用自带的 Electron 执行小助手 `out/main/askpass.js`（electron-vite 的第二个主进程入口，打包时 `asarUnpack`）；小助手与主进程经本地套接字（posix 为临时目录下的 socket 文件，Windows 为命名管道）各发一行 JSON。askpass 起不来时 `ssh` 退回在终端里提问，只是不能自动填记住的密码。askpass 只拿到提问原文、不知道是否回显，按原文判断类型：以 `(yes/no…)?` 收尾为主机指纹确认，含 password / 密码（且不含 passphrase）为密码，其余按需保密的输入处理。
- **密码存储**：用 Electron `safeStorage` 加密后存进集中配置（ADR-0002）；密码不以明文落盘，也不经命令行参数或环境变量传递。`safeStorage` 不可用，或 Linux 后端为 `basic_text` 时，不提供「记住密码」。
- **数据模型**：**Server** 记录 id、名称、来源（`~/.ssh/config` 别名，或手填的地址 / 用户 / 端口 / 私钥路径）、添加时间、打开时间、是否置顶、自定义序、是否绕开代理直连（老档案缺省为否）；记住的密码单独存（键为服务器 id，只存密文），不随服务器列表下发渲染端。同一连接目标不重复登记。
- **条目与自定义序**：左树条目键 = **Project** 的绝对路径或 `server:<id>`（绝对路径不会以 `server:` 开头，与 Tab 键的前缀约定同理）。**Project** 与 **Server** 各自带一个 `order`，自定义序按它升序；老档案里的 **Project** 缺 `order` 时按数组下标补齐，原有自定义序原样保住。新登记的条目取全部条目最小值再减一（插到最前）；拖拽松手后在「全部条目按当前规则排好的序列」里挪位并整体重写 `order`，按类型筛掉的条目保留各自相对位置；**Pin** 时取目标区块最小值再减一。工作台现场的「当前项目 / 每项目激活 Tab / 每项目终端壳」相应推广为按条目记（`currentEntryKey` / `activeTabByEntry` / `terminalsByEntry`），读档时把旧字段名迁移过来。
- **左树**：**Server** 行用 lucide `Server` 图标，与项目行一样有折叠箭头与配置区（只有命令型，没有「检测到的配置」）；hover 显示「更多」，右键菜单与之相同：新建终端、新建配置、编辑、置顶 / 取消置顶、移除。**Pin**、排序、拖拽、名称筛选沿用 `project-sort` 的规则，扩展为同时处理两类条目。新增 **Server** 与新增 **Project** 一样插到列表前部、自动选中并滚入视口。
- **排序菜单**：「固定置顶」下方加分隔线，再加「项目」「服务器」两项勾选（样式同「固定置顶」）；只剩一项勾选时，该项不可取消。勾选状态随排序偏好一起持久化。
- **Tab 与工作台**：**Server** 的 Tab 栏没有 Git，常驻 Tab 为 **Status Tab**（见 `docs/prd/server-status.md`）与 **Files Tab**（见 `docs/prd/server-files.md`），其后是它的配置的 **Run Session** 与 **SSH Terminal**。激活 Tab 记忆、默认激活、关闭后回落的规则与 **Project** 一致。**SSH Terminal** 的壳（id、名称、顺序、所连 **Server**）按条目持久化，做法同 **Terminal** 壳（ADR-0008），恢复后是已断开状态。
- **SSH Terminal 生命周期**：`ssh` 进程退出后会话保留、Tab 不关，追加一行「连接已断开，退出代码为 N，按回车重新连接」（形式参照 **Run Session** 的结束行）；按回车就在同一个 Tab 里重新启动 `ssh`；只有手动关闭 Tab 才销毁。与 **Terminal** 一样不计入退出确认。
- **项目里的 SSH Terminal**：**Project** 的新建终端入口加「连接到服务器 ▸」子菜单；开出的 Tab 与本地 **Terminal** 并列在项目 Tab 栏里，壳随项目持久化。
- **移除 Server**：确认方式与移除 **Project** 一致；关闭所有连到它的 **SSH Terminal**，删除记录和记住的密码。
- **找不到 ssh**：启动失败时在 Tab 内输出中文提示。
- **服务器上的命令型配置**：新增一种配置 `kind: 'remote'`（属于某台 **Server**；**Project** 的命令型不变），字段同命令型：名称、命令、工作目录（服务器上的目录，`~` 开头可用，缺省即登录后的目录）、环境变量（在服务器端导出）。运行 = 在 PTY 里起 `ssh -t <目标> '<命令串>'`，命令串由远端登录 shell 按 POSIX sh 语法执行：先打印运行头（同 ADR-0023，由执行命令的 shell 打印；目录缺省显示 `~`），再 `cd`、`export`、执行命令，任一步失败即停。**Run Session** 语义不变（单实例、重跑先停旧的、停止即结束 ssh、结束行「进程已结束，退出代码为 N」），提问同样经 askpass。编辑对话框沿用命令配置那一个：工作目录改为纯文本输入（不能用本机的目录选择器）。移除 **Server** 时连同它的配置与运行会话一起删除。
- **测试连接**：添加 / 编辑对话框底栏左侧「测试连接」。用表单当前的连接目标起 `ssh -o ConnectTimeout=10 <目标> exit`（不分配终端），测试只检验表单里的内容：密码提问不弹给用户——表单里填了密码就用它作答一次，没填时勾着「记住密码」才用记住的；密码被拒、或根本没有密码时立即结束 ssh（不让它以空密码再试，免得在服务器上多记失败次数），结果为「密码错误」或「服务器要求输入密码，请先填写后再测试」。其余提问（首次连接确认指纹、私钥口令、验证码）照常经 askpass 弹窗。测试本身不记住密码。是否直连按表单当前的勾选。结果显示在按钮右侧同一行：退出代码 0 即「连接成功」；否则「连接失败」（鼠标停上去显示 ssh 报错的最后一行），同时另弹错误框显示同一段报错。同一时刻只测一个，新测试取消旧的；对话框关闭即取消。添加时只能测一台：手填的那台，或只勾了一台的 SSH 配置主机。
- **绕开代理直连**（ADR-0039，仅 macOS / Windows）：每台 **Server** 各有一个开关，添加时默认不勾，没有全局设置。Linux 上不显示，已存的值也不生效。**SSH Terminal**、服务器上的配置、测试连接三处起 `ssh` 时，按该服务器的开关（测试连接按表单当前的勾选）决定是否直连。直连时每次连接现查实体网卡与它所在网络的 DNS，然后追加 `-o BindAddress=<实体网卡的 IPv4 地址>`；目标是域名时，用绑定该地址的查询向那个 DNS 取 A 记录，再追加 `-o HostName=<真实地址>` 与 `-o HostKeyAlias=<原主机名>`（端口不是 22 时写成 `[主机名]:端口`；用户配置里已有 `HostKeyAlias` 就不加）。原主机名与是否插手都按 `ssh -G` 的结果判断：生效配置里有 `ProxyJump`、`ProxyCommand`、`BindAddress` 或 `BindInterface` 时不插手。查不到时不起 `ssh`：**SSH Terminal** 与 **Run Session** 的结束行、测试连接的失败结果写明原因（「无法直连：未找到可用的本机网络」/「无法直连：未能解析 X 的真实地址」），不退回经代理连接。

## Testing Decisions

沿用项目约定：只测纯函数，零 mock。

- `~/.ssh/config` 里可直接连接的别名：跳过通配符与取反模式。（`Include` 展开与读文件在 IO 层，不在单测范围）
- `ssh -G` 输出解析。
- `ssh` 参数拼装（端口、私钥、以 `--` 结束选项）与手填目标校验。
- 提问类型判断（用真实提问原文）与 askpass 应答决策：有可自动作答的密码时第一次密码提问自动作答，被拒后或没有密码时，正常连接转弹窗、测试连接拒答；非密码提问一律转弹窗；「记住密码」的初始勾选。
- 混合条目的排序、Pin 分区、名称筛选、按类型筛选；拖拽挪位（被筛掉的条目保住相对位置）；Pin 进入目标区块开头。
- 没有常驻 Tab 的 **Server** 条目的默认激活。
- **SSH Terminal** 壳的合并与落盘、旧工作台字段的迁移。
- 在 PATH 里找 `ssh`。
- 服务器上执行的命令串（运行头、`~` 目录、环境变量与单引号转义）；测试连接与运行的 ssh 参数；测试失败说明的提取。
- 绕开代理直连：按 `ssh -G` 结果判断是否插手；直连参数拼装（IP 目标只绑定地址，域名目标加 `HostName` 与 `HostKeyAlias`，非 22 端口的写法，已有 `HostKeyAlias` 时不加）；`scutil` 输出（主网卡、DNS 地址）与 Windows 网卡查询结果的解析。

落在 `src/shared/server.test.ts`、`tree-entry.test.ts`、`project-sort.test.ts`、`workspace.test.ts`、`tab-activation.test.ts`、`renderer-bootstrap.test.ts` 与 `src/main/command.test.ts`（在 PATH 里找 `ssh`、服务器上的命令串）。不写 UI / e2e 测试。

实测记录：

- 已实测（macOS 15.7、OpenSSH 9.9）：`SSH_ASKPASS_REQUIRE=force` 下，首次连接的主机指纹确认经启动脚本 → 小助手 → 本地套接字交到 DevCube，原文以 `Are you sure you want to continue connecting (yes/no/[fingerprint])? ` 收尾；回答 `no` 时 `ssh` 以 `Host key verification failed.` 结束。askpass 拿不到「是否回显」，只能按原文判断类型。
- 待实测：密码提问的自动填入、记住与被拒后重问（需要一台用密码登录的服务器）；私钥口令与验证码的提问原文。
- 待实测：Windows 上系统 OpenSSH 是否默认可用、是否支持 `SSH_ASKPASS` / `SSH_ASKPASS_REQUIRE`、cmd 启动脚本能否被 `ssh` 执行；与 Git Bash 自带 `ssh` 的取舍。
- 待实测：Linux 上 `safeStorage` 后端的判定。
- 已实测（macOS 15.7、Clash Verge Rev + mihomo 的 TUN 模式、fake-IP）：照常连接时，TCP 连得上，但在收到服务器问候前就被断开；`ssh -b <en0 的地址>` 能正常收到问候；域名经系统解析得到 `198.18.x.x` 假地址；同一个 DNS（`scutil --dns` 里限定到 en0 的 114.114.114.114），不绑定时同样答假地址，绑定 en0 地址后答真实地址（路由器 DNS 同样可行）。TUN 开着时，`scutil` 读到的主网卡 `PrimaryInterface` 仍是 en0。
- 已实测（同上环境，不登录）：用 DevCube 算出的直连选项连 `git@github.com`：照常连接在问候前被断开；加上 `BindAddress` / `HostName` / `HostKeyAlias` 后收到服务器问候、进入认证；主机指纹按原主机名 `github.com` 记入 known_hosts。算出选项约 50ms。
- 待实测：Windows 上绑定实体网卡地址能否绕开 TUN，以及 PowerShell 查询实体网卡与 DNS 的结果。

## Out of Scope

- 远程文件管理（替代 WinSCP）：另行立项，见 `docs/prd/server-files.md`。
- 端口转发、隧道、SOCKS 代理的管理。
- **Server** 分组、多台批量执行命令。
- 内置 SSH 协议实现（见 ADR-0038）。
- 改写 `~/.ssh/config`；在 DevCube 里编辑来自 `~/.ssh/config` 的连接参数。
- 手填 **Server** 的跳板机等高级选项：需要的话写进 `~/.ssh/config`。
- 自动重连、心跳保活设置。
- 从 FinalShell / Termius 等软件导入服务器列表。
- 在线状态、延迟探测。
- 生成密钥、把公钥装到服务器上（`ssh-copy-id`）。
- 「无项目」：另行立项。
- Linux 上绕开代理（普通进程做不到，见 ADR-0039）；自动识别「被代理拦截」并自动改直连；直连时的 IPv6 目标。
