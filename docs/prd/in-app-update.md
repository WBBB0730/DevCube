# in-app-update

**应用内更新**

## Problem Statement

DevCube 已能打 tag 发到 GitHub Releases，但用户仍须自己去网页下载重装。正式版与 Beta 并行安装时，还容易搞不清该跟哪条线。应用缺少统一的窗口顶栏与设置入口，更新提示也无处安放；退出时若还有配置在跑，进程会被直接杀掉，没有提醒。

## Solution

以公开仓库的 GitHub Release 为唯一更新源，包装好的安装版在应用内检查、静默下载、提示后安装（退出时若已下好也会装上）。正式版与 Beta 各跟自己的 Release，不跨线。Windows Portable 不能自动装，顶栏用同款按钮，点击打开对应 Release 页。一并换上自定义窗口顶栏（中间标题与现有逻辑一致；右侧为更新按钮与设置），设置弹层对齐 WebStorm（关于做实、快捷键只读）。凡会退出整个应用的路径，若仍有运行中的 **Run Session**、未完成的文件传输或服务器上未保存的文件，必须二次确认（**Terminal** 不计入）。

## User Stories

1. 作为正式版用户，我想应用自动发现新的正式 GitHub Release，以便不用自己盯发布页。
2. 作为 Beta 用户，我想应用只发现 Beta / Pre-release，以便不会被升成正式版安装包。
3. 作为正式版用户，我不想收到 Beta / Pre-release，以便稳定线不被预发布打扰。
4. 作为用户，我想启动后稍后自动检查更新（带短随机延迟），以便不和启动抢资源、也避免多实例同时戳 GitHub。
5. 作为用户，我想应用开着时大约每 4 小时再查一次，以便当天后续发版也能收到。
6. 作为用户，我想在设置 → 关于里手动「检查更新」，以便刚发版时立刻查。
7. 作为可自动更新形态的用户，我想发现新版本后后台静默下载，以便不打断当前工作。
8. 作为可自动更新形态的用户，我想只有下载完成、可以安装时，顶栏才出现更新按钮，以便按钮含义单一。
9. 作为可自动更新形态的用户，我想点顶栏更新按钮后先看到更新日志，确认后再重启安装，以便马上用上新版本。
10. 作为可自动更新形态的用户，我想更新已下好后正常退出应用时也自动装上，以便不必非点顶栏按钮。
11. 作为用户，我不想关掉或「跳过」顶栏更新按钮，以便待处理更新一直可见直到装完。
12. 作为 Windows Portable 用户，我想在已知有新版本时看到同款顶栏按钮，看过同一个更新弹窗后打开对应 GitHub Release，以便自行下载便携包。
13. 作为 Windows Portable 用户，我不想应用尝试对我做 NSIS 式静默安装，以便不出现失败或错包。
14. 作为 macOS 用户，我想无论当初用 dmg 还是 zip 装上的 `.app` 都能完整应用内更新，以便行为一致。
15. 作为开发者，我想未包装开发模式与便携版一样只检查、经更新弹窗打开 GitHub Release，以便本地验证更新 UI；不在开发态静默下载安装。
16. 作为用户，我想看到自定义窗口顶栏（隐藏系统标题栏），以便外观靠近 WebStorm。
17. 作为用户，我想顶栏中间标题与现在窗口标题一致，以便不学两套文案。
18. 作为用户，我想顶栏右侧有设置齿轮，以便进入应用设置。
19. 作为用户，我想设置是盖在主窗口上、布局像 WebStorm 设置的大弹层（不是第二个窗口），以便手感熟悉。
20. 作为用户，我想在设置「关于」里看到版本、**Release Edition** 与更新状态，以便更新与版本信息一处看清。
21. 作为用户，我想在关于里点「立即更新」时也先看更新弹窗再确认，以便两个入口一致。
22. 作为用户，我想设置里有「快捷键」只读列表，以便查阅。
23. 作为用户，当还有运行中的 **Run Session**、未完成的文件传输或服务器上未保存的文件时，我想会退出整个应用的操作都先二次确认，以便不误杀正在跑的配置、不丢传输与修改。
24. 作为用户，当只有 **Terminal** 在跑、没有上述三项时，我不想被退出确认拦住，以便终端不挡退出。
25. 作为 macOS 用户，我只关窗口、应用仍留在 Dock 时，不想被当成「退出应用」来确认，以便保持现有「关窗不退出」行为。
26. 作为用户，我想检查失败时当作「已是最新」、不展示错误文案，并在稍后自动重试，以便发版窗口期或网络抖动不骚扰。
27. 作为维护者，我想公开仓库即可更新、不要求用户侧 GitHub Token，以便分发简单。
28. 作为用户，我想正式版与 Beta 的更新与数据目录继续隔离，以便内测不影响稳定安装（见 ADR-0012）。

## Implementation Decisions

- **更新源**：`electron-updater`，`publish.provider = github`，面向公开仓库 `WBBB0730/DevCube`。不以自建 generic 站、不以改回构建期 `--publish` 为主路径。
- **身份封闭（ADR-0014）**：检查结果在采纳前按当前 **Release Edition** 过滤——正式只接受非 Pre-release；Beta 只接受 Pre-release；候选版本号派生的身份还须与本机一致。明确不用官方 `channel=beta`「beta ∪ latest」漏斗作主方案。
- **更新形态**：可自动更新——macOS 上的 `.app`（载体是 Release 上的 zip + `latest-mac.yml`）与 Windows NSIS 安装版（`latest.yml` + setup）。仅打开 Release——Windows Portable 与未包装开发（ADR-0017）：只检查与提示，确认后打开对应 Release，不下载安装。包装后仍解析为 `dev` 的平台（如 Linux）不启用检查。
- **检查节奏**：启动后短随机延迟再查；运行中约每 4 小时；进入关于自动检查（距上次不足 5 分钟则跳过），手动「检查更新」不受此限。检查失败（含发版窗口期 Atom 指向无资产 tag）显示为已是最新、不报错，约 15 分钟后静默重试；已有可用更新时复检不降级、不回到检查中，下载中不打断。下载失败仍在关于页提示。
- **下载与安装**：可自动更新形态通过身份过滤后才显式下载（关掉自动下载，与身份过滤同一处控制）。顶栏按钮可自动更新形态下载完才出现，仅打开 Release 形态已知有新版本即出现；不可关闭、不可跳过，点击先开更新弹窗。安装一律走正常退出：退出确认 → 清理 → 安装（不用 electron-updater 的退出时自动安装），顶栏确认与已下好后的正常退出走同一条路。macOS 上自定义的退出清理会让 Squirrel.Mac 装完不重开，安装前须卸掉拦截退出的监听（ADR-0016）。
- **发布侧依赖**：Release 上须与安装包一起挂 `latest.yml` / `latest-mac.yml`。进 Release 与更新清单的文件名一律用无空格的 `${name}`（`devcube` / `devcube-beta`），否则资产名与清单里的 url 对不上、更新下不下来（ADR-0015）；带空格的显示名「DevCube Beta」只用于 UI。
- **窗口顶栏**：隐藏系统标题栏，macOS 保留原生红绿灯，Windows/Linux 用系统窗口按钮叠层。中间标题与窗口标题同一套（按当前条目显示），字面固定写「DevCube」，不用 Beta 显示名。右侧为条件显示的更新按钮 + 设置齿轮。
- **设置弹层**：主窗口内全屏级模态（非第二个窗口），改动即时生效，底部只有「确定」；与 Git 仓库设置共用外壳。栏目：关于、偏好、系统集成、快捷键（只读）。关于页进入即检查（启用检查的形态）；主按钮只有「检查更新」/「立即更新」两档（检查中、下载中仅禁用、不换文案）：可自动更新已下完，或仅打开 Release 形态有新版本时为「立即更新」，点击开与顶栏同一个更新弹窗。
- **退出确认**：Cmd+Q、托盘「退出」、Linux 关窗、更新重启安装等会结束整个应用进程的路径，若存在运行中的 **Run Session**、未完成的文件传输或服务器上未保存的文件，先确认；**Terminal** 不参与条件。macOS 仅关窗不退出不触发。确认文案逐项列出数量（**Run Session** 用「运行会话」表述）。
- **模块划分（深模块优先）**：**更新策略纯函数**（身份 / 形态 / 候选 → 是否采纳、按钮是否显示、点击动作，供单测）；**主进程更新编排**（检查、下载、退出时安装、打开 Release，经 IPC 推状态）；**退出闸**（汇总三项确认条件、拦截各退出路径）；渲染层的顶栏、设置弹层与关于 / 快捷键 UI。
- **与 ci-release 关系**：发版流水线与双身份以 `docs/prd/ci-release.md` + ADR-0012 为准。

## Testing Decisions

好测试：只测可观察的策略与纯函数（给定身份/形态/候选 → 是否采纳、按钮是否显示、点击语义），以及退出闸的确认条件；不测真实 GitHub 网络、不测真实 NSIS/Squirrel 安装、不测 CI 上传。

要测的模块：

- **更新过滤与形态策略**（正式/Beta、便携/安装、可安装前不显示按钮等）。
- **退出确认条件**（运行中的 Run Session、未完成的文件传输、服务器上未保存的文件；Terminal / SSH Terminal 不计）。
- 既有 **Release Edition** 解析保持绿。

先例：`release-edition`、`project-sort`、`app-shortcut` 等 shared/main 纯函数 vitest。UI 与真机更新靠维护者在包装构建上冒烟。

## Out of Scope

- 快捷键改键与冲突检测持久化
- 官方 electron-builder 多 channel 漏斗（beta 含 latest）
- 私有仓库更新 / 用户侧 GitHub Token
- 跳过某版本 / 暂时隐藏更新按钮
- 从 Release 正文生成更新日志（日志手写在 `CHANGELOG.md`、随更新清单下发，见 `docs/prd/changelog.md`）
- Windows 代码签名（仍可未签名发版；SmartScreen 体验另案）
- Linux 打包与更新
- 单独 BrowserWindow 设置窗
- 顶栏搬入 Run Configuration / 调试按钮等 WebStorm 其余控件
- 将窗口标题字面改成「DevCube Beta」
