## Problem Statement

把一个还没克隆到本地的远程仓库收进 DevCube，现在要分两步走：先切到终端（或别的工具）敲一遍 `git clone`，等它跑完，再回到 DevCube 里「添加现有项目」把那个目录选进来。中间还得自己盯着克隆有没有成功、克隆到哪儿去了、目录叫什么名字。DevCube 已经自带完整的 Git 能力，唯独"把仓库弄到本地"这一步要出门。

## Solution

在左树顶部「新建 / 添加项目」菜单里加第三条入口：**从 Git 仓库克隆…**。填一个仓库地址、选一个存放位置、确认目录名，DevCube 就地克隆，期间在同一个对话框里显示真实进度（当前阶段 + 百分比）并可随时取消。克隆成功后，目录自动登记为 **Project** 并选中滚入视口——收尾与既有的「新建空项目」「添加现有项目」「拖入文件夹」完全一致。

克隆是 **Project** 的第四种登记方式，不引入新实体：克隆出来的项目就是普通 Project，没有任何特殊状态或标记。

## User Stories

1. 作为用户，我想在左树顶部的「+」菜单里看到「从 Git 仓库克隆…」，这样我不必猜这个功能藏在哪儿。
2. 作为用户，我想在左树为空时的提示语里就知道有克隆这条路，这样第一次用也不会漏掉。
3. 作为用户，我想粘贴一个 HTTPS 仓库地址就能克隆，这样最常见的场景零心智负担。
4. 作为用户，我想粘贴 SSH 形式的地址（`git@host:owner/repo.git`）也能克隆，这样用部署密钥的私有仓库照样可用。
5. 作为用户，我想填一个本地路径或 `file://` 地址也能克隆，这样可以从本地裸仓库或另一份检出派生新项目。
6. 作为用户，我想打开对话框时若剪贴板里正好是个仓库地址就自动填进去，这样从网页复制完直接确认即可。
7. 作为用户，我想在剪贴板不是仓库地址时保持地址栏为空，这样不会被无关内容污染。
8. 作为用户，我想目录名从仓库地址自动派生（去掉 `.git` 后缀取最后一段），这样绝大多数情况下不用手填。
9. 作为用户，我想直接粘贴浏览器地址栏里的仓库网页链接（可能带 `/tree/分支`、`/blob/…`、`/pull/52` 或查询串）也能克隆，这样不必先回仓库首页复制「正确」的地址。
10. 作为用户，我想在自动派生的目录名不合我意时能改写它，这样可以避免与既有目录重名或用更贴切的名字。
11. 作为用户，我想改完地址后目录名跟着更新，但一旦我手动改过目录名就不再被覆盖，这样不会丢掉我的输入。
12. 作为用户，我想存放位置默认是我上次添加项目用的父目录，这样连续添项目时不必反复选。
13. 作为用户，我想能点一个按钮用系统文件夹选择器换存放位置，这样不必手敲长路径。
14. 作为用户，我想在对话框里看到最终会落到哪个完整路径，这样确认前心里有数。
15. 作为用户，我想在目标目录已被占用（已存在且非空）时立刻被提示并禁止确认，这样不会等到克隆失败才发现。
16. 作为用户，我想在存放位置还没选（首次使用）时被明确提示，这样知道缺了什么。
17. 作为用户，我想在地址为空时确认按钮是禁用的，并能从悬停提示知道原因。
18. 作为用户，我想勾选「包含子模块」来连带克隆嵌套仓库，这样用子模块的项目一次到位。
19. 作为用户，我想这个勾选框默认不勾，这样行为与 git 默认一致，不会意外下载一大堆东西。
20. 作为用户，我想在克隆期间看到当前阶段的中文名（接收对象 / 处理增量 / 检出文件等）和百分比，这样知道它在干什么、还要多久。
21. 作为用户，我想看到一条随百分比推进的进度条，这样一眼就能判断进展。
22. 作为用户，我想在还没有百分比的早期阶段（枚举对象等）也看到阶段文字，这样不会以为程序卡住了。
23. 作为用户，我想随时点「取消」中止克隆，这样发现地址填错或仓库太大时不必干等。
24. 作为用户，我想取消或失败后磁盘上不留半成品目录，这样重试时不会撞上"目录已存在"。
25. 作为用户，我想克隆失败时回到填写界面并保留我填的内容，同时看到 git 的原始报错，这样能直接改了重试。
26. 作为用户，我想在仓库需要凭据而 DevCube 拿不到时看到一句能看懂的提示，这样知道该去配 credential helper 或改用 SSH 地址。
27. 作为用户，我想克隆期间对话框不能被误点遮罩关掉，这样不会手滑让一个跑着的克隆失去界面。
28. 作为用户，我想克隆成功后项目自动出现在左树里并被选中、滚进视口，这样紧接着就能开始干活。
29. 作为用户，我想克隆成功后这个项目的 Git Tab 直接可用、能看到刚克隆下来的提交历史，这样不必手动刷新。
30. 作为用户，我想克隆用的存放位置被记住，下次添加项目时默认就是它，这样与既有入口的行为一致。
31. 作为用户，我想同一时刻只有一个克隆在跑，这样不会有多个后台任务互相干扰、说不清谁在占目录。
32. 作为用户，我想克隆出来的项目就是普通项目——能置顶、能重命名、能删除、能跑命令，这样不必学新概念。
33. 作为用户，我想在系统上找不到 git 时得到明确提示，这样知道是环境问题而不是地址写错了。

## Implementation Decisions

**模块划分**

- 共享层新增一个纯函数模块，负责：把浏览器网页链接归一成可克隆地址（剥查询串与锚点，遇到 `tree` / `blob` / `pull` / GitLab 的 `-` 等网页路由段即截断到仓库本身；只处理 http(s)，ssh / scp / 本地路径原样放行）、从仓库地址派生目录名（对齐 git 自身 `guess_dir_name` 的口径：剥尾部斜杠与 `<repo>/.git` → 只有主机名时剥端口 → 取最后一个 `/` 或 `:` 之后的一段 → 剥 `.git` 后缀（`.bundle` 不剥，git 只在明确的 bundle 场景剥））、判断一段文本是否像仓库地址（剪贴板预填用）、判断目录名是否合法、把 `git clone --progress` 的 stderr 行解析成结构化进度。全部无副作用、无 electron 依赖，直接单测。
- 主进程新增一个克隆模块：单例语义（同一时刻至多一个克隆在跑），对外是「启动（带进度回调）/ 取消 / 探测目标目录状态」三个入口。它不依赖 electron，项目登记由 IPC 层在克隆成功后调用既有的按路径登记流程完成。
- git 进程执行层新增一条**流式**路径，与既有的「跑完一次性返回」并存、互不影响：接受 stderr 行回调，返回可取消的句柄，其余（登录 shell 环境、git 可执行文件发现与缓存、`GIT_TERMINAL_PROMPT=0` / `GIT_EDITOR=true`）与既有路径共用同一套。
- 渲染层新增一个项目无关的克隆对话框组件，由左树菜单打开、挂在应用根上；开关状态放在应用 store 里，和既有对话框的挂载方式一致。

**执行细节**

- 克隆命令：`git clone --progress [--recurse-submodules] -- <url> <目标路径>`，cwd 取存放位置。`--` 隔开防止以 `-` 开头的地址被当选项。
- 进度来自 stderr（git 用 `\r` 原地刷新），按 `\r` 与 `\n` 同时切行，取形如 `阶段: NN% (a/b)` 的行解析出阶段与百分比；阶段名到中文的映射在共享层。无百分比的行（枚举对象等）只更新阶段文字。
- 进度经 IPC 事件流式推给渲染端（与内容搜索的事件流同一形态），克隆结果由 invoke 的返回值收口。
- 取消用 SIGTERM——git 自己注册了信号清理，会删掉它创建的目标目录。

**目标目录与清理**

- 目标路径 = 存放位置 + 目录名。启动前探测三态：不存在 / 存在且为空 / 被占用；被占用则拒绝（UI 提前禁用确认，主进程执行前再校验一次防竞态）。
- 兜底清理：仅当「克隆前目标不存在」且克隆非成功结束时，删除目标目录。这个条件下该目录必是 git 刚建的，删除安全。克隆前已存在的空目录不删目录本身（Windows 上 kill 不走信号处理器，git 的自清理可能不生效，故需要这条兜底）。

**凭据**

沿用既有口径：靠系统 credential helper / SSH agent，应用内不弹窗要密码（与 fetch / push 一致）。需要交互式认证的仓库会直接失败，把 git 的原始报错原样呈现。这只是当前现状而非产品约束，后续可以再加应用内凭据输入。

**UI 契约**

- 对话框两态共用同一个外壳：填写态（字段 + 「克隆」「取消」）与克隆态（进度条 + 阶段文字 + 只有「取消」，遮罩点击不关闭）。失败回到填写态并保留输入，错误就地显示。克隆态标题里的地址单行截断，完整地址走悬停提示。
- 字段顺序：仓库地址、位置（只读路径 + 文件夹图标按钮换位置）、目录名、最终路径预览、「包含子模块」勾选框。字段只有标签、没有说明文字——标签本身已足够自明，堆说明只会让弹窗变吵。
- 输入框里保留用户粘贴的原文，实际克隆与标题展示用归一化后的地址。
- 表单行与信息图标这两个小组件从 Git 对话框族里抽到通用对话框外壳模块中共用（该模块本就是这套样式的单一定义源），Git 对话框改为引用，行为不变。

**收尾**

克隆成功后主进程登记项目、对齐监听、记住父目录，返回新树与聚焦路径；渲染端复用既有的「添加项目后」收尾（选中 + 滚入视口 + 落盘工作台），与其余三条登记路径完全一致。

## Testing Decisions

只测外部行为，不测实现细节。纯函数层是主战场，和仓库里既有的 `*-parse` / `*-args` 类测试同形：

- **地址 → 目录名派生**：HTTPS 带/不带 `.git`、带尾斜杠、SSH scp 形式、`ssh://` 带端口、`file://`、本地绝对路径、`<repo>/.git`、`.bundle`、网页链接、退化输入（空串、只有斜杠）。
- **网页链接归一化**：`/tree/分支`、`/blob/路径`、`/pull/N`、`/issues`、查询串与锚点、尾斜杠；GitLab 子组路径保留、到 `-` 才截断；已是可克隆地址（含 ssh / scp / 本地路径）原样不动。
- **是否像仓库地址**（剪贴板预填）：各种协议前缀与 scp 形式判真；普通文本、随手复制的句子、单个词判假。
- **目录名合法性**：空、含路径分隔符、含非法字符、`.` / `..`。
- **进度行解析**：各阶段带百分比的行、无百分比的行、`\r` 连续刷新的整块、夹杂 remote 前缀的行、完全不相干的行（返回空）。
- **克隆参数拼装**：默认、勾选子模块、以 `-` 开头的地址走到 `--` 之后。

主进程的克隆模块本身不做端到端克隆测试（需要真实网络与 git 进程），与既有 git 动作层的测试口径一致——动作层只测参数拼装与报错识别。

## Out of Scope

- 指定分支 / 浅克隆深度 / 指定 remote 名：需要这些的人在 **Terminal** 里更快。
- 应用内凭据输入（用户名密码框）：当前靠系统 credential helper / SSH agent。
- 仓库地址的历史记录与下拉补全。
- 多个克隆并行。
- 克隆后自动执行安装依赖之类的后续动作。
- 从 **Git Tab** 内部发起克隆（那里的动作都绑定已有项目，语义不成立）。

## Further Notes

- 克隆不进 **CONTEXT.md** 的术语表：它是 **Project** 的一种登记方式，不是新的领域实体。
- 「同时只允许一个克隆」由对话框单例天然保证，主进程的单例校验是防御性的第二道。
