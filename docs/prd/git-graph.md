# git-graph

**Git 图谱**

## Problem Statement

我在 DevCube 里聚合了多个项目来运行命令、看输出，但想了解某个项目的 git 状态（历史走向、分支、某次提交改了什么、要不要合并/回滚）时，必须切去 IDE 或终端。项目维度的工作台缺一块「仓库视图」，上下文来回切换很割裂。

## Solution

每个项目的 Tab 栏常驻一个 **Git Tab**（排最前、不可关闭）：完整移植 vscode-git-graph 的能力——提交图谱（分支线 + 圆点 + 引用标签）、提交/贮藏/未提交更改的详情与文件变更、应用内 diff 面板、右键执行全套 git 操作（分支/标签/合并/变基/重置/拣选/贮藏/远程同步）、分支筛选、提交查找、仓库设置。数据由主进程直接跑 git CLI 产出；`.git` 与工作区文件变动自动刷新图谱。

## User Stories

1. 作为开发者，我想在项目的 Tab 栏里直接打开 Git Tab，这样不用离开 DevCube 就能看仓库历史。
2. 作为开发者，我想看到提交历史的图形化分支线与每行的分支/标签/贮藏标签，这样一眼读懂仓库拓扑。
3. 作为开发者，我想看到「未提交的更改 (N)」行，这样知道工作区是否干净。
4. 作为开发者，我想点一个提交展开详情（作者/提交者/日期/完整信息/改动文件树），这样了解这次提交做了什么。
5. 作为开发者，我想点详情里的文件直接看 diff（应用内渲染），这样不依赖外部编辑器。
6. 作为开发者，我想 Ctrl/Cmd+点第二个提交进入比较模式，这样看两点之间的全部文件差异。
7. 作为开发者，我想右键提交创建分支/打标签/拣选/回滚/丢弃/重置，这样常用操作不用敲命令。
8. 作为开发者，我想右键分支标签执行检出/重命名/删除/合并/变基/推送，这样分支管理都在图上完成。
9. 作为开发者，我想双击本地分支标签直接检出、双击远程分支标签创建跟踪分支，这样高频操作最短路径。
10. 作为开发者，我想右键远程分支执行拉取/获取到本地分支/删除远程分支。
11. 作为开发者，我想对贮藏执行应用/弹出/丢弃/建分支，并在图上看到贮藏节点。
12. 作为开发者，我想右键未提交行进行贮藏/重置/清理未跟踪文件。
13. 作为开发者，我想用工具栏的分支下拉筛选图谱显示的分支（多选、显示全部）。
14. 作为开发者，我想勾选「显示远程分支」开关控制远程引用的显示。
15. 作为开发者，我想点「刷新」从所有远程 fetch 并重新加载图谱。
16. 作为开发者，我想 Cmd/Ctrl+F 搜索提交（消息/hash/作者/引用，支持大小写与正则），命中行高亮并可跳转。
17. 作为开发者，我想在仓库设置里管理 remote（增删改/清理）、编辑 user.name/email、隐藏某些 remote。
18. 作为开发者，我想让危险操作（删除分支/重置/丢弃提交等）先弹确认对话框，避免误操作。
19. 作为开发者，我想在分支未合并导致删除失败时得到「强制删除」的追问，而不是原始报错。
20. 作为开发者，我想在推送标签时得到「提交不在远程」的预警。
21. 作为开发者，我想操作失败时看到 git 的原始错误信息。
22. 作为开发者，我想 `.git` 目录或工作区文件变化（外部提交/切分支/编辑文件）后图谱与未提交明细自动刷新，且刷新不打断我展开的详情。
23. 作为开发者，我想图谱「加载更多」或滚动到底自动加载更早的提交。
24. 作为开发者，我想对非 git 仓库的项目看到明确的兜底提示而不是报错。
25. 作为开发者，我想交互式变基在项目的 Terminal Tab 里启动，这样可以在终端里完成编辑。
26. 作为开发者，我想注释标签能查看 tagger 与消息详情。
27. 作为开发者，我想从提交详情里打开工作区文件、复制文件路径。
28. 作为开发者，我想把某文件重置到某个提交时的状态。
29. 作为开发者，我想在工具栏左侧的「视图选项」里切换图谱显示与提交排序，这样不必进仓库设置弹窗。

31. 作为开发者，我想从工具栏直接刷新、拉取、推送（可强制）、创建分支，这样常用远程/分支操作不必进右键菜单。

44. 作为开发者，拉取/合并/变基/拣选/回滚撞上冲突后，我想在 Git Tab 里看到一条明确的「操作进行中」状态条，而不是只有一次性的错误框。
45. 作为开发者，我想在状态条上直接 继续/跳过/中止 进行中的变基（拣选/回滚同理），合并则可中止或去提交面板完成提交，不必开终端。

50. 作为开发者，我想在 Git Tab 的标签上始终看到当前分支名，这样不用切到 Git Tab 也知道项目在哪个分支。

## Implementation Decisions

- **入口与 Tab 模型**：Git Tab 是每项目常驻、非会话的 Tab，恒排最前、不可关闭；与会话 Tab 共用激活/循环/回落规则（ADR-0005），面板切走隐藏不卸载。项目成为当前项目时若尚未加载即全量预加载，Tab 标签因此始终能显示当前分支名（括号包住，如 `Git (main)`；detached HEAD 回落缩写 hash）；打开 Git Tab 时若已就绪则只重验仓库根，此后随仓库变化软刷新保鲜。
- **数据源**：主进程直接 spawn git CLI（不经 shell），每个 git 子进程都带上用户登录 shell 的环境（同 VS Code shellEnv：起一次登录交互 shell 取环境、10 秒超时、失败退回进程自身环境；GUI 应用 PATH 缺失，git 的钩子 / git-lfs / 凭据助手都靠它），git 本体也在这份环境里查找并缓存；解析一律基于机器可读输出，解析器是纯函数、与 IO 编排分层。
- **对齐策略**：UI 层为 React 重写（原项目是命令式 DOM + webview，不可复用）；**纯逻辑层以参考项目原源码为唯一权威**——git 命令构造、解析规则、布局算法、菜单可见性、对话框默认值逐函数对照原实现，能照抄的函数体照抄（仅剥 vscode 依赖、调整类型），行为偏差按缺陷修正。
- **右键菜单**：与项目树共用同一右键菜单组件。图谱行 / 引用标签 / 详情与提交面板文件行等多入口记录目标与坐标后受控打开，定位用虚拟 anchor（无法用单一行级 Trigger 包住全部入口）；菜单项可见性只由纯函数 `buildMenuItems` 产出。
- **IPC 契约**：读操作各自独立通道；写操作走单通道判别联合，结果也是判别联合（成功 / 错误之外，还有需要追问的结构化状态，如推送标签预检、删除工作树需强制）；仓库变化推事件，渲染端只对已加载过的项目软刷新。
- **加载语义**：一次加载在主进程内串联仓库概要 + 提交列表 + refs；初始 300 条、加载更多 +100 后整表重拉（多取一条判断还有没有更多）；软刷新保持画面原地换数据，硬刷新（筛选/设置变更/重试）清空重来；空仓库与非仓库是明确的状态而非错误。
- **图谱布局**：忠实移植参考项目的 Vertex/Branch/determinePath 算法为纯函数（网格坐标 → SVG 路径），12 色调色板循环，颜色经 CSS 变量引用。
- **详情与 diff**：详情面板吊底停靠（非参考默认的行内嵌入——React 表格行内嵌套复杂度高，作为已知取舍）；左栏提交信息在最上，按空行分段（第一段即标题、半粗；段距 8px，小于提交信息与字段区之间的 16px），字段区（含 GitHub 检查）在其下。diff 面板由 `@git-diff-view/react` 渲染（ADR-0007；无虚拟滚动，大文件全量渲染），数据为主进程透传的原始 unified diff 文本（`git diff -U3`），二进制判定在主进程；比较方向恒按行序归一为老→新，未提交端恒为 to。文件行一律可点开 diff（未跟踪目录整体条目除外），是否二进制点开后才判定、在面板内说明；未跟踪文件的行数由主进程读文件补算（numstat 口径，二进制/超大文件无统计）。二进制中的图片（png/jpg/gif/webp 等，svg 走文本 diff）给新旧预览（M 双栏、A/U/D 单栏；「提交自身变更」的旧端取父提交）；无 hunk 的 diff（纯重命名 / 模式变更等）显示「没有差异内容」。
- **仓库监听**（ADR-0021，与 Files / discovery 共用订阅）：忽略规则零硬编码——`.git` 仅放行白名单元数据（引用存储整类 HEAD / refs / packed-refs / reftable，及 index / config）；工作区事件在防抖到期后经 `git check-ignore` 批量过滤（.gitignore / info/exclude / 全局 excludesfile 全部由 git 裁决），全部被忽略的事件不触发刷新。
- **Diff 面板导航**（对齐 WebStorm）：头部按钮组为 `↑ ↓ | ← → | 打开文件 视图切换 关闭`。上下箭头（F7/⇧F7）在文件内改动块（连续 +/- 行为一块）之间跳：当前块为显式下标，首末块禁用、不跨文件；手动滚动后按视口约 1/3 处的锚重推，跳转落点同锚；块按渲染出的 diff 行分组（统一/对比视图同源，跟进异步渲染与 hunk 展开）。左右箭头（⌥←/⌥→）按详情文件树的**完整**视觉顺序切文件（不管文件夹是否收起；未跟踪目录条目不跳过，切到时显示提示、不请求 diff）；提交面板两段相连（已暂存在前、未暂存含冲突在后，端点随段切换）。「打开文件」同文件行菜单语义（已删除 / 未跟踪目录禁用）。快捷键仅 diff 打开时生效。
- **树高亮模型**：详情树与提交面板共用一种高亮视觉，数据分两源——「正在看的 diff 文件」是 diff 状态的纯派生（关 diff 即失、换段跟随，零同步规则）；「操作选区」是提交面板为批量操作维护的显式状态（目录行单击、Cmd/Ctrl 加减选、Shift 范围选、右键选区外的行重置为该行，两段互斥）。选区非空（含单选文件夹）时只显示选区，否则显示前者。文件行普通单击只开 diff、不写选区，但记 Shift 锚点（Finder 语义：单击的行即后续 Shift 范围的起点）。刷新落地后从选区与锚点剔除树里已不存在的 key；目录 key 须对着单链压缩后的树校验——仅按前缀匹配会让看不见的选区把文件偷偷带进批量操作。
- **Diff 面板是临时盖板**：再点已激活的 Git Tab、换详情目标（另一条提交 / 比较 / 提交面板）、或当前文件树里已没有该文件（已暂存 + 未暂存 + 冲突都算在树里；刷新中树未落地不误关）即关，Esc / × 也可关。切走 / 切项目 / 双击进 Files Tab 保留现场（切回 Git Tab 的那一下不算再点）；暂存、拉取、刷新、外面改文件都不单独关。活端点（已暂存 HEAD→index、未暂存 index→工作区、与工作区对比）随软刷新重拉，同文件换段则端点跟着走、尽量保住滚动位置；两端都是 hash 的历史提交不刷。单击文件开 diff；双击进 **Files Tab** 打开工作区那份（已删除 / 未跟踪目录除外；会先闪一下 diff，接受）。
- **写操作安全**：动作对话框与追问链对齐参考（强删确认、重名替换、推送标签预检）；「不再提示」标记持久化于跨项目视图偏好；写动作在主进程按仓库排队串行（git 遇锁即失败，自动获取与拉取 / 推送等因此不互相抢锁）；某仓库有动作排队 / 执行中（含 1500ms 余震）时，该仓库的项目监听**挂起**通知（discovery / files / git），转闲后补发一次，完成时另主动推刷新（ADR-0021）。
- **自动获取**：「偏好」一个开关，默认开，随启动快照带给渲染端、首帧即按真实设置。两种触发都走工具栏「刷新」同一流程（在途跳过、fetch 期间刷新钮转圈），失败不弹错误框（手动刷新钮 / ⌘R 照旧弹）：① Git Tab **到前台**（本 Tab 可见且窗口激活）立即；② 固定 180s（与 VS Code `git.autofetchPeriod` 默认一致）刷新当时的当前项目，不论选中哪个 Tab、窗口是否在前台。与写动作撞车由主进程按仓库排队兜住。关掉开关后 Git Tab 到前台只在尚未加载时补拉。不做：后台轮询非当前项目、可调间隔。
- **凭证**：依赖系统凭证助手（ssh-agent/钥匙串），注入 GIT_TERMINAL_PROMPT=0 快速失败，错误原样呈现；不做 askpass。
- **交互式变基**：不在主进程跑——渲染端在该项目新建 Terminal 并写入 `git rebase --interactive` 命令行。
- **持久化**：每项目 git 设置（显示开关三态/排序/隐藏 remote）与跨项目视图偏好统一存 electron-store（ADR-0002 同一份 JSON）。
- **不做头像**（无网络依赖）；**不做 GPG 签名校验**（tag 详情仅展示是否签名）。
- **工具栏**：右侧操作钮 = 提交 / 刷新 / 拉取 / 推送 / 创建分支 / 设置；查找钮在左侧。「刷新」= fetch 全部远程 + 静默软重载（本地图谱先原地更新、远程 fetch 完成后再软刷新一次；全程不置全局 loading、不弹进行中遮罩）；git ≥ 2.31 时逐个 remote 执行 `git fetch <remote> --atomic`（`--atomic` 与 `--all` 互斥，逐个执行在多 remote 下保住「中断不留损坏引用」；不理会罕见的 `remote.<name>.skipFetchAll`），旧版 git 用 `fetch --all`。拉取 / 推送 / 创建分支复用既有对话框，预设为当前分支 / HEAD；推送在 detached 或无 remote 时置灰，拉取同此条件（无上游不置灰——目标在对话框内选）；推送模式有常规 / force-with-lease / 强制。
- **拉取 / 推送对话框**（表单式）：拉取 = remote（默认上游 remote，其次首个）+ 远程分支（默认上游分支，其次同名，再次留空；选项来自已加载 refs；旁有「刷新」钮 fetch 所选 remote，期间禁用对话框按钮）+ 整合方式：合并（附「即使可以快进也创建新的合并提交」，仅此项生效）/ 变基（提示会重写本地未推送的提交）/ 压缩提交，默认值 = 记住的上次选择（跨项目视图偏好）> git 配置（`branch.<name>.rebase`，其次 `pull.rebase`）> 合并。推送 = remote 单选 + 本地分支（默认按入口预设）+ 目标远程分支可输可选（默认与本地分支同名并随其切换，手动编辑过即不再跟随；旁有同款「刷新」钮）+「同时推送该分支上的标签」（默认不勾；该分支历史上的全部标签，附注与轻量都含，并入同一条 push）+ 推送模式三档；目标名 ≠ 本地名时「设置上游」默认不勾（避免偶发的 dev→main 推送改掉 dev 的上游），同名时默认勾。
- **视图选项**：图谱显示三态开关（远程分支/贮藏/标签/reflog/首父）与提交排序放在工具栏**左侧**的 Popover（与分支下拉之间隔着工作树钮）。分支下拉有「全部分支」与「当前分支」（筛选传 `HEAD` 动态跟随；不持久化，随重启回落全部分支）。
- **仓库设置**：只放仓库级配置（用户信息、远程管理、隐藏远程、工作树存放目录）。不做参考实现的「显示名」（从不被读）与「Issue 链接」；提交信息中的 URL / 邮箱自动链接保留。
- **日期**：完整日期用 `Intl.DateTimeFormat('zh-CN')` 输出「YYYY年M月D日 HH:MM:SS」（零依赖标准 API，不手写月份表）；提交表格「日期」列为中文相对时间，全表读同一个整秒共享时钟、每秒刷新，各行基准一致，只重画文案有变化的格子。
- **操作进行中（冲突）处理**：加载时经 `git rev-parse --git-path` 检测 rebase-merge / rebase-apply / MERGE_HEAD / CHERRY_PICK_HEAD / REVERT_HEAD（工作树下亦稳），状态文件变化经 `.git` 监听自动跟进。工具栏下方出常驻状态条：变基/拣选/回滚给「继续 / 跳过 / 中止」，合并给「中止」并提示去提交面板完成提交；继续/跳过注入 GIT_EDITOR=true 防编辑器挂起，中止走危险确认框；拣选 / 回滚的 `--skip` 要求 git ≥ 2.23。进行中时会撞车的入口（拉取 / 合并 / 变基 / 拣选 / 回滚 / 检出 / 贮藏应用与弹出等）置灰并 hover 说明原因，推送与只读操作不受影响。冲突文件按 porcelain XY 任一位为 U 或 AA/DD 判定，须从 status 单独成桶（两段 diff 按 AMDR 过滤，冲突文件天然缺席）；在未暂存段以红「冲突」徽标标出，勾选 = `git add` = 标记已解决；其 diff 尽力渲染，库吃不下 combined diff 时按「二进制/无差异」同款兜底文案。
- **未提交更改的暂存与提交**（见 ADR-0006）：提交面板为版式 A（左提交信息框 +「修正」/「绕过提交钩子」/「推送」勾选 +「提交」，右已暂存/未暂存两段文件树）；勾选 = `git add`、取消勾选 = unstage、区头 = 全部；勾了「推送」则提交后打开推送对话框（含强制）。「绕过提交钩子」= `--no-verify`（命名取 SourceTree / GitHub Desktop 的「Bypass commit hooks」，git 文档本身也用 bypass 一词；JetBrains 反向的「Run Git hooks」与 VS Code 的「Commit (No Verify)」不采用），提交成功即复位（对齐 GitHub Desktop / JetBrains，避免 SourceTree 式保持勾选的误用），不持久化。文件行 `…` 菜单：未暂存 = 撤销更改…（未跟踪则删除文件…）/ 打开文件（进入该项目 **Files Tab**；「在其他应用中打开」由 Files Tab 提供）/ 复制路径；已暂存 = 取消暂存 / 打开文件 / 复制路径。提交面板不随「未提交更改」行消失而关闭（目标是工作区、恒不过期）：无改动时工具栏提交钮也可打开面板（仅空图禁用——空仓库且无改动时详情面板无处停靠），提交/丢弃清空全部改动后面板保持打开、两段显示空占位。

## Testing Decisions

只测纯函数、零 mock（项目既有约定），「构造输入 → 断言输出」；不写 UI/e2e 测试。

- **git 输出解析**：用真实样本字符串，含参考实现的已知坑（二进制 numstat、rename 跨 NUL 段、annotated tag 双行、空仓库）；暂存 / 未暂存 / 未跟踪（含同一文件同时落在两段）；porcelain 冲突桶（UU/AA/DD/DU 等）。
- **动作层**：参数构造与错误聚合语义——stage / unstage / commit；拉取整合方式三态、推送的 `local:target` 与标签 refspec 拼装、fetch 逐 remote atomic 展开；继续 / 跳过 / 中止与 `--skip` 的版本门槛文案。
- **图谱布局**：列分配、线段坐标、路径 d 串到具体数值。
- **日期**：相对时间的阈值边界与中文 Intl 输出的边界串。
- **未跟踪行数补算**：空内容、末行无换行、NUL 判二进制。
- **监听**：路径分类（`.git` 白名单 → git-meta，含 packed-refs / reftable 与工作树私有 reftable；objects 噪声忽略；工作区路径 → git-worktree，是否刷新仍靠运行时 check-ignore，单测不起真实 git）；调度（尾沿防抖与最长等待的延迟、三通道并入、路径攒到上限转强制、需重扫时三通道强制）；写动作排队用真实 Promise 测（同仓库串行、前一个失败不阻塞后续、跨仓库并行、忙态含余震）。
- **diff 盖板收口**：表驱动（关 / 留着 / 换段重拉），含树未落地不误关、冲突算在树里、历史 hash 不刷。
- **diff 导航**：文件序列（提交面板两段相连、端点随段，完整树序，未跟踪目录条目保留）、按端点 + 路径定位、连续行分块与 ±2px 容差的锚定位。
- **树高亮的幽灵清理**：单链压缩后树的全部行 key（目录 + 文件，压缩形态变化即失效）。

## Out of Scope

- Pull Request 创建（提供方模板配置整块不做，设置形状留 null 占位）
- Code Review 跟踪（已读文件标记）
- 作者头像、GPG 签名校验、askpass 凭证交互
- 提交列表列宽拖拽与列显隐持久化、refs 标签三种对齐模式（v1 固定 Normal）
- 消息内 emoji shortcode / markdown 富渲染（v1 纯文本 + URL/邮箱自动链接）
- 行内嵌入式详情（v1 吊底停靠）
- 多仓库/子模块发现（每项目即其根仓库）
- Issue 链接（提交信息 issue 号链接化；URL / 邮箱自动链接保留）
- 部分暂存（hunk / 行级 staging）—— 仅文件级
- 文件夹级复选框 —— 暂存靠单文件勾选或区头「全部」
- 分支筛选持久化（含「当前分支」模式）—— 纯内存，随重启回落「全部分支」
- 推送对话框的多分支批量勾选（一次推多个分支）与 remote 多选（要推多个 remote 分两次）
- 拉取后自动设置上游；拉取遇脏工作区自动暂存（--autostash）—— 直接呈现 git 报错
- 应用内三方合并编辑器 / 逐 hunk 冲突解决 —— 解决冲突交给编辑器/IDE，应用只负责状态呈现与继续/中止
