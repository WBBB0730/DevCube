# git-remote-github

**远程仓库：从 GitHub 选择、在浏览器中打开、快速添加**

## Problem Statement

要给仓库填远程地址的时候（克隆、初始化、仓库设置里添加远程），我得先去 GitHub 网页上找到仓库、复制地址，再回来粘贴；DevCube 明明已经登录了 GitHub，却列不出我自己的仓库。想看远程仓库的网页，也只能自己开浏览器去找。新建的本地仓库还没有远程时，Git Tab 的推送钮是灰的，我得先去 GitHub 网页上建一个仓库，再到仓库设置里添加远程，绕一大圈。

## Solution

三块能力：

1. **从 GitHub 选择仓库**：登录 GitHub 后，所有填仓库地址的输入框（克隆的「仓库地址」、初始化的「远程地址」、仓库设置里添加 / 编辑远程的「Fetch URL」「Push URL」、工具栏「添加远程」的「远程地址」）右边多一颗 GitHub 标志的图标钮，点开列出当前账号能访问的仓库（自己的、参与协作的、所在组织的），可筛选，选中即填好地址。填 HTTPS 还是 SSH 地址在设置的「账号」栏选，默认 HTTPS。
2. **在浏览器中打开**：Git Tab 工具栏多一颗图标钮，用系统浏览器打开当前分支推送用的那个远程的仓库网页；GitHub、GitLab、Gitee、Bitbucket、Azure DevOps 等按常见写法换算，SSH 地址里的主机别名按 `~/.ssh/config` 解出真实主机。
3. **添加远程**：仓库没有远程时，同一处换成「添加远程」：要么填已有仓库的地址（同样可以从 GitHub 选），要么直接在当前 GitHub 账号或所在的组织下新建一个空仓库，添加为 origin。

## User Stories

1. 作为开发者，我想克隆时直接从自己的 GitHub 仓库里选，这样不用去网页上复制地址。
2. 作为开发者，我想初始化仓库、在仓库设置里添加或编辑远程时也能从自己的 GitHub 仓库里选，这样各处填地址的方式一样。
3. 作为开发者，我想仓库列表里也有我参与协作的、所在组织的仓库，这样工作仓库也能直接选。
4. 作为开发者，我想最近推送过的仓库排在前面、能按名字筛选，这样仓库多也能很快找到。
5. 作为开发者，我想在设置里选从 GitHub 选仓库时填 HTTPS 还是 SSH 地址，并且一直记住，这样用 SSH 密钥的人不必每次手改。
6. 作为开发者，我没登录 GitHub 时，地址输入框和以前一样，不多出用不了的按钮。
7. 作为开发者，我想在 Git Tab 工具栏一键在浏览器里打开远程仓库的网页，这样不用自己去找。
8. 作为开发者，我想打开的是当前分支推送去的那个远程，这样有多个远程（如 origin 与 upstream）时也开对。
9. 作为开发者，我用 SSH 主机别名（如 `github-work:owner/repo`）配置远程时，也想打开正确的网页。
10. 作为开发者，远程是本地路径或自建服务器上的裸仓库时，我想按钮置灰并说明原因，这样不会打开一个错误的网页。
11. 作为开发者，仓库没有远程时，我想同一处变成「添加远程」，这样一眼就知道下一步做什么。
12. 作为开发者，我想在「添加远程」里粘贴或从 GitHub 选一个已有仓库，添加后立即获取，这样远程的历史马上出现在图谱里。
13. 作为开发者，我想在「添加远程」里直接新建一个 GitHub 仓库（名字默认用文件夹名、默认私有、可以写描述），这样不用去网页上建。
14. 作为开发者，我想新建时选建在自己账号下还是我能建仓库的组织下，这样工作仓库也能直接建。
15. 作为开发者，我在这个功能上线前就登录过 GitHub、列不出组织时，想在选所有者的地方直接重新登录，这样不必猜为什么没有组织。
16. 作为开发者，我没登录 GitHub 时，想在「新建仓库」里直接登录，这样不必先去设置。
17. 作为开发者，新建失败（如同名仓库已存在）时，我想看到明确的原因，填的内容还在，这样改个名字就能重试。

## Implementation Decisions

- **GitHub 授权**：沿用 ADR-0054 的 OAuth App。列出仓库（`GET /user/repos`）与新建仓库（`POST /user/repos`、`POST /orgs/{org}/repos`，含私有仓库）在 `repo` 里；列出所在的组织需要 `read:org`，登录时一并申请。加这项之前登录的凭证照常可用（列仓库、在自己账号下新建都不受影响），只是列不出组织：GraphQL 回 `INSUFFICIENT_SCOPES` 时界面在「所有者」旁给「重新登录」，不强制重新授权。组织开了第三方应用限制且未批准 DevCube 时，该组织的仓库不出现在列表里（同提交检查），在它下面新建会被拒，照 GitHub 的原因报错。
- **可选的所有者**：当前账号 + 它能新建仓库的组织（GraphQL `viewer.organizations` 的 `viewerCanCreateRepositories`，逐页读完，按 GitHub 给的顺序）。对话框一打开就读（切到「新建仓库」时已就绪），重新登录后重读；读不出（出错或缺授权）时只有当前账号可选。
- **仓库列表**：REST `GET /user/repos`（默认的三种从属：自己的、协作的、组织成员的），按最近推送排序，每页 100 条、逐页读完。渲染端每个窗口缓存一份；每次打开选择都重读，改筛选文字时列表若已读到超过 10 秒也重读（筛选只在已读到的列表里过滤，与重读无关；正在读时不再叠读），读到之前显示上次读到的，重读失败不丢掉上次的；换账号或退出即清空。新建成功的仓库直接放到列表最前。
- **地址形式**：应用偏好 `githubRepoProtocol`（`https` | `ssh`，默认 `https`），在设置「账号」栏登录后出现的「仓库地址」分段按钮里改，选中即生效。选仓库时取 GitHub 给的 `clone_url` 或 `ssh_url`。推送认证仍走本机 git 自己的凭据或 SSH 密钥，DevCube 的登录不参与 git 推拉。
- **仓库地址输入框**（`RepoUrlInput`）：等宽输入 + 登录后才出现的「从 GitHub 选择仓库」图标钮（可筛选的下拉，钮不带箭头，弹层定宽右对齐）；选中即覆盖输入框内容。五处共用这一个组件；初始化对话框的「远程地址」因此改为等宽。克隆对话框选中后目录名照常跟随地址派生。
- **网页地址换算**（主进程）：取 `git remote get-url`（已展开 `insteadOf`）；http(s) 地址剥认证信息与 `.git`，保留协议与端口；ssh / git 协议与 scp 形式换成 https、去掉端口，主机先经 `ssh -G` 解出真实主机名（WSL 里的仓库由发行版里的 ssh 连接，本机解不了它的别名，照地址里的主机）；SSH 专用入口（`ssh.github.com`、`altssh.gitlab.com`、`altssh.bitbucket.org`）换成网页主机；Azure DevOps 的 SSH 地址换成它的 `/_git/` 网页路由。本地路径、`file://`、`~user` 路径、scp 形式的绝对路径（自建服务器上的裸仓库）没有对应网页，为 null；以 `-` 开头的主机不认（会被 ssh 当成选项，git 同样拒绝）。打开的是仓库首页。
- **打开哪个远程**：同推送对话框的默认远程——当前分支的 `pushRemote` → `remote` → `remote.pushDefault` → origin → 第一个；分离 HEAD 时跳过前两级。远程或它的地址变了（增删改远程）、切分支后重新换算。
- **工具栏一处两用**：钮在右侧钮组最前（未登录 GitHub 时的登录钮之后），和它们一起与 Git 操作的钮隔一条竖线。有远程为「在浏览器中打开」，地址没有对应网页时置灰并 hover 原因；没有远程为「添加远程」。仓库第一次读到之前按有远程画（置灰），没远程的不会先闪一下「添加远程」。推送钮在没有远程时照旧置灰，从工具栏添加远程不推送。
- **添加远程对话框**：远程名固定 origin（要别的名字走仓库设置）。「已有仓库」= `add-remote` 且立即获取，失败时对话框留着、地址原样保留（同仓库设置的添加远程）；「新建仓库」=「所有者」（默认当前账号）/「仓库名」/「描述」/「私有仓库」，先在所选所有者下新建（空仓库，不带 README 等初始文件，免得与本地历史冲突），成功后关掉对话框，再按设置的地址形式 `add-remote`（空仓库无可获取，不获取）；添加失败由 Git 的错误框说明，仓库已经建好，之后可从列表里选到它。仓库名按 GitHub 的规则校验（ASCII 字母、数字与 `.` `-` `_`，不超过 100 个字符，不能是 `.` / `..`），默认由仓库根的目录名派生，不收的字符换成 `-`（同 GitHub 网页）；同名已存在说明为「仓库 “X” 已存在」，其余照 GitHub 给的原因。
- **凭证失效**：列出、新建时 GitHub 回 401 即退出登录（同提交检查），说明为「GitHub 登录已失效，请重新登录」。

## Testing Decisions

只测纯函数、零 mock：

- 远程地址 → 网页地址：http(s) / ssh / git 协议 / scp 形式、认证信息与端口、`.git` 与斜杠、SSH 专用主机、Azure DevOps、别名换成解出的主机名；本地路径、`file://`、Windows 盘符、`~` 路径、scp 绝对路径、以 `-` 开头的主机为 null。
- 仓库名校验与默认名派生；按地址形式取地址。
- 可选组织的筛选（只取能新建仓库的、跳过空节点）；认出缺授权的 GraphQL 出错。
- REST 仓库的解析；新建失败的说明（同名已存在、逐项原因、总说明、都没有）。

## Out of Scope

- 用 DevCube 登录的 GitHub 账号负责 HTTPS 的推送与拉取（记在 `docs/backlog.md`）。
- 点「推送」时没有远程就引导添加远程。
- 打开分支、提交或文件的网页；GitHub 以外的平台的仓库列表与新建。

## Further Notes

- 「在浏览器中打开」不需要登录 GitHub，任何平台的远程都能用。
- 仓库设置的远程列表与添加 / 编辑远程对话框不变，只是地址输入框多了从 GitHub 选择。
