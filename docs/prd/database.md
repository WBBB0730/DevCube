# database

**数据源**

## Problem Statement

我写代码时经常要看数据库里的数据、跑几条查询。现在用 WebStorm 的数据库插件，毛病有这几样：慢；重；东西太多，数据源设置有一堆页签，会话、事务模式这些概念一股脑摆在面前；改了表结构以后，目录和补全跟不上；开着 TUN 模式代理时绕不开代理。我连的库以云数据库为主，偶尔有本地的和服务器上的（服务器上的库也开放端口），也有几个项目共用的。我想在 DevCube 里轻量地看表、写查询。项目、服务器都能把常用命令存成配置、一点就跑，数据库这边常跑的几段语句却只能每次在控制台里找出来再执行。

## Solution

把数据库连接登记为 **Data Source**，和 **Project**、**Server** 并列在左树里。一个库通常只登记一份，几个项目共用；也允许登记多份，提交前确认一次（ADR-0043）。支持 PostgreSQL、MySQL、MariaDB、SQLite、Redis。

- **Data Source Tab**：点开一个 Data Source，就是它的 Data Source Tab。右侧是目录；左侧在「当前对象」和「控制台」两格间切换。点目录里的表，在「当前对象」里看数据；切到「控制台」写查询、看结果。两格各自保留内容，点表不会冲掉查询结果。Tab 里不再分小 Tab；要同时看两张表，就再开一个同库的 Tab，另开的一打开就连接。
- **在项目里打开**：**Project** 的 Tab 栏「+」可以把任意 Data Source 开成一个 Data Source Tab，和 Terminal、Run Session 挨着，Tab 随项目保存。项目里开着哪些库，看 Tab 就知道，不另建绑定关系。
- **首版只做「看 + 查询」**：改数据、改表结构都在控制台里写语句。
- **目录不过时，也不用等**：目录、对象定义与补全用的表名列名存成表结构缓存，显示时先用缓存、同时现查核对，读到了原地替换；连上后在后台分两批读完目录里的对象，先是表和视图，再是其余对象的名字（ADR-0045）。PostgreSQL、MySQL / MariaDB 的库多时，目录只列勾选显示的库，后台也只读它们。
- **回到上次的地方**：每个 Tab 记住上次打开的对象、停在哪一格和目录的展开，连上即回到那里；顶栏「最近打开」列出这个数据源最近打开的对象，⌘E 直接弹出。
- **选在哪个库上执行**：控制台工具栏上的「库」选控制台在哪个库上执行（PostgreSQL 另有「模式」），也可以在目录里右键「在控制台中打开」，一步换到那一行所在的库和模式；Redis 在键列表顶栏选库编号；在控制台里写 `use`、`set search_path`、`SELECT n` 切过去，它们同样跟着变。每个 Tab 各自记住（ADR-0046）。
- **按上下文补全**：控制台、运行配置对话框与 WHERE / ORDER BY 框共用一个补全引擎，按光标所在的子句补表、列、别名、函数和关键字，JOIN 时按外键补出连接条件，这个数据源上用得多的排前；做法照抄 pgcli（ADR-0047）。Redis 控制台补全命令名。
- **筛选、排序与分页**：表和视图顶上有 WHERE、ORDER BY 两个框，点表头排序也写进 ORDER BY 框；表格用分页器翻页，每页行数可以设置；表和查询结果都能导出为 CSV、JSON 或 SQL INSERT 语句。
- **运行配置**：在 Data Source 上存几段常跑的 SQL（Redis 为几行命令），像项目、服务器上的配置一样一点就跑，结果显示在它的 Tab 栏里的运行会话里（ADR-0044）；内容里可以留 `${{名称}}` 参数，每次运行前填值（同项目、服务器上的配置，见 `docs/prd/run-config-params.md`）。
- **连得上**：加密自动处理，不用选；开着 TUN 代理时可以绕开代理直连。
- **SQLite 文件**：**Files Tab** 里点开 SQLite 文件，正文区直接就是同一套视图。
- **Redis**：同一种布局，右侧是按 `:` 分组的键，左侧是「当前键」和控制台。
- **操作结果不在界面上留文字**：进行中显示在按钮本身（转圈并置灰），成功不提示，失败弹错误框；可疑但允许的操作（如重复登记）提交前确认一次。

## User Stories

**登记与连接**

1. 作为用户，我想添加一个 **Data Source**：选类型（PostgreSQL / MySQL / MariaDB / SQLite / Redis），填名称（可选，默认由地址派生）、地址、端口（按类型给默认值）、用户名、密码、默认库（可选）；SQLite 改为选一个本机文件。
2. 作为用户，我想把 `postgres://…`、`mysql://…`、`redis://…`、`rediss://…` 这样的连接串粘贴进来，自动拆成类型、地址、端口、用户名、密码和库名，以便不用逐项抄写。
3. 作为用户，我不想操心加密：PostgreSQL、MySQL、MariaDB 能加密就加密，服务器明确回答不支持时才不加密，和它们官方客户端的默认行为一样，表单里没有这一项。
4. 作为用户，当我粘贴的连接串里写了加密要求（如 `sslmode=verify-full`）时，我想按它的要求连接，并在表单里看到这条要求、可以清除。
5. 作为 Redis 用户，我知道 Redis 的协议不能协商加密，所以只有 Redis 的表单里有「TLS 加密」勾选；粘贴 `rediss://` 开头的连接串时自动勾上。
6. 作为用户，我想在添加、编辑时「测试连接」，失败时看到数据库给出的原因；网络不通时不至于一直等下去。
7. 作为用户，我想在添加时就勾选「记住密码」（默认不勾）；没记住密码的数据源连接时，我想在 Tab 里直接输入密码（可以留空）并勾选是否记住。根本没给密码而库要求密码时，页面写「X 要求输入密码」；给了密码（填的或记住的）却被拒时，密码框上方红字「密码被拒绝」，让我重新输入并更新。连上后按勾选记住或忘掉，左树立即跟上。系统没有可用的钥匙串时，看不到「记住密码」，添加、编辑对话框里的密码框置灰并说明原因（同服务器对话框），所以在对话框里测不了要密码的连接；密码在连接时于 Tab 里输入。
8. 作为开着 TUN 模式代理的用户，我想给 Data Source 打开「绕开代理直连」，规则同 **Server**（ADR-0039）：仅 macOS / Windows，添加时默认不勾。
9. 作为用户，我想编辑 Data Source：只有连接信息（连接目标、加密要求、是否直连）变了，已连上的 Tab 才断开、回到未连接；只改名或只改密码时不断开，之后另开的连接用新密码。连接信息变了，连到的可能已是另一个库，所以这个数据源显示的库回到默认，最近打开、各个 Tab 记住的上次打开的对象、目录的展开与控制台所在的库一并忘掉；停在哪一格、控制台里写的内容留着。
10. 作为用户，我想移除 Data Source；移除时，所有连到它的 Tab 一并关闭（包括开在项目里的），它的运行配置、记住的密码、表结构缓存一并删除。
11. 作为用户，同一个库我通常只登记一份；真要再登记一份（添加时，或编辑成与已登记的相同时），我想在提交时被确认一次（「“X” 连接的是同一个库。仍要添加吗？」），确认了就照样登记，而不是被悄悄合并或不让保存。

**左树**

12. 作为用户，我想 Data Source 和 Project、Server 排在同一个左树里，图标不同；置顶、排序、拖拽、名称筛选的规则一致；排序菜单的类型勾选多一项「数据源」，至少保留一项勾选。
13. 作为用户，我想左树里的 Data Source 行和 Server 行一样有折叠箭头、配置区、「更多」菜单和相同的右键菜单（新建标签页 / 新建配置 / 编辑 / 置顶 / 移除数据源）。

**Tab**

14. 作为用户，点开一个 Data Source 时，我想看到它常驻的 Data Source Tab（不可关闭）；需要时，在它的 Tab 栏「+」、右键菜单「新建标签页」或 ⌘T 再开一个，可以关闭。在数据源自己下面另开的从「prod (2)」编号起（常驻的算第 1 个），开在项目里的从「prod」起。这样就能同时看两张表，或开两份查询。数据源自己的 Tab 栏里，另开的紧跟在常驻的后面，运行会话 Tab 排在它们之后。
15. 作为用户，我想在 **Project** 的 Tab 栏「+」菜单和项目右键菜单里选「连接到数据源 ▸」，在项目里开一个 Data Source Tab。它和 Terminal、Run Session 并列，行为和 Data Source 下的完全一致。子菜单按左树当前的排序列出（置顶的在前），「连接到服务器 ▸」也改成这样。移除项目时，开在里面的 Data Source Tab 一并关闭，控制台里写的内容一并删除。
16. 作为用户，另开的 Data Source Tab 我想一打开就连接（同新开 SSH Terminal），不用再点一次「连接」；常驻的 Tab 与跨重启恢复的 Tab 点「连接」才连，以便启动时不会一下子连一堆库、弹一堆提问。
17. 作为用户，我想 Data Source Tab 跨重启保留名称、顺序和控制台里写的内容。
18. 作为用户，连接断开后，我想 Tab 保留并显示断开的原因，点一下就能重连。

**目录**

19. 作为用户，我想在 Tab 右侧看到目录：先列出这个 Data Source 上的库（系统库与系统模式不列），展开后按对象类型分组，只列有对象的分组并显示个数。PostgreSQL 的每个库各自连接，展开时自动连。PostgreSQL、MySQL / MariaDB 的服务器上常有很多库，我只想列出要用的那几个：目录顶上的根行右端写着「N / M 个库」，点开是能打字筛选的勾选列表，勾上或取消立即生效，同一个数据源的各个 Tab 一样。从没勾选过时只列默认库（PostgreSQL 没填默认库时为连上后所在的库）；MySQL / MariaDB 没填默认库时一个都不列，目录里提示我去勾选。改了连接信息后回到默认，库被删掉后从勾选里去掉。根下的角色、用户不是库，照常列出。
20. 作为用户，连上时和展开某一层时，我想有读过的结构就立即显示，不再等「正在读取…」，同时在后台核对，读到了原地替换；每次展开都重新核对，以便看到的既快又是当前结构。
21. 作为用户，我想连上后 DevCube 在后台把显示的库读完：先读表和视图，读完即可用，再读函数、触发器、角色等其余对象的名字；之后展开这些层都不用等，界面上不因此多出任何提示。勾上一个库时，也在后台把它读完；取消勾选的库不再读。
22. 作为用户，我想目录顶上有刷新按钮：刷新期间旧树照常显示、展开状态不变，读完原地替换；没展开的层也跟着更新。
23. 作为用户，我在控制台执行建表、改表、删表这类改结构的语句后，想让目录与补全自动重读；提交或回滚事务（COMMIT / END / ROLLBACK / ABORT）后同样重读，这样 PostgreSQL 事务里建的表提交后就能在目录里看到。回滚到保存点、释放保存点不结束事务，不算。
24. 作为用户，遇到账号没有权限读取的内容，我想看到「无权查看」，而不是报错。
25. 作为用户，我想在目录顶上按名称筛选，没展开过的层也能找到：在 DevCube 已经拿到的目录里找（读过的层，加上连上后在后台读好、存在表结构缓存里的层），不为筛选另查数据库；刚连上就开始筛选时，后台读完的内容会自己出现在结果里，还在读时没有匹配显示「正在读取…」，读完仍没有才显示「无匹配对象」；命中项连同各级祖先显示、保留层级，所在的层自动展开（后来出现的命中也是；我手动开合过的层保持我的开合），清空筛选后回到筛选前的展开。筛选只在显示的库里找。我还想一键全部折叠；焦点在目录上时直接打字就进筛选框。
26. 作为用户，我想在目录的对象行上右键「复制名称」。

各数据库的目录里有这些对象：

| 数据库          | 对象                                                                                 |
| --------------- | ------------------------------------------------------------------------------------ |
| PostgreSQL      | 模式、表、视图、物化视图、函数与存储过程、触发器、序列、自定义类型、扩展、角色与权限 |
| MySQL / MariaDB | 表、视图、存储过程、函数、触发器、事件、用户与权限                                   |
| SQLite          | 表、视图、索引、触发器                                                               |
| Redis           | 见 Further Notes                                                                     |

**当前对象**

27. 作为用户，点目录里的表或视图时，我想在「当前对象」里分页看它的数据，顶上有 WHERE、ORDER BY 两个框：写的是不带关键字的子句，回车生效，末尾可以写 `--` 行注释（MySQL 也可以写 `#`）。两个框同控制台一样按方言高亮，补全这张表的列、函数与关键字；PostgreSQL 的表不在控制台所在的库上时也一样；在控制台里改了表结构后，这里马上补得出新的列。
28. 作为用户，我想点表头排序：点一下升序、再点降序、第三下取消，生成的排序写进 ORDER BY 框，我可以接着手改；手写或改过的排序不显示表头箭头。
29. 作为用户，点函数、存储过程、触发器这类对象时，我想在「当前对象」里看到它的定义（只读，语法高亮，可以 ⌘F 查找）；点角色或用户时，看到它的权限。读过的先显示，同时核对。
30. 作为用户，我想点另一个对象时只替换「当前对象」这一格，控制台不受影响。
31. 作为用户，看着一个对象时我想点「在目录中显示」，目录展开到它并滚到它那一行；被目录的筛选挡住时先清掉筛选，它所在的库没显示时先把这个库勾上。这个按钮只在「当前对象」那一格出现，切到控制台时收起。

**表格**（「当前对象」、控制台结果与运行会话结果共用）

32. 作为用户，我想在表格里拖选一片格子、按住 Shift 扩展、按 Cmd/Ctrl+A 全选，复制后能直接贴进 Excel。
33. 作为用户，我想拖动列宽；列多时，滚动照样流畅。
34. 作为用户，我想 NULL 和空字符串分得清；JSON、二进制、大整数、小数、时间按数据库给的原样显示，不被转换失真。
35. 作为用户，我想在任何表格里按 ⌘F 查找：只查当前这一页（或取回的这些行），命中的格子高亮，当前命中选中并滚入视口。

**分页**

36. 作为用户，我想在表格底部用分页器翻页：上一页、下一页、页码、跳到某页。
37. 作为用户，我想设置每页行数：可以直接输入，旁边的小钮列出几个常用值；默认 500，记住我上次的选择，所有 Tab 共用。
38. 作为用户，翻表时我想每一页都是现查的，带着当前的 WHERE 和 ORDER BY，翻页稳定（排序列有重复值时也不重不漏）；总行数在后台计算、只受 WHERE 影响，算好后显示总页数，计算期间照样能翻页。
39. 作为用户，我明白控制台的结果执行时一次取回，最多 1 万行，在本地翻页；超过时看到「只取回了前 10000 行」。翻页不会重新执行语句。

**控制台**

40. 作为用户，我想在控制台里写查询：按数据库方言高亮，也能格式化，格式化不了时弹错误框告诉我原因。我想补全按光标所在的位置给候选：FROM、JOIN 之后补表和视图，JOIN 之后还补与已有的表有外键关联的表连同 ON 条件，ON 之后补连接条件；SELECT、WHERE、ORDER BY 这些位置补语句里这几张表的列（认别名、CTE 与子查询），列的旁边写着类型；也补函数、类型，以及这个子句里用得上的关键字；MySQL / MariaDB 在「列 = 」之后补这一列的枚举值。匹配得一样好时，我在这个数据源上执行过的语句中用得多的名字和关键字排前，重启后照旧。表结构的范围：PostgreSQL 补控制台所在的库里的，MySQL / MariaDB 补全部库的，不写前缀的表补全到控制台所在的库；先用读过的，同时核对。
41. 作为用户，我想按 ⌘Enter 执行光标所在的那条语句，或执行选中的部分；选中了多条时依次执行。MySQL / MariaDB 里我想同 mysql 客户端一样用 `DELIMITER` 换分隔符，照搬来的建存储过程、触发器的脚本不用改；mysqldump、mariadb-dump 导出的脚本也能整段执行。
42. 作为用户，我想在编辑器下方看到结果：查询语句显示结果表格；其他语句显示影响的行数；出错时显示数据库给的原话。执行了多条时，表格显示最后一个结果。再次执行时，上次的结果留着，新结果到了才替换。
43. 作为用户，我想取消正在执行的查询；叫停进行中「取消」钮本身转圈、置灰，叫停失败时弹错误框告诉我原因。
44. 作为用户，我想控制台里写的内容跨重启保留；结果不保留，重启后要重新执行。
45. 作为用户，我想改数据、改表结构时，直接在控制台里写语句执行。
46. 作为用户，退出 DevCube 时，我不想服务器上还跑着我刚发出的语句：还在执行的先叫停再断开，但不因为网络不好拖住退出。

**导出**

47. 作为用户，我想把「当前对象」的整张表导出为 CSV、JSON 或 SQL INSERT 语句，带着当前的 WHERE 和 ORDER BY，不只是当前页；导出的 SQL INSERT 语句能直接导回同结构的表（生成列的值由数据库算出，不写进去；PostgreSQL 总是自动生成的标识列照原来的值写回）。
48. 作为用户，我想把控制台、运行会话已取回的结果导出为同样的格式；不会为了导出重新执行语句。
49. 作为用户，我想用 Excel 打开导出的 CSV 时中文不乱码；导出的 JSON 里数字还是数字，大整数也不失精度。
50. 作为用户，导出时我想先选保存位置（默认在「下载」目录、文件名为表名，表名里不能当文件名的字符替换掉）；写文件期间导出钮本身转圈、置灰，写好了不打扰我，失败时弹错误框给出原因。

**运行配置**

51. 作为用户，我想在数据源菜单里「新建配置」：名称、在哪个库上执行（可以输入，也可以从连过这个数据源时读到的库里选；留空即数据源的默认库；Redis 为库编号；SQLite 没有这一项）、内容（SQL 为一段语句，Redis 为一行一条命令）；写 SQL 时同控制台一样按上下文补全，表结构取这个库的（PostgreSQL 不写模式前缀的表按新连接默认的 search_path 补全：配置每次在新连接上跑，控制台里改的 search_path、下拉选的模式都不影响它），也能格式化（`${{名称}}` 参数原样保留）；可以编辑、删除、拖拽排序，同服务器上的配置。

## Implementation Decisions

- **进程分工**：驱动和连接都在主进程；渲染端只拿到整理好的目录节点，和一页一页的结果行。
- **驱动**：
  - PostgreSQL 用 `pg`，取控制台结果用 `pg-cursor`（node-postgres 官方配套）。读够上限（结果被截断、游标停在中途）才关游标；读完或读取出错时不关（连接断开后关游标会一直等下去）。
  - MySQL / MariaDB 用 `mysql2` 的回调接口（控制台要按事件逐行收）。TEXT 与 BLOB 在协议里同属一类，只能靠字段的字符集区分：这几类先取原始字节，查完再按字符集（63 为二进制）转成十六进制或按 UTF-8 解码。MySQL 的 JSON 列字符集总标成 63，内容按规范是 UTF-8，照 `mysql2` 的建议用 `field.string('utf8')` 取（默认按二进制解码成乱码，每格还打一条警告）。`CALL` 可以返回几个结果集，之后还补发一个 OK 包：有结果集时取最后一个，没有才算影响的行数。事件式的查询收不到网络错误（`mysql2` 只报给连接），所以查询与导出期间另外监听连接的 `error` 与 `end`，断了即以出错结束，不会一直等下去。
  - SQLite 用 `better-sqlite3`。它是原生模块，照 `node-pty` 的做法按 Electron 重新编译，要加进 `onlyBuiltDependencies`。它的接口是同步的，所以一个数据库文件由一个 worker 线程持有、查询都在线程里执行（electron-vite 的 `?modulePath` 单独打包），免得大查询卡住主进程；关闭或取消即结束线程：还在等结果的查询当场以「查询已取消」失败，不等线程真正结束（线程回到 JS 时才结束；正停在一步原生调用里——一步就要算很久的 count、聚合、不出行的递归 CTE——要等这一步做完，`better-sqlite3` 没有 `sqlite3_interrupt`，这一步若是自动提交的写入照样会提交）。打开后先读一次文件头，不是数据库的文件在打开时就报出来。数字列按取回的值判断（SQLite 按值存类型，声明类型不可靠）。Electron 自带的 `node:sqlite` 在 Node 22 上还是实验功能，暂不用。
  - Redis 用官方 node-redis 的基础客户端包 `@redis/client`。不用元包 `redis`：它另带 bloom、json、search、time-series 四个模块，我们的命令全走 `sendCommand`，用不上它们，装了还会打进 app.asar（ADR-0036）。`ioredis` 的文档写明新项目推荐 node-redis；官方包的连接选项也直接支持 `localAddress` 与 TLS 的 `servername`，直连不必自写连接器。协议用 RESP2（redis-cli 的默认；node-redis 默认 RESP3）：分数这类小数是字符串、不会与整数混同，`HGETALL` 这类映射是按服务器次序的数组、不解码成 JS 对象（那样会丢 `__proto__` 字段、把数字字段提到前面）。
  - 每个连接都挂上 `error` 监听（驱动的要求），不论是 Tab 的连接还是各种临时连接。
- **原样显示**：结果一律取数据库给的文字，不经过 JS 的类型转换。`pg` 把类型解析覆盖成原样返回字符串（`bytea` 转成十六进制）；`mysql2` 用 `typeCast` 一律取原样文字（可能是二进制的几类先取字节，见上）；SQLite 的整数按字符串取（`safeIntegers`），二进制转成十六进制。结果里二进制与文字分开标记，表格显示为长度加十六进制的开头部分。
- **加密**：
  - **默认档**：PostgreSQL / MySQL / MariaDB 默认「能加密就加密、不校验证书」，即 libpq 的 `sslmode=prefer`、MySQL 的 `PREFERRED`。
  - **为什么要自己补一步**：`pg` 和 `mysql2` 都没有这一档，要求加密而服务器不支持时会直接报错。`pg` 是在服务器对 SSLRequest 回答 `N` 时报错；`mysql2` 是在握手里发现服务器没有 SSL 能力时报 `HANDSHAKE_NO_SSL_SUPPORT`。所以先按加密去连，只在收到这两种「不支持」时改用不加密重连；其他加密错误照常报出，不退回明文。认这两种回答写成纯函数（`isTlsUnsupported`）。
  - **连接串里的加密要求**：记在 Data Source 上，按 libpq 的语义执行：`disable` 不加密；`require` 必须加密、不校验证书；`verify-ca` 校验证书、不校验主机名；`verify-full` 两者都校验；`prefer` / `allow` 即默认档。PostgreSQL 取 `sslmode`，MySQL / MariaDB 取官方连接串的 `ssl-mode`（DISABLED / PREFERRED / REQUIRED / VERIFY_CA / VERIFY_IDENTITY），映射到同一套；其余参数不认。
  - **Redis**：`rediss://` 或勾选了 TLS 时加密，不做协商。
- **直连**（ADR-0039）：
  - 用 `ssh-direct` 的 `resolveDirectRoute(主机名, 是否直连)`：没开直连（或平台不支持）时为空，照常连接；开了就现查实体网卡地址和真实地址，自建 TCP 连接（绑定本机地址、连真实地址），再交给驱动：`pg` 用 `stream` 选项（它会对传入的 Socket 调 `connect(port, host)`，所以给一个按直连路线改写 `connect` 的 Socket 子类），`mysql2` 用 `stream` 选项交给它一条已连上的 Socket（同 `mysql2` 自己建连接时一样开 `noDelay` 与 `keepAlive`），`@redis/client` 直接给 `localAddress`。SSH 的连接走同一个函数。
  - 加密连接握手时，SNI 和证书校验仍用原来的主机名，因为有些云数据库靠 SNI 区分实例。
  - 找不到实体网卡、或查不到真实地址时，直接报出原因，不退回经代理连接。
- **时限**：建连超时 15 秒（与 SSH 没设 `ConnectTimeout` 时共用一个常量，`shared/connection`）；测试连接整次最多 2 分钟，超时报「连接超时」。
- **连接串**：四种类型统一用 WHATWG `URL` 解析成字段，写成纯函数（`shared/data-source`），对话框里直接调用。连接时用的是拆好的字段，不是原始字符串，所以不引 `pg-connection-string`（它解析时遇到证书参数还会去读本机文件）。
- **数据模型**：**Data Source** 记录以下字段：
  - id、名称、类型；
  - 连接目标：`{ host, port }`，SQLite 为 `{ file }`；
  - 用户名、默认库；
  - 加密要求：缺省即默认档，只由连接串写入；Redis 是 TLS 开关；
  - 是否直连；
  - 添加时间、打开时间、是否置顶、自定义序；
  - 显示的库（PostgreSQL、MySQL / MariaDB）：按勾上的先后记下的库名，缺省即从没设置过（按默认库，见「目录」）。

  记住的密码和 Server 的存法一样：单独存，用 safeStorage 加密，键为 Data Source 的 id，不下发渲染端。它的运行配置存在配置数组里（见「运行配置」）。

- **重复登记**（ADR-0043）：「同一个库」按连接目标判断（`sameDataSourceTarget`）——类型、地址（不分大小写）、端口、用户名、默认库，SQLite 为文件路径。主进程的添加总是新增；渲染端在提交时发现与已登记的重复就先弹确认框（`DuplicateTargetConfirm`，Server 共用），确认了才提交。编辑时只有目标改成与别人相同才问，目标没改（只改名、改密码）不问。
- **编辑与移除**：
  - 编辑后按 `dataSourceConnectionChanged` 判断连接信息变没变（连接目标、加密要求或 TLS、是否直连）。变了：它的各个 Tab 断开、回到未连接（运行会话的连接除外），表结构缓存删掉，显示的库回到默认，最近打开、各个 Tab 记住的上次打开的对象、目录展开与控制台上下文一并删掉（都在 `forgetDataSourcePlaces`；停在哪一格、控制台内容不动）；没变而换了密码：各会话之后另开的连接（PostgreSQL 连别的库、数总行数、导出、叫停语句）改用新密码，已建立的连接不断开。**Server** 同理（`serverConnectionChanged`：连接目标、是否直连），只改名、改密码时不断开状态与文件连接，也不问未保存的服务器文件。
  - 移除：先删它名下的配置并销毁其运行会话，断开并忘掉连到它的各个 Tab（含开在项目里的）、删掉表结构缓存，再删这些 Tab 的控制台内容、工作台现场、登记与记住的密码。
- **左树**：条目键是 `datasource:<id>`，和 `server:` 用同一种前缀约定。`TreeEntry` 加第三类。排序、Pin、拖拽、名称筛选沿用 `project-sort`，排序菜单在「项目」「服务器」之后加「数据源」勾选。数据源行与服务器行一样有折叠箭头与配置区（只有命令型，没有「检测到的配置」）。
- **连接子菜单**：「连接到数据源 ▸」和「连接到服务器 ▸」都按 `sortTreeEntries` 算出的左树顺序（含置顶分区）列出，不受左树按类型筛选的影响。
- **密码**：
  - 不像 **Server** 那样弹窗提问，直接在未连接页出密码框（没记住、或记住的被拒时），连上后按勾选记住或忘掉，并广播数据源列表变化，左树的「是否记住」随之更新。未连接页（`DataSourceConnectForm`）连同连接中一起渲染，密码框的输入、「记住密码」的勾选、上一次给没给密码在「未连接 → 连接中 → 被拒」之间不丢；Data Source Tab 与运行会话共用。
  - 「记住密码」的勾选规则同 SSH 提问弹窗（`rememberPasswordDefault`）：没勾过时按是否已记住，之后沿用上一次的勾选。
  - 判断密码被拒：PostgreSQL 的 `28P01`（或没给密码时驱动报的「client password must be…」）、MySQL / MariaDB 的 1045、Redis 的 `WRONGPASS` / `NOAUTH`，写成纯函数。主进程只报「被拒」，分不出「没给密码」与「给了被拒」，由页面自己记上一次提交给没给密码；自动发起的连接（新开 Tab、运行配置）按是否记住推断。
  - 点「连接」后、主进程回话之前，页面按连接中显示，不拿旧的失败状态闪一下红字。
- **Tab 与工作台**：
  - 另开的 Data Source Tab（键 `db-tab:<uuid>`）和本地 Terminal、SSH Terminal 同属终端组：同一份壳列表（多一个 `dataSourceId`）、同样按条目持久化（ADR-0008）、拖拽排序、编号与改名。控制台内容另存（见「控制台」）。
  - Data Source 条目的 Tab 栏最前面是常驻的 Data Source Tab（键 `db:datasource:<id>`），其后是另开的，它的配置的运行会话排在最后（`orderedTabKeysOf` 的 `termTabsFirst`：终端组排在运行会话之前，只有 Data Source 条目如此，Project、Server 仍是运行会话在前）；⌘1–9、循环切换、关闭后回落左邻都按这个顺序，另开的之间仍可拖动排序。
  - 新开即连接：五个入口（条目「+」、⌘T、右键「新建标签页」、项目右键「连接到数据源」、项目 Tab 栏「+」子菜单）都走同一个动作，建好 Tab 立即连接（有记住的密码就用，没记住也先直接连，要密码时页面里再问）。常驻 Tab、跨重启恢复的 Tab、添加数据源后只选中它，都不自动连接。连接状态还没从主进程取到时页面留白，免得新开的先闪一下未连接页。
  - 默认名（`nextTerminalName`）：在数据源条目自己下面另开的，常驻 Tab 算第 1 个，从「prod (2)」起；开在项目里的从「prod」起。数据源改名时默认名跟着改、序号保留。
  - 激活、默认激活、关闭后回落的规则和 Project / Server 一样；移除数据源后，原来激活的 Tab 所在的栏回落到左邻，其次右邻。
  - 移除项目时，开在项目里的 Data Source Tab 的连接一并关掉、控制台内容一并删除。
- **连接数**：
  - 一个 Data Source Tab 用一条连接（PostgreSQL 是每个展开过的库一条，按需另连并缓存），目录读取和查询排队共用这条连接。PostgreSQL 的控制台切到别的库时，在那个库的按库连接上执行；每条按库连接连上时取后端进程号，叫停在它上面执行的语句要用。
  - 临时连接：数总行数、导出、叫停语句，以及连上后、刷新目录时分两批读完主体结构，各另开一条，用完即关。执行语句用的临时连接（数总行数、导出、读主体结构）在 PostgreSQL 上先取进程号，以便叫停。
  - 数据源上的配置每次运行另开一条（见「运行配置」）。
  - 关连接不等在途的语句（PostgreSQL `end()` 不等回应、MySQL `destroy()`、Redis `destroy()`）；断开、关 Tab、重连时，还在执行的语句（控制台、数总行数、读主体结构）先叫停再关。MySQL 的 `destroy()` 只是半关，在途的结果仍会收完，所以要服务器停下必须先发 `KILL QUERY`。
  - 退出时先叫停所有还在执行的语句（控制台、运行会话、数总行数、导出、读主体结构）再关，最多等 2 秒，到点没发完的直接关掉。
- **目录**：
  - 每种数据库各有目录查询：PostgreSQL 读 `pg_catalog`，MySQL / MariaDB 读 `information_schema`，SQLite 读 `sqlite_schema` 和 `PRAGMA`。结果在主进程整理成统一的节点。
  - SQLite 不列 `sqlite_` 开头的系统对象，也不列虚拟表（如 FTS5 全文检索）自己存数据用的影子表（`pragma_table_list` 里 type 为 `shadow`，同 Datasette 的做法）：目录的分组、个数与补全都不算，逐层读与一次读完用同一个条件。
  - 连上即读根这一层；展开一层读一层，每次展开都重新读。读到前先显示缓存（收起前读成功的那份，或表结构缓存里的），读到了原地替换；都没有时显示「正在读取…」，这一行要等 120 毫秒才出现，读得快时不闪。
  - 一次读完主体结构（ADR-0045）：依次读第一批、补全、第二批。第一批为各模式或库的分组个数与表、视图、物化视图（PostgreSQL 另有库这一层），第二批为其余分组的对象（PostgreSQL 的函数、存储过程、序列、类型、触发器与这个库的扩展、根下的角色，MySQL / MariaDB 的存储过程、函数、触发器、事件与根下的用户，SQLite 的索引、触发器）；补全要的是表与视图的列，排在第二批之前，不被函数等拖慢。各模式或库的对象按类型批量查，一类一条，查询与逐层读取同源、只是范围分成「单个模式或库 / 库里的全部模式（MySQL / MariaDB 为显示的各库）」两种；行到节点的整理（按模式归组、整理成分组各层与对象各层）写成纯函数，与逐层读取的结果逐层一致。扩展、角色、用户各只有一层，直接用逐层读取的查询；MySQL / MariaDB 的用户读不出来（多半是无权读 `mysql.user`）即不写这一层，不影响其余的。每写进一批、读取结束（读完最后一次读取，或读不出来）时推给这个 Tab（`onDataSourceCatalogLayersChanged`）。连上时的这一次只写进缓存，读完之前展开照旧逐层现查。Files 面板里直接打开的 SQLite 文件同样读，读到的只放在会话内存里（见「表结构缓存」）。
  - 显示的库（PostgreSQL、MySQL / MariaDB，ADR-0045）：目录根下只列显示的库（`catalogShownRoot`；根下的角色、用户分组不是库，照列），后台只读它们，筛选只在其中找，控制台的「库」也只列它们。按数据源记在登记里（`DataSource.shownDatabases`），各个 Tab 一样，不存进表结构缓存。从没设置过时按默认库（`catalogShownDatabases`）：连接信息里填的库，PostgreSQL 没填时为连上后所在的库（`current_database()`），MySQL / MariaDB 没填时一个都没有；连上后的默认库随连接状态交给渲染端（`defaultDatabaseOf`）。根行右端「N / M 个库」：M 为根这一层列出的库（`catalogDatabases`），N 为其中显示的（`catalogListedDatabases`）；点开是多选的 combobox，列根这一层的库，勾上 / 取消即把整份名单记下（`setDataSourceShownDatabases`）。一个库都没显示时根下先出一行提示「勾选要显示的库」。编辑数据源、连接信息变了时回到默认；根这一层读到时，名单里不再列出的（已删掉）去掉并推送数据源列表（`pruneDataSourceShownDatabases`）。没显示的库里展开着的层收起、不读（`catalogPathShown`），再勾上时从收起开始。SQLite 只有一个库，Redis 的键列表照旧，都没有显示的库。
  - 读哪些库（`catalogBulkReads`）：PostgreSQL 一条连接只通一个库，显示的库一个库一次读取、一条临时连接，依次进行、不并发；连接所在的库显示时排在最前，它的两批之间读补全，其余的库不读补全。MySQL / MariaDB 仍是一条临时连接一次读完，范围换成显示的库（已删掉的不写）；没有显示的库时不读。一次读取读不出来（连不上、已删掉）不管，接着读下一次。根下的角色、用户每次读取都连带读。勾上新的库时（`updateDataSourceSessionsShown`，这个数据源连着的各个 Tab 都读）：这个 Tab 正在读就排到最后，否则另起一次只读新勾上的库；都不读补全，也不交给刷新时等待的层。取消勾选的还排着的，轮到时跳过（正在读的读完为止），缓存照留。断开、关 Tab、重连、刷新时整体叫停，叫停后不再写缓存、不再推送。
  - 刷新（手动，或控制台执行了改结构、结束事务的语句后）：先经主进程做刷新前的事——SQLite 重开文件（连接上开着事务时不重开，见「结束事务语句的识别」）、忘掉记住的主键、重跑一次读完主体结构（两批都重跑）——再重读根与所有展开着的层（筛选时另加筛选视图里展开着的、读过的层），各层读到即原地替换。在这次批量读取范围里的层（`catalogBulkBatchOf`：这次读的各库这一层及其下各层，与根下的角色、用户（算第一次读取的），SQLite 为根与各分组）等读它那次读取的那一批的结果，不另查同一层，没读到的层照常现查；所以第一批的层与根读完就换上，不被展开着的第二批的层挡住，第二批的层等补全与第二批读完才换上，PostgreSQL 排在后面的库里的层等读到它那个库的那一批，刷新钮转到那时。根这一层换上时，刷新前读过、这次不重读、刷新期间也没另读到或又展开的层（收起着的）即丢掉，不等全部读完：下次展开时现读，筛选改在表结构缓存里找它们，所以筛选视图里第一批写进缓存的新内容也不被它们挡住。
  - 按名称筛选：纯函数 `filterCatalog`，在 DevCube 已经拿到的各层里找——已读取的，加上表结构缓存里有的（同一层以已读取的为准）——不另查数据库。从根往下找，上一层没列出的节点，缓存里它下面的层不算。库、模式、对象名称不分大小写包含即命中，命中节点连同各级祖先显示，命中的库或模式下拿到的层整支纳入；分组按标签不算命中。缓存经 `peekDataSourceCatalogLayers` 一次取全（主进程包成 `CatalogResult`，同 `peekDataSourceCatalog`），连同这个 Tab 的批量读取还在不在进行；只在进入筛选（筛选词从空变为非空）、根这一层重读后（连上、刷新）与收到批量读取的推送（写进一批、读取结束）时取，以最新的一次为准，改筛选词不重取；所以刚连上就开始筛选时，读完的内容会自己出现。取到之前先只在已读取的层里找；取到之前、或批量读取还在进行时，没有匹配不显示「无匹配对象」，改为「正在读取…」，读完仍没有匹配才显示「无匹配对象」（同 Files 冷索引扫描完成前不显示「无匹配文件」）。缓存里取来的层显示时不核对，刷新时也不重读（ADR-0045）。从根这一层只留显示的库往下找，没显示的库里的对象找不到，缓存里它们的层也不算。筛选视图的开合只记用户的显式操作（层键到开 / 合，`FilterOverrides`），没开合过的层按默认展开：命中项所在的层没展开过也展开，缓存重取后新筛出的层同样展开；「全部折叠」记为把当前各层都合上。开合只作用于筛选视图，筛选词一变（包括清空后再输入）即清空这些开合、回到全部展开，清空时一并丢掉取来的缓存；筛选时点开还没拿到的层照常现读（先显示缓存），不写进展开着的节点，所以清空筛选即回到筛选前的展开（同 Files 的树顶过滤）。
  - 表与视图以外的对象：PostgreSQL 取 `pg_get_functiondef` / `pg_get_triggerdef`，MySQL / MariaDB 取 `SHOW CREATE …`，SQLite 取 `sqlite_schema.sql`，其余（序列、类型、扩展、角色、用户的权限）显示信息表。MySQL 的存储过程与函数不是它的定义者来看时，要有 `SHOW_ROUTINE`（8.0.20 起）或全局 `SELECT` 权限，库级的全部权限不包含它；没有时服务器不报错，只把定义这一格返回为 NULL，所以按无权处理，显示「无权查看」。
  - 右键菜单（`DataSourceTreeMenu`，同 Files 树菜单在鼠标点弹出）：各行与根行都有「在控制台中打开」，对象行另有「复制名称」。「在控制台中打开」切到「控制台」一格，焦点进编辑器（走正文焦点的登记，同点最近打开后焦点进正文；关菜单时不把焦点还给右键前的地方）；再按这一行在目录里的位置换控制台上下文（`catalogConsoleContextChange`）：PostgreSQL 的模式行及其下的分组、对象换到那个库并把模式放到 search_path 最前，库行及库下不属于某个模式的行（扩展）只换库；MySQL / MariaDB 的库行及其下的行换库；根行与根下不属于某个库的行（PostgreSQL 的角色，MySQL / MariaDB 的用户）只切格；SQLite 没有控制台上下文，也只切格。切换同工具栏的「库」「模式」（`useContextSwitch`，见「控制台上下文」）：与当前一致时不切；要变的钮转圈，右键别的库里的模式及其下的行时库与模式都变，两个钮都转；切不过去弹错误框，标题按没切过去的那一级（跨库切模式时，连那个库失败为「无法切换库」，设 search_path 失败为「无法切换模式」）。控制台正在执行或正在切换时这一项置灰，悬停说明「控制台正在执行」/「控制台正在切换」；控制台上下文还不知道时（刚连上，主进程还在应用记住的，工具栏这时也不出下拉），要换库、模式的行这一项同样置灰，悬停说明「正在确定控制台所在的库」，只切格的行不受影响。
- **定位**：「当前对象」「当前键」顶栏右端的定位钮（「在目录中显示」「在键列表中显示」，同 Files「在文件树中显示」），只在停在「当前对象 / 当前键」那一格时显示；对象或键已是树里选中的那一行，定位只负责展开和滚动。点「最近打开」的一项、核对它还在并打开后，同样走这一套。
  - 目录：按对象的位置从根往下展开库、模式、分组各层（`shared/data-source-catalog` 的 `catalogRevealLayers`，按类型用到其中几层）；没读过的层照常先显示缓存再现查，目标行出现即滚入视口。筛选视图里还列着它，就只在筛选视图里展开；被筛选挡住则先清掉筛选。对象所在的库没显示时，「在目录中显示」先把它勾上（记进名单）再定位；点最近打开时不替用户勾上，目录不动。
  - 键列表：展开各级文件夹（`redisKeyFolders`，`user:1:name` 为 `user:`、`user:1:`）。有模式筛选、而这个键不在列出的键里时，先清掉模式、重新列出。
- **表结构缓存**（ADR-0045）：只有登记的数据源的 Data Source Tab 读写磁盘上的缓存。Files 面板里直接打开的 SQLite 文件不写盘：读到的结构（目录各层、对象定义、补全；目录同样分两批读完）只放在会话内存里的一份，接口与用法同缓存，关掉即丢；运行会话不用。每个数据源一个 JSON 文件，放在 `<userData>/data-source-schemas/<id>.json`，格式带版本号（`CACHE_VERSION`，对不上即按没有缓存处理），分目录各层、对象定义、补全三部分，只存读成功的；显示的库是用户的设置，记在数据源登记里，不在缓存里。第一次用到时读进内存；写盘防抖 1 秒，先写临时文件再改名；退出时把待写的写完。渲染端经三个只读缓存、不访问数据库的接口取（`peekDataSourceCatalog` / `peekDataSourceObjectDetail` / `peekDataSourceCompletionSchema`；补全那份 PostgreSQL 按库各存一份），与现查同时发出，现查先到就不用缓存；目录的按名称筛选另经 `peekDataSourceCatalogLayers` 一次取目录各层的全部缓存，连同批量读取还在不在进行（见「目录」）。运行配置对话框另用两个不依赖 Tab 的：`peekDataSourceDatabases`（目录根这一层的库，只读缓存）与 `readDataSourceCompletionFor`（见「运行配置」）。写回前核对会话还是发起读取时那一个，断开、重连、连接信息被改之前发出的读取不写回。
- **补全**（ADR-0047）：
  - **读什么**：照 pgcli / mycli / litecli 读表结构的查询，分几条查询读出库、模式、表与视图的列（连同类型与默认值；MySQL / MariaDB 的类型取 `COLUMN_TYPE`，枚举列的取值由补全引擎从中解析；SQLite 不照 litecli 取 `pragma_table_info`，改取 `pragma_table_xinfo`，生成列也列出，虚拟表的隐藏列不算；逐个表或视图读，取不到列的——未注册模块的虚拟表（如 zipfile、SpatiaLite 的模块），引用了它、没有的函数或已删掉的表的视图——只列名字、不带列，其余照常，连表一次读完会因为其中一个整个失败；只放过 SQLite 报的这类一般错误，连接断开、被取消照常失败）、库里的自定义函数（PostgreSQL 读 `pg_proc`，MySQL / MariaDB 读 `information_schema.routines` 连同参数）与类型、MySQL / MariaDB 的存储过程、外键（SQLite 没写父表列的取父表的主键，主键只读普通表：虚拟表不能作父表），以及不写前缀时查找的模式或库（`searchPath`）；系统库与系统模式不算（SQLite 为 `sqlite_` 开头的对象与影子表，同目录）。MySQL / MariaDB 另照 mycli 读 `CHARACTER SET`、`COLLATE`、`SHOW` 之后与补用户名的位置要的：字符集与排序规则（`SHOW CHARACTER SET`、`SHOW COLLATION` 的第一列）、`SHOW` 之后的各项（帮助表 `mysql.help_topic` 里以 SHOW 开头的主题去掉第一个词）与用户（`mysql.user` 的 `'user'@'host'`）；这几项读不出来（如无权读 `mysql` 库）即没有这一项的候选，不影响其余的。PostgreSQL 读一个库，MySQL / MariaDB 读全部非系统库，SQLite 读这个文件。查询结果整理成补全引擎要的形状（`CompletionSchema`）写成纯函数（`buildCompletionSchema`、`pgFunctionOf`、`mysqlRoutinesOf`、`mysqlShowItemsOf`、`sqliteForeignKeysOf`）。
  - **不写前缀时查找哪里**：PostgreSQL 的缓存里存新连接上的——由会话开始时的 search_path（`pg_settings.reset_val`，不随 `SET` 改变）与 `session_user` 算出（`pgDefaultSearchPath`：`"$user"` 换成登录的用户，没写 `pg_catalog` 时它在最前），运行配置对话框直接用（配置每次在新连接上跑）；MySQL / MariaDB 的缓存里存的是读它的那条连接上的 `database()`（在 Tab 的连接上现查时即控制台所在的库），这一项不用：运行配置对话框按填的库、控制台按控制台所在的库换掉。控制台用的在控制台的连接上另读（PostgreSQL `current_schemas(true)`，MySQL / MariaDB `database()`），渲染端再按推送来的控制台上下文换上（`consoleSearchPath`：PostgreSQL 为 `pg_catalog`、`current_schema()` 与 search_path 的其余各项，MySQL / MariaDB 为控制台所在的库），`use`、`set search_path` 之后不用重读整份。SQLite 没有控制台上下文，为 `main`。
  - **范围**：跟着控制台上下文（见「控制台上下文」）：PostgreSQL 在控制台所在的库上读、按库各存一份，切库即换一份；其余只有一份。Data Source Tab 读一份，交给控制台与表数据的 WHERE / ORDER BY 框共用，重读了两处一起换；控制台上下文还没得知时先不读，两处只补关键字、内置函数与类型。先用缓存里的，现查到了替换，现查失败时保留缓存。连上后与刷新目录后，后台那次批量读取读了补全（PostgreSQL 连接所在的库显示着，MySQL / MariaDB 有显示的库）而控制台就在这个库上时，等它的结果、不另查（补全紧接第一批读，不等第二批）；没读、读不出来或被叫停时照常现查全部。补全不因显示的库多读。手动刷新目录、执行改结构或结束事务的语句后重读。运行配置对话框里的补全见「运行配置」。
  - **别的库里的表**（PostgreSQL，`useTableCompletion`）：打开的表数据类对象（表、视图、物化视图，即有 WHERE / ORDER BY 框的，`DATA_GROUPS`）不在控制台所在的库上时，两个框另读那个库的一份：在它的按库连接上读（翻页查询也用这条连接），按库写回缓存，不写前缀时查找的模式为这条连接的（看缓存时用缓存里存的）；先用缓存、现查到了替换，何时重读同上。同一个库里换着打开表不重读；打开函数、序列等别的对象（没有这两个框）时不读。例外：同一个库里按「表 → 别的对象 → 表」的顺序打开时，回到表时重读一次（先用已有的，现查到了替换）。
- **补全引擎**（ADR-0047，渲染端 `lib/sql-completion`）：
  - **照抄 pgcli**：上下文判断（`sqlcompletion.py`）、表 / 别名 / CTE 的提取（`parseutils`）、匹配与排序（`pgcompleter.py`）逐函数照搬；MySQL / MariaDB 照 mycli，SQLite 照 litecli；子查询作用域参照 sqls，关键字按子句过滤参照 Tabularis 的 `KEYWORD_ALLOWED_CLAUSES`；内置函数、关键字与类型取三者自带的数据；PostgreSQL 另补 pgcli 补全关键字表漏掉、写查询常用的关键字（`PG_MISSING_KEYWORDS`：`ILIKE`、`SIMILAR`、`OFFSET`、`RETURNING`、`INNER`、`END`、`TRUE` 等，都在它的保留字表里；只在 `EXPLAIN`、`VACUUM` 等语句里用的如 `VERBOSE`、`ANALYSE` 不补）。mycli / litecli 独有、pgcli 没有的功能不吸收（见 ADR-0047）。
  - **切词**：唯一的差异。适配层把 lang-sql 语法树的叶子转成与 sqlparse 等价的记号流，交给照搬的 sqlparse 切分与分组。
  - **补全源**（`sqlCompletionSource`）：只取光标所在的那条语句（语法树的 Statement 节点）；注释与字符串里不补（MySQL / MariaDB 的字符串里补枚举值，PostgreSQL 的 `$$` 函数体里照常补）；有输入的词、句点之后或按补全快捷键时才补。排序与筛选全照引擎，不用 CodeMirror 自己的筛选，只借它标出匹配的字符；列的类型写在候选旁。语法树还没解析完时（刚载入很长的文字）最多再解析 50 毫秒，仍没解析完这次不补全，解析的进度留着下次接着用。
  - **接入**：编辑器的语言用 `sqlLanguage(kind, { metadata, prefix?, prioritizer? })`，其中 `metadata` 是表结构（取不到为 null），`prefix` 是前缀文字，表结构或前缀变了就重建语言。它是 lang-sql 的方言语言配上这个补全源，不用 `sql()`（它总会挂上自带的关键字补全）。WHERE / ORDER BY 框给 `prefix`：`SELECT * FROM 这张表 WHERE `（或 `ORDER BY `）接上框里的文字再判断。关键字 PostgreSQL 补成大写，MySQL / MariaDB / SQLite 随输入的大小写（各照来源）；列名只在语句里有多张表时带上表名或别名，FROM 里不自动加别名。
  - **使用次数**（照 pgcli 的 `PrevalenceCounter`）：执行成功的语句里各名字与各关键字出现的次数；匹配程度与候选的类别都相同时，次数多的排前。名字按名字的次数，关键字与内置函数按关键字的次数（内置函数只有同在关键字表里的才数得到，同 pgcli）。关键字的次数按关键字表的写法（大写）记，查的时候也换成大写：MySQL / MariaDB / SQLite 的关键字与内置函数随输入的大小写，小写输入时补成小写，照样按次数排；PostgreSQL 的关键字总补成大写。登记的 SQL 数据源各一个计数器（`useCompletionUsage`），它的控制台、WHERE / ORDER BY 框与运行配置对话框共用，表结构换了、补全器重建时沿用；Files 面板里直接打开的 SQLite 文件没有计数器，不按次数排。控制台与运行配置每执行完一次，有执行成功的语句时，主进程把这些语句连同数据源当时的类型推给主窗口（`onDataSourceExecuted`），渲染端按这个类型的关键字表与切词计数（`countExecutedStatements`），再整份存回主进程（持久化键 `dataSourceCompletionUsage`：数据源 id → 各关键字与各名字的次数）；第一次用到时读回，计数先等读回，免得存回时盖掉存下的。跨重启保留，移除数据源时删掉，改连接信息、改类型不删。
- **改结构语句的识别**：去掉开头的注释后，按语句的第一个关键字判断，包括 CREATE、ALTER、DROP、RENAME、TRUNCATE、COMMENT、GRANT、REVOKE。写成纯函数。
- **结束事务语句的识别**（`isTransactionEnd`）：执行后同样重读目录与补全——事务里改的结构提交了，在临时连接上重读才看得到；回滚了，已在 Tab 连接上读到的也要撤掉。只认真正结束事务的：COMMIT、END、ROLLBACK 与 PostgreSQL 的 ABORT，含 COMMIT / ROLLBACK PREPARED、AND [NO] CHAIN 以及带 WORK、TRANSACTION 的写法。回滚到保存点（ROLLBACK [WORK | TRANSACTION] TO …）与释放保存点（RELEASE …）不结束事务，不算。判断方式同上，去掉开头的注释后看第一个关键字。两种语句都只在执行成功（没有出错、没被取消）时才触发重读。SQLite 刷新前要重开文件，而事务还开着时重开会把它连同之前的改动悄悄回滚（如 `begin; insert …; create table …` 触发的那次重读，或事务中手动刷新）：所以重开前先问查询线程连接上是否开着事务（better-sqlite3 的 `inTransaction`），开着就不重开，只重跑主体结构读取（在另开的临时连接上，看不到事务里还没提交的改动，提交后那次重读才看得到）；等 COMMIT / ROLLBACK 触发的那次重读，事务已结束，才重开。
- **编辑与执行**：
  - 编辑器（控制台、对象定义、运行配置对话框共用 `CodeEditor`）同 Files 编辑器：主题与高亮、自绘选区、⌘F 查找栏（`useEditorFind`，与 Files 编辑器共用），行号由 basicSetup 提供；对象定义用 CodeMirror 的 `readOnly`（能聚焦、查找、复制，不能改），不用 `editable={false}`。
  - 语句边界照 pgcli / mycli / litecli 执行前的切法（`sqlparse.split`，即补全引擎照搬的 sqlparse 切分，ADR-0047），切词同补全引擎（`@codemirror/lang-sql` 的语法树经适配层转成的记号流），不另外引入 SQL 解析库。字符串与注释里的分号不切。MySQL / MariaDB 的注释照 mysql 客户端认：`--` 之后是空白或已到末尾才是注释（mysqldump 单独一行的 `--` 也是；`1--1` 不是），lang-sql 原来只认空格，用 pnpm patch 修正，高亮也随之一致；可执行注释 `/*! … */`（带版本号的 `/*!50003 … */`，MariaDB 另有只在 MariaDB 上执行的 `/*M! … */`，MySQL 把它当普通注释）不是注释，里面是要执行的代码：切词适配层照常切里面的内容，开头与结尾算语句的一部分，连同注释原样发出，由服务器按版本号决定执行与否（mysqldump 把 SET 头、视图、触发器、事件整条写在里面），里面的分号同样切开（同 mysql 客户端）；找它的结尾时也照 mysql 客户端跳过里面的字符串、带引号的名字与注释，其中的 `*/` 不算结尾（mysqldump 写在里面的视图、触发器、事件可能带这样的字符串），lang-sql 原来遇到第一个 `*/` 就算结尾，同样用 pnpm patch 修正（给方言加 `versionComments` 选项）；编辑器里仍按注释高亮，范围随之一致。建存储过程、函数、触发器、事件时 BEGIN … END 块里的分号不切，整条发出（MySQL / MariaDB 的过程体、SQLite 的触发器、PostgreSQL 的 `BEGIN ATOMIC` 函数体；块里的 `IF`、`CASE`、`LOOP`、`WHILE` 也认，`REPEAT … END REPEAT` 照 sqlparse 不认）；开事务的 `BEGIN`、`CASE` 表达式照常切。MySQL / MariaDB 照 mycli 的 `DelimiterCommand` 认客户端命令 `DELIMITER`：切出的一条以它开头时换上新的分隔符，从命令之后重新切，命令本身不发给服务器；按别的分隔符切时照 mycli 先把原文的分号换成占位符（U+FFFC）、分隔符换成分号，再用同一套切法切（换成的文字与原文等长，语句直接从原文里取）。分隔符为同一行里 `DELIMITER` 之后第一段不含空白的文字（不分大小写；同 mysql 客户端按行取，mysqldump 写的 `DELIMITER ;;` 也认）；没写、写在下一行、写成 `delimiter` 的不算命令，照常发出。分隔符只在这次执行的文字里有效，每次都从分号切起（执行选中的部分时从选区开头算），控制台与运行配置一样；PostgreSQL、SQLite 不认。只有空白、注释与分号的不算一条（MySQL 执行只有注释的语句会报错）。MySQL / MariaDB 的字符串里反斜杠是转义符（`'\''` 是一个引号）：lang-sql 自带的这两个方言没开 `backslashEscapes`，照它们的 spec 另定义一份开上（`codemirrorDialect`），高亮、补全切词也按它。执行时把整段（或选中的文字）同步完整解析一遍、不设时限，不用编辑器里的语法树（刚载入很长的文字时它可能还没解析完）。光标落在两条语句之间（空行、注释）时取上面那条，上面没有（光标在第一条之前）就取下面那条。
  - ⌘Enter 用 CodeMirror 的 keymap 处理，放在最高优先级（默认 keymap 把它当插入空行），执行中、切换控制台上下文时按了不起作用。
  - 控制台在控制台上下文所在的库上执行（PostgreSQL 在默认库上即 Tab 的连接，在别的库上为那个库的按库连接），先等连上后应用完记住的上下文；各条语句依次执行、遇错即停；再执行时上次的结果留着，新的到了才替换。
  - 方言按类型选：PostgreSQL、MySQL、MariaSQL、SQLite。
  - 补全见「补全引擎」。格式化用 `sql-formatter`，控制台与运行配置对话框共用 `formatSqlInEditor`（格式化选中的部分或全部，内部调 `formatSql`）：`formatSql` 把运行配置的参数 `${{…}}` 经 `paramTypes.custom` 认作一个参数、原样保留（正则与认参数的同源，`RUN_PARAM_SOURCE`；不加这条 sql-formatter 会报错），方言自带的参数写法照旧；失败时弹错误框「无法格式化」。
- **控制台上下文**（ADR-0046，`shared/data-source-context`）：Data Source Tab 的控制台在哪个库上执行。
  - **是什么**：PostgreSQL 为所在的库、`current_schema()` 与原样的 `search_path`；MySQL / MariaDB 为 `database()`（没选库为空）；Redis 为库编号，键列表也列这个库。SQLite、运行会话没有。
  - **以服务器为准**：主进程按 Tab 持有，只推送回查到的（`onDataSourceConsoleContextChanged`），渲染端不自己推算。回查在控制台的连接上：PostgreSQL `select current_database(), current_schema(), current_setting('search_path')`，MySQL / MariaDB `select database()`，Redis `CLIENT INFO`（6.2 起才有；问不到时按执行成功的 `SELECT n` / `RESET` 推算，`redisDatabaseAfter`）。
  - **下拉切换**（`switchDataSourceConsoleContext`）：先在控制台的连接上执行，再回查、记住并推送；点的就是现在那一项时不执行（`isCurrentConsoleContext`）；切不过去（库连不上、库编号超出范围、无权，Redis 的控制台开着事务，见「Redis」）交回原因（`ConsoleContextFailure`：出错在改 search_path 那一步的另记下），界面弹错误框（「无法切换库」「无法切换模式」，见「执行与切换互斥」），上下文不变。PostgreSQL 切库改用会话里的按库连接，Tab 的连接不动；从「模式」选了模式即在控制台所在的库上用 `set_config('search_path', …, false)` 把它放到最前（加双引号，原有各项原样跟在后面，去掉同名的那一项，`prependSearchPath`；值作参数交给服务器，不拼进语句），从「库」切库不改 search_path。MySQL / MariaDB 发 `USE`，Redis 发 `SELECT`。
  - **下拉里列什么**：「库」列目录根这一层里显示的库（控制台正在没显示的库上时，钮上照常是它的名字，列表里不列；一个都没显示时列表里写「没有显示的库」），PostgreSQL 的「模式」列控制台所在库的模式这一层（`useCatalogLayer`：列表打开时读、收起即丢掉，同目录先显示表结构缓存、同时现查，但现查读不出来时有缓存就留着缓存——有总比没有好，同补全）；筛选在渲染端按输入的文字（Base UI Combobox 自带的筛选，不分大小写），打字时自动高亮第一个匹配项（`autoHighlight`），回车即选中。列表开着时是模态的（`modal`，另加 Base UI 的 Backdrop 盖过吸顶的行，同菜单）：点外面只收起，不穿透到下面的钮。Redis 的下拉打开时读 `CONFIG GET databases`（托管的 Redis 常禁用 `CONFIG`，取不到按 16）与 `INFO keyspace`（各库的键数），列 0 到个数 − 1，另补上有键的与当前所在的（`redisDatabaseIndexes`）。
  - **执行后回查**：执行成功的语句里有可能改它的，执行完回查并推送。SQL 按 `changesConsoleContext` 认（去掉开头的注释后看第一个关键字）：PostgreSQL 为改 search_path 的（`SET [SESSION | LOCAL] search_path`、`SET SCHEMA`、`RESET search_path`、`RESET ALL`、`DISCARD ALL`），换角色的（`SET [SESSION | LOCAL] ROLE`、`SET [SESSION | LOCAL] SESSION AUTHORIZATION` 与对应的 `RESET`：默认的 search_path 里有 `"$user"`），所有改结构的（`isSchemaChange`，见「改结构语句的识别」：建、删、改名模式或授予、收回模式的使用权会改 `current_schema()`，按第一个关键字认不出是哪一种，所以都查），结束事务的（事务里的 `SET` 随之生效或撤销）；MySQL / MariaDB 为 `USE` 与 `DROP DATABASE` / `DROP SCHEMA`（删的正是控制台所在的库时变为没选库）。Redis 按回复认（`recheckRedisDatabase`）：执行成功的 `SELECT`，以及 `RESET`、`EXEC`、`DISCARD`（出错的也算，事务同样结束了）；回复 `QUEUED` 的 `SELECT` 只是排进事务，不算；执行完连接仍在 `MULTI` 里时不回查（回查的命令也会排进事务），等结束事务的那一次。
  - **记住**：登记的数据源的 Tab 按 Tab 键记住（持久化键 `dataSourceConsoleContexts`：PostgreSQL 记库与整个 search_path，MySQL / MariaDB 记库，没选库时不记、删掉记住的，Redis 记库编号），下拉切换、执行后回查到的都记。PostgreSQL 的控制台连接在事务里时（`getTransactionStatus()` 不是 `I`），回查到的只推送、不记：事务里的 `SET` 随回滚撤销，`SET LOCAL` 随事务结束失效；结束事务的语句触发的那次回查才记。关 Tab、移除项目或数据源时随控制台内容一起删，连接信息被改时清掉（见「编辑与移除」）。
  - **连上即应用**（连同重连、重启后恢复）：Data Source Tab 连上后先把记住的设上（PostgreSQL 切到那个库，search_path 整个设成记住的），再回查并推送；记住的库已不在、切不过去时这一次用默认的，记住的留着下次再试；数据源改过类型、对不上的不用。控制台执行、补全与 Redis 的各种读取都先等这一步；渲染端得知上下文之前不出下拉、不列键。控制台所在库的按库连接断开后重连时，把控制台的 search_path 重新设上。
  - **执行与切换互斥**：渲染端 `data-source-store` 按 Tab 记正被什么占着（`consoleBusyByTab`：执行，或切换中要变的各级——库、模式，`consoleContextChangeLevels`：PostgreSQL 带了模式时模式要变，要切到的库不是控制台所在的库时库也要变，其余只有库要变），SQL 与 Redis 同一套。执行中「库」「模式」与库编号下拉置灰；切换中要变的钮转圈并置灰（切库为「库」或库编号，切模式为「模式」，目录右键跨库切模式时两个都转；从 Redis 最近打开等别处发起的也一样），其余只置灰，「执行」置灰、⌘Enter 不执行。切换经 `switchConsoleContext`（`lib/data-source-context`），SQL 的「库」「模式」、目录右键「在控制台中打开」、Redis 的库编号下拉、点 Redis 最近打开里别的库的键共用：控制台被占着时不切（点最近打开的这一项也不打开）。「库」「模式」（combobox）与库编号下拉（菜单）同在 `ConsoleContextDropdown`，与目录右键「在控制台中打开」共用一套切换（`lib/data-source-context` 的 `useContextSwitch`：互斥、转圈与置灰、点的就是当前那一项时不切、切不过去的错误框）；切不过去的标题与正文由 `contextSwitchFailure` 给出，Redis 点最近打开也用它：标题按没切过去的那一级（`consoleContextFailureLevel`：出错在改 search_path 那一步为「无法切换模式」，在那之前为要变的第一级——跨库切模式时连那个库失败为「无法切换库」，同库切模式为「无法切换模式」），正文为原因，无权为「无权切换」；两个下拉另共用钮上的图标、当前值；库编号的菜单项由键列表给。
- **分页**：原则是不长时间占着数据库。开着的游标会挡住别人改表结构，SQLite 下还会挡住写入。
  - **表**：
    - WHERE 与 ORDER BY 框是单行的 CodeMirror（`BarCodeInput`）：始终一行（粘贴进来的换行换成空格），按方言高亮，补全见「补全」「补全引擎」；回车提交、Esc 清空并把焦点交给下面的表格（表格不在时只失焦），补全浮层开着时回车接受补全、Esc 先关浮层。
    - 每页一条 `LIMIT` / `OFFSET` 查询。WHERE 与 ORDER BY 框里的文字（不带关键字）原样拼进去，之后先换行：`where (条件\n)`、`order by 文字\n, 主键…`，末尾的行注释只注释它自己那一行，不吞掉右括号、主键与 `LIMIT`。
    - 翻页稳定：有主键时总把主键列（按方言引用、按主键顺序、不带方向）排在 ORDER BY 最后；ORDER BY 为空时只按主键排；没有主键就不加。主键在会话里按「库 \0 模式 \0 表」记住，同时发出的请求共用一次查询，查失败的不记；刷新目录、执行改结构或结束事务的语句、重连、断开后重新查。
    - 点表头：生成这一列的排序文字（`"col" ASC` / `DESC`，MySQL 用反引号），写进 ORDER BY 框（覆盖没提交的草稿）并立即生效、回到第一页；升序 → 降序 → 空，不叠加。生效的 ORDER BY 文字是排序唯一的状态，表头箭头由它推出：恰好等于某列的点表头结果才显示那一列的箭头。这三个函数（`headerOrderBy`、`headerSortOf`、`nextHeaderOrderBy`）写成纯函数。
    - 总行数另开一条连接执行 `COUNT(*)`，只带 WHERE；换表、改 WHERE 或关闭 Tab 时取消，已发出的先叫停再关。
  - **控制台结果**：
    - 读到 10001 行为止：多读的那一行只用来判断有没有超过 1 万行。PostgreSQL 用 `pg-cursor`，读够即关游标、结束语句；SQLite 在查询线程里 `iterate()`，读够即结束语句；MySQL 用 `mysql2` 的回调接口按事件逐行收，超过的行不再留存（语句仍读到底：中途结束要另开连接 `KILL QUERY`，与「取消」同一套，见「取消」）。
    - 在渲染端本地翻页；当前页的行按结果、页码、每页行数缓存，表格的选区与查找进度不因父组件重渲染而重置。
  - **每页行数**：记在全局设置里，1–10000；常用值 100 / 200 / 500 / 1000。
- **表格**：用 TanStack Table 9 管状态（`cellSelectionFeature`、列宽；排序不用它的，见「分页」的点表头），配合 TanStack Virtual 做行列双向虚拟化，按 DESIGN.md 用 Tailwind 自己画（ADR-0042）。「当前对象」、控制台结果与运行会话结果共用这一个表格。复制时生成 TSV。⌘F 查找与 Files 表格预览共用 `useSheetFind`（`lib/use-sheet-find`：查找状态、起点格、命中底色与 `FindBar` 的接法；命中函数仍是 `sheetFindMatches` / `sheetFirstMatchFrom`）：只查交进来的这些行，按格子显示的文字包含匹配；换了那份行即作废查找进度，在新数据里从头找（翻页、改排序、刷新，回到缓存过的同一页也从头找）；⌘F 只在焦点位于这张表格或它的查找栏时响应（隐藏格里的表格仍挂载着）。
- **导出**：
  - **两步**：先弹系统保存对话框（挂在发起导出的窗口上，默认在「下载」目录），选好了才写文件；取消什么都不做。默认文件名由纯函数 `exportFileName` 生成：表名里的 `/ \ < > : " | ? *` 与控制字符换成 `_`，去掉首尾空白，为空时用 `result`，Windows 的保留设备名（CON、NUL、COM1 等，含带扩展名的）后面加 `_`。
  - **怎么写文件**：边读边写，不经过渲染端，写入错误都会作为结果交回。
    - 表：另开一条临时连接（不挡着当前 Tab 的其他查询），按当前的 WHERE 与 ORDER BY（主键排在最后）用一条查询读完整张表。PostgreSQL 用游标每批 1000 行；MySQL 用 `query.stream()` 攒够 1000 行写一次，写入出错时销毁行流，并先对导出连接发 `KILL QUERY` 再关；这两种先打开文件（打不开时语句还没发出），背压与写入错误交给 `stream/promises` 的 `pipeline`。SQLite 在查询线程里自己读写：先准备语句、打开文件，再逐行写，列的类型按前 1000 行判断（取样后接着读完剩下的行），写入出错时结束语句。导出期间这张表一直在被读，SQLite 下别的程序的写入会等到导出结束，或者等到它自己的超时。
    - 控制台、运行会话：用已经取回的行。
  - **反馈**：写文件期间导出钮本身转圈并置灰（同「刷新」钮），写好了不提示，失败弹错误框「导出失败」（无权时为「无权查看」）。
  - **CSV**：CSV 和复制时的 TSV 都用 Papa Parse 的 `unparse` 生成，转义按电子表格的规则。Papa Parse 是项目已有的依赖，主进程要用，所以按 ADR-0036 从 `devDependencies` 挪到 `dependencies`。CSV 文件开头写 UTF-8 BOM，Excel 靠它才认出中文。
  - **JSON**：一个数组，每行一个对象。数字类型的列把数据库给的文字原样写成 JSON 数字，布尔写成布尔，NULL 写成 `null`，其余写成字符串。
  - **SQL INSERT**：每行一条 `INSERT INTO … (…) VALUES (…);`，按当前数据库的方言引用标识符和字符串（MySQL 默认把反斜杠当转义符，也写两遍）；数字列像数字的原样写，布尔写成 TRUE / FALSE；二进制写成该方言的十六进制写法（PostgreSQL 为 `'\x…'::bytea`，其余为 `X'…'`）。PostgreSQL 的表有总是自动生成的标识列（`GENERATED ALWAYS AS IDENTITY`）时，INSERT 里加 `OVERRIDING SYSTEM VALUE`（同 pg_dump 的 `--inserts`），照原来的值导回，不然给它写值会报错；只在导出为 SQL INSERT 时另读（`alwaysIdentityColumnsOf`：`pg_attribute.attidentity` 为 `a`，10 以前没有标识列），`BY DEFAULT` 的本来就能写值、不加，其余数据库没有这种列。整表导出时不写生成列：生成列插入时不能给值，写了就导不回同结构的表；只在导出为 SQL INSERT 时另读这张表的生成列（`generatedColumnsOf`），PostgreSQL 看 `pg_attribute.attgenerated`（12 以前没有生成列），MySQL / MariaDB 看 `information_schema.columns` 的 `generation_expression`（不看 `extra`：MySQL 用表达式作默认值的列也标 `DEFAULT_GENERATED`；这一列 MySQL 5.7.6、MariaDB 10.2.5 起才有，先按 `select version()` 看版本：之前的 MySQL 没有生成列，之前的 MariaDB 看 `extra` 为 `VIRTUAL` 或 `PERSISTENT`，由纯函数 `mysqlGeneratedColumnCondition` 定），SQLite 看 `pragma_table_xinfo` 的 hidden 为 2 或 3；CSV、JSON 照旧含生成列。控制台、运行会话的结果不知道来自哪张表，表名先写成 `result`，各列照原样写。
  - 三种格式的生成都写成纯函数。
- **取消**：
  - PostgreSQL：另开一条连接，执行 `pg_cancel_backend(<pid>)`，pid 为执行这条语句的那条连接的（控制台在别的库上时为那个库的按库连接）；
  - MySQL / MariaDB：另开一条连接，执行 `KILL QUERY <线程 id>`；
  - SQLite：结束 worker 线程，再重新打开文件。不等旧线程真正结束：被打断的查询当场以已取消收口，Tab 随即换上新线程，其间的读取不会一直是「未连接」；旧线程停在一步原生调用里时，要等这一步做完才真正结束（见「驱动」）；
  - 叫停后语句照常返回的，同样记为已取消（MySQL 的 `SLEEP()` 被 `KILL QUERY` 打断时不报错、照常返回 1），后面的语句不再执行；
  - Redis：控制台不提供取消。Redis 的命令通常很快；不设超时的阻塞命令（如 `BLPOP key 0`）会占住这条连接，断开重连即可，被打断的那条记为「已取消」。
  - 叫停本身失败（如叫停用的连接连不上）作为结果交回，控制台弹错误框「无法取消执行」（无权时为「无权取消」）。
- **运行配置**（ADR-0044）：
  - **模型**：命令型 **Run Configuration** 的第三种归属，`{ kind: 'dataSource', dataSourceId, name, script, database? }`：`script` 为整段 SQL（Redis 为一行一条命令），`database` 为在哪个库上执行（PostgreSQL / MySQL / MariaDB 为库名，Redis 为库编号，缺省即数据源的默认库，SQLite 没有）。存在同一份配置数组里（ADR-0002），顺序即数组顺序；归属键为 `datasource:<id>`，会话键同命令型 `cmd\0<id>`；下发给渲染端时挂在 `DataSourceNode.configs` 上，项目只收 `command` 与 `referenced`。
  - **对话框**：与命令配置共用外壳（`ConfigDialogFrame`：`SettingsModal`、底栏左侧参数说明、右侧「取消 / 保存」，Esc 已被编辑器收下时——关补全、关查找栏——不关对话框），按条目种类分派。字段为名称、库（SQLite 不出）、内容，名称与内容去掉首尾空白后都不能为空。
    - 库：可输入也可选（`AutocompleteInput`），选项为表结构缓存里目录根这一层的库（`peekDataSourceDatabases`，不访问数据库，连过这个数据源才有）；占位只写默认值（数据源的默认库，没设时空着；Redis 为数据源的库编号，没设为 0）。Redis 为库编号，按 `redisDatabaseError` 校验。
    - 内容：`CodeEditor`，Redis 为纯文本；输入 `${{` 时补上 `}}`（见 `docs/prd/run-config-params.md`）。SQL 按方言高亮，有格式化钮（同控制台，见「编辑与执行」）；补全按「数据源 + 库」取（`readDataSourceCompletionFor`，不依赖 Tab）：先取表结构缓存，没有时借一个连着的 Data Source Tab 现查并写回缓存，都没有就只补关键字、内置函数与类型。PostgreSQL 各库各一份：库留空（即数据源的默认库；连接信息里没写时，取连着的 Tab 连上时服务器给的那个）、是默认库或是选项里的库时才取，输入到一半的库名不去连；MySQL / MariaDB 与 SQLite 只有一份，不写前缀时补全到填的库（留空即数据源的默认库）。
    - 不加「模式」：要在别的模式上执行，在内容里写 `set search_path`。
  - **参数**：
    - 写法、参数框、替换与记住的值同项目、服务器上的配置，见 `docs/prd/run-config-params.md`（ADR-0048）：写作 `${{名称}}`，写在内容里，字符串与注释里也算，Redis 命令同样认。不认 `${名称}`、`?` 与 `:名称`：三处一种写法；也免得与 PostgreSQL 的 `::` 类型转换冲突，免得普通语句误弹参数框。
    - 先换后切：填的值按文字原样换进内容（`fillRunParams`），再切语句，所以填的值里有分号、换行时，照样按换好的内容切语句（`dataSourceRunStatements`）。
    - 等密码时交上密码的重跑是同一次运行的继续：每个参数在记住的值里都有，就直接沿用、不弹框。只有等密码期间配置里新加了没填过的参数才再弹，这时取消即停止这次运行，以「已取消」结束，不会停在「正在连接…」。
  - **切语句**：运行时由渲染端先换好参数（见「参数」），再按数据源当前的类型切好交给主进程：SQL 用 `allStatements`（同步完整解析，不设时限，与控制台同一套切法，见「编辑与执行」），Redis 用 `redisCommandLines`（去首尾空白、丢空行）。所以这类配置只能由渲染端发起运行，主进程不必带上语言包。
  - **连接**：每次运行在数据源连接会话里开一条自己的连接（键即运行会话键），库按配置覆盖（`dataSourceRunTarget`：PostgreSQL 直接连到那个库，MySQL / MariaDB 作默认库，Redis 作库编号）；先用记住的密码，没记住就不带密码。它不写表结构缓存、不读主体结构。运行结束、被重跑取代时断开并推送未连接。编辑数据源的连接信息不断开它，下次运行才用新的连接信息。
  - **密码**：被拒（含要密码却没给）时运行会话保持「运行中」等密码，正文出未连接页同款的密码框；交上来即带着密码重跑（沿用这次填的参数，见「参数」），连上后按勾选记住或忘掉。
  - **执行**：SQL 同控制台（依次执行、遇错即停、每条最多 1 万行、表格显示最后一个结果集），Redis 同 Redis 控制台；不自动包事务。结果由主进程持有，执行完一次推送（执行中只显示「正在执行…」），渲染端重载后取回。
  - **结束状态**：全部执行完、没有出错、没被停止时为「已退出」（绿点，退出代码 0），其余（出错、已取消、没执行完、整个没能执行）为「失败」（`dataSourceRunSucceeded(output, 总条数)`，已执行的少于总条数即失败）。整个没能执行的原因：数据源已移除、没有要执行的语句、库编号不合法（连接前即结束）、连接失败的原因、已取消、无权执行。
  - **停止与重跑**：停止即取消：还在连接或等密码时立即以「已取消」结束；执行中叫停正在执行的语句再断开，被打断的那条记为已取消，在两条之间停下的后面的语句不出现。重跑先叫停旧的一次。
  - **生命周期**：关 Tab、⌘W、删除配置即叫停并销毁；移除数据源连同配置与运行会话一起删除；数据源改了类型，配置照旧保留，按当前类型切语句、执行；退出确认把运行中（含等密码）的算作运行会话，退出时先叫停；跨重启配置保留，运行会话不恢复。
  - **界面**：运行会话 Tab 同其他配置；正文是控制台同款的结果区（`ConsoleResultView`，Redis 为回复列表），不是 xterm；操作栏为运行 / 重跑、停止，SQL 类型另有「导出」，不出「清空」与摘要。
- **Redis**：
  - 列键用 `SCAN … MATCH … COUNT 1000`（不用会阻塞服务器的 `KEYS`），读够 1 万个即停；回复的格式不对时报错（`parseRedisScanReply`），不当作已列完。列的是控制台上下文所在的库，换了库（下拉切换、控制台里 `SELECT`）即重新列出，「当前键」清空（它属于原来的库；点最近打开里别的库的键时，打开可能先于切库的推送到达，已是新库的键不清）。
  - 读一个键先查 `TYPE` 与 `PTTL`，再按类型取值：字符串 `GET`；哈希、集合用 `HSCAN` / `SSCAN`，读够 1000 项即停；列表 `LRANGE`、有序集合 `ZRANGE … WITHSCORES` 取前 1000 项，用 `LLEN` / `ZCARD` 判断有没有截断；流 `XRANGE … COUNT 1000`，每条的字段写成一个 JSON 对象。其他类型（如模块提供的）提示不支持查看。
  - 字符串是对象或数组的 JSON（按标准 JSON 判断）时排版显示（渲染端 `formatJsonText`）：用 `jsonc-parser` 的 `format` 只改 token 之间的空白（2 个空格缩进、`\n` 换行、去掉首尾空白），token 原样保留，不经 `JSON.parse` 再序列化，所以大整数不失精度、数字与转义的写法不变。它给出的修改按顺序一次拼好，不用它的 `applyEdits`（每条修改都重拼整段，耗时随大小平方增长，几百 KB 就卡几秒）。显示在只读编辑器里（`lang-json` 高亮、⌘F），复制的即排好版的文字。`jsonc-parser` 按 ADR-0036 放在 `devDependencies`。
  - 命令都走 node-redis 的 `sendCommand`，拿原样的回复。控制台的一行按 redis-cli 的规则拆成参数（双引号里认转义与 `\xHH`，单引号里只认 `\'`；`\xHH` 是一个字节，拼出的不是合法的 UTF-8 时整个参数按字节原样发出），依次执行、遇错即停；执行中被断开（关 Tab、断开连接）时，被打断的那条记为「已取消」。
  - **回复的显示**（`formatRedisReply`，照 redis-cli 的 RESP2 输出）：控制台取回复时把批量字符串映射成字节（node-redis 的 `typeMapping`），才与状态回复分得开——状态回复（`OK`、`PONG`、`TYPE` 的类型名）原样，批量字符串（含分数这类小数）加引号，整数带 `(integer)`，空为 `(nil)`，数组逐项编号；数组里的错误回复（如 `MULTI` 后 `EXEC` 里执行出错的那条）显示为 `(error) 消息`，同 redis-cli。redis-cli 按原样输出的几条（`INFO`、`CLIENT LIST` / `INFO`、`MEMORY DOCTOR` 等，清单与参数个数的条件同 redis-cli，`redisRawOutput`）按行原样显示。
  - **不执行的命令**（`redisConsoleRefusal`）：`SUBSCRIBE`、`PSUBSCRIBE`、`SSUBSCRIBE`、`MONITOR`、`SYNC`、`PSYNC` 让连接只收服务器推送的内容、不再一问一答（同 RedisInsight 的控制台）；`HELLO 3` 把连接的协议切到 RESP3，回复换了格式，而这条连接固定用 RESP2。这条连接与键列表、看键共用，之后的回复就对不上了；控制台报出原因，不发给服务器（如「控制台不支持 HELLO 3：连接固定使用 RESP2 协议，不能切换」）。`HELLO`、`HELLO 2` 照常执行。
  - **RESET**：它把连接退回未认证的 default 用户（库回到 0 号、事务结束）。执行成功后照连接时的账号重新认证（`AUTH`），这条共用的连接照常可用；库编号照常回查（见「控制台上下文」）。重新认证失败时这一条报出原因。
  - **事务**：键列表、看键、核对键在不在、库编号下拉、命令表都与控制台共用 Tab 的那条连接。控制台执行了 `MULTI`、还没 `EXEC` / `DISCARD` 时（主进程每次执行完按回复记下，`redisInTransactionAfter`：执行成功的 `MULTI` 开始，`EXEC`、`DISCARD` 结束——出错的也算——`RESET` 也结束，跨几次执行接着算；重连即是新连接，不在事务里），别的读取发出去只会排进事务、回复 `QUEUED`（`EXEC` 时还多出结果），所以只发控制台执行的命令（`withRedisClient` 的 `fromConsole`），其余都不发，交回「事务还没结束（先 EXEC 或 DISCARD）」（`REDIS_IN_TRANSACTION`）；下拉切库同样交回它，界面弹错误框「无法切换库」。
  - **命令名补全**（不走补全引擎）：连上后向服务器取一次命令表（`readRedisCommands`：先发 `COMMAND DOCS`，Redis 7 以前没有它时发 `COMMAND`；`parseRedisCommandDocs` / `parseRedisCommandTable`），转成大写、去重、排序。光标在一行的第一个词里（前面只有空白，`redisCommandWordBefore`；命令名可含 `_ . -`，如模块的 `JSON.GET`）时列出，交给 CodeMirror 自己筛选；还没输入时只在按补全快捷键时列。取不到时不补；不补键名。
  - 拆参数、切行、摘要、显示回复、键分组成树、键的各级文件夹（`redisKeyFolders`）、剩余过期时间的说明都写成纯函数（`shared/redis`）。
  - 键列表和键的值都不自动刷新，点「刷新」重读；刷新时旧列表留着，读完替换。
- **SQLite 并发**：
  - 打开时设 `better-sqlite3` 的 `timeout` 为 5000 毫秒：写入时遇到锁，最多等 5 秒，还拿不到就报「数据库正被其他程序占用，请稍后重试」。
  - 表分页每页一条短查询，控制台读到上限就结束语句，都不长时间持有读锁。
  - 刷新时关掉再重新打开文件，这样文件被整个替换后也能读到新内容；连接上开着事务时不重开（见「结束事务语句的识别」）。查询线程意外退出时，会话摘下连接并显示断开。
- **Files Tab**：
  - `FilesOpenKind` 加一种 `sqlite`，按 `file-type` 识别出的 `application/x-sqlite3` 判断。
  - 只在本机的 Files Tab 和 Preview Window 里生效；服务器的 Files Tab 不变。
  - 正文区嵌入同一个 Data Source Tab 组件，连的是一个临时数据源，不登记，也不落盘（控制台内容、打开的对象与展开都不记，没有最近打开）。每个面板各自一条会话（同一个文件可以同时开在项目的 Files Tab 与 Preview Window 里），记下发起打开的页面，页面关闭或重载时一并关掉；切到别的文件时经单独的接口（`closeSqliteFileSession`）只断开连接，不走关 Data Source Tab 的收尾。路径校验失败时推送断开，面板显示原因。
- **控制台内容**：按 Tab 键另存（跨重启保留），防抖 500 毫秒写盘。关 Tab、移除项目或数据源时连同记住的界面状态与控制台上下文一并删掉（`deleteDataSourceTabState`）；删过的键在主进程里记下，之后晚到的写入一律不收，不会留下没人用的记录。
- **记住上次打开的**：
  - 每个 Tab 记住的界面状态（`DataSourceTabUi`：停在哪一格、上次打开的对象或键、目录展开着的节点——节点键与它下一层的位置）按 Tab 键存在主进程（持久化键 `dataSourceTabUi`），随控制台内容一起删（见上）；连接信息被改时忘掉上次打开的对象与目录的展开，停在哪一格留着。只有登记的数据源的 Tab 记；Files 面板里直接打开的 SQLite 文件不记。
  - 连上后恢复：先读回记住的（本机读取，读到前正文留白），目录按记住的展开读各层（同展开：先显示缓存、同时现查），停在记住的那一格。上次的对象先核对还在：读它所在的那一层，列着它才显示（`catalogHasObject`），核对期间「当前对象」格为加载中；那一层读到了却没有它即空着，并从最近打开里去掉；读不出来（连不上、无权）也空着，但不去掉。Redis 用 `EXISTS` 核对键（`hasRedisKey`）；记下的库与连上后所在的库对不上时不恢复（安静地空着，不核对、不去掉）。恢复出来的不算一次打开，不再写回。键列表的展开不记。
  - SQL 数据库与 Redis 共用 `useDataSourceOpened`（`lib/data-source-opened`：停在哪一格、当前打开的、恢复时的核对与过期判断、最近打开的记与删），核对的方式与 Redis 的切库各自实现；「核对中为加载中」由 `DataSourceLayout` 显示。
- **最近打开**：
  - 按数据源存（持久化键 `dataSourceRecents`：数据源 id → 新到旧最多 10 个），同一个数据源的各个 Tab 共用：渲染端 `data-source-store` 持有各数据源的一份，改动经主进程去重、截断、落盘后交回（`pushRecentOpened` / `dropRecentOpened`，按 `openedKey` 认同一个：对象为它的节点键，分组、区分重载的说明都算；Redis 的键按库编号与键名）。Redis 的键连同所在的库记下（`DataSourceOpened` 的键为 `{ key, database? }`）：点一项时不在那个库，先切过去（切不过去弹错误框「无法切换库」）再核对、打开；库编号未知时记下的一项没有库编号，按所在的库打开，并先去掉旧的一项、再记成带库编号的，不会变成两项。在目录里点开对象、点最近打开的一项都算打开一次；点最近打开时同样先核对还在，还在就打开并在目录（键列表）里定位（见「定位」）。移除数据源、连接信息被改时删掉；数据源改了类型，另一类的旧记录不列。
  - 焦点（同 Files 的最近打开文件）：点一项、核对还在并打开后，焦点进「当前对象 / 当前键」的正文（表格、只读编辑器，或 Redis 字符串的原文）；正文还在读取时（只读编辑器要等编辑器建好），等它出现再聚焦，其间从树里打开别的、切到另一格或核对失败，这次聚焦即作废。⌘E 弹出的下拉被 Esc 关掉时，焦点回到当前显示那一格的正文（停在「控制台」时为控制台的编辑器），正文没挂上时不动。正文在 `DataSourceLayout` 给当前显示那一格的登记处登记（`lib/data-source-content-focus`），控制台的结果区、运行会话等别处不登记。
  - 下拉与 Files 的「最近打开文件」共用 `RecentMenu`（`ui/recent-menu`）：每项名称 + 淡色的位置（`openedLocation`：「库.模式」，没有的省掉；Redis 的键为完整键名 + 所在的库，如 `db1`，库编号未知时记下的没有位置）。⌘E：当前条目为数据源时，切到它当前激活的 Data Source Tab（激活的是运行会话时切到常驻的那个）并弹出，预选第一个不是当前那一项的；只认下拉挂载（连上）之后按的，没连上时按的不补。
- **接口命名**：渲染端与主进程的会话接口统一写作「动词 + DataSource + 名词」（`runDataSourceConsole`、`readDataSourceTablePage` 等）；只属于 Redis 的写作「动词 + Redis + 名词」（`scanRedisKeys`、`hasRedisKey` 等），Files 里直接打开的 SQLite 文件写作「动词 + SqliteFile + 名词」（`openSqliteFileSession`、`closeSqliteFileSession` 等）；会话状态为未连接 / 连接中 / 已连接 / 已断开（`disconnected`，带原因与是否密码被拒）。生命周期同服务器的状态连接：连接信息被改即 reset，被移除即 dispose，退出时 disposeAll。意外断开的原因经 `dataSourceFailureMessage` 转成中文（网络错误为「无法连接到 地址：原因」；`mysql2` 在服务器关掉连接——如被 `KILL`——时报的 `PROTOCOL_CONNECTION_LOST` 先于连接的 `end` 到达，为「连接被服务器关闭」，执行中被打断的那条语句同样）。

## Testing Decisions

沿用项目约定：只测纯函数，零 mock。

- 连接串解析：各种类型、缺省端口、加密参数、`rediss://`、URL 编码过的密码。
- 加密：`isTlsUnsupported` 认出「服务器不支持加密」的两种回答，证书错误、连接重置不算，每种驱动只认自己的回答。
- 出错的说明（`dataSourceFailureMessage`）：网络错误写明连不上哪里、服务器关掉了连接（`PROTOCOL_CONNECTION_LOST`）、SQLite 的常见错误给中文，其余照原话。
- 与 **Server** 共用的连接规则（`shared/connection`）：记住密码的保存值与测试值（`passwordChangesOf`）、端口的解析与校验（`portOfText` / `portError`）、直连能力的平台判断。
- 编辑前后连接信息是否变了：`dataSourceConnectionChanged`、`serverConnectionChanged`。
- 连上后的默认库（`defaultDatabaseOf`：PostgreSQL 为连上后所在的库，MySQL / MariaDB 为填的、没填为空，SQLite 与 Redis 为空）。
- Redis 库编号的校验（`redisDatabaseError`）。
- 三类条目的排序（按同一条自定义序混排）、Pin、名称筛选、按类型筛选；连接子菜单的顺序（只列一类时同样按左树的排序与置顶，不受类型筛选影响）。
- Data Source Tab 壳的合并与落盘；另开 Tab 的键与默认名（`newDataSourceTabKey`、`nextTerminalName`）。
- Data Source 条目的 Tab 序（`orderedTabKeysOf`：常驻 → 另开的 → 运行会话，另开的组内顺序照旧）；默认激活仍是第一个运行中的会话，没有时为常驻 Tab；关闭后按新顺序回落左邻。
- 焦点在树上打字转进树顶输入（`typeToInputEdit`）。
- 各数据库目录查询结果整理成目录节点；层键与节点键互逆（`catalogLayerKey`）；按模式归组（`groupBySchema`）；批量读取整理成分组各层与对象各层（`catalogBulkGroupLayers`、`catalogBulkObjectLayers`，与逐个模式读取的结果一致）；分组在哪一批读（`catalogBulkGroupBatch`）、某层由批量读取里哪次读取的哪一批读出（`catalogBulkBatchOf`：含扩展、角色、用户，各库的层归它所在的库，根下的角色、用户归第一次读取，SQLite 都归那一次，根不在其中；各批整理出的层都在那一批里）；各次读取读哪些库（`catalogBulkReads`：PostgreSQL 一个库一次、连接所在的库显示时在前，MySQL / MariaDB 一次读完显示的库，没有显示的库不读，SQLite 读一次）；显示的库（`catalogShownDatabases`：设置过的照记下的、一个都不勾也算，从没设置过为默认库、没有默认库时为空）；根这一层列出的库与其中还列着的（`catalogDatabases`、`catalogListedDatabases`：先后不变，同名的分组不算）；根下只留显示的库（`catalogShownRoot`：分组照留，读不出来的原样）；一层在不在显示的库里（`catalogPathShown`：根与根下的分组都算，没有显示的库时都算）；拍平时读取中的提示行带标记。
- 目录按名称筛选（`filterCatalog`：已读取的层与缓存里的层一起找、同一层以已读取的为准、上一层没列出的节点下的缓存不算、给出筛过的各层的位置）；筛选视图的开合（`filterViewExpanded`：没开合过时筛过的层展开、开合过的以开合为准、缓存重取后新筛出的层照样展开；`collapseFilterView`：当前各层连同开合过的都合上，之后新筛出的照样展开）。
- 定位：从根到对象要展开的各层（`catalogRevealLayers`：PostgreSQL 为库、模式、分组，MySQL 没有模式，SQLite 只有分组；按它展开后目录里出现目标对象）；键的各级文件夹（`redisKeyFolders`：键名本身不算，按它展开后键列表里出现这个键）。
- 改结构语句的识别；结束事务语句的识别（`isTransactionEnd`：COMMIT / END 的各种写法，含两阶段提交、跳过开头的注释；ROLLBACK 的各种写法与 ABORT；回滚到保存点、释放保存点不算）；切出光标所在的语句、选中的多条语句与整段的全部语句（`allStatements`：字符串与注释里的分号、最后一条没有分号、只有注释、PostgreSQL 的 `$$` 函数体与 `BEGIN ATOMIC`、MySQL / MariaDB 的反斜杠转义与建过程 / 函数 / 触发器 / 事件的 BEGIN … END 块、SQLite 的触发器、开事务的 BEGIN 与 CASE 表达式照常切；`DELIMITER`：换上的分隔符切开各条、命令本身不发出、mysqldump 的 `;;`、同一行里的其余照常切、过程体里 `END;` 与下一行的 `IF` 不连成 `END IF`、`REPEAT` 块不切开、字符串里的分隔符不切、首尾与单独的分号不算、不是命令的照常发出、PostgreSQL 与 SQLite 不认、选中的部分从分号切起、光标所在的那条；MySQL / MariaDB 的注释：`--` 之后是空白或已到末尾才是注释、可执行注释连同注释整条发出、只有它的一条也算、里面照常切、结尾照 mysql 客户端（字符串、带引号的名字与注释里的 `*/` 不算）、mysqldump 写在里面的触发器与事件、`/*M!` 只在 MariaDB 上算、光标在它里面取这一条）；切词适配层另测这两种注释（`--` 的各种写法、可执行注释的开头与结尾另记、结尾跳过字符串、带引号的名字与注释、没有结尾时读到末尾、`/*M!` 与其余方言）；MySQL / MariaDB 的 CodeMirror 方言开了反斜杠转义（`codemirrorDialect`）。
- 补全引擎（ADR-0047）：pgcli、mycli、litecli 的补全测试翻译成 vitest，当作验收标准（上下文判断、表 / 别名 / CTE 的提取、匹配与排序；与原测试的差别逐条写在用例旁）；另测切词适配层（期望值由 sqlparse 对同样的文字切出；按位置纠正非保留字）、子查询作用域（照 sqls 的测试）、按子句过滤关键字（照 Tabularis 的规则）、补全源（光标所在的语句、注释与字符串里不补、WHERE / ORDER BY 框的前缀、按使用次数排）；使用次数（取出的次数读回后一样、读回的加到已有的上、按给出的类型计数、表结构换了重建的补全器沿用同一个计数器、MySQL 的关键字补成小写时同样按次数排）。
- 补全数据：整理成补全引擎要的形状（`buildCompletionSchema`：按模式归组、没有对象的模式也列、列带类型与默认值、布尔值两种写法都认、函数与类型与存储过程归到各自的模式、外键缺项的不要；`pgFunctionOf`；`mysqlRoutinesOf`：函数的参数按行合起来、过程只要名字；`mysqlShowItemsOf`：去掉第一个词、只有一个词的留它自己、空的不要；`sqliteForeignKeysOf`：没写父表列的取父表主键的对应列、补不上的不要）；新连接上的查找次序（`pgDefaultSearchPath`：`"$user"` 换成登录的用户、没写 `pg_catalog` 时补在最前、写了按写的位置、去重）；控制台的查找次序（`consoleSearchPath`：PostgreSQL 为 `pg_catalog`、`current_schema()` 与其余各项，MySQL / MariaDB 为控制台所在的库，Redis 为空）。
- 控制台上下文：数据源类型对应的类别（`consoleContextKind`）、要记住的部分（`savedConsoleContext`：MySQL 没选库不记）、点的是不是现在那一项（`isCurrentConsoleContext`）、切换要变的各级（`consoleContextChangeLevels`：同库切模式只有模式，跨库切模式库与模式都变，不带模式只有库）、切不过去时没切过去的那一级（`consoleContextFailureLevel`：出错在改 search_path 那一步为模式，在那之前为要变的第一级）、目录里一行在控制台中打开要切到的（`catalogConsoleContextChange`：PostgreSQL 模式及其下的行换库与模式，库及库下不属于模式的行只换库；MySQL 库及其下的行换库；根行与根下的角色、用户不换）；search_path 拆成各项（`searchPathItems`：引号里的逗号不切）与各项的模式名（`searchPathItemName`：带引号的去引号并还原 `""`，不带的折成小写）、选中的模式放到最前（`prependSearchPath`：原来就有的挪到最前不重复、模式名里的双引号加倍、原来为空）；执行后要不要回查（`changesConsoleContext`：PostgreSQL 改 search_path、换角色、改结构、结束事务的语句算，含注释开头、大小写不同，别的 SET 与查询不算；MySQL / MariaDB 为 USE 与删库；SQLite 一律不算。`recheckRedisDatabase`：执行成功的 SELECT、RESET、EXEC、DISCARD 算，出错的 SELECT 不算、出错的 EXEC 算，排队的 SELECT 不算，执行完还在事务里时不回查（接着执行前的事务状态算，与 `redisInTransactionAfter` 同一套规则））；推算库编号（`redisDatabaseAfter`：事务里排着的 SELECT 到 EXEC 执行了事务才算）；`CLIENT INFO`、`CONFIG GET databases`、`INFO keyspace` 的解析；下拉列出的库编号（`redisDatabaseIndexes`：0 到个数 − 1，补上有键的与当前所在的）。
- 格式化：认得运行配置的参数（`formatSql`：`${{…}}` 原样保留、各方言都认、方言自带的参数写法照旧、字符串里的 `${{…}}` 照旧是字符串、写错的语句抛出；`RUN_PARAM_SOURCE` 与认参数的规则一致）；JSON 排版（`formatJsonText`：2 个空格缩进、空对象与空数组不拆开；大整数、数字写法、转义与字符串里的标点原样；已排过版的按统一的缩进重排；较大的输入与 `jsonc-parser` 的 `applyEdits` 逐条应用的结果一致；不是对象或数组的为 null）。
- 翻页查询的拼装：WHERE / ORDER BY 原样拼接与之后的换行（末尾带行注释，各方言）、主键追加（多列主键顺序、ORDER BY 为空时只按主键、没有主键不追加、主键名里的引号加倍）、页码与每页行数；点表头的排序文字、从文字认出表头排序、点表头后的下一个状态。
- 控制台结果：一条语句的结果说明（`statementOutcomeText`）、一次执行的摘要（`consoleRunSummary`）、结果区显示什么（`consoleRunResult`：无错、出错、已取消）。
- 格子里显示的文字：NULL、二进制、长文本。
- 导出：CSV（BOM、转义）、JSON（数字、布尔、NULL、大整数）、SQL INSERT（各方言的标识符、字符串与二进制写法，生成列不写而 CSV、JSON 照写；MySQL / MariaDB 按版本认生成列的条件；写了总是自动生成的标识列时加 `OVERRIDING SYSTEM VALUE`，没有或没写它时不加）；选区复制成 TSV 时的转义；默认文件名（普通表名、路径分隔符、Windows 不能用的字符与控制字符、处理后为空、保留设备名及其大小写 / 上标 / 扩展名，不是保留名的不动）。
- SQLite 文件按文件头识别。
- Redis：一行命令拆成参数（引号与转义；`\xHH` 拼出的不是 UTF-8 时为字节，是 UTF-8 时为文字）、切行（CRLF、空行、首尾空白）、摘要、回复按 redis-cli 显示（状态回复原样、字符串加引号、分数是字符串、嵌套数组、数组里的错误带 `(error)`；按原样输出的几条分行显示，`redisRawOutput` 的清单与参数个数）、控制台不执行的命令（`redisConsoleRefusal`：含 `HELLO 3`，`HELLO` 与 `HELLO 2` 照常）、键按 `:` 分组成树与按展开状态拍平、剩余过期时间的说明；`SCAN` 的回复（`parseRedisScanReply`：事务里的 `QUEUED`、项数不对、键不是字符串为格式不对）；执行完是否还在事务里（`redisInTransactionAfter`：成功的 `MULTI` 开始，`EXEC`、`DISCARD`、`RESET` 结束，不分大小写，跨几次执行接着算）；命令表（`parseRedisCommandDocs`、`parseRedisCommandTable`：大写、去重、排序，取不到为空）与补命令名的位置（`redisCommandWordBefore`：光标在行首的第一个词里，在参数里不补）。
- 运行配置的参数：见 `docs/prd/run-config-params.md`「Testing Decisions」。
- 记住与最近打开：认同一个对象或键（`openedKey`：分组不同、重载说明不同都算两个；键按库编号与键名；对象与键不会撞上）、放到最前与去重截断（`pushRecentOpened`）、去掉（`dropRecentOpened`）、位置文字（`openedLocation`：对象为「库.模式」，键为所在的库，库编号未知时记下的为空）；对象在不在它那一层里（`catalogHasObject`：同名而说明不同、同名的库不算）；Redis 键在键列表里的名字（`redisKeyName`，与键树一致）。
- 运行配置：运行的连接目标（`dataSourceRunTarget`：SQLite 原样、库为空时原样、各类型覆盖库）、成功判定（全部成功、中途出错、已取消、停在中途、什么都没执行、整个没能执行）；配置的归属键与会话键；首屏保留上次选中的数据源配置；启动时清理引用型配置时保留服务器上与数据源上的配置。

实测清单（都待实测）：

- 云数据库的加密连接，包括靠 SNI 区分实例的服务；服务器不支持加密时改用不加密连接。
- 开着 TUN 代理时直连数据库（macOS + mihomo；Windows）。
- 大表翻页和总行数计算的速度；上百列宽表的滚动流畅度（用正式构建测）。
- 程序正在写 SQLite 文件时，DevCube 同时读、写，双方都不报 `database is locked`，或者等待后正常报出。
- `better-sqlite3` 在 macOS / Windows 上按 Electron 重新编译。
- 表结构缓存：连上后展开主体结构的各层不再等待；别处改了结构后，下次显示即更新；刷新后没展开的层也更新；编辑连接信息、移除数据源后缓存删掉。第一次连上某个数据源就按名称筛选，两批读完后表、函数、角色等没展开过的对象自己出现在结果里，读完前没有匹配显示「正在读取…」、读完仍没有才显示「无匹配对象」；筛选视图里手动开合过之后，后到的命中层照样展开；刷新时展开着函数等分组，表与视图先换上，筛选时新建的表同样先出现（「表」之前展开过又收起也一样）；Files 面板里直接打开的 SQLite 文件同样能筛出没展开过的层。显示的库：PostgreSQL 没填默认库时只列连上后所在的库，MySQL / MariaDB 没填时一个都不列、提示去勾选；勾上一个库后筛选能找到它里面没展开过的对象，同一个数据源的另一个 Tab 也跟着列出它、找得到，重连、重启后照旧；取消勾选后目录、筛选与控制台的「库」都不再列它，展开着的层收起；刷新时展开着其他库里的层，等读到它那个库才换上，控制台与表数据不受影响；库被删掉后从名单里去掉；改了连接信息后回到默认；「在目录中显示」没显示的库里的对象时先勾上它，点最近打开里没显示的库里的对象照常打开、目录不动。
- 运行配置：各类型运行、停止、重跑；没记住密码时在页内输入；大结果集；停止时服务器上的语句确实被叫停（PostgreSQL、MySQL）；有参数时的参数框（预填上次的值、取消什么都不变、等密码时交上密码不再弹）。
- PostgreSQL 控制台里 `begin; create table …; commit;`：提交后目录与补全自动出现新表；`rollback to savepoint` 之后事务照常开着。
- SQLite 控制台里 `begin; insert …; create table t(a);`：自动重读后事务仍开着（再执行 `commit` 照常提交，insert 与新表都在）；事务开着时手动刷新目录同样不回滚。
- 记住与最近打开：重启后连上回到上次的对象、格子与展开，对象被删后安静地空着；两个同库 Tab 的「最近打开」一致；⌘E 在数据源条目弹出最近打开、在项目里仍是 Files 的最近打开文件。
- 控制台上下文：PostgreSQL 从「库」换库、从「模式」换模式后执行不写前缀的查询，两个列表的筛选与键盘操作（打字后回车选中第一个匹配项，↑↓、回车，Esc 只收起列表），列表开着时点「执行」只收起列表，切换中只有被切的钮转圈；控制台里 `set search_path`、`set role`、`create schema` 之后下拉跟上；事务里 `set local search_path` 后提交、回滚；控制台在别的库上时取消执行；重启后连上回到记住的库与 search_path，库被删后回到默认库；MySQL 的 `use`、`drop database`；Redis 下拉切库、控制台里 `select 1` 与 `multi` / `select 1` / `exec`，Redis 6.2 以前的版本（没有 `CLIENT INFO`），禁用了 `CONFIG` 的托管 Redis；目录右键「在控制台中打开」（四种 SQL 数据库的各类行与根行，从「当前对象」一格和停在控制台时点，焦点都进编辑器；执行中置灰；刚连上还不知道控制台在哪个库上时，库里的行置灰、根行照常；PostgreSQL 右键别的库里的模式时「库」「模式」都转圈；切不过去的错误框，其中跨库切模式时连不上那个库与设不了 search_path 的标题不同）。
- 运行配置对话框：「库」的选项；补全（有缓存、借连着的 Tab 现查、都没有只补关键字、内置函数与类型；PostgreSQL 不写模式前缀时按新连接默认的 search_path，控制台里 `set search_path` 之后不受影响）；格式化带 `${{…}}` 的 SQL。
- 补全：控制台、运行配置对话框与 WHERE / ORDER BY 框里的各种位置（FROM、JOIN 与 ON 条件、别名、CTE、子查询、函数、类型，MySQL 的枚举值），四种 SQL 数据库各试一遍；MySQL / MariaDB 在 `CHARACTER SET`、`COLLATE`、`SHOW` 之后与补用户名的位置（含无权读 `mysql` 库的账号）；执行过的语句里用得多的名字与关键字排前（MySQL / MariaDB / SQLite 小写输入时同样），重启后仍在；PostgreSQL 打开别的库里的表时 WHERE / ORDER BY 框补那个库的列，打开别的库里的函数、序列时不读那个库的补全；控制台里改了表结构后 WHERE / ORDER BY 框马上补出新列；控制台里内容很长、刚打开就补全时不卡；上千张表、上万个列时补全的速度。
- Redis：命令名补全（Redis 7 与更早的版本）；`MULTI` 之后用下拉切库、刷新键列表、看键、点最近打开；最近打开里别的库的键；切库后「当前键」清空；重启后所在的库对得上才回到上次的键。
- Redis 字符串是几百 KB 以上的 JSON 时，打开与排版不卡。
- 退出时正在执行的语句被叫停（PostgreSQL、MySQL），网络不好时退出不超过约 2 秒。
- MySQL、PostgreSQL 查询途中断网时，控制台与导出以出错结束。
- 带生成列的表导出为 SQL INSERT 后导回同结构的表（四种 SQL 数据库）；PostgreSQL 带 `GENERATED ALWAYS AS IDENTITY` 列的表同样；带全文检索虚拟表的 SQLite 库，目录与补全里没有影子表；带未注册模块虚拟表（如 zipfile、SpatiaLite）的 SQLite 库，目录与其余表的补全照常；MySQL / MariaDB 的控制台与运行配置里用 `DELIMITER` 建过程、函数与触发器；mysqldump、mariadb-dump（`--routines --triggers --events`）的输出在控制台与运行配置里整段执行。

- 已知的边界情况：
  - 表结构缓存与控制台上下文这两处取舍带来的边界情况（批量读取只看得到已提交的结构、几个 Tab 各读一次主体结构、显示的库越多后台读完越久、缓存没有淘汰、筛选视图里取自缓存的层不核对；只按第一个关键字认改上下文的语句、回滚到保存点不回查、事务中途重连时重设的 search_path），见 ADR-0045、ADR-0046 的 Consequences。
  - SQLite（登记的数据源与 Files 面板里直接打开的文件）同理，批量读取在临时连接上，只看得到已提交的结构；但事务里的改动若已写满、拿到了排他锁，临时连接要等锁（最多 5 秒）读不出来，这时目录照常在 Tab 的连接上重读，反而看得到没提交的结构。
  - MySQL 的 `information_schema` 在大小写不敏感的排序规则下，两个只差大小写的库名，逐层读会混在一起、批量读按名字精确归组，两者可能不一致。
  - 点的正好是主键列时，排序里会出现 `"id" DESC, "id"` 这样的重复项，三种数据库都接受，结果不受影响。
  - SQLite 取消、停止、断开时，一步就要算很久的语句（count、聚合、不出行的递归 CTE）在旧线程里仍会算完这一步才停，其间占着 CPU（写入语句还占着写锁、照样提交）；界面上当场已取消、Tab 换了新线程照常可用。真正立刻中断以后再补，见 `docs/backlog.md`。
  - 过程体里的 `REPEAT … END REPEAT` 照 sqlparse 不认，按分号切时会在块里的分号处切开；用 `DELIMITER` 换了分隔符就不受影响。
