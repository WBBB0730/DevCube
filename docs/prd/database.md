# database

**数据源**

## Problem Statement

我写代码时经常要看数据库里的数据、跑几条查询。现在用 WebStorm 的数据库插件，毛病有这几样：慢；重；东西太多，数据源设置有一堆页签，会话、事务模式这些概念一股脑摆在面前；改了表结构以后，目录和补全跟不上；开着 TUN 模式代理时绕不开代理。我连的库以云数据库为主，偶尔有本地的和服务器上的（服务器上的库也开放端口），也有几个项目共用的。我想在 DevCube 里轻量地看表、写查询。项目、服务器都能把常用命令存成配置、一点就跑，数据库这边常跑的几段语句却只能每次在控制台里找出来再执行。

## Solution

把数据库连接登记为 **Data Source**，和 **Project**、**Server** 并列在左树里。一个库通常只登记一份，几个项目共用；也允许登记多份，提交前确认一次（ADR-0043）。支持 PostgreSQL、MySQL、MariaDB、SQLite、Redis。

- **Data Source Tab**：点开一个 Data Source，就是它的 Data Source Tab。右侧是目录；左侧在「当前对象」和「控制台」两格间切换。点目录里的表，在「当前对象」里看数据；切到「控制台」写查询、看结果。两格各自保留内容，点表不会冲掉查询结果。Tab 里不再分小 Tab；要同时看两张表，就再开一个同库的 Tab，另开的一打开就连接。
- **在项目里打开**：**Project** 的 Tab 栏「+」可以把任意 Data Source 开成一个 Data Source Tab，和 Terminal、Run Session 挨着，Tab 随项目保存。项目里开着哪些库，看 Tab 就知道，不另建绑定关系。
- **首版只做「看 + 查询」**：改数据、改表结构都在控制台里写语句。
- **目录不过时，也不用等**：目录、对象定义与补全用的表名列名存成表结构缓存，显示时先用缓存、同时现查核对，读到了原地替换；连上后在后台分两批读完目录里的对象，先是表和视图，再是其余对象的名字（ADR-0045）。PostgreSQL、MySQL / MariaDB 的库多时，目录只列勾选显示的库，后台也只读它们。
- **回到上次的地方**：每个 Tab 记住上次打开的对象、停在哪一格和目录的展开，连上即回到那里；顶栏「最近打开」列出这个数据源最近打开的对象，⌘E 直接弹出。
- **选在哪个库上执行**：控制台工具栏上的「库」选控制台在哪个库上执行（PostgreSQL 另有「模式」），也可以在目录里右键「在控制台中打开」，一步换到那一行所在的库和模式；Redis 在键列表顶栏选库编号；在控制台里写 `use`、`set search_path`、`SELECT n` 切过去，它们同样跟着变。每个 Tab 各自记住（ADR-0046）。
- **按上下文补全**：控制台、运行配置对话框与 WHERE / ORDER BY 框共用一个补全引擎，按光标所在的子句补表、列、别名、函数和关键字，JOIN 时按外键补出连接条件，这个数据源上用得多的排前；做法照抄 pgcli（ADR-0047）。Redis 控制台补全命令名。
- **筛选、排序与分页**：表和视图顶上有 WHERE、ORDER BY 两个框，点表头排序也写进 ORDER BY 框；表格用分页器翻页，每页行数可以设置；表和查询结果都能导出为 CSV、JSON 或 SQL INSERT 语句。
- **运行配置**：在 Data Source 上存几段常跑的 SQL（Redis 为几行命令），像项目、服务器上的配置一样一点就跑，结果显示在它的 Tab 栏里的运行会话里（ADR-0044）；内容里可以留 `${{名称}}` 参数，每次运行前填值（同项目、服务器上的配置，见 `docs/prd/run-config-params.md`）。
- **连得上**：加密自动处理，不用选；开着 TUN 代理时可以绕开代理直连。
- **SQLite 文件**：**Files Tab** 里点开 SQLite 文件，正文区直接就是同一套视图。
- **Redis**：同一种布局，右侧是按 `:` 分组的键，左侧是「当前键」和控制台。
- **操作结果不在界面上留文字**：进行中显示在按钮本身（转圈并置灰），成功不提示，失败弹错误框（测试连接例外：按钮旁另显示「连接成功」或「连接失败」）；可疑但允许的操作（如重复登记）提交前确认一次。

## User Stories

**登记与连接**

1. 作为用户，我想添加一个 **Data Source**：选类型（PostgreSQL / MySQL / MariaDB / SQLite / Redis），填名称（可选，默认由地址派生）、地址、端口（按类型给默认值）、用户名、密码、默认库（可选）；SQLite 改为选一个本机文件。
2. 作为用户，我想把 `postgres://…`、`mysql://…`、`redis://…`、`rediss://…` 这样的连接串粘贴进来，自动拆成类型、地址、端口、用户名、密码和库名，以便不用逐项抄写。
3. 作为用户，我不想操心加密：PostgreSQL、MySQL、MariaDB 能加密就加密，服务器明确回答不支持时才不加密，和它们官方客户端的默认行为一样，表单里没有这一项。
4. 作为用户，当我粘贴的连接串里写了加密要求（如 `sslmode=verify-full`）时，我想按它的要求连接，并在表单里看到这条要求、可以清除。
5. 作为 Redis 用户，我知道 Redis 的协议不能协商加密，所以只有 Redis 的表单里有「TLS 加密」勾选；粘贴 `rediss://` 开头的连接串时自动勾上。
6. 作为用户，我想在添加、编辑时「测试连接」，失败时看到数据库给出的原因；网络不通时不至于一直等下去。
7. 作为用户，我想添加时就能选择记住密码；没记住的，连接时在 Tab 里直接输入，并选择是否记住。库要密码而我没给，和我给的密码被拒，我想看到不同的提示，好知道该做什么。
8. 作为开着 TUN 模式代理的用户，我想给 Data Source 打开「绕开代理直连」，规则同 **Server**（ADR-0039）：仅 macOS / Windows，添加时默认不勾。
9. 作为用户，我想编辑 Data Source：只改名或只改密码时，已连上的 Tab 不断开；改了连接信息时，连到的可能已是另一个库，所以已连上的 Tab 断开，和原来那个库有关的记忆（显示的库、最近打开、上次打开的对象、目录的展开、控制台所在的库）一并忘掉，停在哪一格、控制台里写的内容留着。
10. 作为用户，我想移除 Data Source；移除时，所有连到它的 Tab 一并关闭（包括开在项目里的），它的运行配置、记住的密码、表结构缓存一并删除。
11. 作为用户，同一个库我通常只登记一份；真要再登记一份（添加时，或编辑成与已登记的相同时），我想在提交时被确认一次（「“X” 连接的是同一个库。仍要添加吗？」），确认了就照样登记，而不是被悄悄合并或不让保存。

**左树**

12. 作为用户，我想 Data Source 和 Project、Server 排在同一个左树里，图标不同；置顶、排序、拖拽、名称筛选的规则一致；排序菜单的类型勾选多一项「数据源」，至少保留一项勾选。
13. 作为用户，我想左树里的 Data Source 行和 Server 行一样有折叠箭头、配置区、「更多」菜单和相同的右键菜单（新建标签页 / 新建配置 / 编辑 / 置顶 / 移除数据源）。

**Tab**

14. 作为用户，点开一个 Data Source 时，我想看到它常驻的 Data Source Tab（不可关闭）；需要时再开几个同库的 Tab（可以关闭），以便同时看两张表，或开两份查询。
15. 作为用户，我想从 **Project** 的 Tab 栏「+」或项目右键菜单的「连接到数据源 ▸」，在项目里开一个 Data Source Tab，和 Terminal、Run Session 并列，行为和 Data Source 下的完全一致。
16. 作为用户，另开的 Data Source Tab 我想一打开就连接（同新开 SSH Terminal），不用再点一次「连接」；常驻的 Tab 与跨重启恢复的 Tab 点「连接」才连，以便启动时不会一下子连一堆库、弹一堆提问。
17. 作为用户，我想 Data Source Tab 跨重启保留名称、顺序和控制台里写的内容。
18. 作为用户，连接断开后，我想 Tab 保留并显示断开的原因，点一下就能重连。

**目录**

19. 作为用户，我想在 Tab 右侧看到目录：先列出这个 Data Source 上的库（系统库与系统模式不列），展开后按对象类型分组，只列有对象的分组并显示个数。PostgreSQL、MySQL / MariaDB 的服务器上常有很多库，我只想列出要用的那几个，在目录根行勾选，同一个数据源的各个 Tab 一样。
20. 作为用户，连上时和展开某一层时，我想有读过的结构就立即显示，不再等「正在读取…」，同时在后台核对，读到了原地替换，以便看到的既快又是当前结构。
21. 作为用户，我想连上后 DevCube 在后台把显示的库读完，之后展开都不用等，界面上不因此多出任何提示。
22. 作为用户，我想目录顶上有刷新按钮：刷新期间旧树照常显示、展开状态不变，读完原地替换；没展开的层也跟着更新。
23. 作为用户，我在控制台执行建表、改表、删表这类改结构的语句，或者提交、回滚事务后，想让目录与补全自动重读，这样 PostgreSQL 事务里建的表提交后就能在目录里看到。
24. 作为用户，遇到账号没有权限读取的内容，我想看到「无权查看」，而不是报错。
25. 作为用户，我想在目录顶上按名称筛选，没展开过的层也能找到，又不为筛选另查数据库；命中项连同各级祖先显示，清空筛选后回到筛选前的展开。我还想一键全部折叠；焦点在目录上时直接打字就进筛选框。
26. 作为用户，我想在目录的对象行上右键「复制名称」。

各数据库的目录里有这些对象：

| 数据库          | 对象                                                                                 |
| --------------- | ------------------------------------------------------------------------------------ |
| PostgreSQL      | 模式、表、视图、物化视图、函数与存储过程、触发器、序列、自定义类型、扩展、角色与权限 |
| MySQL / MariaDB | 表、视图、存储过程、函数、触发器、事件、用户与权限                                   |
| SQLite          | 表、视图、索引、触发器                                                               |
| Redis           | 见 Further Notes                                                                     |

**当前对象**

27. 作为用户，点目录里的表或视图时，我想在「当前对象」里分页看它的数据，用顶上的 WHERE、ORDER BY 两个框筛选和排序，框里同控制台一样按方言高亮、补全这张表的列。
28. 作为用户，我想点表头排序：点一下升序、再点降序、第三下取消，生成的排序写进 ORDER BY 框，我可以接着手改。
29. 作为用户，点函数、存储过程、触发器这类对象时，我想在「当前对象」里看到它的定义（只读，语法高亮，可以 ⌘F 查找）；点角色或用户时，看到它的权限。
30. 作为用户，我想点另一个对象时只替换「当前对象」这一格，控制台不受影响。
31. 作为用户，看着一个对象时我想点「在目录中显示」，目录展开到它并滚到它那一行。

**表格**（「当前对象」、控制台结果与运行会话结果共用）

32. 作为用户，我想在表格里拖选一片格子、按住 Shift 扩展、按 Cmd/Ctrl+A 全选，复制后能直接贴进 Excel。
33. 作为用户，我想拖动列宽；列多时，滚动照样流畅。
34. 作为用户，我想 NULL 和空字符串分得清；JSON、二进制、大整数、小数、时间按数据库给的原样显示，不被转换失真。
35. 作为用户，我想在任何表格里按 ⌘F 查找当前这一页（或取回的这些行）。

**分页**

36. 作为用户，我想在表格底部用分页器翻页：上一页、下一页、页码、跳到某页。
37. 作为用户，我想设置每页行数，记住我上次的选择，所有 Tab 共用。
38. 作为用户，翻表时我想每一页都是现查的，带着当前的 WHERE 和 ORDER BY，翻页稳定、不重不漏；总行数在后台计算，计算期间照样能翻页。
39. 作为用户，我明白控制台的结果执行时一次取回，最多 1 万行，在本地翻页；超过时看到「只取回了前 10000 行」。翻页不会重新执行语句。

**控制台**

40. 作为用户，我想在控制台里写查询：按数据库方言高亮，也能格式化；补全按光标所在的位置给出表、列（认别名、CTE 与子查询，旁边写着类型）、函数、类型和这个子句里用得上的关键字，JOIN 时补出有外键关联的表连同 ON 条件；我在这个数据源上用得多的名字和关键字排前。
41. 作为用户，我想按 ⌘Enter 执行光标所在的那条语句，或执行选中的部分；选中了多条时依次执行。MySQL / MariaDB 里我想同 mysql 客户端一样用 `DELIMITER` 换分隔符，照搬来的建存储过程、触发器的脚本不用改；mysqldump、mariadb-dump 导出的脚本也能整段执行。
42. 作为用户，我想在编辑器下方看到结果：查询语句显示结果表格；其他语句显示影响的行数；出错时显示数据库给的原话。执行了多条时，表格显示最后一个结果。再次执行时，上次的结果留着，新结果到了才替换。
43. 作为用户，我想取消正在执行的查询；叫停失败时告诉我原因。
44. 作为用户，我想控制台里写的内容跨重启保留；结果不保留，重启后要重新执行。
45. 作为用户，我想改数据、改表结构时，直接在控制台里写语句执行。
46. 作为用户，退出 DevCube 时，我不想服务器上还跑着我刚发出的语句：还在执行的先叫停再断开，但不因为网络不好拖住退出。

**导出**

47. 作为用户，我想把「当前对象」的整张表导出为 CSV、JSON 或 SQL INSERT 语句，带着当前的 WHERE 和 ORDER BY，不只是当前页；导出的 SQL INSERT 语句能直接导回同结构的表。
48. 作为用户，我想把控制台、运行会话已取回的结果导出为同样的格式；不会为了导出重新执行语句。
49. 作为用户，我想用 Excel 打开导出的 CSV 时中文不乱码；导出的 JSON 里数字还是数字，大整数也不失精度。
50. 作为用户，导出时我想先选保存位置（默认在「下载」目录、文件名为表名）；写好了不打扰我，失败时告诉我原因。

**运行配置**

51. 作为用户，我想在数据源菜单里「新建配置」：起名、选在哪个库上执行、写内容（SQL 为一段语句，Redis 为一行一条命令）；写 SQL 时同控制台一样补全、格式化；可以编辑、删除、拖拽排序，同服务器上的配置。
52. 作为用户，我想在左树的配置行上点 ▶ 运行，在这个数据源的 Tab 栏开一个运行会话 Tab；运行中可以重跑、停止（叫停正在执行的语句），有状态点，⌘W 为停止并关闭。
53. 作为用户，我想在内容里写 `${{名称}}` 这样的参数，运行、重跑前填值，同项目、服务器上的配置。
54. 作为用户，我想运行的结果与控制台一样：全部语句依次执行、遇错即停，最后一个结果集分页显示，可以导出；Redis 按 redis-cli 的样子显示；整个没能执行时写明原因。
55. 作为用户，没记住密码或密码被拒时，我想在运行会话里直接输入密码（可以勾选记住），交上去即重跑，不再问一遍参数。
56. 作为用户，编辑数据源的连接信息时，我不想打断正在运行的配置，下次运行再用新的连接信息；移除数据源时它的配置一并删除；数据源改了类型，配置照旧保留，按当前类型执行。
57. 作为用户，重启后配置还在，运行会话不恢复；有运行中的配置时退出要确认，退出时先叫停它正在执行的语句。

**Redis**

58. 作为用户，我想用同一种 Data Source Tab 看 Redis：右侧列出键，按 `:` 分组成可以展开的树，文件夹后面跟着它下面有多少个键；键太多时只列出前 1 万个，并告诉我只列出了一部分。
59. 作为用户，我想按模式筛选键（写法同 Redis 的 `MATCH`，如 `user:*`），回车生效，筛选在服务器上做，不用先把所有键取回来；焦点在键列表上时直接打字就进筛选框。
60. 作为用户，我想点一个键就在「当前键」里看到它的类型、剩余过期时间和值：字符串显示原文，是对象或数组的 JSON 时自动排版；哈希、列表、集合、有序集合、流显示成表，最多 1000 项，超出时告诉我只显示了一部分；其他类型告诉我不支持查看。
61. 作为用户，看着一个键时我想点「在键列表中显示」，键列表展开到它并滚到它那一行。
62. 作为用户，我想在控制台里一行写一条 Redis 命令（写法同 redis-cli），⌘Enter 执行光标所在的那行或选中的各行，回复按 redis-cli 的样子显示；控制台里写的内容跨重启保留。执行 `SELECT n` 后，键列表跟着换到那个库（见第 79 条）。在行首输入时，我想补全命令名。
63. 作为用户，我想在键行上右键「复制键名」，在文件夹行上右键「复制前缀」。

**SQLite**

64. 作为用户，我想在 **Project** 的 **Files Tab** 或 **Preview Window** 里点开一个 SQLite 文件时，正文区直接就是 Data Source Tab 的那套视图（目录、当前对象、控制台），不用先登记成 Data Source。
65. 作为用户，我理解在 Files Tab 里打开的 SQLite 文件不是 Data Source：它不出现在左树里；切到别的文件，控制台里的内容不保留；文件被别的程序改写后，数据不自动刷新，要手动刷新。
66. 作为用户，我的程序正在用这个 SQLite 文件时，我不想因为在 DevCube 里看数据，就让程序写不进去。
67. 作为用户，我在控制台写入时如果我的程序也正在写，我想 DevCube 等一会儿；实在等不到，就提示「数据库正被其他程序占用，请稍后重试」。
68. 作为用户，文件被删除或被整个替换后（比如程序重建了数据库），我想刷新时重新打开文件，文件不存在了就显示原因；但控制台里开着事务时不重开，免得没提交的改动被悄悄回滚。

SQLite 类型的 Data Source 同样适用第 66–68 条。

**记住上次打开的与最近打开**

69. 作为用户，我想每个 Data Source Tab 记住上次打开的对象、停在「当前对象」还是「控制台」，以及目录展开到了哪里，跨重启保留；Tab 仍不自动连接，连上后回到上次的对象与展开。上次的对象已经不在了，「当前对象」就安静地空着。
70. 作为 Redis 用户，我想 Tab 同样记住上次打开的键（连同它所在的库）和停在哪一格；重启后连上时所在的库不是那个库，就不恢复这个键。
71. 作为用户，我想在内容区顶栏的「最近打开」里看到这个数据源最近打开的 10 个对象（Redis 为键），同一个数据源的各个 Tab 共用；点一下就打开它，目录（Redis 为键列表）也定位到它；点的对象已经不在了，就安静地空着，并从列表里去掉。
72. 作为用户，当前条目是数据源时，我想按 ⌘E 弹出它的「最近打开」；在项目里照旧是 Files 的最近打开文件。

**控制台在哪个库上执行**

73. 作为用户，我想在控制台工具栏右端选控制台在哪个库上执行，钮上写着服务器上的当前值。PostgreSQL 另有「模式」，不写前缀的表就落在它上面；要换到别的库的某个模式，先换库、再换模式。MySQL / MariaDB 只有「库」，SQLite 没有。
74. 作为用户，我在控制台里自己写 `use`、`set search_path`、`set role` 这类语句，或者建、删了模式或库之后，想让下拉跟着变成服务器上实际的样子，而不是停在我上次选的那一项。

## Implementation Decisions

- **进程分工**：驱动和连接都在主进程；渲染端只拿到整理好的目录节点，和一页一页的结果行。
- **驱动**：
  - PostgreSQL 用 `pg`，控制台结果用 `pg-cursor` 取。只在读够上限时关游标；读完或出错后不关，连接断开时关游标会一直等下去。
  - MySQL / MariaDB 用 `mysql2` 的回调接口（控制台要按事件逐行收）；`CALL` 返回几个结果集时取最后一个。事件式的查询收不到网络错误，所以查询与导出期间另听连接的断开，断了即以出错结束，不会一直等下去。
  - SQLite 用 `better-sqlite3`，加载包里自带的各平台 N-API 预编译文件：pnpm `allowBuilds` 里设为不构建（装依赖时那次编译是给 Node 的，在 Windows 上还会因找不到编译器失败），按 Electron 准备原生模块照旧由 `install-app-deps` 负责。它的接口是同步的，所以一个数据库文件由一个 worker 线程持有、查询都在线程里执行，免得大查询卡住主进程。不用 Electron 自带的 `node:sqlite`：在 Node 22 上还是实验功能。
  - Redis 用 node-redis 的基础客户端包 `@redis/client`。不用元包 `redis`：它另带四个用不上的模块，会打进 app.asar（ADR-0036）。不用 `ioredis`：它的文档写明新项目推荐 node-redis。协议用 RESP2（redis-cli 的默认）：小数是字符串、不与整数混同，`HGETALL` 这类映射按服务器次序返回、不解码成 JS 对象（那样会丢 `__proto__` 字段、把数字字段提前）。
  - 每个连接都挂上 `error` 监听（驱动的要求），临时连接也一样。
- **原样显示**：结果一律取数据库给的文字，不经过 JS 的类型转换（SQLite 的整数也按字符串取）；二进制转成十六进制、与文字分开标记，表格显示为长度加开头部分。
- **加密**：PostgreSQL / MySQL / MariaDB 默认「能加密就加密、不校验证书」（libpq 的 `sslmode=prefer`、MySQL 的 `PREFERRED`）。`pg` 和 `mysql2` 都没有这一档，所以先按加密去连，只在服务器明确回答不支持时改用不加密重连；其他加密错误照常报出，不退回明文。连接串里的 `sslmode`（MySQL / MariaDB 为 `ssl-mode`，映射到同一套）记在 Data Source 上，按 libpq 的语义执行，其余参数不认。Redis 在 `rediss://` 或勾选了 TLS 时加密，不做协商。
- **直连**（ADR-0039）：与 SSH 的连接共用 `resolveDirectRoute`：开了直连就现查实体网卡地址和真实地址，自建绑定本机地址的 TCP 连接交给驱动。加密握手时 SNI 和证书校验仍用原来的主机名，因为有些云数据库靠 SNI 区分实例。找不到实体网卡、或查不到真实地址时直接报出原因，不退回经代理连接。
- **时限**：建连超时 15 秒（与 SSH 没设 `ConnectTimeout` 时共用一个常量）；测试连接整次最多 2 分钟，超时报「连接超时」。
- **连接串**：四种类型统一用 WHATWG `URL` 解析成字段。不引 `pg-connection-string`：它解析时遇到证书参数还会去读本机文件。
- **重复登记**（ADR-0043）：「同一个库」只按连接目标判断（`sameDataSourceTarget`）——类型、地址（不分大小写）、端口、用户名、默认库，SQLite 为文件路径；主进程的添加总是新增，确认框（`DuplicateTargetConfirm`）由渲染端在提交时弹，与 Server 共用；编辑时只有目标改成与别人相同才问。
- **编辑与移除**：连接信息（连接目标、加密要求或 TLS、是否直连）变了，各个 Tab 断开（运行会话的连接除外）、表结构缓存删掉，要忘掉的都在 `forgetDataSourcePlaces` 一处；只换了密码时不断开，之后另开的连接用新密码。**Server** 同理：只改名、改密码时不断开状态与文件连接，也不问未保存的服务器文件。移除时，连到它的各个 Tab（含开在项目里的）的控制台内容与工作台现场也一并删掉。
- **左树**：条目键是 `datasource:<id>`，和 `server:` 用同一种前缀约定；排序、Pin、拖拽、名称筛选沿用项目的那一套。数据源行的配置区只有命令型，没有「检测到的配置」。
- **连接子菜单**：「连接到数据源 ▸」和「连接到服务器 ▸」都按左树的顺序（含置顶分区）列出，不受左树按类型筛选的影响。
- **密码**：
  - 记住的密码和 Server 的存法一样：单独存，用 safeStorage 加密，不下发渲染端。不像 **Server** 那样弹窗提问，直接在未连接页出密码框（可以留空），连上后按勾选记住或忘掉，左树随之更新。未连接页（`DataSourceConnectForm`）由 Data Source Tab 与运行会话共用。
  - 没给密码而库要求密码时，页面写「X 要求输入密码」；给了密码（填的或记住的）被拒时，密码框上方红字「密码被拒绝」。主进程分不出这两种，由页面记上一次提交给没给密码；自动发起的连接（新开 Tab、运行配置）按是否记住推断。
  - 「记住密码」添加时默认不勾，连接时的勾选同 SSH 提问弹窗（`rememberPasswordDefault`）。系统没有可用的钥匙串时不出「记住密码」，对话框里的密码框置灰并说明原因（同服务器对话框），所以对话框里测不了要密码的连接。
- **Tab 与工作台**：
  - 另开的 Data Source Tab 和 Terminal、SSH Terminal 同属终端组：同一份壳列表、同样按条目持久化（ADR-0008）、拖拽排序、编号与改名。
  - Data Source 条目的 Tab 栏：常驻的在最前，其后是另开的，运行会话排在最后（只有 Data Source 条目如此）；⌘1–9、循环切换、关闭后回落左邻都按这个顺序。默认名：在数据源条目下另开的从「prod (2)」起（常驻的算第 1 个），开在项目里的从「prod」起；数据源改名时默认名跟着改、序号保留。
  - 五个新开入口（条目「+」、⌘T、右键「新建标签页」、项目右键与项目 Tab 栏「+」的「连接到数据源 ▸」）走同一个动作，建好即连接；常驻 Tab、跨重启恢复的 Tab、添加数据源后只选中它，都不自动连接。连接状态还没从主进程取到时页面留白，免得先闪一下未连接页。
  - 移除数据源后，原来激活的 Tab 所在的栏回落到左邻，其次右邻。移除项目时，开在里面的 Data Source Tab 的连接一并关掉、控制台内容一并删除。
- **连接数**：
  - 一个 Data Source Tab 一条连接，目录读取和查询排队共用；PostgreSQL 每个展开过的库另连一条并缓存，控制台切到别的库时在那条上执行。
  - 数总行数、导出、叫停语句与后台读主体结构，各另开一条临时连接，用完即关；数据源上的配置每次运行另开一条。PostgreSQL 上执行语句的连接都取后端进程号，以便叫停。
  - 关连接不等在途的语句；断开、关 Tab、重连时，还在执行的语句先叫停再关。MySQL 的 `destroy()` 只是半关，在途的结果仍会收完，要服务器停下必须先发 `KILL QUERY`。
  - 退出时先叫停所有还在执行的语句（含运行会话、导出）再关，最多等 2 秒。
- **目录**：
  - PostgreSQL 读 `pg_catalog`，MySQL / MariaDB 读 `information_schema`，SQLite 读 `sqlite_schema` 和 `PRAGMA`，在主进程整理成统一的节点。SQLite 不列 `sqlite_` 开头的系统对象和虚拟表（如 FTS5）的影子表（同 Datasette），补全也不算。
  - 连上读根，展开一层读一层，每次都重读；读到前先显示缓存，都没有时显示「正在读取…」，这一行等 120 毫秒才出现，读得快时不闪。
  - 批量读取主体结构（ADR-0045）的查询与逐层读取同源，整理出的各层与逐层读取的结果一致。MySQL / MariaDB 的用户读不出来（多半无权读 `mysql.user`）即不写这一层。读完之前展开照旧逐层现查。Files 面板里直接打开的 SQLite 文件同样读。
  - 显示的库（ADR-0045）：根行右端「N / M 个库」，点开是能打字筛选的多选列表，勾上或取消立即生效；MySQL / MariaDB 一个都没显示时，根下先出一行「勾选要显示的库」。根下的角色、用户不是库，照列。没显示的库里展开着的层收起、不读，再勾上时从收起开始。勾上新库时，这个数据源连着的各个 Tab 都读它（不读补全）。一次读取读不出来（连不上、已删掉）就接着读下一次。
  - 刷新（手动，或控制台执行了改结构、结束事务的语句后）：SQLite 重开文件（开着事务时不重开，见「结束事务语句的识别」），重跑批量读取（ADR-0045），再重读根与所有展开着的层，读到即原地替换；根换上时，这次不重读的收起着的层即丢掉，下次展开时现读。
  - 按名称筛选：在已读取的层与表结构缓存里的层里找（同一层以已读取的为准），只从显示的库往下，不另查数据库。库、模式、对象名称不分大小写包含即命中，连同各级祖先显示，命中的库或模式下拿到的层整支纳入；分组标签不算。缓存取到之前或批量读取还在进行时，没有匹配显示「正在读取…」，读完仍没有才显示「无匹配对象」（同 Files 冷索引）。筛选视图的开合只记用户的显式操作，没开合过的层默认展开，筛选词一变即清空这些开合；清空筛选即回到筛选前的展开（同 Files 的树顶过滤）。
  - 表与视图以外的对象：能取到建它的语句的显示定义，其余（序列、类型、扩展、角色、用户的权限）显示信息表。MySQL 的存储过程与函数不是它的定义者来看时，要有 `SHOW_ROUTINE`（8.0.20 起）或全局 `SELECT` 权限；没有时服务器不报错、只把定义返回为 NULL，按无权处理，显示「无权查看」。
  - 右键「在控制台中打开」：PostgreSQL 的模式行及其下的行换到那个库与模式，库行及库下不属于某个模式的行（扩展）只换库；MySQL / MariaDB 的库行及其下的行换库；根行、角色与用户，以及 SQLite，只切到控制台。切换与工具栏共用 `useContextSwitch`（见「控制台上下文」）。控制台正在执行或正在切换时这一项置灰，悬停说明「控制台正在执行」/「控制台正在切换」；刚连上、还不知道控制台上下文时，要换库、模式的行也置灰，悬停说明「正在确定控制台所在的库」。
- **定位**：「在目录中显示」「在键列表中显示」同 Files「在文件树中显示」，只在停在「当前对象 / 当前键」那一格时显示；点「最近打开」的一项、核对还在并打开后同样走这一套。被筛选挡住时先清掉筛选（键列表为清掉模式、重新列出）。对象所在的库没显示时，「在目录中显示」先把它勾上；点最近打开时不替用户勾上，照常打开，目录不动。
- **表结构缓存**（ADR-0045）：每个数据源一个 JSON 文件，放在 `<userData>/data-source-schemas/<id>.json`，写盘防抖 1 秒。Files 面板里直接打开的 SQLite 文件只放在会话内存里；运行会话不用。
- **补全**（ADR-0047）：
  - 照 pgcli / mycli / litecli 读表结构的查询来读：PostgreSQL 读一个库，MySQL / MariaDB 读全部非系统库，SQLite 读这个文件。SQLite 改取 `pragma_table_xinfo`（生成列也列出），逐个表或视图读：取不到列的（未注册模块的虚拟表，如 zipfile、SpatiaLite；引用了没有的函数或已删掉的表的视图）只列名字，免得一张表让整份读取失败。
  - 控制台与表数据的 WHERE / ORDER BY 框共用一份，重读了两处一起换；控制台上下文还没得知时只补关键字、内置函数与类型。现查失败时保留缓存。
  - 别的库里的表（PostgreSQL）：打开的表、视图、物化视图不在控制台所在的库上时，WHERE / ORDER BY 框另读那个库的一份（在它的按库连接上，翻页也用这条）。同一个库里换着打开表不重读；例外：按「表 → 别的对象 → 表」的顺序打开时，回到表时重读一次。
- **补全引擎**（ADR-0047）：
  - PostgreSQL 另补 pgcli 补全关键字表漏掉的常用关键字（如 `ILIKE`、`OFFSET`、`RETURNING`），只在 `EXPLAIN`、`VACUUM` 等语句里用的（如 `VERBOSE`、`ANALYSE`）不补。
  - 只取光标所在的那条语句；注释与字符串里不补（MySQL / MariaDB 的字符串里补枚举值，PostgreSQL 的 `$$` 函数体里照常补）；有输入的词、句点之后或按补全快捷键时才补。语法树还没解析完时（刚载入很长的文字）最多再解析 50 毫秒，仍没解析完这次不补。
  - 关键字 PostgreSQL 补成大写，MySQL / MariaDB / SQLite 随输入的大小写；列名只在语句里有多张表时带上表名或别名，FROM 里不自动加别名。
  - 使用次数：登记的 SQL 数据源各一个计数器（`useCompletionUsage`），控制台、WHERE / ORDER BY 框与运行配置对话框共用；第一次用到时读回，计数先等读回，免得存回时盖掉存下的。移除数据源时删掉，改连接信息、改类型不删；Files 面板里直接打开的 SQLite 文件没有计数器。
- **改结构语句的识别**：去掉开头的注释后，按第一个关键字判断：CREATE、ALTER、DROP、RENAME、TRUNCATE、COMMENT、GRANT、REVOKE。
- **结束事务语句的识别**：执行后同样重读目录与补全——事务里改的结构提交了，在临时连接上重读才看得到；回滚了，已在 Tab 连接上读到的也要撤掉。只认 COMMIT、END、ROLLBACK 与 PostgreSQL 的 ABORT（含 PREPARED、AND [NO] CHAIN 与带 WORK、TRANSACTION 的写法）；回滚到保存点、释放保存点不算。两种语句都只在执行成功时触发。SQLite 事务开着时重开文件会把它连同之前的改动悄悄回滚，所以刷新前先问查询线程是否开着事务，开着就不重开。
- **编辑与执行**：
  - 控制台、对象定义、运行配置对话框共用 `CodeEditor`，同 Files 编辑器（⌘F 查找栏与 Files 编辑器共用 `useEditorFind`）。对象定义用 CodeMirror 的 `readOnly`（能聚焦、查找、复制），不用 `editable={false}`。
  - 语句边界照 pgcli / mycli / litecli 执行前的切法（补全引擎照搬的 `sqlparse.split`，ADR-0047），不另外引入 SQL 解析库。只有空白、注释与分号的不算一条（MySQL 执行只有注释的语句会报错）。执行时把整段同步完整解析一遍，不用编辑器里可能还没解析完的语法树。光标落在两条语句之间时取上面那条，上面没有就取下面那条。
  - MySQL / MariaDB 的 `--` 注释与可执行注释照 mysql 客户端认（ADR-0047）：可执行注释连同注释原样发出，由服务器按版本号决定执行与否。字符串里反斜杠是转义符（lang-sql 自带的这两个方言没开 `backslashEscapes`，另定义一份开上）。`DELIMITER` 照 mycli 认，只在这次执行的文字里有效；PostgreSQL、SQLite 不认。
  - ⌘Enter 放在最高优先级的 keymap 里（默认 keymap 把它当插入空行）。
  - 格式化用 `sql-formatter`，控制台与运行配置对话框共用 `formatSqlInEditor`；运行配置的参数 `${{…}}` 原样保留，认参数的正则与运行参数同源（`RUN_PARAM_SOURCE`）。失败时弹错误框「无法格式化」。
- **控制台上下文**（ADR-0046）：
  - 切换：PostgreSQL 切库改用会话里的按库连接，Tab 的连接不动；选模式用 `set_config('search_path', …, false)` 把它放到最前（原有各项原样跟在后面，去掉同名的那一项），值作参数交给服务器，不拼进语句。MySQL / MariaDB 发 `USE`，Redis 发 `SELECT`。切不过去（库连不上、库编号超出范围、无权，Redis 的控制台开着事务）时弹错误框，上下文不变。
  - 下拉：钮上是服务器上的当前值，为空时写灰色的「未选择库」「未选择模式」。「库」只列显示的库（控制台在没显示的库上时，钮上照常是它的名字；一个都没显示时写「没有显示的库」）；「模式」列控制台所在库的模式，打开时读，现查读不出来时留着缓存。Redis 的库编号下拉打开时读 `CONFIG GET databases`（托管的 Redis 常禁用 `CONFIG`，取不到按 16）与 `INFO keyspace`，列 0 到个数 − 1，另补上有键的与当前所在的，有键的库后面淡色写着键数。
  - 执行后回查（只看执行成功的）：PostgreSQL 为改 search_path 的（含 `SET SCHEMA`、`RESET ALL`、`DISCARD ALL`）、换角色的（默认的 search_path 里有 `"$user"`）、所有改结构的与结束事务的；MySQL / MariaDB 为 `USE` 与 `DROP DATABASE` / `DROP SCHEMA`。Redis 按回复认：执行成功的 `SELECT`，以及 `RESET`、`EXEC`、`DISCARD`（出错的也算）；回复 `QUEUED` 的 `SELECT` 不算；执行完连接仍在 `MULTI` 里时不回查（回查的命令也会排进事务）。
  - 记住：PostgreSQL 记库与整个 search_path，MySQL / MariaDB 记库（没选库时不记），Redis 记库编号；关 Tab、移除项目或数据源时随控制台内容一起删；数据源改过类型、对不上的不用。控制台执行、补全与 Redis 的各种读取都先等连上后设回记住的，得知上下文之前不出下拉、不列键。
  - 执行与切换互斥：SQL 与 Redis 同一套；切换中只有要变的钮转圈（目录右键跨库切模式时「库」「模式」都转）。各处切换都经 `switchConsoleContext`，下拉与目录右键另共用 `useContextSwitch`。错误框的标题按没切过去的那一级：改 search_path 那一步出错为「无法切换模式」，之前为要变的第一级（跨库切模式时连那个库失败为「无法切换库」）；正文为原因，无权为「无权切换」。
- **分页**：原则是不长时间占着数据库：开着的游标会挡住别人改表结构，SQLite 下还会挡住写入。
  - 表：每页一条 `LIMIT` / `OFFSET` 查询，WHERE 与 ORDER BY 框里的文字原样拼进去、之后先换行，所以末尾可以写 `--` 行注释（MySQL 也可以写 `#`）。框是单行的 CodeMirror：回车提交，Esc 清空并把焦点交给下面的表格。有主键时总把主键列排在 ORDER BY 最后，翻页才稳定。点表头的排序写进 ORDER BY 框并立即生效、回到第一页，不叠加；生效的 ORDER BY 文字是排序唯一的状态，恰好等于某列点表头的结果时才显示箭头。总行数另开一条连接执行 `COUNT(*)`，只带 WHERE；换表、改 WHERE 或关闭 Tab 时叫停。
  - 控制台结果：读到 10001 行为止，多读的一行只用来判断有没有超过 1 万行；MySQL 超过的行不再留存，语句仍读到底（中途结束要另开连接 `KILL QUERY`）。在渲染端本地翻页。
  - 每页行数：记在全局设置里，1–10000，默认 500；常用值 100 / 200 / 500 / 1000。
- **表格**（ADR-0042）：「当前对象」、控制台与运行会话的结果共用一个表格。⌘F 查找与 Files 表格预览共用 `useSheetFind`：按格子显示的文字包含匹配，换了那份行（翻页、改排序、刷新）即从头找；只在焦点位于这张表格或它的查找栏时响应。
- **导出**：
  - 先弹系统保存对话框（默认在「下载」目录），选好了才写文件。默认文件名为表名：不能当文件名的字符与控制字符换成 `_`，为空时用 `result`，Windows 的保留设备名（CON、NUL、COM1 等）后面加 `_`。
  - 边读边写，不经过渲染端。表另开一条临时连接，按当前的 WHERE 与 ORDER BY 用一条查询读完，每批 1000 行。导出期间这张表一直在被读，SQLite 下别的程序的写入会等到导出结束，或者等到它自己的超时。控制台、运行会话用已经取回的行。
  - 写文件期间导出钮本身转圈并置灰，写好了不提示，失败弹错误框「导出失败」（无权时为「无权查看」）。
  - CSV 和复制时的 TSV 都用 Papa Parse 生成，转义按电子表格的规则；主进程要用它，所以按 ADR-0036 放在 `dependencies`。CSV 开头写 UTF-8 BOM，Excel 靠它才认出中文。
  - JSON：一个数组，每行一个对象；数字列把数据库给的文字原样写成 JSON 数字，布尔写成布尔，NULL 写成 `null`，其余写成字符串。
  - SQL INSERT：按方言引用标识符和字符串（MySQL 的反斜杠也写两遍），二进制写成方言的十六进制写法；控制台、运行会话的结果表名写成 `result`。整表导出时不写生成列（插入时不能给值，写了就导不回同结构的表），CSV、JSON 照写。MySQL / MariaDB 认生成列看 `generation_expression`，不看 `extra`（用表达式作默认值的列也标 `DEFAULT_GENERATED`）；这一列 MySQL 5.7.6、MariaDB 10.2.5 起才有，更早的 MariaDB 看 `extra`。PostgreSQL 的表有 `GENERATED ALWAYS AS IDENTITY` 列时加 `OVERRIDING SYSTEM VALUE`（同 pg_dump 的 `--inserts`），照原来的值导回。
- **取消**：PostgreSQL 另开一条连接执行 `pg_cancel_backend(<pid>)`，pid 为执行这条语句的那条连接的（控制台在别的库上时为那个库的按库连接）；MySQL / MariaDB 另开一条连接执行 `KILL QUERY <线程 id>`；SQLite 结束查询线程、重新打开文件，被打断的查询当场以已取消收口，不等旧线程真正结束；Redis 控制台不提供取消（命令通常很快，阻塞命令如 `BLPOP key 0` 断开重连即可，被打断的那条记为「已取消」）。叫停后语句照常返回的（MySQL 的 `SLEEP()` 被打断时照常返回 1）同样记为已取消，后面的语句不再执行。叫停失败时弹错误框「无法取消执行」（无权时为「无权取消」）。
- **运行配置**（ADR-0044）：
  - 对话框与命令配置共用外壳（`ConfigDialogFrame`）。「库」可输入也可选，选项为表结构缓存里的库（不访问数据库，连过这个数据源才有），占位只写默认值；Redis 的库编号要是非负整数。不加「模式」：要在别的模式上执行，在内容里写 `set search_path`。
  - 对话框里的补全按「数据源 + 库」取、不依赖 Tab：先取表结构缓存，没有时借一个连着的 Data Source Tab 现查并写回，都没有就只补关键字、内置函数与类型。库留空即数据源的默认库（连接信息里没写时，取连着的 Tab 连上时服务器给的那个）。PostgreSQL 只在库留空、是默认库或是选项里的库时才取，输入到一半的库名不去连；不写模式前缀的表按新连接默认的 search_path 补全。
  - 参数的写法、参数框与记住的值同项目、服务器上的配置（见 `docs/prd/run-config-params.md`），写在内容里哪里都算（包括字符串与注释）。不认 `${名称}`、`?` 与 `:名称`：三处一种写法（ADR-0048），也免得与 PostgreSQL 的 `::` 类型转换冲突、普通语句误弹参数框。先换后切：填的值按文字原样换进内容，再切语句，所以填的值里有分号、换行时照样按换好的内容切。等密码时交上密码的重跑沿用填过的参数；只有其间配置里新加了没填过的参数才再弹，这时取消即以「已取消」结束。
  - 连接的库按配置覆盖（PostgreSQL 直接连到那个库，MySQL / MariaDB 作默认库，Redis 作库编号）。不写表结构缓存、不读主体结构。
  - 执行同控制台（每条最多 1 万行），不自动包事务。全部执行完、没有出错、没被停止时为「已退出」（绿点，退出代码 0），其余为「失败」。整个没能执行的原因：数据源已移除、没有要执行的语句、库编号不合法、连接失败的原因、已取消、无权执行。
  - 正文是控制台同款的结果区（`ConsoleResultView`），操作栏不出「清空」与摘要。
- **Redis**：
  - 列键用 `SCAN … MATCH … COUNT 1000`（不用会阻塞服务器的 `KEYS`），读够 1 万个即停；回复格式不对时报错，不当作已列完。换了库即重新列出，「当前键」清空。
  - 哈希、集合用 `HSCAN` / `SSCAN`，与列表、有序集合、流一样取到 1000 项为止；流的每条字段写成一个 JSON 对象。键列表和键的值都不自动刷新，点「刷新」重读。
  - 字符串是对象或数组的 JSON 时，用 `jsonc-parser` 的 `format` 只改 token 之间的空白，不经 `JSON.parse` 再序列化，所以大整数不失精度、数字与转义的写法不变。它给出的修改一次拼好，不用 `applyEdits`：每条修改都重拼整段，几百 KB 就卡几秒。`jsonc-parser` 按 ADR-0036 放在 `devDependencies`。
  - 控制台的一行按 redis-cli 的规则拆成参数，依次执行、遇错即停；回复照 redis-cli 的 RESP2 输出显示。
  - 不执行的命令：`SUBSCRIBE`、`PSUBSCRIBE`、`SSUBSCRIBE`、`MONITOR`、`SYNC`、`PSYNC` 让连接只收推送、不再一问一答（同 RedisInsight），`HELLO 3` 把协议切到 RESP3；这条连接与键列表、看键共用，之后的回复就对不上了，所以控制台报出原因、不发给服务器。`HELLO`、`HELLO 2` 照常执行。
  - `RESET` 把连接退回未认证的 default 用户：执行成功后照连接时的账号重新 `AUTH`，这条共用的连接照常可用。
  - 事务：键列表、看键、库编号下拉、命令表都与控制台共用 Tab 的那条连接。控制台开着事务时（`MULTI` 之后、`EXEC` / `DISCARD` / `RESET` 之前，跨几次执行接着算），只发控制台执行的命令，其余交回「事务还没结束（先 EXEC 或 DISCARD）」：刷新键列表、看键、打开库编号下拉都显示这句原因；下拉切库、点「最近打开」里别的库的键弹错误框「无法切换库」；点「最近打开」里同一个库的键，「当前键」空着，这一项留在列表里。
  - 命令名补全（不走补全引擎）：连上后取一次命令表（`COMMAND DOCS`，Redis 7 以前用 `COMMAND`），补成大写，交给 CodeMirror 自己筛选；还没输入时只在按补全快捷键时列。不补键名。
- **SQLite 并发**：打开时设 `better-sqlite3` 的 `timeout` 为 5000 毫秒：写入遇到锁最多等 5 秒，还拿不到就报「数据库正被其他程序占用，请稍后重试」。表分页每页一条短查询，控制台读到上限就结束语句，都不长时间持有读锁。刷新时关掉再重新打开文件，文件被整个替换后也能读到新内容。查询线程意外退出时显示断开。
- **Files Tab**：按 `file-type` 识别出的 `application/x-sqlite3` 判断，不看扩展名；打不开时同其他预览出错，给出原因和「重试」。只在本机的 Files Tab 和 Preview Window 里生效。正文区嵌入同一个 Data Source Tab 组件，连一个不登记、不落盘的临时数据源（没有最近打开）；每个面板各自一条会话，页面关闭或重载时一并关掉。
- **控制台内容**：按 Tab 另存，防抖 500 毫秒写盘。关 Tab、移除项目或数据源时连同记住的界面状态与控制台上下文一并删掉（`deleteDataSourceTabState`）；删过的 Tab 之后晚到的写入一律不收。
- **记住上次打开的**：只有登记的数据源的 Tab 记；键列表的展开不记。上次的对象先核对还在：读它所在的那一层，列着它才显示，核对期间「当前对象」格为加载中；那一层读到了却没有它即空着，并从最近打开里去掉；读不出来（连不上、无权）也空着，但不去掉。Redis 用 `EXISTS` 核对键。恢复出来的不算一次打开。SQL 数据库与 Redis 共用 `useDataSourceOpened`，只有核对的方式与 Redis 的切库各自实现。
- **最近打开**：按数据源存，新到旧最多 10 个。同一个对象按它在目录里的节点认（分组、区分重载的说明不同都算两个），Redis 的键按库编号与键名认。移除数据源、连接信息被改时删掉；数据源改了类型，另一类的旧记录不列。Redis 的键点开时不在那个库，先切过去；库编号未知时记下的一项，点一次就换成带库编号的，不会变成两项。下拉与 Files 的「最近打开文件」共用 `RecentMenu`，焦点规则也同 Files；⌘E 只认连上之后按的，没连上时按的不补。
- **接口命名**：渲染端与主进程的会话接口写作「动词 + DataSource + 名词」（如 `runDataSourceConsole`）；只属于 Redis 的写作「动词 + Redis + 名词」（如 `scanRedisKeys`），Files 里直接打开的 SQLite 文件写作「动词 + SqliteFile + 名词」（如 `openSqliteFileSession`）。意外断开的原因转成中文：网络错误为「无法连接到 地址：原因」，服务器关掉连接（如被 `KILL`）为「连接被服务器关闭」。

## Testing Decisions

沿用项目约定：只测纯函数，零 mock。

- 连接：连接串解析；认出「服务器不支持加密」的回答；出错说明转成中文；与 **Server** 共用的连接规则（记住密码、端口校验、直连的平台判断）；连接信息变没变；连上后的默认库；Redis 库编号的校验。
- 左树与 Tab：三类条目混排的排序、Pin、筛选与连接子菜单的顺序；Data Source Tab 壳的落盘、另开 Tab 的键与默认名；Data Source 条目的 Tab 序、默认激活与关闭后回落；焦点在树上打字转进树顶输入。
- 目录：查询结果整理成节点；批量读取整理出的各层与逐层读取一致、各层归哪一批、各次读取读哪些库；显示的库；按名称筛选与筛选视图的开合；定位要展开的各层。
- 语句：改结构与结束事务语句的识别；切出光标所在的、选中的与整段的语句（含 BEGIN … END 块、`DELIMITER`、MySQL / MariaDB 的注释与反斜杠转义）。
- 补全引擎（ADR-0047）：pgcli、mycli、litecli 的补全测试翻译成 vitest，当作验收标准；另测切词适配层（期望值由 sqlparse 切出）、子查询作用域（照 sqls 的测试）、按子句过滤关键字、补全源与使用次数。补全数据：查询结果整理成补全引擎要的形状；不写前缀时的查找次序。
- 控制台上下文：要记住的部分、切换要变的各级与没切过去的那一级、目录一行要切到的；search_path 的拆分与放到最前；执行后要不要回查（SQL 与 Redis）；Redis 各条信息命令的解析与下拉列出的库编号。
- 格式化：认得运行配置的参数；JSON 排版（大整数与写法原样，与 `applyEdits` 逐条应用的结果一致）。
- 表数据与导出：翻页查询的拼装与点表头的排序；控制台结果的说明与摘要；格子里显示的文字；CSV、JSON、SQL INSERT（含生成列与标识列）、复制成 TSV 与默认文件名。
- SQLite 文件按文件头识别。
- Redis：拆参数、切行、按 redis-cli 显示回复、不执行的命令、键分组成树、剩余过期时间的说明、`SCAN` 回复的格式、是否还在事务里、命令表与补命令名的位置。
- 记住与最近打开：认同一个对象或键、去重截断、位置文字；对象在不在它那一层里；Redis 键在键列表里的名字。
- 运行配置：连接目标、成功判定、归属键与会话键；首屏保留上次选中的数据源配置；启动时清理引用型配置时保留服务器上与数据源上的配置。参数见 `docs/prd/run-config-params.md`「Testing Decisions」。

不写 UI / e2e 测试。

- 程序正在写 SQLite 文件时，DevCube 同时读、写，双方都不报 `database is locked`，或者等待后正常报出。
- macOS / Windows 的安装包里，`better-sqlite3` 用自带的预编译文件正常打开 SQLite 文件。
- 表结构缓存：连上后展开主体结构的各层不再等待；别处改了结构后，下次显示即更新；刷新后没展开的层也更新；编辑连接信息、移除数据源后缓存删掉。第一次连上某个数据源就按名称筛选，两批读完后表、函数、角色等没展开过的对象自己出现在结果里，读完前没有匹配显示「正在读取…」、读完仍没有才显示「无匹配对象」；筛选视图里手动开合过之后，后到的命中层照样展开；刷新时展开着函数等分组，表与视图先换上，筛选时新建的表同样先出现（「表」之前展开过又收起也一样）；Files 面板里直接打开的 SQLite 文件同样能筛出没展开过的层。显示的库：PostgreSQL 没填默认库时只列连上后所在的库，MySQL / MariaDB 没填时一个都不列、提示去勾选；勾上一个库后筛选能找到它里面没展开过的对象，同一个数据源的另一个 Tab 也跟着列出它、找得到，重连、重启后照旧；取消勾选后目录、筛选与控制台的「库」都不再列它，展开着的层收起；刷新时展开着其他库里的层，等读到它那个库才换上，控制台与表数据不受影响；库被删掉后从名单里去掉；改了连接信息后回到默认；「在目录中显示」没显示的库里的对象时先勾上它，点最近打开里没显示的库里的对象照常打开、目录不动。
- 运行配置：各类型运行、停止、重跑；没记住密码时在页内输入；大结果集；停止时服务器上的语句确实被叫停（PostgreSQL、MySQL）；有参数时的参数框（预填上次的值、取消什么都不变、等密码时交上密码不再弹）。
- PostgreSQL 控制台里 `begin; create table …; commit;`：提交后目录与补全自动出现新表；`rollback to savepoint` 之后事务照常开着。
- SQLite 控制台里 `begin; insert …; create table t(a);`：自动重读后事务仍开着（再执行 `commit` 照常提交，insert 与新表都在）；事务开着时手动刷新目录同样不回滚。
- 记住与最近打开：重启后连上回到上次的对象、格子与展开，对象被删后安静地空着；两个同库 Tab 的「最近打开」一致；⌘E 在数据源条目弹出最近打开、在项目里仍是 Files 的最近打开文件。
- 控制台上下文：PostgreSQL 从「库」换库、从「模式」换模式后执行不写前缀的查询，两个列表的筛选与键盘操作（打字后回车选中第一个匹配项，↑↓、回车，Esc 只收起列表），列表开着时点「执行」只收起列表，切换中只有被切的钮转圈；控制台里 `set search_path`、`set role`、`create schema` 之后下拉跟上；事务里 `set local search_path` 后提交、回滚；控制台在别的库上时取消执行；重启后连上回到记住的库与 search_path，库被删后回到默认库；MySQL 的 `use`、`drop database`；Redis 下拉切库、控制台里 `select 1` 与 `multi` / `select 1` / `exec`，Redis 6.2 以前的版本（没有 `CLIENT INFO`），禁用了 `CONFIG` 的托管 Redis；目录右键「在控制台中打开」（四种 SQL 数据库的各类行与根行，从「当前对象」一格和停在控制台时点，焦点都进编辑器；执行中置灰；刚连上还不知道控制台在哪个库上时，库里的行置灰、根行照常；PostgreSQL 右键别的库里的模式时「库」「模式」都转圈；切不过去的错误框，其中跨库切模式时连不上那个库与设不了 search_path 的标题不同）。
- 运行配置对话框：「库」的选项；补全（有缓存、借连着的 Tab 现查、都没有只补关键字、内置函数与类型；PostgreSQL 不写模式前缀时按新连接默认的 search_path，控制台里 `set search_path` 之后不受影响）；格式化带 `${{…}}` 的 SQL。
- 补全：控制台、运行配置对话框与 WHERE / ORDER BY 框里的各种位置（FROM、JOIN 与 ON 条件、别名、CTE、子查询、函数、类型，MySQL 的枚举值），四种 SQL 数据库各试一遍；MySQL / MariaDB 在 `CHARACTER SET`、`COLLATE`、`SHOW` 之后与补用户名的位置（含无权读 `mysql` 库的账号）；执行过的语句里用得多的名字与关键字排前（MySQL / MariaDB / SQLite 小写输入时同样），重启后仍在；PostgreSQL 打开别的库里的表时 WHERE / ORDER BY 框补那个库的列，打开别的库里的函数、序列时不读那个库的补全；控制台里改了表结构后 WHERE / ORDER BY 框马上补出新列；控制台里内容很长、刚打开就补全时不卡；上千张表、上万个列时补全的速度。
- Redis：命令名补全（Redis 7 与更早的版本）；`MULTI` 之后用下拉切库、刷新键列表、看键、点最近打开；最近打开里别的库的键；切库后「当前键」清空；重启后所在的库对得上才回到上次的键。
- Redis 字符串是几百 KB 以上的 JSON 时，打开与排版不卡。
- 退出时正在执行的语句被叫停（PostgreSQL、MySQL），网络不好时退出不超过约 2 秒。
- MySQL、PostgreSQL 查询途中断网时，控制台与导出以出错结束。
- 带生成列的表导出为 SQL INSERT 后导回同结构的表（四种 SQL 数据库）；PostgreSQL 带 `GENERATED ALWAYS AS IDENTITY` 列的表同样；带全文检索虚拟表的 SQLite 库，目录与补全里没有影子表；带未注册模块虚拟表（如 zipfile、SpatiaLite）的 SQLite 库，目录与其余表的补全照常；MySQL / MariaDB 的控制台与运行配置里用 `DELIMITER` 建过程、函数与触发器；mysqldump、mariadb-dump（`--routines --triggers --events`）的输出在控制台与运行配置里整段执行。

## Out of Scope

- 自动发现连接；从项目里导入连接。
- 其他导出格式：Excel、TSV、JSON Lines、Markdown 等；导入数据。
- 查询历史、执行计划、ER 图、表结构对比、存储过程调试。
- 其他数据库：SQL Server、Oracle、MongoDB、ClickHouse 等。
- Data Source 分组；「连接到数据源 ▸」子菜单的筛选。
- 生产库只读保护、危险语句二次确认；运行配置运行前的二次确认。
- ORDER BY 的叠加排序（按住 Alt 点表头追加一列）；WHERE / ORDER BY 的输入历史。
- 运行配置：定时运行；从控制台存为配置；「模式」字段（要在别的模式上执行，在内容里写 `set search_path`）。
- 表格里 JSON 值的「查看值」面板（见 `docs/backlog.md`）。
- Redis 控制台补全键名。
- 补全里 mycli / litecli 独有、pgcli 没有的功能（见 ADR-0047）。
- 定位的其余入口：运行会话「在左树中显示」；项目里的 Data Source Tab 跳到左树里的数据源；控制台里按光标所在的表名定位到目录（见 `docs/backlog.md`）。
- 缓存表数据。
- 按表记住 WHERE / ORDER BY。
- 服务器 Files Tab 里的 SQLite 文件；把 SQLite 文件登记进系统的「打开方式」。
- Linux 上绕开代理（同 ADR-0039）。

## Further Notes

- 术语见 CONTEXT.md（**Data Source**、**Data Source Tab**、**Console Context**、**Run Configuration**、**Run Session**）；取舍见 ADR-0042（表格）、ADR-0043（独立条目与完整视图，允许重复登记）、ADR-0044（数据源上的配置的运行会话）、ADR-0045（表结构缓存）、ADR-0046（控制台上下文以服务器为准）、ADR-0047（补全照抄 pgcli）；直连复用 ADR-0039。
- Data Source 与 Server 之间没有关系。以后要做经由服务器连接时，让 Data Source 引用一台已登记的 Server，SSH 的地址、账号、记住的密码和直连开关都用它的。
- Redis 只做基本功能（第 58–63、79–80 条），细节用下来再定。
- Files Tab 里的 SQLite 文件用完整视图，这时屏幕右侧会有目录和文件树两棵树并排。用下来有问题，再改成参照 Excel 预览的精简视图：去掉目录，表名做成底部标签。
- 数据源条目下另开的 Data Source Tab 排在运行会话之前，有运行会话时「+」新开的 Tab 因此不在最末；用下来再看。
- 已知的边界情况：
  - 表结构缓存与控制台上下文这两处取舍带来的边界情况（批量读取只看得到已提交的结构、几个 Tab 各读一次主体结构、显示的库越多后台读完越久、缓存没有淘汰、筛选视图里取自缓存的层不核对；只按第一个关键字认改上下文的语句、回滚到保存点不回查、事务中途重连时重设的 search_path），见 ADR-0045、ADR-0046 的 Consequences。
  - SQLite（登记的数据源与 Files 面板里直接打开的文件）同理，批量读取在临时连接上，只看得到已提交的结构；但事务里的改动若已写满、拿到了排他锁，临时连接要等锁（最多 5 秒）读不出来，这时目录照常在 Tab 的连接上重读，反而看得到没提交的结构。
  - MySQL 的 `information_schema` 在大小写不敏感的排序规则下，两个只差大小写的库名，逐层读会混在一起、批量读按名字精确归组，两者可能不一致。
  - 点的正好是主键列时，排序里会出现 `"id" DESC, "id"` 这样的重复项，三种数据库都接受，结果不受影响。
  - SQLite 取消、停止、断开时，一步就要算很久的语句（count、聚合、不出行的递归 CTE）在旧线程里仍会算完这一步才停，其间占着 CPU（写入语句还占着写锁、照样提交）；界面上当场已取消、Tab 换了新线程照常可用。真正立刻中断以后再补，见 `docs/backlog.md`。
  - 过程体里的 `REPEAT … END REPEAT` 照 sqlparse 不认，按分号切时会在块里的分号处切开；用 `DELIMITER` 换了分隔符就不受影响。
