## Problem Statement

在 Finder / 资源管理器里双击一张图、一份 PDF、一段视频，打开的是系统自带或别的看图 / 阅读器。DevCube 的 **Files Tab** 明明已经把看图（缩放手感、超大图瓦片）、PDF（连续滚动、缩略图、查找）、音视频都做好了，却只能在「先把文件夹登记成 **Project**、再切到 Files Tab、再在树里找到文件」之后才用得上。我想把 DevCube 直接设成这些文件的默认打开方式，双击就用它看。

## Solution

1. **设置里一键设为默认打开方式**：设置「系统集成」新增「文件打开方式」一行（与既有入口行同级），其下挂「图片 / PDF / PPT / 音频 / 视频」五个类型子项各自设为默认。安装后 DevCube 就出现在系统「打开方式」列表里；macOS 上按钮一键设为默认（应用自带一个小助手完成），Windows 上按钮注册为候选并打开系统「默认应用」页由用户点选（系统不允许程序自己改默认），Linux 用 `xdg-mime` 设默认。
2. **双击文件 = 一个 Preview Window（预览窗口）**：DevCube 被系统带着一个**文件**路径拉起时，为该文件开一个独立窗口——一文件一窗、可多开、不进项目列表、关掉不留痕。窗口内容就是 Files Tab 本身（左正文 + 右文件树 + 工具栏，文本可编辑、图片 / SVG / PDF / PPT / 音视频内嵌预览、SVG 与 Markdown 的编辑 ↔ 预览切换），只做一张明确的差异清单：没有 Git Tab、Terminal、运行会话、内容搜索，根可上翻，多一颗「添加为项目」。
3. **树的根 = 文件所在文件夹**，树空白区右键「上一级文件夹」可逐级上翻、目录右键「进入此文件夹」可再收回；文件恰好落在某个已登记 Project 内时，根直接取该项目根。
4. **树顶栏专属控件**：预览窗口的树顶栏（筛选框那一行）并入按类型（图片 / PDF / PPT / 音视频 / 文本 / 其他）多选筛选，不另起一行。主窗口 Files Tab 没有。
5. **添加为项目**：窗口顶栏设置钮旁（树空白区右键菜单里另有一份）一键把当前树根登记为 **Project** 并在主窗口里选中（语义同 **External Open**：未登记则登记，已登记则仅聚焦）。
6. **顶栏与主窗口一致**：预览窗口标题栏右侧有同样的更新 / 设置钮，设置弹窗与主窗口完全一致。
7. **从主窗口开新窗口**：左树项目右键 / ⋮ 菜单「在新窗口中打开」，以该项目根开一个 Preview Window（无初始文件），同一项目复开即聚焦。

## User Stories

### 设为默认打开方式

1. As a 用户, I want 装好 DevCube 后 Finder / 资源管理器的「打开方式」列表里就有 DevCube, so that 不用任何设置就能用它临时打开一张图
2. As a 用户, I want 在设置「系统集成」里看到「图片 / PDF / PPT / 音频 / 视频」五个子项并各自设为默认, so that 可以只把 PDF 交给 DevCube、图片仍用系统看图
3. As a macOS 用户, I want 点「设为默认」一下就生效、不用再去「显示简介」里改, so that 设置真的是一键
4. As a Windows 用户, I want 点按钮后 DevCube 出现在系统「默认应用」页里且页面直接打开到 DevCube 那一行, so that 系统不让程序改默认时我也只需点一下
5. As a Linux 用户, I want 文件管理器「用其他应用打开」里有 DevCube 且设置里可设为默认, so that 主流发行版也有同样入口
6. As a 用户, I want 每一行实时显示「已是默认 / 未设置」, so that 一眼看出当前状态而不是靠记忆
7. As a 用户, I want 安装 DevCube 本身不会偷偷抢走任何文件类型的默认程序, so that 只有我在设置里点了才会变
8. As a 用户, I want 正式版与 Beta 都能作为打开方式、互不抢注, so that 双装时各自独立（对齐 Release Edition 隔离）
9. As a 用户, I want 设为默认的类型范围与 Files Tab 能内嵌预览的一致（位图、SVG、PDF、PPT、Chromium 可播的音视频）, so that 不会出现「设成默认却打开一个占位」
10. As a 开发者, I want 未打包的 Dev 身份也能在设置里把「DevCube Dev」设为默认打开方式（与快速操作等入口同一分线、同一口径：运行中的 dev 实例收文件，未运行则只拉起空 Electron）, so that 开发时能验证整条链路且不影响已安装的正式版

### 打开与窗口

11. As a 用户, I want 双击一个文件就弹出一个只装这个文件的窗口, so that 像系统「预览」一样开完就看、看完就关
12. As a 用户, I want DevCube 没在运行时双击文件也能直接开预览窗口，且不弹出主窗口, so that 看一张图不必把整个工作台拉起来
13. As a 用户, I want DevCube 已在运行时双击文件只多开一个预览窗口、主窗口不动, so that 不打断正在看的项目
14. As a 用户, I want 同一个文件再双击一次时聚焦已有窗口而不是再开一个, so that 桌面上不会堆重复窗口
15. As a 用户, I want 一次选中多个文件「打开」时每个文件各开一窗, so that 能并排对比
16. As a 用户, I want 预览窗口的标题是文件名，macOS 标题栏带可拖的代理图标, so that 一眼分清多个窗口
17. As a 用户, I want 预览窗口记住上次的大小与位置（退出应用即清，与主窗口一样但各记各的），新开的窗口跟着还开着的那个：它最大化新窗也最大化、否则逐个错开, so that 不用每次重新拖窗口

19. As a 用户, I want 关掉预览窗口后项目列表、工作台记忆没有任何变化, so that 随手看的文件不留痕迹
20. As a 用户, I want 文件在某个已登记项目内时同样开预览窗口（而不是跳进主窗口）, so that 双击的行为永远只有一种
21. As a 用户, I want 脚本也能用 `devcube://open?path=<文件>` 打开预览窗口, so that 自动化和目录唤起用同一条协议
22. As a 用户, I want 传入的路径不存在时被静默忽略, so that 入口对脏输入稳健
23. As a 用户, I want 预览窗口跟随应用主题, so that 深浅色不打架

24. As a 用户, I want 在主窗口左树的项目菜单里「在新窗口中打开」，把这个项目的文件面板单独开成一个窗口, so that 能一边看主窗口的运行输出一边在另一个窗口翻文件

### 窗口内容

25. As a 用户, I want 预览窗口里左边是正文、右边是文件树、上面是工具栏，和 Files Tab 一样, so that 不用学第二套界面

## Implementation Decisions

### 打开方式注册与设默认

- **声明**：打包配置按 Release Edition 声明文件关联（图片 / PDF / PPT / 音频 / 视频五组扩展名，与 Files Tab 类型判定共享同一张扩展名表；`svg` 归图片组，虽然它的打开分流仍是文本，见下文预览态规则；PPT 组含放映版 / 模板 / 带宏版本，宏不执行）。macOS 写入 Info.plist 文档类型，角色 Viewer、LSHandlerRank 取 Alternate，安装即出现在「打开方式」但绝不自动成为默认；Windows 由 NSIS 按 electron-builder 的 ProgID 规则注册（portable 走设置开关经 `reg.exe` 写 HKCU，与右键菜单同一机制）；Linux 声明对应 MIME（写 freedesktop shared-mime-info 登记的原名，如 PPT 带宏版本的 `macroEnabled` 大小写）。Dev 身份没有打包声明，但设置里的「设为默认」仍按「DevCube Dev」分线工作（见下）。
- **macOS 设默认**：Electron 只暴露协议默认程序接口，没有文件类型的；系统官方接口（NSWorkspace 的 setDefaultApplication，按 UTType）不弹确认框。应用随包携带一个用 `swiftc` 编译的单文件命令行小助手（`get <ext>…` 输出各扩展名当前默认应用的 bundle id 与路径；`set <appPath> <ext>…` 按 .app 路径设默认），随应用一起签名公证；设置行状态由 `get` 实时探测，按钮调用 `set` 对该类全部扩展名逐个设置。LaunchServices 只接受声明了该类型的应用，未声明的设默认静默无效、也不进「打开方式」；Dev 跑的 Electron.app 什么都没声明，所以 Dev 身份在数据目录生成一个「DevCube Dev.app」小壳（`osacompile` 的 AppleScript 应用，声明三类文件，收到文件转给运行中的 dev 实例；改 plist 后 ad-hoc 重签、经助手调公开接口 LSRegisterURL 注册），设默认与「打开方式」都指向它。与打包身份对齐：dev **启动时**就同步小壳（plist 里记指纹，Electron 路径与声明不变则跳过），启动后「打开方式」里即有 DevCube Dev；「设为默认」只负责设默认。「已是默认」按 bundle id 判定（用户搬动 / 多份拷贝仍算）。Dev 下助手需先 `pnpm build:mac-helper` 编译，否则该行显示不可用。不引入 Xcode 工程、扩展或额外权限（与 ADR-0025 拒绝 FinderSync 的理由不冲突）。
- **Windows 设默认**：Win8 起系统用用户级签名锁住默认程序选择，程序不可改；不做伪造签名类 hack。按钮 = 确保 HKCU 下 RegisteredApplications + Capabilities/FileAssociations 已注册（reg.exe，与右键菜单同款投影生成器；打开命令与右键菜单同源——打包 [exe]、Dev [electron.exe, 项目入口]），然后打开 `ms-settings:defaultapps`（Win11 深链到 DevCube 条目）。状态探测：读 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\<ext>\UserChoice` 的 ProgId 是否为本应用。
- **Linux 设默认**：`xdg-mime default <desktop 文件> <mime…>`，状态用 `xdg-mime query default`。系统集成栏目在 Linux 上因此可见，仅含此项；Dev 没有 desktop 文件，不可用。
- **设置 UI**：「系统集成」一列平铺、无分区小标题。「文件打开方式」与既有入口行同级占一行（自身无按钮），其下图片 / PDF / PPT / 音频 / 视频五个子项各占一行、`Info` 紧贴类型名成定宽一块而按钮紧跟其后贴左，各有一颗两字按钮「设置」（完整动作与 Windows 的落差挂 hover）。子项只有类型名与按钮：完整扩展名对用户没有决策价值，收进名字后 `Info` 图标的 hover；已是默认的子项不摆按钮，改带勾灰字「默认」。**子项不做成分段条 / 开关组**：设为默认是单向且不可撤销的系统级动作，按钮必须写着动作名，选择控件的视觉承诺（可来回切）与之相悖。状态全部实时探测、不落盘。视觉细节见 DESIGN.md。

### External Open 收文件

- **External Open** 从「只收目录」扩展为「目录 → 项目语义（不变）；文件 → Preview Window」。`open-file` 事件、启动参数、第二实例 argv、deep link `<scheme>://open?path=` 四个入口统一按 stat 分流；既不是目录也不是文件则静默忽略。系统集成 PRD 的「打开文件语义」Out of Scope 条目随之作废。
- **冷启动**：只有文件参数时，只创建 Preview Window，不创建主窗口；主窗口按既有规则在 Dock 点击 / 托盘 / 目录唤起时才出现。文件与目录混杂时两者各自处理。
- **单实例转发**不变；第二实例带文件路径时主实例开窗，不聚焦主窗口。

### Preview Window（预览窗口）

- **窗口模型**：主进程维护「开窗目标（文件路径，或无文件时的根路径）→ 预览窗口」表；同一目标复开即聚焦。几何只在进程内记、退出即清，与主窗口同但各记一份；开新窗前先把最近聚焦且还开着的预览窗口此刻的状态（最大化 / 全屏 / 位置尺寸）写进记忆再取，新窗因此跟它一样；没有活窗才用最近关掉的那份；多开且非最大化时错位级联。主窗口项目菜单「在新窗口中打开」走 IPC 以已登记项目根开窗、不带初始文件（启动参数里省略 file）。每窗独立 BrowserWindow，加载同一渲染入口并以启动参数（查询串）标记「预览模式 + 初始文件 + 初始根」，渲染层据此挂 Preview Window 壳而非工作台。窗口标题 = 文件名，macOS 设 representedFilename。位置记忆与主窗口分开一份，新开窗按上一窗错位级联。Cmd/Ctrl+W 关窗（主窗口 Files Tab 上 no-op 的规则只属于主窗口）。关窗即销毁，无隐藏；Windows 关到托盘的规则只针对主窗口。
- **根解析**：初始根 = 文件所在文件夹；若文件路径落在某个已登记 Project 的根之内（取最深匹配），根 = 该项目根。「上一级文件夹」= 把根换成父目录、当前打开文件不变、树重新展开到它；到文件系统根为止。「上一级文件夹」不判断项目边界。
- **访问授权**：主进程的目录列举 / 读写 / 媒体协议 / 瓦片 / 文件监听目前都按「已登记项目根」放行；改为一套「根授权表」——已登记项目根天然在表内，每个 Preview Window 的当前根按窗口生命周期登记 / 上翻替换 / 关窗撤销。路径穿越校验规则不变（只是根来源多了一种）。媒体协议的 `p` 参数校验改查该表。
- **渲染层壳**：Preview Window 复用 Files Tab 的整块面板（正文 + 树 + 工具栏 + 树顶栏），把面板的「项目路径」参数泛化为「根路径」；面板本身不再假设根一定是 Project。原则是**同一个组件、两种宿主**：不为预览窗口另写一套面板，差异只通过宿主传入的少数开关表达（初始文件、上翻 / 换根回调、添加为项目、类型筛选集合、状态是否落盘）。预览宿主把专属控件并入既有树顶栏：右侧钮组最左「按类型筛选」；「上一级文件夹」在树空白区右键菜单（到文件系统根置灰）；「添加为项目 / 转到项目」放在窗口顶栏更新 / 设置钮之前（顶栏组件开放宿主动作钮插槽）；主窗口无。预览窗口顶栏与设置弹窗复用主窗口同一套组件，更新状态由主进程广播到全部窗口。
- **SVG 初始态**：初始文件为 `svg` 时面板进预览态（Files Tab 默认编辑态的规则不变；预览窗口是被当图打开的，起手即图）；之后的编辑 ↔ 预览切换与 Files Tab 相同、会话内保持。Markdown 仍默认编辑态。文件状态（当前路径、展开集、最近打开、类型筛选）在预览窗口按窗口内存持有、不走集中配置存储；主窗口 Files Tab 的持久化行为不变。
- **裁掉的能力**：无 Tab 栏、无项目树、无 Git Tab / Terminal / 运行会话、无 Content Search；应用菜单中项目 / Tab / 会话相关的菜单项在预览窗口聚焦时禁用（菜单按平台生成的现有机制上按焦点窗口类型开关）。Files Tab 现有的 Git 联动（打开文件进 Files Tab）不适用于预览窗口。
- **保留的能力**：文本编辑与事件自动保存、冲突弹窗、树右键新建 / 重命名 / 删除、外部变更监听（对当前根递归监听，随根切换重挂）、看图 / PDF / PPT / 音视频预览及其全部快捷键（方向键改为切上一个 / 下一个**媒体**——位图 / SVG / PDF / PPT / 可播音视频同一序列，按树里可见顺序跨目录、只进已展开的目录、受类型筛选约束；看图与音视频四键都切，PDF 与 PPT ←/→ 直接切，↑/↓ 翻页、到第一页 / 最后一页再按也切；音视频即使焦点在播放器上也拦下，播放器自己的键盘进度 / 音量让位；两种宿主同）、正文右键菜单（任何已打开的条目）「复制图片（仅看图 / SVG 预览态）/ 复制文件 / 在文件夹中显示 / 在其他应用中打开」（复制图片走渲染层 canvas 栅格化为 PNG 写系统剪贴板，Chromium 能显示的格式都能复制，超大位图复制其预览图；复制文件由主进程把文件本身放进系统剪贴板——macOS `public.file-url`、Linux `text/uri-list`、Windows 交给系统自带 PowerShell 5.1 的 `Set-Clipboard -LiteralPath`，树菜单同款、文件夹为「复制文件夹」）、树顶路径筛选（索引按根建，仅在输入时触发）、全部展开 / 折叠 / 隐藏树、面包屑、在文件树中显示、在文件夹中显示、在其他应用中打开、行号槽 git 变更标记（根在仓库内时）。
- **添加为项目**：预览窗口顶栏按钮（设置钮旁）与树空白区右键菜单项各一份（都作用于当前根）；点击 = 对该目录走 External Open 的目录语义（未登记则登记，已登记则聚焦），随后显示 / 聚焦主窗口并选中该项目（复用「添加项目后的统一收尾」）。根已登记时工具栏按钮文案「转到项目」。预览窗口不关闭。
- **当前文件夹行**：预览宿主在树顶筛选栏之下、列表之上固定一行，显示当前根的文件夹名（hover 全路径），右键即空白区那份根菜单——文件铺满、没有空白可点时也够得着；同时解决上翻下钻后看不出根在哪的问题。
- **上一级文件夹 / 进入此文件夹**：都在树右键菜单——「上一级文件夹」与「添加为项目 / 转到项目」只在空白区 / 根出现（上一级到文件系统根置灰），「进入此文件夹」只在目录出现（根自身没有），把该目录设为树的根，两者互为反向：上翻看大范围后可再收回到任一子目录。当前打开文件不在新根内时正文回到空态。

### 类型筛选

- **判定**：仅按扩展名归类（图片 / PDF / PPT / 音视频 / 文本 / 其他；音频与视频在树顶筛选里并作「音视频」一类，只有设默认时两者分开），复用 Files Tab 类型判定的扩展名表，`svg` 归「图片」（与默认打开方式的分组一致，虽然其打开分流是文本）；不读魔数（树列举不能付出每文件读头的成本）。无扩展名或未知扩展名归「其他」。
- **UI**：预览窗口树顶栏右侧钮组最左一个筛选按钮，弹出五项多选菜单；默认全选；非全选时按钮点亮。清空路径筛选（Esc）不清类型筛选；菜单内提供「全部」快捷项恢复全选。
- **语义**：作用于树的**展示层**——目录条目恒显示，文件条目按类别过滤；与路径筛选取交集（路径筛选结果树再按类型过滤）。方向键切图按可见树序走，因此也受它约束；不影响「最近打开」。
- **持久化**：集合由预览窗口壳持有，换根保留、关窗即忘；不落盘。

## Testing Decisions

只测外部可观察的纯函数与契约行为，IO 经依赖注入隔离（先例：`external-open.test.ts`、`codex-open-in.test.ts`、`windows-context-menu.test.ts` 的 deps mock）：

- **External Open 分流**：启动参数 / deep link 给目录、文件、不存在路径、flag 混杂 → 分别落入目录集与文件集，去重。
- **根解析**：给定文件路径 + 已登记项目列表 → 初始根（最深匹配项目根 / 父目录）；「上一级文件夹」到文件系统根为止。
- **根授权表**：登记 / 替换 / 撤销后各路径的放行判定；路径穿越仍被拒。
- **类型筛选纯函数**：给定目录条目 + 勾选集合 → 目录恒保留、文件按类别过滤；与路径筛选结果树的组合。
- **投影生成器**：macOS 助手命令行、Windows Capabilities 注册表脚本、Linux xdg-mime 命令，产物包含关键要素（bundle id / ProgID / desktop 文件名 / 扩展名表）；三类扩展名表与 Files Tab 类型判定表一致（同一来源）。
- **设置行状态映射**：探测结果 → 「已是默认 / 未设置」文案与按钮态。

不为 BrowserWindow 创建、open-file 事件挂接、真实注册表 / LaunchServices / xdg 写 e2e。

## Out of Scope

- Windows 一键设默认（系统禁止，只做注册 + 跳系统设置）。
- 按单个扩展名细选设默认（只按图片 / PDF / PPT / 音频 / 视频这几类）。
- 预览窗口里的 Git Tab、Terminal、运行会话、Content Search、内层多文件 Tab。
- 预览窗口状态持久化（树展开 / 最近打开 / 当前文件）。
- 幻灯片 / 自动播放、图片编辑、PDF 标注。
- 类型筛选按魔数判定、类型筛选持久化、自定义类别。
- Quick Look 插件、FinderSync（见 ADR-0025）。

## Further Notes

- 术语 **Preview Window（预览窗口）** 见 CONTEXT.md；决策见 ADR-0031（文件类型默认程序的平台路径与「安装不抢默认」）、ADR-0032（Files 面板从「项目根」泛化为「根授权表」，同一组件两种宿主）。
- 系统集成 PRD 的「打开文件（非目录）语义：所有入口只收目录」条目已由本 PRD 取代。
- macOS 助手随包签名：@electron/osx-sign 会遍历 `Contents/` 下全部二进制逐个签名（已核实源码），放在 `Contents/Resources` 的助手无需额外配置；release 工作流的 `codesign --verify --deep --strict` 是兜底校验。首个正式包出来后仍应在真机上点一次「设为默认」实证。
- Linux desktop 文件名按 electron-builder 的 `<executableName>.desktop` 假定，首个 Linux 包需实证 `xdg-mime query default` 的返回值。
- 视觉（树顶栏专属控件、类型筛选菜单样式）实现时按 DESIGN.md 与树顶栏既有按钮对齐，不另开产品讨论。
