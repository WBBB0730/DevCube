# project-pin

**置顶**

## Problem Statement

左树项目一多，常用 **Project** 容易被埋在下面。现有排序（自定义 / 名称 / 添加时间 / 打开时间）和拖拽只能临时改序，没法把「我天天用的那几个」在任意排序下都钉在上面，滚动长列表时项目名也会滚出视口，还得翻回去找。

## Solution

给每个 **Project** 增加持久的 **Pin（置顶）** 标记（**Server**、**Data Source** 同一规则）：

1. **排序浮顶**：已置顶的项目整段（项目行 + 其下配置）排在未置顶之前；两组内部仍服从当前排序方式。
2. **滚动吸顶**：滚动左树时，所有已置顶的**项目行**在列表顶依次叠放保持可见（行间 1px）；未置顶的**项目行**滚过时贴在置顶堆下方作为当前段、被下一段顶走；配置行照常滚走。
3. **显式开关**：仅通过项目「更多」/ 右键菜单置顶或取消置顶；已置顶的项目行上常显小图钉。

## User Stories

1. 作为用户，我想给常用 **Project** 打上 **Pin**，以便它在任意排序下都整段排在未置顶项目之上。
2. 作为用户，我想取消某个项目的 **Pin**，以便它回到未置顶区块并按当前排序排列。
3. 作为用户，我想在项目行的「更多」菜单里看到「置顶」或「取消置顶」，以便与打开文件夹 / 打开于 / 新建终端等操作同一入口。
4. 作为用户，我想用项目行右键打开与「更多」相同的菜单并开关 **Pin**，以便不必找 ⋮ 按钮。
5. 作为用户，我想已置顶项目的行上常显小图钉，以便一眼认出谁被 Pin 了。
6. 作为用户，我想 **Pin** 跨重启保留，以便不用每次重开再钉。
7. 作为用户，我想新添加的项目默认不 Pin，以便置顶区只保留我明确常用的。
8. 作为用户，我想置顶时该项目进入置顶区块的开头，以便新钉的立刻出现在置顶区最前。
9. 作为用户，我想取消置顶时该项目进入未置顶区块的开头，以便行为与置顶对称、可预期。
10. 作为用户，我想在名称 / 添加时间 / 打开时间排序下，置顶组与未置顶组内仍各自按该规则排，以便 Pin 不破坏组内排序语义。
11. 作为用户，我想在自定义排序下拖拽重排时只能在置顶组内或未置顶组内移动，以便拖拽不会误改 Pin。
12. 作为用户，我想拖过置顶/未置顶边界时无效，以便边界密封。
13. 作为用户，我想非自定义排序下的组内拖拽照旧在松手且顺序真变了后切到自定义，以便与既有拖拽改序习惯一致。
14. 作为用户，我想筛选项目名时，匹配结果里仍是「匹配的置顶在上、匹配的未置顶在下」，以便筛选不吞掉 Pin 分区。
15. 作为用户，我想筛选开启时拖拽仍禁用，但菜单里仍可开关 Pin，以便筛选只拦拖拽不拦置顶。
16. 作为用户，我想往下滚左树时所有已置顶的项目行叠在列表顶部保持可见，以便不用滚回顶部找置顶项目。
17. 作为用户，我想置顶叠放行之间留 1px 间隙，以便叠层仍可分辨边界。
18. 作为用户，我想吸顶只作用于项目行、配置行照常滚走，以便展开的配置不会粘在顶上占空间。
19. 作为用户，我想多个置顶时项目行在顶上依次叠放，以便每个置顶项目名都仍可见。
20. 作为用户，我想在排序菜单里开关「固定置顶」，以便不想要多 Pin 叠放时关掉它。
21. 作为用户，我想滚过某个项目时它的项目行贴在顶上、被下一个项目顶走，以便视口顶的标题不会被切成半截。
22. 作为用户，我想点击已吸顶的置顶项目行时列表滚到该项目在文档中的位置，以便从叠放条回到它的配置区。
23. 作为用户，我想在打开时间排序下打开/选中某项目后列表滚到它，以便看到刚打开的项（有 Pin 时它不一定在列表顶）。
24. 作为用户，我想添加项目成功后的滚入视口与打开时间排序下的滚动一致，以便行为可预期。
25. 作为用户，我想移除项目时其 Pin 一并消失；同路径再添加视为新项目且默认不 Pin，以便不留幽灵状态。
26. 作为用户，我不希望行内再占一个图钉按钮槽，以便保持项目行克制（折叠 + 更多为主）。
27. 作为用户，我想在焦点在别处时用 Alt+CmdOrCtrl+P 聚焦左树项目筛选框，以便不用先点左栏再输入。
28. 作为用户，我想用 Alt+CmdOrCtrl+↑ / ↓ 按左树当前可见序循环切换上一 / 下一 **Project**，以便不用鼠标点树。
29. 作为用户，我想在排序菜单里开关「固定运行中」，以便有配置在运行的项目、服务器、数据源滚过后像当前项目一样钉在顶上，随时看到哪些在运行。
30. 作为用户，我想吸顶中的条目行在右侧显示运行中状态点，以便配置行滚走后仍知道这个条目有配置在运行。

## Implementation Decisions

- **数据模型**：**Project**、**Server**、**Data Source** 各有持久布尔 Pin，老档案缺省为未置顶；不另建置顶路径表。三类条目共用一个开关 Pin 的 IPC，返回更新后的左树。
- **排序**：共享的项目排序纯函数先按 Pin 分成两区（置顶在前），再在各区内套用当前排序（自定义 = 该区内落盘相对序；名称 / 添加时间 / 打开时间 = 既有比较规则）。筛选先排后滤，结果仍保持分区。
- **快捷键**：全局 Alt+CmdOrCtrl+P 聚焦左树项目筛选框并选中已有查询（与 Files 的 Alt+CmdOrCtrl+F 对称；不占用 CmdOrCtrl+F），title / placeholder 里的快捷键按平台显示（共享的快捷键标签格式化，对齐 VS Code UILabel）。全局 Alt+CmdOrCtrl+↑ / ↓：按与左树相同的「先排后滤」可见序循环切换项目并滚到它；列表不足两项且已是当前项时不动。
- **Pin / 取消 Pin 与落盘序**：任意排序模式下开关 Pin 都改写左树自定义序（三类条目共用一条序列）——置顶则排到当前所有已置顶之前（置顶区开头），取消则排到当前所有未置顶之前（未置顶区开头）；不因此切换排序模式。新条目默认不 Pin，落在未置顶区开头。
- **拖拽**：自定义序（及拖拽触发切自定义）时，只允许在同一 Pin 分区内重排；跨区 drop 不改序、不改 Pin。筛选中仍禁用拖拽。
- **菜单**：项目「更多」/ 右键共用菜单里的「置顶」/「取消置顶」放在「移除项目」之上；无行内图钉按钮。
- **视觉**：已置顶时在行尾「更多」钮的位置常显小图钉（muted），hover / 拖拽 / 菜单打开时原地换成 ⋮，不挤到旁边；未置顶无图标。包管理器角标与 hover 让位规则不变。
- **滚动吸顶**：已置顶项目的**项目行**默认叠放吸顶（`top: n×(行高+1px)`，行间 1px 用不透明面板底填满）；排序菜单「固定置顶」可关（默认开、跨重启保留），关闭后置顶行改为当前段吸顶（`top: 0`），与未置顶一致——视口最上的项目行贴住、被下一段顶走。开启时未置顶行贴在整叠置顶下方。只作用于项目行，不含配置行 /「检测到的配置」触发行；吸顶行需不透明底。点击已吸顶的置顶标题时滚它前方的非 sticky 段锚（`scrollIntoView({ block: 'start' })`，`scroll-margin-top` 预留叠放高度）——sticky 行在视口内时直接对它 scrollIntoView 不会动。
- **常驻吸顶**：当前条目，及排序菜单「固定运行中」（默认关、跨重启保留）开启时有配置在运行的条目，其条目行滚过后钉住、不被顶走；三类条目同一规则，仍只作用于条目行。常驻与否不看展开态，拖拽开始全部收起时结构不变。各行吸顶 `top` 只由一个纯函数按「排在其前的钉住行数」统一算出（叠放的置顶行与常驻行都算钉住）。
- **吸顶运行点**：条目行吸顶中且有配置在运行时，名称右侧（包管理器角标之前）显示运行中状态点（与配置行同款，不带数字），进出淡入淡出；未吸顶时不显示。任何原因吸顶都适用（与「固定运行中」开关无关）。是否吸顶中用 CSS `scroll-state(stuck: top)` 容器查询判断，不监听滚动。
- **滚入视口**：打开时间排序下选中 / 打开项目后，以及添加项目成功后，都把该项目滚入视口：已滚过该项目段起点时走段锚（同点击吸顶标题），否则 `nearest`。

## Testing Decisions

好测试：只测外部可观察的纯函数行为，不测吸顶 CSS / dnd 命中细节。扩展既有项目排序的 vitest 单测：

- **分区排序**：置顶整段在前；组内各排序模式的相对序正确；Pin 缺省当未置顶。
- **Pin 落盘位移**：置顶 → 置顶区开头；取消 → 未置顶区开头；多次开关后相对序稳定。
- **吸顶位置**：固定置顶开 / 关、置顶 / 未置顶常驻、多个常驻时各行是否常驻与钉住位置。
- **筛选 + 分区**：过滤后仍保持置顶在前。

不写 UI/e2e（吸顶叠放、跨界拖拽弹回靠手动验证）。

## Out of Scope

- 行内一键图钉按钮
- 置顶区与未置顶区之间的分隔线
- 置顶数量上限
- 添加项目流程里的「同时置顶」选项
- 拖拽跨界自动改 Pin
- 项目分组 / 多级收藏夹
- 键盘快捷键置顶
- 为 Pin 单独建 ADR（可逆、不令人意外）

## Further Notes

- 术语见 CONTEXT.md（**Pin**）；口语里「新项目碰巧排到最前」不是 Pin。
- 吸顶与「拖拽中全部暂时收起」同时存在时，以拖拽手感优先；松手后恢复吸顶即可，不另发明拖拽期特殊 Pin 语义。
