# 服务器状态

## Problem Statement

登上服务器后，我常想先看一眼它现在忙不忙：CPU、内存、硬盘还剩多少，网络有没有在跑流量，是谁在占资源。现在只能开一个 **SSH Terminal** 敲 `top`、`free -h`、`df -h`，一条条看，看完还得自己比较前后变化。FinalShell 左侧有一块随时刷新的监控，但 DevCube 里没有。

## Solution

每台 **Server** 恒有一个 **Status Tab**（状态标签页），常驻它的 Tab 栏最前，像 **Project** 的 **Git Tab** 一样不可关闭。连上后每 2 秒刷新一次：

- 四张指标卡两两一行，各带最近 5 分钟的曲线（有刻度，鼠标移上去读数）：CPU（使用率、核数）、内存（使用率、已用）、系统盘（使用率、已用、读写速度，另有分区时逐个列出用量）、网络（下行 / 上行速度并排，开机以来的累计量）；
- 进程排行：前 10 个进程，可按 CPU 或内存排序；
- 系统信息：主机名、连接地址、内网 IP、系统、内核、架构、CPU 型号、开机时间、已运行。

- **点「连接」才连**：和 **SSH Terminal** 一样，不会一点服务器就自动连上、弹出密码框。
- **连上后一直刷新**：切到别的 Tab 或别的条目也不停，曲线连续；系统卡底部的「断开连接」可手动停。
- **服务器上什么都不用装**：经内置连接（ADR-0041）连上服务器，在服务器上用它自带的 `sh` 读 Linux 的系统信息。只支持 Linux 服务器。

## User Stories

1. 作为用户，我想点开一台 **Server** 就看到它的 **Status Tab**，尚未连接时显示「尚未连接到 X」和「连接」按钮。
2. 作为用户，我想点「连接」后看到它的 CPU、内存、网络与各硬盘分区，每 2 秒刷新一次。
3. 作为用户，我想看到 CPU、内存、网络最近 5 分钟的曲线，切走再切回来曲线也是连续的，以便一眼看出是不是突然升高了。
4. 作为用户，我想看到上行与下行速度一样醒目，并知道开机以来累计收发了多少。
5. 作为用户，我想看到前 10 个进程，并能按 CPU 或内存排序，以便服务器变慢时知道是谁在占资源；CPU 要反映当下，而不是进程一生的平均；进程名要是完整的程序名，而不是线程名或被截断的名字。
6. 作为用户，我想看到主机名、连接地址（我连过去用的地址，云服务器上即公网地址）、内网 IP、系统版本、内核、架构、CPU 型号和开机时间，以便确认连的是哪台机器。
7. 作为用户，我想看到系统盘的用量与读写速度及其曲线，鼠标停上去看得到设备名，而不是一个费解的「/」；曲线要有刻度和时间，鼠标移上去看得到那一刻的数值。
8. 作为用户，我想随时点「断开连接」停下这条连接；5 分钟内重新连上，曲线还接得上。
9. 作为用户，连接断开时（网络断了、服务器重启），我想看到断开原因和「重新连接」按钮。
10. 作为用户，服务器不是 Linux 时，我想看到明确的「暂不支持」，而不是一堆乱码或空白。
11. 作为用户，需要密码时，我想照常在 SSH 提问弹窗里回答；记住的密码自动填上。
12. 作为用户，编辑服务器的连接信息或移除服务器时，它的状态连接随之断开。
13. 作为用户，重启 DevCube 后，**Status Tab** 回到未连接状态，不自动连接。

## Implementation Decisions

- **Tab**：**Status Tab** 键为 `status:server:<id>`，与 Git / Files 同属常驻非会话 Tab：不可关闭，⌘W 无效；Tab 序为「常驻 Tab → 运行会话 → 终端」，Server 的常驻 Tab 为它（⌘1）与 **Files Tab**（⌘2，见 `docs/prd/server-files.md`）。默认激活规则不变（有运行中的 **Run Session** 先激活它，否则 Tab 序首位），所以点开服务器默认就是 **Status Tab**。原先服务器没有 Tab 时的占位页（「尚未连接到 X」+「连接」，点了开一个 **SSH Terminal**）合并进 **Status Tab** 的未连接状态，那里的「连接」改为开始看状态；开终端用 Tab 栏的「+」。
- **激活规则的数据结构**：Tab 激活的纯函数接收「按序的常驻 Tab 键列表」，不为每种常驻 Tab 各设一个参数；**Project** 为 Git、Files，**Server** 为 Status、Files。
- **连接**：每台服务器至多一条状态连接，由主进程管理。经内置连接（ADR-0041，`docs/prd/ssh-connection.md`）自己连一条，沿用 **Server** 的连接目标与「绕开代理直连」（ADR-0039），在上面开一个 exec 通道跑脚本（不分配终端）；保活取 ssh 配置，未设时 15 秒、3 次无应答即断开，网络断了约 45 秒内发现。提问经新的提问弹窗，记住的密码自动作答。
- **服务器上的脚本**：远端命令为 `sh -c '<脚本>'`（不依赖登录 shell 的语法）。脚本先检查 `/proc/stat` 可读，否则输出「不支持」标记后退出；再输出一次基本信息（主机名、`/etc/os-release` 的 `PRETTY_NAME`、`uname` 的内核与架构、CPU 核数与型号、默认路由所在网卡及其 IPv4 地址、`/proc/stat` 的 btime、`getconf` 的页大小与每秒时钟嘀嗒数），然后循环：**每从标准输入读到一行，就输出一帧数据**——`/proc/stat` 首行、`/proc/meminfo` 里用到的七行、`/proc/loadavg`、`/proc/uptime`、默认网卡在 `/proc/net/dev` 的那一行、`df -kP`、系统盘在 `/proc/diskstats` 的那一行（按 `/proc/self/mountinfo` 里 `/` 的设备号取，LVM 等也对得上；根在 overlay 上时没有）、进程排行。各段以 `@@` 开头的标记行分隔；登录时 rc 文件打印的杂项落在帧外，一律忽略。每帧约 1 KB。
- **进程排行**：在服务器上算好再传回。每帧读全部 `/proc/<pid>/stat` 的 utime + stime（时钟嘀嗒）与常驻页数，和上一帧相减，输出 CPU 前 10 与常驻内存前 10 的并集（增量、常驻页数、pid、内核记录的名字），切换排序不用等下一帧；再用一次 `ps -o pid=,user:32=,args= -p …` 补上它们的用户名（没有对应用户名时 procps 给出 uid 数字）与命令行。程序名取命令行首个词的文件名（去掉进程改标题时的尾冒号，如「sshd: …」）；没有命令行的（内核线程）用内核记录的名字。不用 `ps` 的 %CPU（进程一生的平均，反映不了当下），也不用 `top`（输出格式会被用户自己的 toprc 改掉）。主进程换算：CPU = 嘀嗒增量 /（每秒嘀嗒数 × 两帧间隔）× 100%，按单核计（同 top）；内存 = 常驻页数 × 页大小。界面按所选列降序取前 10，默认按 CPU。第一帧没有上一帧可比，排行为空。
- **连接地址**：云服务器的公网 IP 在网关上转发，服务器自己读不到；也不去问第三方网站。主进程连接时按本机 ssh 配置取连接目标的 hostname（`ssh -G`）作为「连接地址」，与服务器上读到的「内网 IP」分开显示。
- **系统盘读写**：`/proc/diskstats` 第 6、10 列为读、写扇区数（恒按 512 字节），两帧相减除以间隔即速度。
- **刷新**：连上后主进程立即、此后每 2 秒向 ssh 的标准输入写一个换行，触发一帧，不管 **Status Tab** 是否可见。连接保留到点「断开连接」、网络断开、服务器的连接信息被改或服务器被移除、或 DevCube 退出。
- **数值计算（纯函数）**：CPU 使用率 = 1 − 两帧间（idle + iowait）增量 / 总 jiffies 增量；网络速度 = 默认网卡收发字节增量 / 两帧 `/proc/uptime` 之差，同时给出开机以来的累计量（没有默认路由则不显示网络）；内存已用 = MemTotal − MemAvailable（老内核用 MemFree + Buffers + Cached）；交换区已用 = SwapTotal − SwapFree；负载与交换区照常采集，留作以后使用，界面暂不显示；硬盘只列 `/` 与来源为 `/dev/…`（排除 `/dev/loop…`）的分区，同一来源只列一次，使用率 = 已用 /（已用 + 可用），与 `df` 一致。
- **曲线**：主进程为每台服务器记最近 5 分钟的点（本机收到该帧的时间，CPU%、内存%、下行、上行、系统盘读、写），随状态一起推送，切走不丢；手动断开后保留，重新连上时丢掉 5 分钟以前的点；服务器的连接信息被改时清空；不落盘。渲染端用成熟的图表库 Recharts 画折线：横轴按时间（整分钟刻度），右边缘为最新一帧；纵轴百分比为 0 / 50 / 100%，字节速率按 1024 进位的单位取 1 / 2 / 5 步长、3 段左右；相邻两点相隔超过 2.5 个刷新间隔（断开过）时补一个空点，曲线在那里断开；鼠标移上去出竖线与读数框，列出那一刻每个系列的数值。两个系列用 `--chart-1`（蓝）、`--chart-2`（橙），按 dataviz 规范的验证脚本在深、浅两档面板底上验过（色弱可分、对比度 ≥ 3:1）；不用状态色区分系列。
- **推送**：主进程每帧推一次该服务器的完整状态（阶段、基本信息、最新一帧、曲线），渲染端按服务器 id 分发（`createKeyedSubscription`）。状态阶段：未连接 / 连接中 / 已连接 / 不支持 / 已断开（带原因：ssh 报错的最后一行，没有输出时为「连接失败（退出代码 N）」，与测试连接一致）。渲染端首次挂载时向主进程取当前状态（渲染端重载后能接上）。
- **生命周期**：点「断开连接」即结束连接、回到未连接；编辑服务器时连接信息（连接目标、是否绕开代理直连）变了即断开、清空曲线并回到未连接，只改名、只改记住的密码、只改地址大小写不断开；移除服务器即断开并忘掉它；DevCube 退出时一并结束，不计入退出确认。

## Testing Decisions

沿用项目约定：只测纯函数，零 mock。

- 帧解析：标记行分段、帧外杂项忽略、基本信息解析（读不到的项、`getconf` 缺席的默认值）、「不支持」标记。
- 数值计算：CPU 使用率（含 iowait）、内存与交换区、负载、开机时长、网络速度与累计量（按默认网卡、按 uptime 计时）、系统盘读写（扇区换算、读不到为空）、第一帧无增量、硬盘分区筛选与去重、`df` 挂载点含空格、进程排行（用户与程序名取自 `ps`、`ps` 缺席时的回落、负增量按 0、嘀嗒换算成百分比）、程序名（尾冒号、内核线程）。
- 曲线：按时间追加、只留最近 5 分钟；断开过的时段补空点；字节速率纵轴的刻度与单位。
- 开机时间的写法「2026-05-02 15:21」。
- 远端脚本：不含连续两个反斜杠（fish 这类登录 shell 也能原样转交给 sh）。
- 常驻 Tab：Server 的 Tab 序与默认激活（**Status Tab** 在前，运行中的会话优先）。

落在 `src/shared/server-status.test.ts`、`src/shared/tab-activation.test.ts`、`src/shared/server.test.ts` 与 `src/main/command.test.ts`。不写 UI / e2e 测试。

实测记录：

- 已实测（macOS 上以 `sh` 运行真实脚本，`/proc` 换成临时目录里造的数据）：语法检查通过；两次换行产出两帧；默认网卡、CPU 型号、页大小与时钟嘀嗒读得到；第二帧的进程排行按嘀嗒增量换算正确，名称含空格与括号的进程解析正确，期间退出的进程不列、新出现的进程要等下一帧；没有 `/proc` 时给出「不支持」。
- 已实测（同上方式）：系统盘读写按扇区换算正确；CPU 前 10 与内存前 10 的并集正确。
- 已实测（Electron 离屏渲染界面组件，喂模拟数据截图）：深浅两档下的布局、曲线刻度、hover 读数框。
- 待实测：真实 Linux 服务器上的整体效果（数值与 `top` / `free -h` / `df -h` / `iostat` 对照）、`ps -o user:32=` 取到的用户名（macOS 的 `ps` 不支持这种写法，只能在 Linux 上验）。

## Out of Scope

- Docker 容器（以后再加）。
- 装了 sysstat 的服务器读它的记录，做「按天看」的历史图（下一步，见 `docs/backlog.md`）。
- 非 Linux 服务器（macOS、BSD、Windows）。
- 历史数据落盘、告警阈值、通知。
- 左树里显示服务器在线状态或指标。
- 与 **SSH Terminal** 共用同一条连接（ssh 的连接复用）。
