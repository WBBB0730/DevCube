# run-config-params

**运行配置的参数**

## Problem Statement

常跑的命令里总有一小段每次不一样：部署的版本号、要看哪天的日志、连哪个环境、跑哪个测试文件。现在只能每次先编辑配置改掉这一段再运行，或者为每种取值各建一条配置。**Data Source** 上的 **Run Configuration** 已经能在内容里留**参数**、每次运行前填值，**Project**、**Server** 上的配置还不能。

## Solution

**Project**、**Server** 上的命令型 **Run Configuration** 也能留**参数**，与 **Data Source** 上的是同一套：写作 `${{名称}}`，运行、重跑前弹框逐个填值，预填这条配置上次用的值，填的值按文字原样换进去。本机与服务器上的配置可以写在命令、工作目录与环境变量的值里。数据源上的写法从 `${名称}` 改成同样的 `${{名称}}`，三处一种写法（ADR-0048）。

## User Stories

1. 作为用户，我想在项目或服务器的命令型配置的命令里写 `${{名称}}` 这样的参数，比如 `pnpm deploy --tag ${{tag}}`，运行前弹框让我填值。
2. 作为用户，我想在工作目录和环境变量的值里也能写参数，比如工作目录 `packages/${{包}}`、环境变量 `API_TOKEN` 的值 `${{token}}`；同一个参数写在几处，只问一次。
3. 作为用户，我想命令里原有的 shell 变量（`${HOME}`、`$PWD`）照旧交给 shell，不被当成参数。
4. 作为用户，我想参数框预填这条配置上次用的值，重启后也在；第一次运行时为空。
5. 作为用户，我想回车即运行，Esc 取消，取消时什么都不变（不选中、不切 Tab、不运行）；没有参数时照旧直接运行。
6. 作为用户，我想左树的 ▶ 与重跑钮、运行会话操作栏的运行与重跑都先问参数。
7. 作为用户，我想填的值原样换进去、不自动加引号：要把带空格的值当成一个参数传，我自己在命令里加引号（`git commit -m "${{message}}"`）。
8. 作为用户，我想在运行会话开头的运行头里看到换好参数后实际执行的命令与目录。
9. 作为用户，我想数据源上的配置也用同一种写法 `${{名称}}`。
10. 作为用户，删除配置、移除项目或服务器时，它记住的参数值一并删掉。
11. 作为用户，我想在配置对话框里看到可以用参数，悬停即知格式并看到示例。
12. 作为用户，我想输入 `${{` 时自动补上 `}}`，以便少打括号，照习惯打完整个参数也不多出括号。

## Implementation Decisions

- **写法与识别**（ADR-0048）：只认 `${{名称}}`；名称去掉首尾空白，空的、跨行的、含花括号的不算；写在哪里都算，包括引号与注释里。参数名去重、按第一次出现的顺序：本机与服务器上的配置依次为命令、工作目录、各环境变量的值（环境变量名不认），数据源上的为内容。识别与替换只在 `shared/run-params` 一处实现，格式化 SQL 认参数的正则也取自这里（`RUN_PARAM_SOURCE`）。
- **替换**：按文字原样替换，不加引号、不转义；只换一遍（填的值里的 `${{…}}` 不再展开），没给值的原样留着。换好后各字段照原来的用法：命令交给 shell，工作目录相对项目根解析（服务器上为服务器上的目录，照旧加引号），环境变量的值叠加进环境（服务器上照旧加单引号导出）；运行头里是换好后的命令与目录。本机与服务器上的配置由主进程按 id 取配置再换（渲染端只交填的值）；数据源上的配置照旧由渲染端换好、切好语句再交（ADR-0044）。
- **参数框**：样子与交互见 DESIGN.md「运行参数框」。全部命令型配置运行前都先问参数；同一时刻只问一个，又有一次运行要问时，前一个当作取消。等密码时交上密码不再问，只适用于数据源上的配置（`docs/prd/database.md`「运行配置」）。
- **记住的值**：按配置 id 存。每次运行整份替换，只留这次用到的参数；配置已不在或是引用型时不记。删除配置、移除 **Project** / **Server** / **Data Source** 时一并删掉。
- **配置对话框**：底栏左侧「使用参数」，悬停显示格式与示例（命令、SQL、Redis 各给一个，DESIGN.md「设置弹层」）；命令配置与数据源上的配置共用外壳，两边都有。命令仍为单行（同 WebStorm 的脚本文本）。
- **自动补全**：命令、工作目录、环境变量的值（输入框）与数据源上的配置的内容（编辑器）里，照 CodeMirror closeBrackets 的通行规则：输入 `${{` 的第二个 `{` 时补上 `}}`、光标停在中间，光标后紧跟字母、数字时不补；`$` 之后的第一个 `{` 照原样输入（免得编辑器自带的补括号补成 `${}`）；在参数里输入 `}` 而光标后是 `}` 时跳过它；光标在空的 `${{` 与 `}}` 之间时，退格删掉 `{` 与 `}}`。规则是纯函数，输入框与编辑器共用。输入框经 `execCommand` 写入，改动留在原生撤销记录里（用 `setRangeText` 会撤不回更早的输入）；编辑器里以高优先级接入，先于自带的补括号，其余括号照旧。

## Testing Decisions

沿用项目约定：只测纯函数，零 mock；不写 UI / e2e 测试。

- **认参数**：上文写法与顺序的各条规则；反例 shell 变量、Go 模板（`{{.Names}}`）、`${名称}`、`?`、`:名称`、`::` 都不算；Redis 命令同样认。
- **替换**：原样、同名都换、只换一遍，没给值的原样留着；只认自己的键，不认原型上的；只动命令、工作目录与环境变量的值。
- **格式化 SQL** 认得 `${{…}}`；**记住的值**按配置删掉。
- **自动补全**：各位置（行尾、空格前、引号里、括号前）的补全与不补、`$` 后的第一个 `{`、打完整个参数、刚补完退格。

已实测（headless Chromium，真实的 React 输入框与带自带补括号的 SQL 编辑器）：补全、退格、其余括号照旧；输入框撤销照常，React 状态与输入框一致。

待实测：项目、服务器上的配置带参数运行、重跑、取消；工作目录与环境变量里的参数；同名参数只问一次；重启后预填上次的值；运行头里是换好的命令；数据源上的配置改用 `${{名称}}` 后照常运行与格式化。

## Out of Scope

- 默认值写法（第一次运行时预填）。
- 输入时遮住的参数（WebStorm 的 `$Password$`、VS Code 的 `password`）。
- 下拉选值（VS Code 的 `pickString`）、选文件（WebStorm 的 `$FilePrompt$`）。
- 转义：内容里要原样写出 `${{…}}`。
- 引用型配置的参数（它不可编辑）。
- 配置对话框里参数名的补全（列出已写过的参数名）。

## Further Notes

- 写法的取舍见 ADR-0048；数据源上的参数先换后切、等密码时的处理见 `docs/prd/database.md`「运行配置」。
