# git-nested-repos

**Git 嵌套仓库与多仓库项目**

## Problem Statement

**Git Tab** 原先默认每个 **Project** 就是一个仓库：从项目目录往上找到的第一个仓库算它的，只认这一个（`git-graph.md` 曾把「多仓库 / 子模块发现」列为范围外）。项目里还有别的仓库时就处理不好：

- 项目本身是仓库，里面还套着独立的仓库（嵌套仓库）：Git Tab 只看得到外层。嵌套仓库在外层的未提交更改里显示成一个未跟踪的文件夹，暂存后 git 只记下一个指向它的空壳（嵌入仓库），不收它里面的文件，git 自己也提示这多半是误操作。
- 项目本身不是仓库、下面几个文件夹是（如把 `~/code` 整个加成项目）：Git Tab 只给「初始化」，点了会在外层新建仓库，下面的仓库又变成上一种情况。
- 子模块：外层只把它当一条改动，看不到它自己的提交历史。
- 项目目录被上层仓库忽略（如把整个家目录做成仓库、里面全部忽略）：项目被当成那个大仓库的一部分。
- 项目是仓库的子目录时，从 Git Tab 打开文件、复制绝对路径会按项目目录拼路径，拼错；Files Tab 的 Git 颜色也对不上。

## Solution

一个 **Project** 有 0..N 个 **Repository**（术语见 CONTEXT.md）：项目自己所在的仓库，加上项目里的嵌套仓库与子模块。**Git Tab** 一次显示其中一个，工具栏最左边的仓库下拉切换，选中的按项目记住。每个文件归离它最近的仓库：外层不再列出嵌套仓库，Files Tab 的 Git 颜色与编辑器的改动条纹也按文件所在的仓库。

几家主流工具都是「一个项目对应多个仓库」：WebStorm 扫遍整个项目、自动登记找到的仓库，所有仓库的提交混在一张 Log 图里；VS Code 默认往下找一层、打开文件时补上它所在的仓库，仓库列表可一起看或一次看一个；Zed 用仓库选择器一次看一个；Git Graph（Git Tab 的参考实现）顶部下拉一次看一个。DevCube 取「扫整个项目」（WebStorm）+「下拉一次看一个」（Git Graph / Zed）。

## User Stories

1. 作为开发者，我把一个本身不是仓库、下面有几个仓库的文件夹加成项目，Git Tab 直接显示其中一个仓库，并能用下拉切到其他仓库。
2. 作为开发者，我的仓库里套着一个独立 clone 的仓库，我能在 Git Tab 里切到它，看它的历史、在它里面提交、拉取、推送。
3. 作为开发者，外层仓库的未提交更改里不再出现嵌套仓库那一项，「全部暂存」也不会把它误收进外层。
4. 作为开发者，子模块也出现在仓库下拉里，能看它自己的历史；外层仍把它显示成一条改动，方便提交它指向的新版本。
5. 作为开发者，我在项目里新建、clone 或删除一个仓库后，仓库下拉自动跟上，不用重新打开项目。
6. 作为开发者，我切到某个仓库后，下次打开项目（含重启后）还停在这个仓库；Tab 栏上「Git (分支)」显示的是它的分支。
7. 作为开发者，项目里只有它自己这一个仓库时，界面和以前一样，不多出仓库下拉。
8. 作为开发者，项目根不是仓库但下面有仓库时，我仍能从仓库下拉里「初始化 Git 仓库…」把项目根初始化成仓库，初始化后自动选中它。
9. 作为开发者，我把整个家目录做成了仓库并忽略了全部内容，家目录下的项目不再被当成这个仓库的一部分。
10. 作为开发者，Files Tab 里嵌套仓库中的文件按它自己的仓库显示 Git 颜色，打开文件时的改动条纹也和它自己仓库的 HEAD 比。
11. 作为开发者，在任务清单里，嵌套仓库上的拉取 / 推送写着「项目名 · 仓库名」，点它回到那个项目的 Git Tab 并选中那个仓库。

## Implementation Decisions

- **发现**（主进程 `git-repos`，ADR-0060）：项目自己所在的仓库经 `rev-parse --show-toplevel` 往上找；项目是上层仓库的子目录时，在项目目录跑 `check-ignore -q .`，被忽略就不认（同 JetBrains）。仓库里的嵌套仓库交给 git：`ls-files --others --exclude-standard` 里以 `/` 结尾的条目正是嵌套仓库（git 不进嵌套仓库，被忽略的不列）；子模块读 `.gitmodules`。两种候选都再经 `rev-parse` 确认是仓库根（子模块要已检出），与加载图谱同一口径，再逐个往里找。不在任何仓库里的目录逐层读目录找 `.git`，深度不限。隐藏目录与 `node_modules` 一概不进（JetBrains 跳过隐藏目录、VS Code 跳过 `node_modules`）。同时在跑的 git 进程与读目录上限 8 个。
- **什么时候发现**（同主流工具「打开项目时才找」）：启动时每个项目只查它自己所在的仓库（监听要它，一两个 git 进程，与原先同等开销）；渲染端第一次要某个项目的仓库清单时——它是当前项目、打开它的 Git Tab 或 Files Tab——才完整发现，发现完把嵌套仓库接进监听。没打开过的项目里，嵌套仓库的事件归项目自己的仓库（与原先一样），它们的状态本就没加载过。
- **清单与排序**：项目自己的仓库排第一个（名字为仓库根的目录名），其后是嵌套仓库与子模块，名字为相对项目根的路径，按名字自然排序。清单按项目缓存在主进程；Preview Window 的根同样适用（按根目录缓存）。
- **跟进**：项目监听（`project-watchers`）里，某处 `.git` 的增删、嵌套仓库所在目录被删或改名、监听报事件丢失，都触发重新发现（没打开过的项目仍只重查项目根）；清单变了才对齐监听并推 `git:repos-changed`。Git Tab 到前台时只重查项目根（一两个 git 进程），项目根变了才整个重新发现——嵌套仓库的增删交给监听，免得每次切回都把整个项目扫一遍；非仓库页的「刷新」、选中的仓库加载出来已不是仓库时整个重新发现。项目根 init 后显式重新发现。
- **按仓库的状态**：渲染端 git-store 每个仓库一桶状态，键是 `GitRepo.path`——项目自己的仓库为项目路径（原有的每项目设置、状态原样沿用），嵌套仓库为它的根目录。主进程的 git 读写接口本就以「在哪个目录跑 git」为参数，换成仓库目录即可；每仓库设置（显示开关、隐藏的远程、拉取方式等）按同一个键存。同一个仓库同时出现在几个项目里（嵌套仓库所在目录也登记成了项目）时共用一桶。移除项目时按路径清掉每仓库设置：在它目录里、又不在别的项目目录里的（没打开过的项目没找过嵌套仓库，不能靠清单）。
- **选中与记住**：选中的仓库按项目存在 `gitUi`（同 Files 的 `filesUi`），跨重启。记住的不在了按默认选：项目自己的仓库，没有则第一个。Tab 栏的分支名、自动获取都针对选中的仓库。
- **监听按仓库分发**：一个项目一条原生订阅（盯项目自己所在仓库的根，没有则项目目录）；gitdir 里的白名单元数据归那个仓库（一条路径可以同时在几个仓库的 gitdir 里，如主仓库与它的链接工作树），工作区路径归离它最近的仓库、在那个仓库里 `check-ignore`。子模块的变化顺带通知它的上级仓库（上级的工作区状态跟着变）。gitdir 在监听根之外的（链接工作树的公共 gitdir 等）各另起一条只驱动 git 通道的订阅。项目里任一仓库有写动作排队 / 执行中时，整个项目的通知挂起，转闲补发。
- **外层不含嵌套仓库**：解析 `status --untracked-files=all` 时去掉以 `/` 结尾的未跟踪条目（这种写法下只有嵌套仓库会这样出现），计数与未提交详情都不算它；「全部暂存」带 `:(exclude,literal)<嵌套仓库>` 排除。原先为「未跟踪目录整体条目」写的界面处理（不可点开 diff 等）随之去掉。子模块照常在外层显示为一条改动。
- **按文件所在的仓库**：Files Tab 的 Git 颜色取树根下全部仓库的未提交状态，按仓库根换算成相对树根的路径（落在树根外的丢掉），写文件后只作废它所在仓库的快照；编辑器改动条纹从文件所在目录查仓库根（git 查到的就是离它最近的仓库）。Git Tab 里「打开文件」「复制文件绝对路径」按仓库根拼路径；项目是仓库的子目录时，项目外的文件不在 Files Tab 的树里，「打开文件」不做任何事。
- **Task**：Git 动作的 Task 属于仓库（`repoPath`），渲染端经仓库清单找到所在项目（先当前项目，再按左树顺序）；任务清单里嵌套仓库的写「项目名 · 仓库名」，找回时选中那个仓库。交互式变基的终端开在所在项目、起在仓库目录。
- **仓库下拉**：版式见 DESIGN.md「Git 图谱」；项目里只有它自己所在的那一个仓库时不显示（`showsRepoPicker`）。项目根不是仓库时最上面一行「初始化 Git 仓库…」，对话框开在项目路径那一桶上，初始化成功即选中新仓库。

## Testing Decisions

- **发现**（真实 git 搭仓库）：嵌套仓库（没有提交的、深层的、普通目录里的、嵌套里再嵌套的）；被忽略的、隐藏目录里的、`node_modules` 里的不算；项目不是仓库时逐层找到、跳过隐藏目录与 `node_modules`；子模块记下上级、gitdir 在上级的 `.git/modules` 里、没检出的不算；项目是上层仓库子目录时只找项目里面的；项目目录被上层仓库忽略时不认上层仓库；重新发现的变化判断；只重查项目根时根没变不重新发现、项目根 init 后整个重新发现；没打开过的项目监听只拿到它自己的仓库、重新发现也只重查项目根，要过清单后才有嵌套仓库。
- **移除项目清设置**：在移除的项目目录里、又不在剩下项目目录里的仓库键才清（剩下的项目在它里面、或它在剩下的项目里面都留着）。
- **输出解析**：`ls-files --others -z` 只取以 `/` 结尾的条目；`.gitmodules` 的 path 值。
- **监听分类**：嵌套仓库的文件归它自己、gitdir 元数据只归它；子模块的 gitdir 元数据归子模块不归上级；主仓库与链接工作树都在项目里时任一工作树切分支两边都是元数据、链接工作树自己的 index 只归它；嵌套仓库所在目录被删或改名、某处新出现 `.git` 为重新发现；gitdir 没解析出来时按 `<根>/.git` 认。
- **调度**：git 通道按仓库攒路径、元数据只让该仓库强制刷新；探测只置重新发现；需重扫时全部仓库强制刷新并重新发现。
- **状态解析**：嵌套仓库条目不计入未提交条数、不进未跟踪列表；「全部暂存」按字面排除嵌套仓库（含通配符与空格的路径）。
- **共享纯函数**：默认选中、仓库下拉的显隐、路径归哪个仓库（含 Windows 盘符与反斜杠）。

## Out of Scope

- WebStorm 式把所有仓库的提交混在一张图里；跨仓库同时执行分支操作（「Execute branch operations on all roots」）
- 手动添加 / 忽略某个仓库（Git Graph 的「Add / Remove Git Repository」、VS Code 的 `git.ignoredRepositories`）；发现时跳过的目录名可配置
- 子模块的专门操作（更新、同步、初始化子模块）——照常在终端里做
- 没打开就预先加载项目里每个仓库的图谱（只加载选中的；切到哪个加载哪个）

## Further Notes

- 术语见 CONTEXT.md（Repository、Git Tab），取舍见 ADR-0060。工作树仍是「一个工作树目录就是一个 Project」（ADR-0028）；嵌套仓库的工作树同样经工作树下拉前往。
- 发现的代价：项目里每个仓库一次 `ls-files --others` 与一次 `.gitmodules` 读取，外加每个候选一次 `rev-parse`；不在仓库里的目录逐层读目录。只在第一次打开项目、`.git` 增删与手动刷新时发生，启动时不为没打开的项目发现。
