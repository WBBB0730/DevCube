## Problem Statement

仓库和下载文件夹里的 Excel 表格（数据导出、配置表、关卡清单）在 Files Tab 里只能看到「无法在此编辑此文件」占位，得跳去 Excel / WPS / Numbers 才能看内容。CSV / TSV 虽然能打开，却只是一堆逗号分隔的纯文本，列对不齐、带引号和换行的格子更难读。PDF、PPT 都已能内嵌预览，表格还是断的。

## Solution

打开 Excel 时在正文区内嵌一张只读表格：数字 / 日期 / 百分比按文件里的格式显示，合并单元格、冻结的行列、图表、图片都在；底部是工作表标签，点一下换表；Cmd/Ctrl+滚轮与触控板捏合按光标缩放、Cmd/Ctrl +/- 逐档、Cmd/Ctrl+0 回原倍率，手感与 PDF / PPT 一致；Cmd+F 在当前工作表里查找，命中格标黄、当前命中标橙并滚过去；可以选中格子、Cmd+C 复制；网址链接用系统浏览器打开。认 .xlsx 及同一格式的模板（.xltx）与带宏版本（.xlsm / .xltm，宏不执行），外加老式 .xls。超过 10 MB 的 Excel 不预览，给出「文件较大」与「在其他应用中打开」。

CSV / TSV 仍在编辑器里打开，工具栏多一个与 Markdown 相同的「编辑 ↔ 预览」切换；预览态显示成同一张表格，缩放、查找、选中复制都一样。格子一律按原文显示：`00123` 不丢前导零、长数字不变科学计数法、`=` 开头不当公式算。Markdown、SVG、CSV 三类可预览的源文件打开时都默认落在预览态，新建的空文件落在编辑态。

## Implementation Decisions

- 分流：主进程按魔数识别 SpreadsheetML 的四种 MIME（工作簿 / 模板，及两者的带宏版本）→ 打开类型 xlsx；老 .xls 与老 Word / PPT 同是 CFB 容器、魔数分不开，要内容是 CFB 且文件名是 .xls 才认（改了扩展名的其他老 Office 文件会在解析时失败、给出「无法预览」）。文件走既有 `dc-media` 协议 URL，同时带回文件大小供渲染层判断上限；渲染层一次取回交给库。扩展名表（五种）并入「文件打开方式」同一张表：打包时声明文件关联（角色 Viewer、优先级 Alternate），设置「系统集成 → 文件打开方式」多一个「Excel」子项，预览窗口的树顶类型筛选多一项「Excel」（CSV 仍归「文本」），文件树图标与 CSV 同为表格（`Table2`）；Linux 设默认用 freedesktop 登记的 MIME 原名。Excel 与 CSV 不进方向键切换的媒体序列——方向键归表格移动选中格。
- 渲染引擎：react-xlsx（@extend-ai/react-xlsx），只读、DOM 渲染（默认的画布渲染不画溢出到邻格的长文字、会丢居中的合并大标题）、页面线程解析（后台线程里没有 DOMParser，条件格式、表格样式、合并标题等靠 XML 结构的信息会悄悄丢掉；也省得在 `file://` 下起线程）。库自带工具栏与标签不用，工具栏、查找栏、工作表标签、快捷键、缩放是 DevCube 自己的。选型与各项取舍见 ADR-0034。
- 大小上限：页面线程解析时整个界面等它，900 KB 约 1.5 秒，所以 Excel 超过 10 MB 不解析，直接出占位（「文件较大 / 超过 10 MB 的表格不在此预览」+「在其他应用中打开」）。CSV 受编辑器 5 MB 的文本上限约束，不另设。
- WebAssembly：库的解析核心（@dukelib/sheets-wasm）是 WebAssembly。文件随应用打包（electron-builder extraResources 复制到 resources/xlsx，开发态直接读 node_modules），经 `dc-media` 的应用资源通道读取——与 PDF.js 的字体表 / wasm 同一条通道，通道泛化为按资源包声明放行路径（ADR-0030 的做法）。CSP 的 `script-src` 加 `'wasm-unsafe-eval'`（只放开编译 WebAssembly，不放开字符串求值）。库自带的解析线程脚本不用，但打包时仍要过它：渲染层打包的线程输出格式改为 ES 模块（默认的 iife 不支持线程里的动态 import）；打包产物因此多带一份用不到的线程脚本与 WebAssembly，见 ADR-0034。
- 主题：表格保持库的浅色（它的深色模式会把白字画到浅底上、边框也看不见），与 PDF / PPT 页面白底同理；四周与标签条随主题。
- 工作表标签：底部一条（高 32px、`--bg-panel`、顶边 `--separator`），每张表一颗按钮，当前表 `--selection-row` 底 + 正文色，其余 muted、hover `--bg-row-hover`；只有一张表时不出；隐藏的工作表不列。
- 缩放：库在 DOM 渲染下不接滚轮缩放，由 DevCube 驱动：Cmd/Ctrl+滚轮与捏合复用看图的倍率常量（与 PDF / PPT 同手感），按光标锚定；Cmd/Ctrl +/- 每档乘 1.1 后按 10% 取整（放大向上、缩小向下，同 PDF / PPT 的逐档规则），按视口中心锚定；Cmd/Ctrl+0 回工作表自带的倍率（工作表没写则 100%），锚在左上角。倍率范围用库的 10%–400%（同 Excel），库只收整数百分比，滚轮的连续倍率在我们这边累积、提交时取整。表格所有尺寸（行高、列宽、表头）都乘同一个倍率，所以锚点换算是「(滚动位置 + 锚点) × 新旧倍率比 − 锚点」；新倍率提交后在库自己按左上角换算滚动之后再覆盖成按锚点的位置。缩放按工作表各自记，换表后接着该表的倍率。
- 快捷键：Cmd+F / Esc / Cmd+0 / Cmd +/- 与 PDF / PPT 共用同一个键盘外壳（让路规则相同）；表格不给翻页与切文件回调，外壳就不接方向键，方向键留给表格。表格就绪时焦点交给表格（CSV 内容变化重建时不再抢焦点）。
- 查找：打开查找时把当前工作表已用范围里、未隐藏行列中有内容的格子连同显示文字（与表格上看到的一致）建一次索引，每次输入只在索引里匹配。建索引按已用范围逐格取文字（解析核心没有可用的「只列出有内容格子」的接口），耗时与已用范围的面积成正比：常规表格 50 万格约 0.4 秒，角落里有孤零零远处格子的表会明显变慢。查找有区分大小写 / 全词两个开关、无正则（同 PDF / PPT），全词的词界同编辑器——前后紧挨字母、数字、下划线（含中文）即不算，查询自身两端不是词字符时那一端不要求。一格只算一次，按行优先排序；首个命中取「打开查找 / 改查询时的选中格」及之后的第一个；上一个 / 下一个循环；换表后在新表里从头找。高亮用库的逐格样式接口，在格子原有底色之上叠一层半透明色（命中黄 / 当前橙，同 PDF / PPT 的两种色），不盖掉格子自己的渐变填充；当前命中选中并滚入视口，滚动规则同方向键移动选中格（滚到刚好完整可见、不被冻结窗格挡住）——库的「选中格子」原本不滚动，以 pnpm 补丁给它加了 `reveal` 选项。
- CSV / TSV：用 Papa Parse 解析（.csv 自动识别分隔符、.tsv 固定制表符；去掉 BOM 与末尾换行造成的空行，中间的空行保留），每格按原文字符串写进一个新工作簿（不走引擎自带的 CSV 导入——它会把 `00123` 转成数字、也不认 TSV），带换行的格子设自动换行（同 Excel 打开 CSV），列宽按每列最长一行的显示宽度估算（全角算两个字符、加一个字符留白，下限 Excel 默认列宽、上限 50），再存成 xlsx 字节交给同一个预览。不固定首行（同 Excel 打开 CSV）。预览的内容是编辑器当前的文字；预览态下内容变了（如外部修改）重新转换，转好前保留旧表不闪空白。
- 编辑 ↔ 预览两态：Markdown / SVG / CSV 共用一个会话内的开关，默认预览；新建文件时切回编辑（空文件在预览里没什么可看）；切到预览前先落盘（既有行为）。
- 字体与图标集：库原先缺字体时一律补无衬线备选，宋体表格会被画成黑体。改为按原字体风格补同风格备选（等宽 / 衬线——中文宋体类优先 / 其余无衬线），规则同 PPT 预览那次；条件格式的图标集没写样式时按 OOXML 规定默认三色交通灯（原先整条规则被丢掉）。两处与「选中后滚入视口」「大表取数」一起以 pnpm 补丁修在库上，见 ADR-0034。
- 大表滚动：库在页面线程按「视口上下各多 48 行」整批向解析核心取格子数据（含样式），但把冻结行也算进范围、且每滚一步整批重取，带冻结表头的大表越往下越卡（4000 行的表底部每帧近 1 秒）。补丁改为只按滚动区算范围（冻结行走逐格读取），并按 128 行一块对齐、块内滚动沿用已取的行：各处滚动每帧约 17 毫秒，跨块那一帧约 0.1 秒。
- 链接：库以 `window.open` 打开格子里的网址，走 Chromium 开窗请求 → 主进程开窗守卫 → 系统浏览器（同 PDF / PPT）；指向本工作簿其他格子的内部链接由库自处理。

## Testing Decisions

- 分流：四种 SpreadsheetML MIME → xlsx、CFB 容器仅文件名是 .xls 才认（`files-kind.test.ts`）；Excel 扩展名判定、CSV / TSV 判定、可切预览的源文件含 CSV、方向键媒体序列不含表格（同上）；文件树图标（`files-tree-icon.test.ts`）；预览窗口类型筛选归「Excel」、CSV 归「文本」（`files-type-filter.test.ts`）。「文件打开方式」的注册与设默认是逐类遍历同一张表的既有逻辑，新增一类不另配单测，注册效果装打包版人工验证。
- 纯逻辑表驱动单测（`files-sheet.test.ts`）：列名换算、CSV 解析（分隔符识别、TSV、引号里的逗号与换行、BOM 与末尾空行）、列宽估算、CSV 转工作簿后格子保持原文且无公式、换行格自动换行、列宽写入；查找匹配（大小写、全词含中文与非词字符两端、一格一次、空查询）、从选中格起的首个命中；逐档与滚轮倍率、按锚点缩放后的滚动位置。转换测试在 Node 里直接初始化同一份 WebAssembly 跑真实引擎。
- 补丁（字体风格、图标集默认、选中后滚入视口、大表取数）与渲染是第三方代码与浏览器行为，不在本仓库配单测；取数修正前后在 5 个文件、14 张工作表、每张 4 个滚动位置逐格比对了文字与样式（约 8.8 万格），完全一致，并在真实应用的正式构建里测过大表顶部 / 中部 / 底部的滚动帧间隔；在临时页面里挂上真实组件用无头浏览器实测过：加载与标签切换、滚轮缩放后光标下仍是同一格、键盘缩放后视口中心仍是同一格、查找高亮 / 计数 / 上下一个 / 关闭后清除、查找滚到远处的命中、CSV 原文与换行、TSV、10 MB 占位、老 .xls。WebAssembly 经 `dc-media` 加载与 CSP 需在应用里人工验证。

## Out of Scope

- 格子内分段的富文本颜色、文字旋转（库尚未画出，要改得深入其内部）。
- 编辑、保存、导出、打印。
- GBK 等非 UTF-8 编码的 CSV：编辑器目前按 UTF-8 读，打开就是乱码，预览同样；要从读取文件那一层改，会影响编辑器保存，另做。
- 跨工作表的全工作簿查找、正则查找、替换。
- 超过 10 MB 的 Excel；后台线程解析（见上）。
- .xlsb 二进制工作簿、Numbers、ODS。

## Further Notes

- 选型的实测对比（react-xlsx / FortuneSheet + FortuneExcel / File Viewer 的表格模块）与各项取舍见 ADR-0034；补丁内容见仓库的 pnpm 补丁文件，升级库版本时须重做或随上游修复删除。
- react-xlsx 与其解析核心都还年轻（0.x、主要一人维护），出问题可能只能靠补丁；这是在「效果最好」与「最稳」不是同一个库时做的选择。
