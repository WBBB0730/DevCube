## Problem Statement

在 DevCube 里浏览项目时，只能按文件名筛选文件树，无法按「文件里写了什么」找东西。想找一段代码、一个配置项、一处 TODO，只能切去 IDE 或终端 grep，破坏了「在一个面板里完成日常操作」的体验。

## Solution

⌘⇧F（Windows/Linux Ctrl+Shift+F）呼出 **Content Search**（内容搜索）浮层面板，在当前 **Project** 内按文本搜索文件内容：边敲边搜、结果按文件分组并高亮命中词、选中即见只读预览，回车或双击经 **Files Tab** 打开文件并定位选中命中处。大小写 / 全词 / 正则 / 文件掩码四个开关对齐 IDE 的 Find in Files。

## User Stories

1. 作为开发者，我想用 ⌘⇧F 在当前项目内搜索文件内容，以便不离开 DevCube 找代码。
2. 作为开发者，我想边敲字边看到结果流式出现，以便不必按回车等全量结果。
3. 作为开发者，我想结果默认按文件分组（文件行 = 图标 + 名称 + 目录 + 跟随其后的计数徽标），命中行显示该行内容（整行语法着色、高亮命中词）与行尾行号，以便一眼判断是不是要找的。
4. 作为开发者，我想选中某条结果就在面板底部看到该文件的只读预览并定位到命中行，以便不用打开文件就能确认上下文。
5. 作为开发者，我想回车或双击结果后切到 Files Tab 打开该文件、滚到该行并选中命中区间，以便直接接着编辑。
6. 作为开发者，我想有「区分大小写 / 全词匹配 / 正则」三个开关，以便控制匹配精度。
7. 作为开发者，我想用文件掩码（如 `*.ts`，逗号分隔多个）收窄搜索范围，以便排除无关文件类型。
8. 作为开发者，我想正则写错时看到明确的错误提示而不是空结果，以便知道是我写错而非无匹配。
9. 作为开发者，我想搜索自动跳过 gitignore 与 IDE 忽略项（与树顶过滤同口径），以便 `node_modules` 不刷屏。
10. 作为开发者，我想结果封顶并提示「请细化搜索」，以便宽泛查询不拖垮应用。
11. 作为开发者，我想用 ↑↓ 在结果间移动、Esc 关闭面板，以便全程不碰鼠标。
12. 作为开发者，我想改查询或开关后旧结果保留到新结果到达，以便打字过程不闪空白。
13. 作为开发者，我想同一项目内面板重开时恢复上次的搜索词与开关，以便接着上次的思路继续；切到别的项目则从干净状态开始，互不串扰（会话内、不落盘）。
14. 作为开发者，我想搜索中看到进行中提示、无结果时看到「无匹配结果」，以便区分「还在搜」与「没有」。
15. 作为开发者，我想二进制 / 超大文件在预览区显示占位而不是乱码或卡顿，以便面板始终可用。
16. 作为开发者，我想换一个词搜索时旧搜索立即作废，以便结果永远对应当前查询。
17. 作为开发者，我想在状态行用开关切换「按文件分组 / 平铺」视图（平铺时每行行尾显示文件名与行号），以便按场景选择浏览方式；该视图选择随搜索词一起按项目会话内记忆。
18. 作为开发者，我想点击文件行收起 / 展开该文件的命中（↑↓ 导航跳过收起项，新一轮搜索恢复全展开），以便在多文件结果里聚焦关心的文件。

## Implementation Decisions

- **形态**：全屏遮罩 + 居中浮层（复用对话框族外壳），非 Tab、非第二窗口；同一时刻至多一个，作用于当前 Project。快捷键经主进程 before-input-event 拦截下发（同其它应用快捷键），面板开关状态放应用级 store。
- **引擎**：主进程 spawn ripgrep `--json`（复用 ADR-0027 引入的 @vscode/ripgrep 二进制），流式解析后按批（30ms 合批）经 IPC 推送渲染端；搜索单例——新搜索自动 kill 旧进程；封顶（1 万条）即杀进程并标记 limitHit。渲染端以自增 seq 收敛：迟到的旧代事件一律丢弃。
- **匹配选项映射**：大小写 → `-s`/`-i`；全词 → `-w`；非正则 → `-F` 字面量；文件掩码 → 逗号拆分逐个 `-g`。查询经 `--` 保护（可搜以 `-` 开头的文本）。gitignore / 隐藏文件 / IDE 忽略名口径与文件名索引一致（`--hidden` + 剪枝 `.git` + 按路径段后滤 IDE 忽略名）。
- **结果解析**（共享纯函数，可测）：rg submatch 的字节偏移换算为 UTF-16 字符偏移；展示文本去行尾换行与首缩进、超长按首个命中开窗截断（加省略号），展示区间随之平移；原始行内的首个命中区间（col/endCol）单独保留供跳转选中。非 match 事件、二进制 / 非 UTF-8 行（base64 形态）跳过。
- **错误面**：rg 退出码 0/1 与封顶 kill 均为正常；退出码 2（如正则无效）取 stderr 拼一行提示展示在状态行。
- **跳转**：Files 挂起打开机制扩展为「路径 + 可选定位（行 / 列区间）」；FilesPane 消费后打开文件、Markdown 强制回编辑态，编辑器就绪后选中命中区间并滚至居中。
- **预览**：选中结果换文件时经既有「读文件」通道取全文，只读 CodeMirror（复用编辑器主题 / 语法高亮 / 语言推断）+ 活动行高亮 + 滚至命中行；非文本结果占位。顶部标题栏显示文件名与目录；与列表五五开分栏、分隔线可拖，每次打开面板重置五五开（不持久化）。
- **列表**：虚拟滚动（同文件树，行高固定），两种可切换视图——按文件分组（文件汇总行 + 命中行，默认）与平铺（行尾「文件名 行号」，连续同文件淡化文件名）；行号 / 目录 / 计数等附属信息统一 infoForeground 灰；行文本整行按语言做单行语法着色（脱离全文的近似解析，跨行结构容忍），命中片段盖胶囊且不透语法色；计数「N 处匹配 · M 个文件」由渲染端从已收结果计算。

## Testing Decisions

- 纯函数层，先例：`files-tree-search` / `app-shortcut` 的 vitest「构造输入 → 断言输出」。
  - **rg 参数组装**：给定查询 + 选项 → 参数数组（开关映射、掩码拆分、`--` 保护、显式搜索路径）。
  - **rg JSON 行解析**：match 事件 → 结构化命中（字节→字符偏移含多字节字符、去缩进平移、超长开窗、非 match / base64 / 坏行 → null）。
  - **快捷键匹配**：⌘⇧F 命中内容搜索且不与 ⌥⌘F / ⌘F 混淆。
- **引擎集成测试**（仓库首例破除「纯函数 only」口径，理由：spawn 环境特有的 bug——rg 对非 TTY stdin 的「从 stdin 搜」语义、收尾批次因存活守卫被丢——纯函数测试原理上覆盖不到）：spawn 真实 rg 打临时 fixture 目录，断言事件流外部行为——瞬时完成不丢结果（回归）、IDE 忽略名过滤、封顶恰好上限、新搜索取代旧搜索、大小写 / 全词 / 掩码、无匹配、正则错误。
- 不写面板 UI 的 e2e（与仓库既有口径一致）。

## Out of Scope

- 批量替换（Replace in Files）——单独立项
- 搜索范围选择器（仅某目录 / 自定义 scope）；固定当前项目
- 搜索历史下拉、跨项目搜索、结果导出
- 命中词在预览区内的逐词高亮（预览只做活动行高亮 + 定位）
- 搜索词 / 开关跨重启持久化（仅会话内记忆）
