# compress

**压缩**

## Problem Statement

把文件或文件夹打成 zip 发给别人时，系统自带的压缩有几处不顺手：

- Finder 多选压缩时，包名一律是「归档.zip」，看不出装的是什么。
- Finder 压出的包会夹带 `__MACOSX`、`._文件名`、`.DS_Store` 这类只有 Mac 认得的文件，在 Windows 或 Linux 上解开就是一堆杂物。
- 压一个项目时，`node_modules`、构建产物、`.env` 会一并装进去：包很大，还可能带出密钥。Finder 和 Windows 资源管理器都不能按 .gitignore 排除。
- 在 DevCube 里浏览项目文件时没有压缩入口，要先到 Finder 或资源管理器里找到它。

## Solution

新增「压缩」，有三个入口：**Files Tab**（含 **Preview Window**）文件树右键「压缩」、macOS Finder 快速操作「用 DevCube 压缩」、Windows 资源管理器右键「用 DevCube 压缩」。三个入口都弹出同一个独立的小窗口（压缩窗口），在里面可以：

- 改包的名称和存放位置；
- 排除被 Git 忽略的文件、排除 `.git`、排除 Mac 专属文件；
- 预览将装入多少文件、共多大。

点「压缩」后，按钮本身显示进度，可以取消；压完窗口自动关闭。只产出 zip。

## User Stories

1. 作为用户，我想在 **Files Tab** 文件树里右键任一文件或文件夹选「压缩」，以便不离开 DevCube 就能打包。
2. 作为用户，我想在 **Preview Window** 的文件树里同样能右键压缩，以便两处行为一致。
3. 作为 macOS 用户，我想在 Finder 里选中一个或多个文件、文件夹，经「快速操作」→「用 DevCube 压缩」压缩，以便替代 Finder 自带的压缩。
4. 作为 Windows 用户，我想在资源管理器里选中一个或多个文件、文件夹，右键选「用 DevCube 压缩」（Windows 11 上在「显示更多选项」里），以便和 macOS 一样顺手。
5. 作为用户，我想在设置「系统集成」里自己决定是否添加 Finder 和资源管理器的压缩入口，以便系统菜单里只出现我要的东西。
6. 作为用户，我想 DevCube 没开着时从系统入口压缩，只弹出压缩窗口、不弹出主窗口，压完 DevCube 自动退出，以便它像系统压缩一样用完即走。
7. 作为用户，我想 DevCube 开着时从系统入口压缩，压缩窗口出现在最前面、一出来就能打字和按回车，以便马上开始。
8. 作为用户，我想名称已经替我填好（单个条目用它自己的名字，多选用它们所在文件夹的名字），以便多数时候直接回车。
9. 作为用户，我想预填的名称自动避开已存在的同名包，以便不会误覆盖。
10. 作为用户，我想能改名称，以便按需要命名。
11. 作为用户，我想把名称改成一个已存在的包名时，点「压缩」先问我是否替换，以便不会悄悄覆盖。
12. 作为用户，我想包默认放在被压缩内容所在的文件夹、也能换位置，以便和系统压缩的习惯一致，又能直接放到想要的地方。
13. 作为用户，我想默认就按项目自己的 .gitignore 排除依赖、构建产物和 `.env` 这类文件，以便发给别人的包干净又安全。
14. 作为用户，我想排除规则与 Git 完全一致（已跟踪的文件即使匹配也保留），以便包里的内容和 Git 眼中的项目一致。
15. 作为用户，我想只有在要压的内容位于 Git 仓库内、或里面包含仓库时，才出现这个勾选框，以便压普通文件夹时界面里没有用不上的选项。
16. 作为用户，我想要压的内容里有 `.git` 时能选择排除它（默认排除），以便发给别人的包不带仓库历史。
17. 作为用户，我想「排除 Mac 专属文件」默认勾上，以便包在别的系统上解开也是干净的。
18. 作为用户，我想只有当要压的内容里确实有 Mac 专属文件时才出现这个勾选框，以便压单个文件或干净的文件夹时不多一个用不上的选项。
19. 作为用户，我想这几个勾选框记住我上次的选择，以便不用每次重新勾。
20. 作为用户，我想看到一行预览「将装入 N 个文件，共 X MB」，并随勾选变化，以便压之前心里有数。
21. 作为用户，我想按回车直接压缩、按 Esc 关闭窗口，以便不碰鼠标也能完成。
22. 作为用户，我想点「压缩」后看到进度、随时可以取消，以便压大文件夹时知道进展、也能反悔。
23. 作为用户，我想取消或失败后不留下压了一半的包，以便重试时不撞上残缺文件。
24. 作为用户，我想压缩成功后窗口自动关闭、不弹任何提示，失败时弹出错误框说明原因。
25. 作为用户，我想符号链接作为链接本身存进包里（与 Finder 和 Git 一致），以便解开后还是链接，也不会把链接指向的大量内容重复装进去。
26. 作为用户，我想空文件夹也被保留（被排除的除外），以便解开后的目录结构完整。
27. 作为用户，我想压单个文件夹时包里顶层就是这个文件夹，多选时各项并列在包的顶层，以便与 Finder 的习惯一致。
28. 作为用户，我想可以同时开几个压缩窗口，以便连续压几样东西不用等。
29. 作为用户，我想压缩期间 DevCube 其他界面照常可用，以便压大文件夹时不卡住。

## Implementation Decisions

**入口**

- **文件树**：只在本机宿主的文件树里出现（项目的 **Files Tab** 与 **Preview Window**），服务器的 **Files Tab** 不加。菜单项「压缩」放在「复制文件 / 复制文件夹」之后。文件树不支持多选，这里一次只压一个条目。
- **macOS 快速操作**：沿用 ADR-0025 生成 `.workflow` 的机制，另生成一个「用 <ProductName> 压缩」，接收文件与文件夹。脚本以参数接收全部选中项，用系统自带的 `osascript`（JavaScript）按 URL 编码拼成 deep link `<scheme>://compress?path=…&path=…`，经 `open -g` 一次交给 DevCube（只触发一次 `open-url`，没在运行时也会被拉起）；`-g` 让投递时先不切到前台，由压缩窗口显示时再到前台。不走 `open-file`：Electron 对多个文件会逐个发事件，主进程无从知道这一批是否到齐。
- **Windows 资源管理器**：原生经典右键扩展，多选时一次交付全部路径，以启动参数 `--compress <路径…>` 交给 DevCube（命令行装不下时改传临时目录里的清单文件 `--compress-list=<文件>`；只认按约定命名的文件，读完即删），已在运行时经单实例转发（ADR-0049）。
- **设置「系统集成」**新增两行，沿用既有句式：macOS「在 Finder 的「快速操作」中添加「用 <ProductName> 压缩」」，Windows「在资源管理器的右键菜单中添加「用 <ProductName> 压缩」」。状态实时探测，与既有各行一致。Linux 不加文件管理器入口。
- 三种入口在主进程汇成同一个动作：带一组路径打开一个压缩窗口（**External Open** 的「压缩」动作）。

**压缩窗口**

- 独立窗口，不挂在主窗口里：一次压缩一个窗口，可以多开。冷启动只为压缩时不创建主窗口；最后一个压缩窗口关闭、且期间用户没有打开主窗口时，退出应用。
- 压缩窗口一显示就接管键盘，DevCube 随之到前台。macOS 上应用一到前台就会把它的主窗口一起带出来（系统规则），所以主窗口会同时出现在压缩窗口后面，顺着它做。不用面板窗口：会一直浮在所有窗口上、出现在每个桌面，且 macOS 27 上点一下照样把应用切到前台（Electron 未修）；也不只把压缩窗口放到最上面、不切前台：那样要先点一下窗口才能打字、按回车。
- 窗口尺寸固定，按内容最多时（名称、位置、三个勾选框、底栏）定好，之后不再改变；建好即显示、以主题底色铺底。标题、默认名称与位置由主进程建窗前算好、经查询串传入，上次的勾选取启动快照里的偏好。
- 内容自上而下：顶栏标题「压缩 “名字”」（多选为「N 项」）、名称（输入框 + `.zip` 后缀）、位置（路径输入框 + 选择文件夹按钮，同克隆对话框）、勾选框（按适用条件出现；「排除 Mac 专属文件」名字旁的信息图标悬停列出是哪些文件）、底栏（左侧预览行，右侧「取消」+「压缩」主按钮）。视觉沿用小对话框的控件。
- 默认名称：单个条目取其名（文件含扩展名，`report.pdf` → `report.pdf.zip`）；多选取共同上层文件夹名。Finder 列表视图里可以跨子文件夹多选，所以取「共同上层」而不是「所在文件夹」。默认位置同理取共同上层文件夹。目标已存在时，预填名依次加「 (2)」「 (3)」……避开，编号格式与终端默认名共用同一个函数，全应用统一。
- 勾选框的出现条件与默认值：
  - 「排除被 Git 忽略的文件」：内容在仓库内或包含仓库时出现；首次默认勾上。找不到 git 时不出现。
  - 「排除 .git」：内容里有 `.git`（含子模块的 gitlink 文件）时出现；首次默认勾上。
  - 「排除 Mac 专属文件」：内容里有这些文件时出现（各平台一样）；首次默认勾上。
  - 三者都记住上次的选择（全局，不分路径）。
- 加载：第一次统计回来之前，窗口里只有一个转圈；回来后名称、位置、勾选框、预览、按钮一起出现，不一部分先出、一部分后跳。勾选框那块按三个都出现时的高度留好，出现几个都不改变窗口尺寸；勾选框随统计结果出现或消失（如取消「排除被 Git 忽略的文件」后，被忽略的文件夹里的 Mac 专属文件进入内容，「排除 Mac 专属文件」随之出现，勾回去又消失），新结果回来前保持原样。之后改勾选重新统计时，只有预览行转圈并显示「正在统计…」，「压缩」照样可按，用当前的勾选。读不了（如没有权限）时弹错误框「无法读取」，预览行留空。
- 名称改成已存在的包名时，点「压缩」先弹确认（替换 / 取消）。
- 压缩中：主按钮显示进度百分比，其余控件禁用；「取消」与 Esc 都是关窗，关窗等同取消。成功即关窗，不提示；失败弹错误框「压缩失败」，窗口回到可编辑状态。

**清单**

- 只选一个时，它本身总会装进去（明确选了它），排除规则只作用于它里面的内容；多选（如在 Finder 里全选一个文件夹的内容）等同于压它们所在文件夹的内容，所选条目本身也按规则处理——所在文件夹在仓库里时，把全部所选条目交给 `git ls-files`（按字面匹配、分批传）一次列出。同时选了文件夹和它里面的条目时（Finder 列表视图可以），去掉被包含的那些：选了文件夹就已包含里面的内容。不跟随符号链接：符号链接作为链接条目，空文件夹作为目录条目；套接字、FIFO 等特殊文件不装（读不了，git 也不列）。
- 「被 Git 忽略」交给 git 自己判定：仓库里的内容用 `git ls-files --cached --others --exclude-standard` 列出（已跟踪的加上未跟踪且没被忽略的），所以嵌套 .gitignore、全局排除、`info/exclude`、「已跟踪的文件不算忽略」（包括被忽略的目录里强制提交的文件）都与 Git 一致；嵌套仓库（子模块或未跟踪的仓库）只给出入口，其下按它自己的规则列。git 不列目录：目录由文件路径补齐；空文件夹从已列出内容的目录（嵌套仓库除外，它的空文件夹由它自己那一轮补上）往下找没列到的子目录，逐层交给 `git check-ignore --stdin -z` 判定，没被忽略的补上，被忽略的整支跳过、不进去遍历；多选时只在所选条目里面找（跨子文件夹多选时，为补路径加上的上层目录里还有没选的内容）。macOS 上 git 把文件名转成合成形式（core.precomposeUnicode），读目录与系统给的路径是磁盘原样，先转成合成形式再与 git 列出的路径比较、交给 git 判定。
- 仓库判定：所选文件夹用 `git rev-parse --is-inside-work-tree`；不在仓库里的部分遍历磁盘，遇到有 `.git` 且 git 认的文件夹即为仓库，改由 git 列出；指向已不存在位置的 `.git` 文件（主仓库已删的 worktree、从父仓库拷出来的子模块）按普通文件夹遍历。不在任何仓库里的部分不做忽略判定。
- Mac 专属文件的认法：`__MACOSX` 文件夹按名字认（只有 Mac 的压缩工具会生成这个名字），连同里面的内容；`.DS_Store` 与 `._` 开头的文件，名字对得上还要文件头对得上才算——AppleDouble 以 00 05 16 07 开头（RFC 1740），`.DS_Store` 以 00 00 00 01 "Bud1" 开头；名字像、内容不对的（如自己起名叫 `._notes.txt` 的普通文件）照常装。
- `.git` 与 Mac 专属文件在清单里只做标记，勾选变化时在内存里过滤；「排除被 Git 忽略的文件」的两种取法各缓存一份清单。
- 读写用户的文件一律用 `original-fs`（Electron 改装过的 fs 会把 `.asar` 文件当成文件夹往里读），压缩时 `.asar` 就是一个普通文件（ADR-0051）。
- 不复用 ripgrep 文件索引（ADR-0027）：实测 `rg --files` 不列符号链接与空文件夹，也不区分已跟踪的文件。
- 预览与压缩用同一套判定，压缩按当时的勾选重新生成清单（磁盘可能已变）。

**写包**

- 用 yazl 写包，放在 worker 线程里，压缩时主进程与界面照常响应（ADR-0050）。进度按扫描时的总字节数估算，封顶 99%，写完才算完成。
- 先写到目标文件夹下的隐藏临时文件，完成后改名为最终名称；取消或失败时删除临时文件，退出 DevCube 时也一样。需要替换时，到改名这一步才替换旧包。
- 勾选记在应用偏好里，开始压缩时写入。

## Testing Decisions

只测外部可见的行为，IO 经依赖注入隔离（同 `system-integration.md` 的做法）：

- 纯函数：默认名称与位置的推导（单个文件 / 单个文件夹 / 多选 / 跨子文件夹多选 / 重名递增）、去掉被包含的所选条目、Mac 专属文件与 `.git` 的匹配、deep link 与启动参数里压缩请求的解析（含清单文件只认约定命名）、勾选框的出现条件、快速操作与 Windows 注册表参数的生成。
- 清单：在临时目录里搭仓库现场测判定结果（隔离用户的全局 / 系统 git 配置），覆盖嵌套仓库与子模块（含其中的子文件夹）、已跟踪但在被忽略目录里的文件、整个未跟踪的新文件夹里的空文件夹与被忽略的 `node_modules`、符号链接、特殊文件、仓库外的 .gitignore 不生效、git 不认的 `.git`、macOS 上分解形式的文件名、条目不重复、中途取消，以及多选（全选仓库根目录的内容）时所选条目本身按规则处理、跨子文件夹多选时没选的内容不装。
- 产物：读回生成的 zip，确认符号链接是链接条目、文件名是 UTF-8、没有 Mac 专属文件、单个文件夹时顶层是该文件夹。
- 不为 Finder / 资源管理器菜单写端到端测试，按下面的实测清单手测。

## Out of Scope

- 其他格式（7z、tar 等）、压缩级别、密码、分卷、压缩后删除原文件、每项单独压成一个包、预设、自定义排除规则，以及字典、线程等专家选项。
- 服务器 **Files Tab** 的压缩。
- 文件树多选。
- Windows 11 一级右键菜单：需要受信任的签名（ADR-0049）。
- macOS FinderSync 一级右键菜单（ADR-0025）。
- Linux 文件管理器入口。
- Windows ARM64 上的资源管理器扩展（Windows 只发 x64）。
- 解压（系统自带的已够用）。

## Further Notes

macOS 上已验证：快速操作拼出的 deep link 对含空格、中文、`&` 的路径编码正确；产出的包用 `ditto -x -k`（与 Finder 同族的解压）解开后符号链接、中文文件名、空文件夹都还原正确，没有 Mac 专属文件。

待实测：

- macOS：Finder 多选时快速操作是否一次收到全部选中项；Dev 身份下经 `open -a <Electron.app> <deep link>` 投递是否收得到（Dev 不注册协议，见 ADR-0025）；从 Finder 唤起时压缩窗口与主窗口同时出现、压缩窗口在最前且能直接打字、按回车。
- Windows：多选一次 `Invoke`（含超过 15 项、超过 100 项）；Windows 10 与 Windows 11「显示更多选项」里都出现；升级后 DLL 替换不被资源管理器占用阻塞；便携版可用；命令行超长时走清单文件。
- 含 `node_modules` 的大项目：取消勾选「排除被 Git 忽略的文件」后，预览统计的耗时。
